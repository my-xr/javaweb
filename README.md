## 二、课程定位与设计理念

### 2.1 课程定位

本课程**不采用**传统 JavaWeb 教材的老旧路线（HTML/CSS/JS → JSP → Servlet → JDBC → 传统 MVC → 老式 SSM XML 配置）作为主线。上述内容仅作为背景与底层原理适度讲解，帮助学生理解"为什么现代后端开发是这样做的"。

课程采用**现代企业后端开发思路**，以"从需求到接口、从接口到业务、从业务到数据库、从开发到部署"为主线，帮助学生完成从"会写 Java 程序"到"能开发规范后端系统"的能力跃迁。

**课程主线**：

```
HTTP 请求 → Controller 接收请求 → Service 处理业务逻辑
        → Mapper/DAO 访问数据库 → 返回 JSON 数据
        → 接口调试与前后端联调 → 打包部署
```

### 2.2 八大设计理念

| 序号 | 理念 | 落地方式 |
| --- | --- | --- |
| 1 | PBL 项目化教学导向 | 以"校园实训任务管理系统"贯穿全程，知识点服务于项目任务 |
| 2 | 产教融合导向 | 内容贴近 Java 后端岗位能力要求，体现接口开发、分层、认证、部署等能力 |
| 3 | 理论实践结合 | 每模块配套实践任务、课堂练习或阶段性项目成果 |

| 5 | 避免技术堆砌 | 围绕一个完整后端项目所需核心技术组织内容，不追求面面俱到 |
| 6 | 就业能力导向 | 教学与习题结合岗位工作任务与面试考点 |
| 7 | 课堂持续互动 | 每次课设明确互动任务，用问题/案例/代码/接口设计/小测验激活参与 |
| 8 | 课程思政自然融入 | 思政结合真实开发场景（数据安全、隐私、责任、协作、质量），不空泛拔高 |

### 2.3 能力递进路径

## 三、课程目标

### 3.1 知识目标

1. 理解 B/S 架构、前后端分离、HTTP 协议、RESTful API 设计思想。
2. 掌握 Spring Boot 项目结构、Maven 依赖管理、配置文件与自动装配基础。
3. 掌握 Controller 层请求映射、参数接收、JSON 响应的处理方法。
4. 掌握 MyBatis / MyBatis-Plus 持久层开发，包括 Mapper 接口、SQL 映射、动态 SQL、条件查询与分页。
5. 理解并掌握 Controller / Service / Mapper 三层分层架构及 DTO / VO / Entity / Result 的职责划分。
6. 掌握参数校验、统一异常处理、统一响应结果、接口文档等工程规范。
7. 掌握基于 JWT 的登录认证与拦截器实现，理解 Session 与 Token 认证差异。
8. 理解 Maven 打包、Spring Boot 部署、配置文件管理与数据库初始化脚本。

### 3.2 能力目标

1. 能够独立搭建 Spring Boot 后端项目并完成接口开发。
2. 能够根据业务需求设计数据库表并编写 Mapper 与 SQL。
3. 能够按企业规范完成分层架构与接口设计，编写可维护的后端代码。
4. 能够实现用户注册登录、JWT 认证、登录拦截与简单角色权限控制。
5. 能够完成一个具备完整业务流程的后端项目（含多表关联、条件查询、分页、增删改查、权限控制）。
6. 能够使用 Apifox / Postman / Knife4j 进行接口调试与文档编写。
7. 能够完成项目打包、部署与演示答辩，提交完整交付物。

### 3.3 素质目标（课程思政）

1. 树立工程伦理与软件质量责任意识，编写规范、可维护、可测试的代码。
2. 培养数据安全与用户隐私保护意识，在认证、存储、传输各环节审慎处理敏感数据。
3. 培养工匠精神与代码规范意识，追求高质量交付。
4. 培养团队协作与职业素养，理解接口契约、文档规范对协作的意义。
5. 增强自主可控软件技术认同感，了解国产开源框架与自主创新生态。
6. 树立服务社会、解决真实问题的工程价值观。

| 拦截 | `HandlerInterceptor` | 登录拦截器 |
| 接口文档 | Knife4j（Swagger 增强） | 在线接口文档与调试 |
| 接口调试 | Apifox / Postman | 课堂演示与学生练习 |

## 五、贯穿课程项目设计

### 5.1 项目名称

**校园实训任务管理系统（Campus Training Task System，CTTS）后端**

### 5.2 项目选型理由

1. **场景真实**：贴合高校实训管理实际业务，学生易理解、有代入感。
2. **业务完整**：覆盖用户、项目、任务、提交、评审等多实体多表关联业务。
3. **角色多元**：学生、教师、管理员三种角色，天然支撑权限控制教学。
4. **状态流转**：任务有"未开始/进行中/已提交/已评审"等状态，体现业务逻辑复杂度。
5. **可扩展**：便于在课程不同阶段逐步增量构建，契合 PBL 能力递进。
6. **可演示**：最终成果可运行、可调试、可部署、可答辩。

### 5.3 系统角色与核心业务

| 角色 | 核心功能 |
| --- | --- |
| 管理员 | 用户管理（增删改查、分配角色）、实训项目管理、系统统计 |
| 教师 | 创建/维护实训项目、发布任务、评审学生提交、查询进度 |
| 学生 | 查看实训项目与任务、提交任务成果、查看评审反馈、查询个人成绩 |

### 5.4 核心数据表（初步设计，细节在各次课中逐步完善）

| 表名 | 说明 | 关键字段 |
| --- | --- | --- |
| `sys_user` | 用户表 | id, username, password, name, role, phone, create_time |
| `training_project` | 实训项目表 | id, title, description, teacher_id, start_date, end_date, status |
| `task` | 任务表 | id, project_id, title, description, deadline, score |
| `task_submission` | 任务提交表 | id, task_id, student_id, content, submit_time, status |
| `task_review` | 评审记录表 | id, submission_id, teacher_id, score, comment, review_time |

### 5.5 项目八阶段构建（与课程模块对应）

| 阶段 | 对应模块 | 阶段成果 |
| --- | --- | --- |
| 阶段 1 | 模块 1-2 | 理解需求，搭建 Spring Boot 项目，完成首个 Hello 接口 |
| 阶段 2 | 模块 2 | 完成基础查询接口（模拟数据返回 JSON） |
| 阶段 3 | 模块 3 | 设计数据库表，完成持久层 CRUD |
| 阶段 4 | 模块 4 | 改造为三层架构，抽离 Service / Mapper / Entity |
| 阶段 5 | 模块 3-5 | 完成条件查询、分页查询、动态 SQL |
| 阶段 6 | 模块 5 | 完成参数校验、统一响应、全局异常、接口文档 |
| 阶段 7 | 模块 6 | 完成用户注册登录、JWT 认证、登录拦截、角色权限 |
| 阶段 8 | 模块 7-8 | 完成综合业务整合、打包部署、文档提交、答辩 |

## 七、48 学时课程进度总览（24 次课）

> 下表为每次课的概要信息，详细的"知识点 / 互动 / 思政 / 练习题 / 课后任务"将在 `01` ~ `24` 各文档中逐次展开。

### 模块 1：Web 后端开发认知

#### 第 1 次课（理论）— Web 后端开发认知与课程项目导入
- **主题**：什么是后端开发；B/S 架构与前后端分离；后端岗位与企业项目流程；课程项目导入
- **知识点**：B/S 架构、前后端分离、后端开发岗位职责、企业项目流程、Servlet+JSP 历史背景
- **项目任务**：下发"校园实训任务管理系统"需求说明书，分组认领角色
- **互动**：课前 5 分钟讨论"你理解的后端开发是什么"
- **思政**：服务社会与解决真实问题——用技术改善校园实训管理
- **考核点**：后端开发核心职责、前后端分离概念

#### 第 2 次课（理论）— HTTP 协议、JSON 与 RESTful API 思想
- **主题**：HTTP 请求与响应；URL、请求方法、状态码；Header/Cookie/Session；JSON 数据格式；RESTful API 基本思想
- **知识点**：HTTP 报文结构、GET/POST/PUT/DELETE、200/400/401/403/404/500、JSON 语法、REST 资源化设计
- **项目任务**：用 Apifox 模拟访问一个公开 API，分析其请求与响应
- **互动**：API 路径设计投票——同一业务多种 URL 设计方案对比
- **思政**：接口设计责任——良好的接口契约是协作的基础
- **考核点**：HTTP 方法语义、状态码含义、RESTful 路径设计

### 模块 2：Spring Boot 后端接口开发

#### 第 3 次课（理论）— Spring Boot 项目搭建与 Maven 管理
- **主题**：Spring Boot 简介；项目结构；Maven 依赖管理；配置文件；启动类
- **知识点**：Spring Boot 特性、`pom.xml`、起步依赖、`application.yml`、`@SpringBootApplication`
- **项目任务**：使用 Spring Initializr 创建 CTTS 后端项目骨架
- **互动**：代码阅读——对比传统 SSM 与 Spring Boot 项目结构
- **思政**：自主可控与开源生态——Spring Boot 与国产开源框架
- **考核点**：Spring Boot 项目结构、Maven 坐标、配置文件作用

#### 第 4 次课（理论）— Controller 开发与接口参数接收
- **主题**：Controller 编写；请求映射注解；参数接收；JSON 返回
- **知识点**：`@RestController`、`@RequestMapping`/`@GetMapping`/`@PostMapping`、`@RequestParam`/`@PathVariable`/`@RequestBody`、`@ResponseBody`
- **项目任务**：实现 CTTS 的"查询实训项目列表"接口（模拟数据）
- **互动**：接口设计讨论——参数该用 path 还是 query
- **思政**：代码规范意识——命名、路径、参数的一致性
- **考核点**：注解使用、参数绑定、JSON 返回

#### 第 5 次课（理论）— 接口调试与 JSON 返回实践
- **主题**：Apifox/Postman 接口调试；Knife4j 接口文档；常见接口问题排查
- **知识点**：接口调试流程、请求头设置、JSON 响应分析、Knife4j 集成
- **项目任务**：为 CTTS 已有接口编写 Knife4j 文档并完成联调测试
- **互动**：Apifox 接口调试竞赛——限时完成 5 个接口调试
- **思政**：软件质量责任——接口可调试、可验证才是合格交付
- **考核点**：接口调试能力、接口文档编写

### 模块 3：数据库访问与持久层开发

#### 第 6 次课（理论）— JDBC 回顾与 MyBatis 入门
- **主题**：JDBC 简要回顾；MyBatis 简介；MyBatis-Plus 简介；环境集成
- **知识点**：JDBC 核心步骤与痛点、MyBatis 定位、MyBatis-Plus 优势、依赖与配置
- **项目任务**：在 CTTS 项目中集成 MyBatis-Plus，连接 MySQL
- **互动**：代码找错——JDBC 代码常见资源泄漏问题
- **思政**：数据准确性与审慎修改——数据库操作的底线
- **考核点**：JDBC 与 MyBatis 的关系、MyBatis-Plus 集成

#### 第 7 次课（理论）— Mapper 接口与 SQL 映射
- **主题**：Mapper 接口；实体类与表映射；CRUD 操作；注解 SQL 与 XML SQL
- **知识点**：`@Mapper`、`BaseMapper`、`@TableName`/`@TableId`/`@TableField`、`@Select`/`@Insert`/`@Update`/`@Delete`
- **项目任务**：实现 `sys_user` 与 `training_project` 的 Mapper 与实体类
- **互动**：SQL 查询挑战——同一查询多种写法对比
- **思政**：数据安全意识——SQL 注入风险与参数化查询
- **考核点**：实体映射、Mapper 方法定义、注解 SQL

#### 第 8 次课（理论）— 动态 SQL、条件查询与分页
- **主题**：动态 SQL；条件查询；分页查询；MyBatis-Plus 条件构造器
- **知识点**：`<if>`/`<where>`/`<foreach>`、`QueryWrapper`/`LambdaQueryWrapper`、分页插件
- **项目任务**：实现任务列表多条件查询与分页接口
- **互动**：两人一组讲解动态 SQL 执行流程
- **思政**：用户体验——分页与条件查询让系统更好用
- **考核点**：动态 SQL、条件构造器、分页

#### 第 9 次课（实践）— 持久层开发综合实践
- **主题**：综合实践——完成 CTTS 全部核心表的持久层
- **任务**：完成 `task`、`task_submission`、`task_review` 三张表的实体、Mapper、自定义查询
- **互动**：项目任务复盘——持久层踩坑与最佳实践
- **思政**：工匠精神——SQL 写得好不好直接影响系统性能
- **考核点**：完整持久层实现、复杂查询编写

### 模块 4：后端分层架构

#### 第 10 次课（理论）— 分层架构与 Service 层开发
- **主题**：为什么分层；Controller/Service/Mapper 职责；Service 接口与实现；事务基础
- **知识点**：分层动机、`@Service`、接口与实现分离、`@Transactional`
- **项目任务**：将 CTTS 的业务逻辑从 Controller 下沉到 Service
- **互动**：代码阅读与纠错——把所有逻辑写在 Controller 的反例
- **思政**：职业素养——分层是团队协作的契约
- **考核点**：分层原则、Service 编写、事务注解

#### 第 11 次课（理论）— DTO/VO/Result 与包结构规范
- **主题**：Entity/DTO/VO 职责划分；统一响应 Result；项目包结构规范；对象转换
- **知识点**：PO/Entity/DTO/VO 区别、`Result<T>` 设计、包结构约定、BeanUtils/MapStruct
- **项目任务**：为 CTTS 定义 DTO/VO/Result，重构包结构
- **互动**：小组讨论——接口返回格式统一方案
- **思政**：工程规范——良好的结构是可维护性的基础
- **考核点**：对象职责划分、统一响应设计、包结构

### 模块 5：接口规范与工程规范

#### 第 12 次课（理论）— RESTful API 设计与接口文档
- **主题**：RESTful API 设计；接口路径与参数设计；响应数据设计；接口文档规范
- **知识点**：资源化路径、HTTP 方法语义、状态码使用、Knife4j 注解
- **项目任务**：完成 CTTS 全部接口的 RESTful 设计与文档
- **互动**：接口设计评审——同学互评接口路径合理性
- **思政**：接口设计责任——契约一旦确定就是承诺
- **考核点**：RESTful 设计、接口文档

#### 第 13 次课（理论）— 参数校验、统一异常处理与日志

### 12.2 每次课配套题量标准（题库录入基准）

每次课配套一套完整题库，**题量与题型固定**，便于直接录入考试系统题库：

| 题型 | 数量 | 分值建议 | 说明 |
| --- | --- | --- | --- |

### 12.3 题库组织

- **按次课组织**：每次课配套一套完整题库（题量见 12.2），含答案解析与评分标准，可直接录入考试系统。
- **按模块汇总**：每模块结束提供模块综合题库，用于阶段复习与期中测验命题。
- **期末复习题库**：课程结束提供覆盖全部模块的复习题库与上机模拟题（含 2~3 套上机模拟卷）。
- **难度分层**：基础题约占 50%（覆盖核心概念）、提高题约占 30%（应用与辨析）、综合题约占 20%（实战与综合），便于按需组卷。

### 12.4 命题原则（严格遵循，确保可录入考试系统）

1. **严谨正确**：题目知识点必须正确，答案必须明确，杜绝错题、争议题。
2. **无歧义**：题干表述严谨，避免歧义；选择题确保**唯一正确答案**，杜绝"都对/都错"或多解陷阱。
3. **不靠文字游戏**：选择题选项有迷惑性但靠概念辨析，不靠偷换字眼、抠字眼误导学生。
4. **选项规范**：选择题四个选项长度相近、结构一致，正确答案分布均衡，避免规律性分布。
5. **判断题可明确判对错**：判断题必须能明确判断对错，不出"部分正确"的模糊题。
6. **填空题答案唯一**：填空题答案唯一或基本唯一，避免开放性填空。
7. **程序补全题上下文充分**：提供必要上下文（类定义、注解、表结构），保证答案唯一或基本唯一。
8. **编程题要求明确**：编程/接口设计题须明确输入、输出、接口要求、数据库表结构或评价标准。
9. **评分标准清晰**：论述/简答题按要点给分，编程/接口设计题按功能完整度/规范性/正确性分项给分，每题附评分标准。
10. **上机题可限时完成**：上机题可在限定时间内完成，并能体现真实开发能力。
11. **贴近岗位与面试**：题目结合 Java 后端岗位常见工作任务与面试考点（Controller 参数接收、RESTful 路径、MyBatis 查询、JWT 流程、统一异常处理等）。
12. **难度分层**：兼顾基础题、提高题、综合题，标注难度等级（★/★★/★★★），便于组卷。

### 12.5 题库元数据规范（便于录入考试系统）

### 15.2 三个文档的关系

- **教学设计**是教师的"教案"，偏组织流程，回答"**这节课怎么教**"。
- **教学资料**是学生的"讲义/复习资料"，偏知识内容，回答"**这节课学了什么**"，包含定义、问题、完整示例代码等学习材料。
- **题库**是测评依据，偏考核评价，回答"**这节课考什么**"。

三者相互独立又彼此呼应：教学设计引用教学资料中的知识点编号，题库题目对应教学资料中的知识点，形成"教—学—考"闭环。

### 15.3 每次课三文档统一内容规范

#### 一、`教学设计.md`（教师教案）包含：

1. 课程信息（次序 / 学时 / 理论或实践属性 / 教学主题）
2. 教学目标（知识 / 能力 / 素质）
3. 主要知识点纲要（简要列出，详细内容见同文件夹内 `教学资料.md`）
4. 项目任务或案例任务
5. 课堂互动设计（互动问题 / 组织方式 / 预期学生输出 / 教师点评要点）
6. 课程思政融入点（融入点 / 技术关联 / 引导问题 / 预期价值目标）
7. 课堂练习或随堂测验
8. 课后任务
9. 对应岗位能力或面试考点
10. 教学资料与题库索引（指向同文件夹内 `教学资料.md` 与 `题库.md`）

#### 二、`教学资料.md`（学生复习资料）包含：

1. 学习导读（本节定位、先修基础、学习目标）
2. 知识点详解（每个知识点统一结构：**定义 → 原理 → 问题/场景 → 完整示例代码 → 图示 → 易错点 → 小结**）
3. 综合示例（贴近 CTTS 项目的完整代码案例）
4. 拓展阅读（选学内容、原理深挖）
5. 本节小结与知识结构图（思维导图 / 知识卡片）
6. 复习思考题（非题库题，开放式思考，引导复习）

> **教学资料质量要求（严格执行）**：
> 1. 内容**完整详细**，有严谨的定义、原理讲解，不遗漏关键概念。
> 2. 示例代码须**完整可运行**（含包声明、import、注解、完整方法体、配置文件、SQL 语句、运行结果），不能只给片段。
> 3. 确保学生可以**独立操作**：提供详细的操作步骤（如项目创建步骤、依赖添加、配置修改、运行验证）、配置说明、预期运行结果、常见问题排查。
> 4. 代码示例贴近 CTTS 项目，前后连贯，形成可运行的项目代码。
> 5. 每个知识点后附易错点与小结，帮助学生避坑与复习。

#### 三、`题库.md`（考试系统题库）包含：

- 40 道选择题（单选/多选混合，每题 2 分）
- 20 道判断题（每题 1 分）
- 10 道填空题（每题 2 分）
- 4 道论述题/简答题（每题 5~10 分）
- 2 道程序阅读/补全题（每题 10~15 分）
- 2 道编程/接口设计题（每题 15~20 分）
- **全部题目**含：参考答案、解析、难度标注（★/★★/★★★）、所属知识点、题目编号（`XX-题型-序号`）
- **主观题**（论述/简答、程序阅读/补全、编程/接口设计）另附**评分标准**（按要点/分项给分）
