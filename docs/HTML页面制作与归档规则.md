# HTML 页面制作与归档规则

> 适用项目：`MVVM前端框架开发技术` 课程 01-16 次课资料。  
> 本文件用于固化 HTML 页面制作规范。后续如果用户提出新的页面风格、内容严谨性或归档要求，应及时更新本文件。

---

## 1. 总体目标

将每个次课目录中的 Markdown 文件制作成统一风格、可阅读、可归档的 HTML 页面。

每个 `01-16` 目录通常包含：

- `教学设计.md`
- `教学资料.md`
- `题库.md`

对应生成：

- 教学设计 HTML
- 教学资料 HTML
- 题库 HTML

HTML 页面应做到：

1. 风格统一、排版清晰；
2. 内容准确、严谨，必要时可修正文案；
3. 图示必须美观、准确，不能直接照搬 Markdown 字符图；
4. 表格、题库、目录等组件要适合网页阅读；
5. 生成后必须复查 HTML 效果，不能只完成转换。

## 5. 整体页面风格

页面整体采用现代教学资料风格：

- 顶部 hero 区：蓝绿渐变背景；
- 正文白色卡片；
- 圆角、轻阴影、浅色边框；
- 主色：蓝色 + 青绿色；
- 字体优先使用系统中文字体；
- 行高适合教学阅读；
- 移动端要能正常单列显示。

建议视觉关键词：

```text
简洁、清晰、现代、教学感、科技感、但不过度装饰
```

## 6. 左侧目录规则

### 6.1 通用要求

HTML 页面应优先使用左侧目录 + 右侧正文布局。

左侧目录要求：

- 层级清楚；
- 可滚动；
- 滚动条样式轻量；
- hover 有浅色反馈；
- 目录不应挤压正文过多空间。

### 6.2 教学设计 HTML 目录风格

教学设计页当前确认的目录风格：

- **简洁风格**，不要复杂卡片；
- 不使用数字徽章；
- 不使用过重渐变；
- 一级目录用轻量文字导航；
- 左侧可有细蓝色指示线；
- 二级目录使用细线缩进；
- 保留目录收起 / 展开功能。

教学设计页目录必须支持：

1. 点击“收起”隐藏左侧目录；
2. 隐藏后右侧正文自动占满空间；
3. 页面左侧出现“目录”浮动按钮，可恢复目录；
4. 小屏幕下目录自动变为顶部区域，不强制左右布局。

## 7. 正文布局规则

正文区域要求：

- 使用白色卡片；
- 卡片圆角适中；
- 正文宽度要充足；
- 目录隐藏后正文应自动扩展；
- 不要出现正文被目录挤压得过窄的情况；
- 代码块、表格、图示不能溢出正文卡片。

---

## 8. 表格规则

表格是重点检查项。

### 8.1 基本样式

表格应：

- 宽度铺满正文区域；
- 表头有浅蓝背景；
- 单元格边框清晰但不厚重；
- 行间距适合阅读；
- 代码、路径、英文长词必须允许换行；
- 不允许内容遮挡其他列；
- 不允许出现“一半空白”的异常效果。

### 8.2 列宽分配原则

不要简单平均分配列宽。应根据内容多少分配：

- 内容少的列少占空间；
- 内容多的列多占空间；
- 所有列仍必须允许换行。

常见规则：

| 表格类型                 | 推荐列宽思路                              |
| ------------------------ | ----------------------------------------- |
| `项目 / 内容`            | `项目` 较窄，`内容` 较宽                  |
| `编号 / 知识点 / 要点`   | `编号` 最窄，`知识点` 中等，`要点` 最宽   |
| `资料类型 / 文件 / 说明` | `资料类型` 较窄，`文件` 中等，`说明` 较宽 |
| `时段 / 内容 / 时长`     | `时段` 窄，`内容` 宽，`时长` 窄           |

### 8.3 课堂时间分配表专用规则

对于表头为：

```text
时段 | 内容 | 时长
```

推荐比例：

```text
时段：16%
内容：70%
时长：14%
```

要求：

- “内容”列占主宽；
- “时段”“时长”不要挤占过多空间；
- 所有列都允许换行，不允许遮挡。

### 8.4 生成后必须检查表格

每次生成或修改 HTML 后，必须检查：

- 表格是否铺满；
- 长内容列是否有足够空间；
- 是否有内容溢出；
- 是否出现单元格遮挡；
- 是否有过多空白列。

## 9. 图示规则

这是强制规则。

### 9.1 不允许直接使用 Markdown 字符图

不要直接把 Markdown 中的 ASCII / 字符图转换进 HTML，例如：

```text
Model ───▶ ViewModel ───▶ View
┌──────┐   ┌──────────┐   ┌──────┐
```

这类图在 HTML 中效果差、不美观，也容易不准确。

### 9.2 必须重新绘制图示

遇到 Markdown 字符图、流程图、结构图时，应改为 HTML/CSS 可视化组件，例如：

- 卡片式流程图；
- 网格结构图；
- 步骤卡片；
- 对比卡片；
- 轻量示意图；
- 终端风格代码块 + 操作说明；
- 文件树样式组件。

### 9.3 图示必须准确

图示不能为了好看而牺牲准确性。

例如 MVVM 相关图示必须表达：

- 普通展示主要是 **数据 → 视图**；
- 用户输入或事件通过 ViewModel 回写数据；
- Vue 表单场景常用 `v-model` 实现便捷双向绑定；
- 不应画成 Model 与 View 直接双向相连；
- 不应暗示“所有数据都必须双向绑定”。

推荐表达：

```text
Model 数据变化 → ViewModel 响应式追踪 / 计算 / 渲染 → View 更新
View 用户交互 → ViewModel 事件处理 / v-model → Model 更新
```

---

## 10. 内容严谨性规则

不要简单说：

```text
MVVM 的核心机制是双向绑定
```

推荐说法：

```text
MVVM 的核心是数据绑定与响应式同步。
普通展示通常是数据驱动视图；用户输入或事件处理结果再由 ViewModel 回写数据。
在 Vue 中，表单双向绑定通常通过 v-model 实现。
```

题库、教学资料、教学设计中涉及 MVVM 时，应避免以下误导性表述：

- 所有数据都双向绑定；
- Model 与 View 直接双向相连；
- View 直接修改 Model；
- 双向绑定等于 MVVM 的全部核心。

## 11. 题库 HTML 规则

题库页面重点是可读性。

### 11.1 题目卡片

每道题建议使用独立卡片：

- 题号明显；
- 题干清楚；
- 选项和解析分区；
- 卡片之间留足间距。

### 11.2 ABCD 选项样式

选择题选项不要使用普通 Markdown 列表原样显示。

推荐样式：

- 每个选项是独立块；
- A/B/C/D 使用圆形或徽章标识；
- 选项块有浅边框、圆角；
- hover 可轻微高亮；
- 两列布局为主，小屏幕变一列。

### 11.3 答案解析

答案解析可使用绿色提示块或浅色 blockquote，但不要过重。

## 13. Vite / Vue 版本内容规则

涉及 Vite、Node.js 等现代工具时，应保持准确。

当前课程中已采用的表述：

```text
Node.js 20.19+ 或 22.12+
```

如未来版本要求发生变化，应优先核对官方文档后再更新。

Vite 创建 Vue3 项目流程建议表达为：

1. 检查环境：`node -v`、`npm -v`
2. 创建项目骨架：`npm create vite@latest ctts-frontend`
3. 选择模板：`Vue` + `JavaScript`
4. 进入目录：`cd ctts-frontend`
5. 安装依赖：`npm install`
6. 启动开发服务器：`npm run dev`
7. 浏览器访问终端给出的本地地址，如 `http://localhost:5173/`

## 19. 公共 CSS 与本地代码高亮规则

当前已将 01 已确认页面的大量内联 CSS 抽取为本地公共样式文件：

```text
docs/assets/course-html.css
docs/assets/highlight-local.css
```

后续制作 02-16 的 HTML 时，应优先引用这两个本地 CSS 文件，避免每个 HTML 页面继续堆大量内联样式。

建议在 HTML `<head>` 中加入：

```html
<link rel="stylesheet" href="../docs/assets/course-html.css">
<link rel="stylesheet" href="../docs/assets/highlight-local.css">
```

要求：

1. `course-html.css` 存放课程页面通用布局、目录、表格、题库、图示等样式；
2. `highlight-local.css` 存放本地代码高亮样式，不依赖在线 CDN；
3. 教学资料中的代码块必须保留原始换行、缩进和横向滚动；
4. 表格中的行内 `code` 可以自动换行，避免撑破表格；
5. 如果后续页面新增了通用组件样式，应优先更新公共 CSS，而不是继续写入大量内联 CSS；
6. 如某一页确实需要少量特殊样式，可单独追加，但应尽量保持最小化。
### 19.1 代码块换行规则修正记录

注意不要写全局规则：

```css
.article code { white-space: normal !important; }
```

这会误伤 `<pre><code>` 代码块，导致原始换行和缩进失效。

正确做法：

```css
.article pre code { white-space: pre !important; }
.article table code { white-space: normal !important; overflow-wrap: anywhere !important; }
```

也就是说：

- 代码块必须保持 `white-space: pre`；
- 表格内的行内代码才允许自动换行；
- 如果出现冲突，应优先保证教学资料代码块的原始格式。
### 19.2 Vue SFC 代码高亮规则

Pandoc 对部分 `vue` 代码块可能只生成：

```html
<pre class="vue"><code>...</code></pre>
```

这种结构没有 token span，纯 CSS 无法识别 `<template>`、`<script setup>`、`<style scoped>` 等语法，因此需要本地脚本增强。

当前本地脚本：

```text
docs/assets/vue-sfc-highlight.js
```

后续 HTML 页面如包含 Vue 单文件组件代码，应在 `<head>` 中引用：

```html
<script src="../docs/assets/vue-sfc-highlight.js" defer></script>
```

并继续引用：

```html
<link rel="stylesheet" href="../docs/assets/highlight-local.css">
```

要求：

- 不使用在线 CDN；
- `<pre class="vue"><code>...</code></pre>` 应通过本地脚本增强高亮；
- 已由 Pandoc 分词的 `sourceCode html/js/bash` 代码块继续由 CSS token 样式处理；
- 代码块必须保留原始换行、缩进和横向滚动。
### 19.3 MVVM 图示布局规则

`MVVM 数据绑定与响应式同步（Vue 场景）` 图示不要使用过窄的五列布局，否则连接说明会挤压节点。

当前公共样式采用稳定布局：

- Model / ViewModel / View 三个主节点在宽屏下三列展示；
- “数据变化 / 渲染视图 / 写回 Model / 交互进入 ViewModel”等连接说明单独成行；
- 小屏幕下自动改为单列纵向布局；
- 连接说明不再塞在节点之间，避免挤在一起；
- 图示必须保持“数据驱动视图，交互经 ViewModel 回写数据”的准确含义。
### 19.4 MVVM 图示重绘规则 v2

根据常见 MVVM 图示和 Vue 场景，本课程的 MVVM 图不再使用复杂多连接块布局。

推荐结构：

```text
Model        ViewModel        View
数据状态  →  绑定与协调层  →  界面渲染
             ↑          ↓
        交互 / v-model / 事件回写
```

实际 HTML/CSS 图示应遵循：

1. 三个主体卡片：`Model`、`ViewModel`、`View`；
2. `ViewModel` 作为中介层应居中并略突出；
3. “状态变化”“响应式更新视图”“用户输入/点击”“事件/v-model 回写数据”等说明应做成小标签，不喧宾夺主；
4. 不允许画成 `Model` 和 `View` 直接相连；
5. 宽屏三栏展示，小屏单栏展示；
6. 连接线和状态标签不能重叠主体卡片。
