二、教学目标

2.1 知识目标

  1. 掌握 JWT 拦截器与 Spring MVC HandlerInterceptor 的整合流程。
  2. 理解自定义注解 @RequireRole 配合拦截器实现声明式权限控制的原理。
  3. 掌握 @RestControllerAdvice + @ExceptionHandler 全局异常处理体系。
  4. 理解统一响应 Result<T> 在分层架构中的规范作用。
  5. 掌握 SLF4J + Logback 日志配置与使用方法。

2.2 能力目标

  1. 能将 JWT 认证拦截器配置到全部业务接口，完成登录态校验。
  2. 能使用 @RequireRole 注解为各 Controller 接口标注角色权限。
  3. 能编写 GlobalExceptionHandler，分类处理校验异常、业务异常、权限异常与兜底异常。
  4. 能将原有 Controller 返回值统一改造为 Result<T> 结构。
  5. 能独立完成越权访问、Token 伪造、参数篡改三类安全自查。

2.3 素质目标（课程思政）

  1. 质量责任意识：上线前自检是工程师的基本素养，不放过任何一个权限漏洞。
  2. 严谨求实态度：通过交叉审查与测试用例发现潜在缺陷，践行"对代码负责"。
  3. 安全合规意识：理解最小权限原则，树立"安全设计优先"的工程价值观。

三、教学重点与难点

3.1 教学重点

  1. JWT 拦截器的注册与放行路径配置。
  2. @RequireRole 注解 + RoleInterceptor 的声明式权限控制实现。
  3. GlobalExceptionHandler 对五类异常的分类处理与统一返回。
  4. Result<T> 对所有 Controller 的统一改造。

3.2 教学难点

  1. 拦截器执行顺序与异常处理器的协同（拦截器抛出异常时如何被全局处理器捕获）。
  2. 自定义注解的反射读取与角色匹配逻辑。
  3. 越权访问测试用例的设计与执行。
  4. 在改造旧接口时不破坏原有业务逻辑的回归验证。

3.3 重点难点突破策略

  • 分层演示法：先认证后权限再异常，由外到内逐层加固。
  • 对比教学法：改造前后 Controller 代码并排展示，直观感受 Result<T> 的统一价值。
  • 交叉审查法：学生两两结对互测对方接口，模拟真实 Code Review。
  • 漏洞复现法：通过 Postman/Knife4j 实际构造越权请求，让漏洞"可见"。

四、学情分析

  • 学生已完成第21次课全部业务接口开发，5 张表的 CRUD 均已实现，但接口处于"裸奔"状态：无认证、无权限、无统一异常、无统一响应。
  • 学生在前序课程中已学习 JWT 原理、全局异常处理、统一响应等知识，但尚未整合到统一项目中。
  • 部分学生对自定义注解 + 反射的组合用法不够熟练，需要在课堂上演示完整链路。
  • 学生安全意识薄弱，对越权、Token 伪造等攻击手段缺乏直观认识，需要通过实战自查建立认知。

六、教学准备

6.1 教师准备

  • CTTS 项目第21次课完整代码（已实现5张表 CRUD）。
  • 整合后的参考实现代码（含拦截器、异常处理器、@RequireRole、Result<T>、日志配置）。
  • Postman 集合文件（含三类漏洞自查测试用例）。
  • 演示用思维导图：权限与异常整合架构图。

6.2 学生准备

  • 携带第21次课完成的 CTTS 项目代码。
  • 安装 Postman 或使用 Knife4j 在线调试界面。
  • 复习 JWT 拦截器、@RestControllerAdvice、统一响应相关知识点。

6.3 环境准备

  • JDK 17、Maven 3.8+、MySQL 8.0、IDEA 2023.x。
  • 项目依赖：Spring Boot 3.x、MyBatis-Plus、jjwt、knife4j-openapi3-jakarta-sdk。

8 15min 课堂互动：代码交叉审查 组织学生两两结对，互相审查对方接口、互测漏洞 结对审查、提交审查报告 模拟真实Code Review，培养质量责任

7.1 验收标准

任务 验收标准
任务1 JWT认证 未携带 Token 访问任意业务接口返回 401；登录接口、Knife4j 文档可正常访问
任务2 角色权限 学生 Token 访问教师/管理员接口返回 403；管理员 Token 可访问全部接口
任务3 异常处理 参数校验失败、业务异常、权限异常均返回统一 Result 结构且 code 正确
任务4 统一响应 全部 Controller 返回 Result<T>，Knife4j 文档模型正确显示
任务5 日志 关键操作（登录、增删改）写入日志文件，控制台彩色输出
任务6 漏洞自查 三类漏洞自查清单全部通过，无越权、无伪造、无篡改风险

八、课程思政设计

8.1 思政元素

  • 质量责任：上线前自检是工程师的基本素养，任何权限漏洞都可能造成数据泄露。
  • 严谨求实：通过交叉审查与测试用例发现缺陷，践行"对代码负责"。
  • 安全合规：最小权限原则是系统安全的基石，权限设计应"宁紧勿松"。

8.2 融入方式

  • 导入环节：以真实数据泄露案例（如某高校教务系统越权查询成绩）切入，唤起安全意识。
  • 实践环节：漏洞自查环节让学生亲自构造攻击请求，体会"漏洞就在身边"。
  • 总结环节：引用"代码如施工，质量即生命"，强调工程师的质量责任。

九、教学评价

9.1 过程性评价（60%）

评价项 权重 评价方式
6项实践任务完成度 30% 教师巡场检查 + 验收标准对照
漏洞自查清单通过率 15% 自查报告提交
交叉审查参与度与质量 15% 审查报告 + 同伴互评

9.2 结果性评价（40%）

评价项 权重 评价方式
项目最终运行状态 20% 教师验收
代码规范与注释 10% 代码审查
思政感悟与总结 10% 课后反思提交

9.3 评价标准

  • 优秀（90-100）：6项任务全部完成，漏洞自查零遗漏，交叉审查发现2个以上真实问题。
  • 良好（80-89）：6项任务完成，漏洞自查通过，交叉审查能发现1个问题。
  • 合格（60-79）：4项以上任务完成，基本通过漏洞自查。
  • 不合格（<60）：任务完成不足4项，存在明显未修复漏洞。
