二、教学目标

知识目标

  1. 掌握 Apifox/Postman 接口调试工具的基本使用：创建请求、设置方法/URL/Headers/Body、发送请求、查看响应。
  2. 理解 HTTP 请求头的作用，重点掌握 Content-Type: application/json、Accept、Authorization 三个常用头字段。
  3. 能够分析 JSON 响应：状态码、响应头、响应体结构。
  4. 掌握 Knife4j 的集成步骤：依赖引入、配置类、@Tag/@Operation/@Parameter 注解、访问 doc.html。
  5. 掌握常见接口问题排查：404（路径不对）、500（代码异常）、415（Content-Type 不对）、400（参数不匹配）、跨域 CORS。

能力目标

  1. 能够使用 Apifox 独立完成 GET/POST/PUT/DELETE 接口的调试，正确设置请求方法、URL、请求头与请求体。
  2. 能够为已有 Spring Boot 项目集成 Knife4j，并通过 doc.html 在线浏览与调试接口。
  3. 能够使用 @Tag、@Operation、@Parameter 注解为接口添加中文文档说明。
  4. 能够根据状态码与响应信息定位常见接口问题并给出解决方案。

素质目标（课程思政）

  1. 树立"软件质量责任"意识——接口可调试、可验证、有文档才是合格交付。
  2. 培养严谨的工程习惯——接口测试不是"跑通就行"，而是覆盖正常与异常场景。
  3. 体会国产开源工具（Knife4j、Apifox）的价值，增强对国产技术生态的认同感。

三、主要知识点纲要

详细讲解内容见同文件夹 教学资料.md，此处为纲要。

编号 知识点 要点
K5-1 Apifox/Postman 接口调试 创建请求、设置方法/URL/Headers/Body、发送请求、查看响应；接口调试是后端开发必备技能
K5-2 请求头设置 Content-Type: application/json（请求体格式）、Accept（期望响应格式）、Authorization（认证令牌）

K5-5 常见接口问题排查 404（路径不对）、500（代码异常）、415（Content-Type 不对）、400（参数不匹配）、跨域 CORS

四、项目任务或案例任务

贯穿项目任务：为 CTTS 已有接口集成 Knife4j 文档并用 Apifox 完成联调测试

本次课任务：

  1. 在第 4 次课已开发的 ProjectController（实训项目管理接口）基础上，集成 Knife4j 接口文档。
  2. 为 ProjectController 中已有的 5 个接口（GET 查询列表、GET 单个查询、POST 新增、PUT 更新、DELETE 删除）添加 @Tag、@Operation、@Parameter 注解，生成中文文档。
  3. 访问 http://localhost:8080/doc.html 验证 Knife4j 文档正常显示。
  4. 使用 Apifox 依次调试这 5 个接口，覆盖正常与异常场景。

任务背景：

  • 第 4 次课已经完成了 ProjectController 的开发，接口可以运行，但缺少文档、未做完整联调。
  • 真实企业项目里，接口开发完成后必须：①补全文档（Knife4j）→ ②自测联调（Apifox）→ ③交付前端。
  • 本次课就是模拟这一真实流程。

📌 本次课不写新的业务代码，重点是给已有接口"补文档 + 做联调"，体会企业开发中的"可调试、可验证、有文档"标准。

五、课堂互动设计

互动 1：开场 5 分钟讨论 — "接口写完了，下一步怎么办？"

项目 内容
互动问题 "你写完了一个 Controller 接口，运行没报错，能直接交付给前端吗？还差什么？"
组织方式 自由发言，教师板书关键词
预期学生输出 "要测试""要写文档""前端不知道接口长什么样""万一传错参数怎么办"
教师点评要点 引出"接口可调试、可验证、有文档才是合格交付"的工程价值观，明确本节课目标

互动 2：Apifox 接口调试竞赛（核心互动，限时完成 5 个接口调试）

项目 内容
竞赛任务 限时 20 分钟内，用 Apifox 完成以下 5 个接口的调试并截图提交：①GET /api/projects 查询列表；②GET /api/projects/{id} 查询单个；③POST /api/projects 新增；④PUT /api/projects/{id} 更新；⑤DELETE /api/projects/{id} 删除
组织方式 个人赛，全班同时开始；教师在大屏投影倒计时；前 5 名完成且全部 200 响应的同学加分
评分标准 每个接口正确返回 200 且响应体结构合理得 20 分，满分 100；超时按完成数量计分
常见坑点提示 POST/PUT 必须设置 Content-Type: application/json；路径参数 {id} 要替换为实际值；DELETE 通常无请求体
教师点评要点 现场统计完成率，针对典型错误（415、404、400）现场分析，引出 K5-5 排查内容

互动 3：错误现场诊断（讲解 K5-5 时）

项目 内容
互动任务 教师现场演示 4 个错误场景（404、500、415、400），学生抢答原因与解决方案
组织方式 教师演示 → 学生举手抢答 → 答对加分
预期学生输出 404 路径不对；500 代码异常；415 Content-Type 不对；400 参数不匹配
教师点评要点 强调"看响应找原因"的排查思路：先看状态码 → 看响应信息 → 看后端日志

六、课程思政融入点

项目 内容
融入点 软件质量责任——接口可调试、可验证、有文档才是合格交付
技术关联 Knife4j 文档（有文档）、Apifox 调试（可调试）、状态码排查（可验证）三者共同构成"质量交付"的工程实践
引导问题 "如果你是前端工程师，拿到一个没有文档、没有测试过的接口，你敢用吗？如果接口出了问题谁负责？"
预期价值目标 让学生理解"代码能跑 ≠ 交付合格"，养成补文档、做测试、写注释的工程责任感

思政自然融入：不空喊"质量第一"，而是通过"前端拿到你的接口会怎样"的真实场景让学生体会责任。

七、课堂练习或随堂测验

随堂练习（5 分钟，讲解结束前进行）

判断题（口头快速作答）：

  1. POST 请求提交 JSON 数据时，请求头 Content-Type 应设置为 application/json。（✓）
  2. Knife4j 是接口文档工具，可以替代 Apifox 完成所有接口测试。（✗）
  3. 接口返回 404 状态码，说明后端代码出现了空指针异常。（✗）
  4. Knife4j 集成后访问 doc.html 即可在线查看与调试接口。（✓）

详细题目与解析见 题库.md。此处仅作课堂快速互动，不计分。

八、课后任务

  1. 完善项目：为第 4 次课的 ProjectController 补全 Knife4j 注解（@Tag、@Operation、@Parameter），并截图 doc.html 页面提交。
  2. 联调报告：用 Apifox 完成 5 个接口的调试，每个接口提交一张"请求 + 响应"截图，并标注状态码与响应时间。
  3. 错误排查练习：故意制造 4 种错误（404、400、415、500 各一），截图并写出原因与解决方案。
  4. 阅读：通读同文件夹 教学资料.md，重点掌握 Knife4j 集成步骤与常见状态码排查表。
  5. 拓展（选做）：尝试为 CTTS 的 TaskController（任务接口）也集成 Knife4j 文档，下次课抽查。
