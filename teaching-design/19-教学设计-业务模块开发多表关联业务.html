二、教学目标

知识目标

  1. 理解多表关联查询的语法差异（INNER JOIN / LEFT JOIN），能够根据业务场景选择正确的连接方式。
  2. 掌握 MyBatis 多表映射的两种方式：注解 @Results 映射与 XML ResultMap 嵌套映射（association 一对一、collection 一对多）。
  3. 理解业务对象（VO）的设计原则，能够根据接口需要设计 TaskWithSubmissionVO、ProjectTaskVO 等 VO 类。
  4. 识别 N+1 查询问题的产生原因，掌握 JOIN 一次查询与批量查询两种解决方案。
  5. 掌握完整 Controller-Service-Mapper 链路实现多表关联查询接口的流程。

能力目标

  1. 能够独立编写包含 LEFT JOIN 的多表关联 SQL。
  2. 能够独立编写 XML ResultMap 嵌套映射，完成一对多关联结果组装。
  3. 能够在 Service 层组装多表数据并返回 VO 对象。
  4. 能够排查多表查询常见报错（列名歧义、映射错位、N+1 性能问题）。

素质目标（课程思政）

  1. 性能与责任：低效查询是对服务器资源的浪费，工程师对每一行 SQL 都应怀有敬畏之心，培养性能意识和资源责任感。
  2. 工匠精神：多表映射的细节决定数据正确性，培养严谨细致的工程态度。
  3. 系统思维：从单表到多表，从局部到整体，建立系统级的数据视角。

三、教学重点

  1. LEFT JOIN 多表关联 SQL 编写与列名歧义处理。
  2. XML ResultMap 嵌套映射（association + collection）。
  3. VO 对象设计与 Service 层多表数据组装。
  4. N+1 查询问题的识别与解决方案。

四、教学难点

  1. ResultMap 嵌套映射中一对多关系的 collection 配置，特别是 id 列与 result 列的正确标注。
  2. JOIN 查询结果集中重复主键列导致的映射错位问题。
  3. N+1 问题的本质理解——从代码表象到数据库执行过程的思维跃迁。

十、课后作业与教学反思

课后作业

  1. 基础题：编写 SQL，使用 LEFT JOIN 查询某学生（user_id）的所有提交记录及对应任务名称、项目名称。
  2. 应用题：独立实现"查看某学生所有提交及评审意见"接口，要求：
    • 编写 JOIN SQL（task_submission + task_review + sys_user）
    • 编写 XML ResultMap 嵌套映射（一对多：提交→评审列表）
    • 设计 SubmissionWithReviewVO
    • 完成 Mapper / Service / Controller 全链路
  3. 思考题：对比"JOIN 一次查询"与"批量查询 <foreach>"两种 N+1 解决方案的适用场景。

反思维度 反思要点
