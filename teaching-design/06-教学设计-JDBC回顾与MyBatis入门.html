二、教学目标

知识目标

  1. 掌握 JDBC 操作数据库的核心六步：加载驱动、获取连接、创建 Statement、执行 SQL、处理 ResultSet、关闭资源。
  2. 理解 JDBC 原生开发的四大痛点：代码繁琐、资源易泄漏、SQL 硬编码、结果集手动映射。
  3. 理解 MyBatis 作为半自动 ORM 框架的定位：SQL 与 Java 代码分离，灵活度高。
  4. 了解 MyBatis-Plus 作为 MyBatis 增强工具的核心优势：内置 CRUD、条件构造器、分页插件、代码生成。
  5. 掌握 Spring Boot 3 项目集成 MyBatis-Plus 的完整步骤：依赖添加、数据源配置、建库建表、连接验证。

能力目标

  1. 能够独立编写一段完整的 JDBC 查询代码（含 try-with-resources 资源关闭）。
  2. 能够识别 JDBC 代码中的资源泄漏、SQL 注入、硬编码等常见问题。
  3. 能够在 Spring Boot 3 项目中正确添加 MyBatis-Plus 与 MySQL 驱动依赖，配置数据源。
  4. 能够创建 CTTS 项目数据库 ctts 与 sys_user 表，并启动项目验证数据库连接成功。
  5. 能够排查常见的数据库连接报错（时区错误、驱动类找不到、密码错误等）。

素质目标（课程思政）

  1. 树立"数据准确性与审慎修改"的工程底线意识——一个 SQL 写错可能导致数据丢失，数据库操作必须严谨。
  2. 培养对国产开源生态的认同感——MyBatis-Plus 是国产增强工具，被企业广泛采用。
  3. 建立"先理解痛点、再学习方案"的工程思维——理解 JDBC 痛点才能体会 MyBatis-Plus 的价值。

三、主要知识点纲要

详细讲解内容见同文件夹 教学资料.md，此处为纲要。

编号 知识点 要点
K6-1 JDBC 核心步骤 加载驱动 Class.forName → 获取 Connection（DriverManager.getConnection）→ 创建 Statement/PreparedStatement → 执行 SQL（executeQuery/executeUpdate）→ 处理 ResultSet → 关闭资源（try-with-resources）
K6-2 JDBC 痛点 代码繁琐（6 步流程）；手动管理资源易泄漏；SQL 硬编码在 Java 文件中；结果集手动映射到对象
K6-3 MyBatis 简介与定位 半自动 ORM 框架，SQL 与 Java 代码分离（写在 XML 或注解中），灵活度高，开发者自己写 SQL，框架负责参数绑定与结果映射
K6-4 MyBatis-Plus 简介与优势 MyBatis 增强工具（不改变 MyBatis 本身），内置 CRUD（BaseMapper）、条件构造器（QueryWrapper）、分页插件、代码生成器，开箱即用
K6-5 环境集成 添加 mybatis-plus-spring-boot3-starter 依赖、mysql-connector-j 依赖；application.yml 数据源配置（url/username/password/driver-class-name）；创建数据库 ctts 与 sys_user 表

贯穿项目阶段任务：CTTS 持久层环境搭建

本次课任务：

  2. 教师演示在 CTTS 项目中集成 MyBatis-Plus，配置 MySQL 数据源。

五、课堂互动设计

互动 1：JDBC 代码找错（讲解 K6-1、K6-2 后）

项目 内容
互动问题 展示一段有资源泄漏、SQL 注入、硬编码问题的 JDBC 代码，让学生找出所有问题
组织方式 全班共同找错，教师板书每个问题点，学生举手发言
预期学生输出 找出"ResultSet/Statement/Connection 未关闭""SQL 拼接易注入""密码硬编码在代码里""加载驱动写错类名"等问题
教师点评要点 肯定合理发现，引导总结为四大痛点（繁琐、泄漏、硬编码、手动映射）；引出 K6-3 MyBatis 的解决方案

展示代码示例（教师投屏，不直接发给学生）：

public class BadJdbcDemo {
    public static void main(String[] args) throws Exception {
        Class.forName("com.mysql.cj.jdbc.Driver");  // 问题1：驱动类名可能写错
        Connection conn = DriverManager.getConnection(
            "jdbc:mysql://localhost:3306/ctts", "root", "123456");  // 问题2：密码硬编码
        Statement stmt = conn.createStatement();
        String name = "admin";
        String sql = "SELECT * FROM sys_user WHERE username = '" + name + "'";  // 问题3：SQL 拼接，易注入
        ResultSet rs = stmt.executeQuery(sql);  // 问题4：未用 PreparedStatement
        while (rs.next()) {
            System.out.println(rs.getString("username"));
        }
        // 问题5：rs、stmt、conn 都没有关闭，资源泄漏！
        // 问题6：异常直接 throws，没有 try-catch 处理
    }
}

六、课程思政融入点

项目 内容
融入点 数据准确性与审慎修改——数据库操作的底线
技术关联 JDBC 中一个 executeUpdate 写错 SQL（如漏写 WHERE 条件的 UPDATE/DELETE）可能导致整表数据被改/被删，造成不可逆损失
引导问题 "如果你在生产环境执行了 UPDATE sys_user SET status = 0（漏写 WHERE），会发生什么？如何避免？"
预期价值目标 树立"对数据心存敬畏"的工程底线意识：写 SQL 前 SELECT 确认、UPDATE/DELETE 必带 WHERE、生产环境操作必须备份、重要操作需 double check

思政自然融入：通过真实案例（漏写 WHERE 导致数据丢失）让学生体会数据库操作的严肃性，培养审慎的工程习惯。

七、课堂练习或随堂测验

随堂练习（5 分钟，讲解结束前进行）

判断题（口头快速作答）：

  1. JDBC 中 Class.forName("com.mysql.cj.jdbc.Driver") 的作用是加载 MySQL 驱动类。（✓）
  2. JDBC 操作完成后，只需关闭 Connection 即可，Statement 和 ResultSet 会自动关闭。（✗）
  3. MyBatis-Plus 是 MyBatis 的替代品，使用 MyBatis-Plus 就不能用 MyBatis 原生功能。（✗）
  4. Spring Boot 3 项目集成 MyBatis-Plus 应使用 mybatis-plus-spring-boot3-starter 依赖。（✓）

详细题目与解析见 题库.md。此处仅作课堂快速互动，不计分。

八、课后任务

  1. 阅读：通读同文件夹 教学资料.md，重点理解 JDBC 六步流程、四大痛点、MyBatis-Plus 优势、环境集成步骤。
  2. 动手实践：在本地 CTTS 项目中完成 MyBatis-Plus 集成，创建 ctts 数据库与 sys_user 表，启动项目验证连接成功，截图提交。
  3. 代码练习：独立编写一段完整的 JDBC 查询代码（查询 sys_user 表所有用户），使用 PreparedStatement 与 try-with-resources，下次课抽查。
  4. 报错排查练习：故意制造 3 种连接错误（改错密码、改错时区、删驱动依赖），观察并记录报错信息，写出排查思路。
  5. 思考：用 200 字描述"为什么 MyBatis-Plus 比 JDBC 更适合企业项目开发"，下次课抽查。
  6. 拓展阅读（选做）：了解 JPA(Hibernate) 与 MyBatis 的设计理念差异，思考"全自动 ORM"与"半自动 ORM"的取舍。
