二、教学目标

知识目标

  1. 理解 B/S 架构与 C/S 架构的区别，明确前后端分离的开发模式。
  2. 理解 Web 后端开发的核心职责：接收请求 → 处理业务 → 访问数据 → 返回结果。
  3. 了解 Java 后端开发岗位的典型工作内容与企业项目研发流程。
  4. 了解早期 Servlet + JSP 开发模式及其被现代框架替代的原因（作为背景）。
  5. 明确本课程贯穿项目"校园实训任务管理系统（CTTS）"的业务背景与整体目标。

能力目标

  1. 能够用自己的语言准确描述"什么是后端开发""前后端分离"。
  2. 能够识别一个 Web 系统中前端、后端、数据库各自承担的职责。
  3. 能够阅读并理解一份简单的项目需求说明书，明确系统角色与核心业务。

素质目标（课程思政）

  1. 树立"技术服务于真实问题"的工程价值观——用所学技术改善校园实训管理。
  2. 培养对国产开源生态与自主创新技术的认同感。
  3. 建立"软件质量责任"的初步意识——后端开发关乎数据与系统稳定。

三、主要知识点纲要

详细讲解内容见同文件夹 教学资料.md，此处为纲要。

编号 知识点 要点
K1-1 什么是 Web 后端开发 后端 = 接收请求 + 处理业务 + 访问数据 + 返回结果；后端运行在服务器端
K1-2 B/S 架构与 C/S 架构 B/S 浏览器/服务器、C/S 客户端/服务器；B/S 零安装、易维护，是 Web 主流
K1-3 前后端分离 前端负责界面展示，后端负责数据与业务，通过 API（JSON）通信；对比传统 JSP 混合模式
K1-4 后端开发岗位与企业项目流程 岗位职责、需求→设计→开发→联调→测试→部署→维护
K1-5 Servlet + JSP 历史背景（背景讲解） 早期 JavaWeb 方式及其痛点，为何现代转向 Spring Boot；仅作背景，不作主线
K1-6 课程项目导入：CTTS 校园实训任务管理系统，三角色五表，八阶段构建

四、项目任务或案例任务

贯穿项目导入：校园实训任务管理系统（CTTS）

本次课任务：

  1. 教师下发《CTTS 项目需求说明书（简版）》，介绍系统业务背景。
  2. 学生分组（每组 4~5 人），认领项目角色（学生/教师/管理员视角），从不同角色立场阅读需求。
  3. 每组用 5 分钟口头描述：从你认领角色的角度看，这个系统需要哪些核心功能？

项目背景概述（详见 教学资料.md 综合示例）：

  • 系统名称：校园实训任务管理系统（Campus Training Task System，CTTS）
  • 三种角色：学生、教师、管理员
  • 五张核心表：sys_user、training_project、task、task_submission、task_review
  • 课程八阶段逐步构建，本课程结束时交付可运行、可演示、可部署的后端项目

📌 本节课不写代码，重点是理解项目、建立全局认知。代码开发从第 3 次课开始。

五、课堂互动设计

互动 1：课前 5 分钟讨论（开场导入）

项目 内容
互动问题 "在你理解中，后端开发到底是做什么的？和你学过的 Java 程序设计有什么不同？"
组织方式 自由发言，教师板书关键词，不评判对错
预期学生输出 提到"服务器""数据库""处理请求""写接口""不画界面"等关键词
教师点评要点 肯定合理认知，纠正"后端=写 SQL""后端=运维"等偏差；引出 K1-1

互动 2：架构辨识小活动（讲解 K1-2、K1-3 后）

项目 内容
互动问题 给出 5 个常见软件（微信 PC 版、淘宝网页版、手机银行 APP、在线文档、教务系统网页版），请学生判断哪些是 B/S、哪些是 C/S，哪些是前后端分离
组织方式 全班举手投票，少数派陈述理由
预期学生输出 能区分 B/S 与 C/S；对"前后端分离"判断可能有分歧
教师点评要点 强调 B/S 不等于前后端分离（JSP 也是 B/S 但未分离）；引出现代后端开发主流模式

互动 3：项目角色认领（讲解 K1-6 时）

项目 内容
互动任务 分组认领 CTTS 角色，从该角色视角列出"我最希望系统有的 3 个功能"
组织方式 小组讨论 5 分钟 → 每组派代表发言 1 分钟
预期学生输出 学生视角：查看任务、提交成果、看成绩；教师视角：发布任务、评审、看进度；管理员视角：管用户、管项目
教师点评要点 引导发现"同一系统不同角色需求不同"，这正是后端要做权限控制的原因（伏笔，第 6 模块）

六、课程思政融入点

项目 内容
融入点 用技术解决真实问题：CTTS 是为了改善校园实训管理中"任务下发混乱、提交易丢失、评审难追溯"的真实痛点
技术关联 后端开发的本质是"用技术解决业务问题"，而非堆砌技术
引导问题 "如果让你手动统计全班 40 人的实训任务提交与评审情况，你会遇到什么麻烦？一个系统能解决什么？"
预期价值目标 树立"技术服务社会、解决真实问题"的工程价值观；激发学生学习内驱力——所学即所用

思政自然融入，不空喊口号。通过真实校园痛点让学生体会"为什么要学后端开发"。

七、课堂练习或随堂测验

随堂练习（5 分钟，讲解结束前进行）

判断题（口头快速作答）：

  1. B/S 架构的软件都需要在客户端安装专门的程序。（✗）
  2. 前后端分离后，前端和后端可以由不同团队并行开发。（✓）
  3. JSP 页面中既写 HTML 又写 Java 代码，属于前后端分离的开发模式。（✗）
  4. 后端开发的核心职责包括接收请求、处理业务、访问数据、返回结果。（✓）

详细题目与解析见 题库.md。此处仅作课堂快速互动，不计分。

八、课后任务

  1. 阅读：通读同文件夹 教学资料.md，重点理解 B/S 架构、前后端分离、后端开发职责。
  2. 思考：用 200 字描述"前后端分离与传统 JSP 模式的区别"，下次课抽查。
  3. 项目准备：每组讨论并提交一份《CTTS 角色功能清单》（1 页），列出三种角色各自期望的核心功能（至少各 5 条）。
  4. 环境准备（可选预习）：安装 JDK 17、IntelliJ IDEA、MySQL 8.x、Apifox/Postman，为第 3 次课搭建项目做准备。
  5. 拓展阅读：了解 Apache、Tomcat、Nginx 等 Web 服务器的基本概念（选做）。
