课程名称：Java Web 后端开发技术 项目载体：CTTS 校园实训任务管理系统 课时：2 学时（90 分钟） 课型：实践课（M7 综合项目开发模块）

一、课程信息

要素 内容
课程名称 Java Web 后端开发技术
授课对象 软件工程 / 计算机科学与技术专业本科三年级
先修内容 Spring Boot 基础、MyBatis-Plus、JWT 鉴权、统一异常处理、Knife4j 接口文档
技术栈 Java 17 + Spring Boot 3.x + MyBatis-Plus + MySQL 8.x + JWT + Knife4j
项目包名 com.ctts
教学场地 机房（每人一机，预装 JDK17、IDEA、MySQL、Apifox）

二、教学目标

知识目标

  1. 掌握多角色（学生 / 教师 / 管理员）业务接口的分层设计方法。
  2. 理解 Controller-Service-Mapper 三层链路在复杂业务中的职责划分。
  3. 掌握多表关联查询在 MyBatis-Plus 中的实现方式（XML 自定义 SQL + DTO 映射）。
  4. 熟悉接口契约（请求 / 响应 / 状态码）的设计规范。

能力目标

  1. 能够独立完成教师端 5 个核心接口的开发与联调。
  2. 能够独立完成学生端 5 个核心接口的开发与联调。
  3. 能够独立完成管理员端用户管理接口的开发。
  4. 能够使用 Apifox 完成接口联调测试，定位并修复常见 Bug。
  5. 能够编写符合规范的参数校验、统一响应、异常处理代码。

素质目标（课程思政）

  1. 团队协作精神：通过接口契约让前后端各司其职，体会"契约精神"在团队协作中的价值。
  2. 工程严谨态度：参数校验、异常处理体现对用户和系统的负责。
  3. 规范意识：统一响应结构、统一异常处理体现"行业规范"意识。

三、教学重点与难点

教学重点

  1. 教师端"查看项目下任务列表"多表关联查询的实现。
  2. 教师端"评审提交"业务的事务处理与状态流转。
  3. 学生端"提交任务成果"的参数校验与文件 / 文本处理。
  4. 接口的参数校验（@Valid + 分组校验）、统一响应（Result<T>）、全局异常处理。

教学难点

  1. 多角色权限隔离：同一接口不同角色返回不同数据范围。
  2. 多表关联结果的 DTO 映射：MyBatis-Plus 自定义 SQL 与结果集映射。
  3. 接口契约设计：如何让接口既满足当前需求又具备一定扩展性。

四、学情分析

  1. 学生已掌握 Spring Boot、MyBatis-Plus、JWT 基础用法，但缺乏完整业务链路的整合经验。
  2. 学生在前期课程中多写"单表 CRUD"，对多表关联 + 权限隔离的复杂场景较生疏。
  3. 部分学生对 Apifox 联调不熟练，容易出现"代码写完但调不通"的问题。
  4. 学生独立排查 Bug 的能力较弱，需要通过"常见问题排查表"辅助。

五、教学方法

方法 说明
任务驱动法 以 CTTS 三角色核心接口为任务，按模块拆解逐步实现
演示-模仿法 教师演示一个完整链路（创建实训项目），学生模仿完成其余接口
小组协作法 2 人一组，分别承担"教师端 / 学生端"，通过接口契约联调
问题复盘法 课堂末尾进行"接口联调问题汇总"复盘，强化排错能力
思政融入法 在接口契约讲解中融入"团队协作-各司其职"思政元素

七、教学过程与时间分配（90 分钟）

阶段一：任务导入与契约讲解（15 分钟）

时间 环节 教师活动 学生活动 思政融入
0-5 min 项目回顾 回顾 CTTS 系统架构、5 张表关系、三角色权限 检查本地项目能否启动 —
5-10 min 任务发布 发布本课实践任务清单（10 个接口），讲解验收标准 记录任务清单 责任意识：明确"交付"标准
10-15 min 接口契约讲解 讲解统一响应结构 Result<T>、接口文档规范、前后端契约 理解契约样例 团队协作：契约让前后端各司其职

阶段二：教师端核心接口演示与实践（25 分钟）

时间 环节 教师活动 学生活动
15-25 min 演示"创建实训项目"完整链路 演示 ProjectController → ProjectService → ProjectMapper 全链路 + 参数校验 + 异常处理 跟随编码，完成创建项目接口
25-35 min 演示"查看项目下任务列表"多表关联 演示自定义 XML SQL + DTO 映射 + Knife4j 测试 模仿完成"发布任务"接口
35-40 min 教师端其余接口实践 巡回指导 完成"查看学生提交情况""评审提交"接口

实践步骤：①建 DTO/VO → ②写 Controller → ③写 Service → ④写 Mapper → ⑤Knife4j 验证。 验收标准：5 个教师端接口在 Knife4j 中均能正确返回 Result<T>，参数校验生效。

阶段三：学生端核心接口实践（20 分钟）

时间 环节 教师活动 学生活动
40-50 min 学生端接口讲解 讲解 StudentController 的 5 个接口设计要点（权限隔离、提交校验） 完成"查看实训项目列表""查看任务详情"
50-60 min 学生端提交与评审反馈 巡回指导，重点讲解"提交任务成果"的校验 完成"提交任务成果""查看评审反馈""查看个人成绩"

验收标准：5 个学生端接口在 Knife4j 中均能正确返回，且与教师端数据一致。

阶段四：管理员端接口实践（10 分钟）

时间 环节 教师活动 学生活动
60-70 min 管理员端用户管理 讲解 AdminUserController 的增删改查 + 项目状态管理 完成管理员端接口

验收标准：管理员端能完成用户增删改查，项目状态管理生效。

阶段五：Apifox 联调与问题复盘（15 分钟）

时间 环节 教师活动 学生活动
70-80 min Apifox 联调 指导学生使用 Apifox 完成三角色联调测试用例 2 人一组互测对方接口
80-90 min 问题复盘 汇总课堂联调问题，对照"常见问题排查表"分析根因 提交本组联调问题清单

课堂互动：项目任务复盘——接口联调问题汇总 教师收集各组联调问题，分类（参数 / 权限 / 关联查询 / 事务 / 文档），现场点评。

阶段六：课后拓展（5 分钟，可延伸至课后）

时间 环节 内容
课末 作业布置 ① 完善未完成接口；② 补充 Apifox 测试用例；③ 预习第 22 次课"权限精细化控制"
课后 拓展任务 为评审接口增加"批量评审"功能；为提交接口增加文件上传支持

八、实践任务清单与验收标准

实践任务清单（10 个核心接口）

序号 角色 接口 难点
1 教师 创建实训项目 POST /api/teacher/projects 参数校验
2 教师 发布任务 POST /api/teacher/projects/{pid}/tasks 关联项目
3 教师 查看项目下任务列表 GET /api/teacher/projects/{pid}/tasks 多表关联
4 教师 查看学生提交情况 GET /api/teacher/tasks/{tid}/submissions 多表关联
5 教师 评审提交 PUT /api/teacher/submissions/{sid}/review 状态流转 + 事务
6 学生 查看实训项目列表 GET /api/student/projects 权限隔离
7 学生 查看任务详情 GET /api/student/tasks/{tid} 关联查询
8 学生 提交任务成果 POST /api/student/tasks/{tid}/submissions 校验 + 唯一性
9 学生 查看评审反馈 GET /api/student/submissions/{sid} 关联查询
10 学生 查看个人成绩 GET /api/student/grades 聚合查询

管理员端接口（用户 CRUD + 项目状态管理）作为基础任务，不计入核心 10 个。

验收标准

  1. 所有接口在 Knife4j 中可访问，文档注释完整。
  2. 所有接口返回统一 Result<T> 结构，参数校验生效，异常由全局处理器捕获。
  3. 教师端接口 3、4 的多表关联查询结果正确。
  4. 学生端接口 8 的"唯一性校验"（同一任务未评审前不可重复提交）生效。
  5. Apifox 联调测试用例全部通过（含正常 + 异常用例）。

思政元素 融入环节 融入方式
