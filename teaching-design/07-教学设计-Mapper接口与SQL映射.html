二、教学目标

知识目标

  1. 理解 @Mapper 注解与 @MapperScan 注解的作用与差异，掌握 Mapper 接口注册到 Spring 容器的两种方式。
  2. 掌握 MyBatis-Plus 内置 BaseMapper 接口的常用方法：insert、deleteById、updateById、selectById、selectList 等。
  3. 掌握实体类与数据库表的映射注解：@TableName、@TableId、@TableField，并能正确处理字段不一致与非持久化字段。
  4. 掌握注解 SQL 的写法：@Select / @Insert / @Update / @Delete，理解参数绑定 #{param} 与 ${param} 的本质区别。
  5. 掌握 XML SQL 映射文件的结构：namespace、select/insert/update/delete 标签、resultMap、parameterType。

能力目标

  1. 能够为 CTTS 项目中的 sys_user、training_project 表编写符合规范的实体类与 Mapper 接口。
  2. 能够针对同一查询需求，分别使用注解 SQL 与 XML SQL 两种方式实现并对比优劣。
  3. 能够独立排查 Mapper 开发中的常见错误：Mapper 未扫描、XML 路径不对、字段映射不一致等。
  4. 能够识别 SQL 注入风险，并在编码中坚持使用 #{} 参数化查询保障数据安全。

素质目标（课程思政）

  1. 树立"数据安全第一"的意识——SQL 注入是 OWASP Top 10 之首，写代码必须考虑安全。
  2. 培养"按规范做事"的工程素养——Mapper 接口与 XML 的命名空间、字段映射必须严格对应。
  3. 增强"对比辨析"的批判性思维——注解 SQL 与 XML SQL 各有适用场景，需根据复杂度选择。

三、主要知识点纲要

详细讲解内容见同文件夹 教学资料.md，此处为纲要。

编号 知识点 要点
K7-1 @Mapper 注解与 @MapperScan @Mapper 标注在接口上逐个声明；@MapperScan 标注在启动类上批量扫描 mapper 包，二者二选一
K7-2 BaseMapper 接口 MyBatis-Plus 内置 CRUD 方法：insert、deleteById、updateById、selectById、selectList、selectBatchIds 等，无需写 SQL 即可用
K7-3 实体类与表映射 @TableName 映射表名；@TableId 映射主键（IdType.AUTO/ASSIGN_ID）；@TableField 映射字段、exist=false 标记非表字段
K7-4 注解 SQL @Select/@Insert/@Update/@Delete 写在接口方法上；参数绑定 #{} 预编译防注入，${} 字符串拼接有注入风险
K7-5 XML SQL 映射 mapper.xml 文件结构：namespace 绑定接口全限定名；select/insert/update/delete 标签；resultMap 字段映射；parameterType 参数类型

四、项目任务或案例任务

贯穿项目推进：CTTS 持久层落地（第 3 阶段）

本次课任务：为 CTTS 系统的 sys_user 与 training_project 两张表完成持久层基础搭建。

  1. 创建实体类：根据表结构编写 SysUser、TrainingProject 实体类，正确使用 @TableName、@TableId、@TableField 注解。
  2. 创建 Mapper 接口：分别编写 SysUserMapper、TrainingProjectMapper，继承 BaseMapper 获得内置 CRUD；同时在 SysUserMapper 上用 @Select 编写一个按用户名模糊查询的自定义方法，在 TrainingProjectMapper 上用 XML 编写一个按状态查询的自定义方法。
  3. 编写 XML 映射文件：为 TrainingProjectMapper 编写 TrainingProjectMapper.xml，包含 namespace、resultMap 与 select 标签。
  4. 验证 CRUD：编写一个 MapperTest 测试类（或简易 Controller），调用 selectById、insert、selectList、自定义查询方法，验证数据读写正常。

📌 本节课聚焦"持久层 Mapper 与 SQL 映射"，不涉及 Service/Controller 完整业务层（后续课程内容）。建表 SQL 见 教学资料.md 综合示例。

互动 2：SQL 查询挑战（讲解 K7-4、K7-5 后）

项目 内容
互动任务 同一查询需求——"按状态查询 training_project 表中所有进行中的项目"——分两组分别用注解 SQL和XML SQL实现，3 分钟内完成，对比两种写法
组织方式 全班分两组，每组选一种方式，组长展示代码并讲解

教师点评要点 强调两种方式本质都是"接口 + SQL"，区别只在 SQL 写在哪里；简单查询用注解更轻量，复杂动态 SQL 用 XML 更清晰；过渡到课程思政——#{} 防注入

互动 3：SQL 注入演示（课程思政环节）

项目 内容
互动问题 "如果查询用户的 SQL 写成 SELECT * FROM sys_user WHERE username = '${username}'，当用户输入 ' OR '1'='1 时会发生什么？"
组织方式 教师演示拼接结果，学生观察并回答
预期学生输出 "条件变成 WHERE username = '' OR '1'='1'，永远成立，会查出全部用户"
教师点评要点 这就是 SQL 注入的经典案例；强调必须用 #{} 参数化查询；引出数据安全意识

六、课程思政融入点

项目 内容
融入点 数据安全意识——SQL 注入风险与参数化查询的重要性
技术关联 ${param} 是字符串拼接，可被注入恶意 SQL；#{param} 是预编译占位符，参数会被安全转义，从根本上防止注入
引导问题 "你写的一行 SQL，如果用错了 ${}，可能让整个数据库被人拖走——这不是危言耸听，是每年都在真实发生的安全事故"
真实案例 2024 年某高校教务系统因登录接口使用 ${} 拼接用户名，被攻击者绕过登录获取全部学生信息——技术细节决定数据安全
预期价值目标 树立"代码即安全"的意识：写代码时主动考虑安全风险，养成默认使用 #{} 的习惯；培养工程师对用户数据负责的职业操守

思政自然融入技术细节，不空喊口号。通过 ${} 与 #{} 的对比让学生体会"一行代码可能引发安全事故"。

七、课堂练习或随堂测验

随堂练习（5 分钟，讲解结束前进行）

判断题（口头快速作答）：

  1. @Mapper 和 @MapperScan 可以同时使用，但通常二选一即可。（✓）
  2. 继承 BaseMapper 后，无需写任何 SQL 即可完成单表的增删改查。（✓）
  3. @TableField(exist = false) 表示该字段在数据库表中不存在，不会被 MyBatis-Plus 当作表字段处理。（✓）
  4. #{param} 和 ${param} 在功能上完全等价，可以互换使用。（✗）

详细题目与解析见 题库.md。此处仅作课堂快速互动，不计分。

八、课后任务

  1. 阅读：通读同文件夹 教学资料.md，重点理解 @MapperScan、BaseMapper 方法、@TableName/@TableId/@TableField 三大注解、#{} 与 ${} 的区别。
  2. 动手实践：在本机 CTTS 项目中完成 sys_user 与 training_project 两张表的实体类、Mapper 接口、XML 映射文件，并通过测试类验证 CRUD（详见教学资料综合示例）。
  3. 对比思考：用 200 字描述"注解 SQL 与 XML SQL 的适用场景对比"，下次课抽查。
  4. 拓展练习（选做）：尝试为 sys_user 表编写一个使用 ${} 的"动态排序字段"查询（如 ORDER BY ${column}），思考为什么排序字段必须用 ${} 而不能用 #{}。
  5. 拓展阅读：阅读 MyBatis-Plus 官方文档关于 BaseMapper 方法清单，了解 selectPage、selectByMap 等扩展方法（选做，为后续课程铺垫）。
