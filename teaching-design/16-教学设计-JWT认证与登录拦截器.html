二、教学目标

2.1 知识目标

  • K1：能够复述 JWT 的三段结构（Header 头部、Payload 载荷、Signature 签名），并说明每段的作用与编码方式。
  • K2：能够阐述 HS256 签名算法的原理（HMAC + SHA-256 + 密钥），并能说明"为什么签名能防篡改"。
  • K3：能够说明 jjwt 库生成与解析 Token 的核心 API（Jwts.builder()、Jwts.parser()、Claims）。
  • K4：能够阐述 HandlerInterceptor 接口三个方法（preHandle/postHandle/afterCompletion）的执行时机与作用。
  • K5：能够说明 WebMvcConfigurer 的 addInterceptors 方法注册拦截器的机制，并能区分拦截路径与排除路径。
  • K6：能够阐述基于 Token 中 role 字段实现简单角色权限控制的思路（拦截器校验或注解校验）。

2.2 能力目标

  • A1：能够独立在 pom.xml 中添加 jjwt 依赖（jjwt-api/jjwt-impl/jjwt-jackson）。
  • A2：能够独立编写 JwtUtil 工具类，实现生成 Token（含 userId/username/role claims）、解析 Token、验证过期。
  • A3：能够独立实现 LoginInterceptor 拦截器，从 Authorization Header 获取 Bearer Token 并校验。
  • A4：能够独立实现 WebMvcConfig 配置类，注册拦截器并配置拦截/排除路径（登录、注册、Knife4j 放行）。
  • A5：能够改造登录接口，登录成功返回 JWT Token。
  • A6：能够使用 ThreadLocal 封装 CurrentUserContext，在拦截器中存入当前用户，在 Controller/Service 中取出使用。
  • A7：能够使用 Apifox/Postman 完成"无 Token 401→登录获取 Token→携带 Token 访问"完整认证流程测试，并定位 Token 过期/格式错误/未带 Token 等常见报错。

2.3 素质目标（课程思政）

  • S1：树立"安全责任"意识——认证授权是系统的第一道防线，一行 Token 校验代码的疏漏可能导致全量数据泄露。
  • S2：培养"防御式编程"思维——永远不信任客户端输入，所有受保护接口必须校验 Token。
  • S3：建立"工程规范"意识——拦截器路径配置、密钥管理、Token 过期时间等均需遵循团队规范。
  • S4：理解"权限最小化"原则——不同角色只授予完成任务所需的最低权限。

三、教学重点

  1. JWT 三段结构（Header + Payload + Signature）与 HS256 签名原理。
  2. 使用 jjwt 库生成与解析 Token 的完整代码（JwtUtil 工具类）。
  3. HandlerInterceptor.preHandle 校验 Token 的完整流程。
  4. WebMvcConfigurer.addInterceptors 注册拦截器与路径配置。
  5. ThreadLocal 存储当前用户的最佳实践（与内存泄漏防范）。

四、教学难点

  1. JWT 为什么能防篡改：学生需理解签名 = HMAC-SHA256(base64(header) + "." + base64(payload), secret)，任一段被改则签名校验失败。
  2. 拦截器执行时机与 Spring MVC 流程的关系：preHandle 在 DispatcherServlet→HandlerMapping→HandlerAdapter 之间执行，先于 Controller。
  3. ThreadLocal 与内存泄漏：为什么必须在 afterCompletion 中 remove，否则线程池复用线程会导致用户串号。
  4. 拦截路径与排除路径的优先级：excludePathPatterns 优先于 addPathPatterns，且 /** 与子路径的匹配规则。
  5. Bearer Token 的约定：为什么 Header 是 Authorization: Bearer xxx，Bearer 前缀的作用与剥离。

五、学情分析

  • 前置基础：学生已学习第15次课，掌握了 BCrypt 密码加密、Session/Token 认证对比，知道"登录成功返回 Token"的概念，但尚未亲手实现 JWT。
  • 薄弱环节：
    • 约 40% 学生对 Base64 编码、HMAC 算法等密码学基础不熟悉，看 JWT 结构会发懵。
    • 约 30% 学生没写过拦截器，对 Spring MVC 请求处理流程不清晰。
    • 多数学生未使用过 ThreadLocal，不理解"线程内共享"的用途。
  • 学习诉求：JWT 是面试高频考点（"JWT 结构""JWT 与 Session 区别""JWT 怎么防篡改"），学生希望学到"能写也能讲"的深度。
  • 班级差异：约 25% 学生基础扎实，可挑战注解式权限控制；约 20% 学生需在 jjwt 依赖导入与 API 调用上多花时间演示。

七、教学准备

  • 教师准备：
    • CTTS 项目骨架代码（已含第15次课的注册登录接口、sys_user 表）。
    • jwt.io 在线解析演示素材。
    • Apifox 测试集合（含"无 Token""带 Token""过期 Token""错误 Token"四个用例）。
    • JWT 三段结构图解、Spring MVC 拦截器执行流程图。
    • 真实安全事件案例（某系统因未校验 Token 导致越权访问）。
  • 学生准备：
    • 复习第15次课 Session/Token 对比、BCrypt 加密。
    • 预读 jjwt 官方文档 jjwt-api README。
    • 复习 Spring MVC 请求处理流程。
  • 环境准备：JDK 17、IDEA 2023.x、MySQL 8.x、Apifox/Postman、Git、Maven 3.8+。

九、课程思政融入

融入点 思政元素 教学方式
开场案例：某系统未校验 Token 导致越权访问 安全责任——认证授权是系统第一道防线 案例讲述
preHandle 返回 false 拦截非法请求 防御式编程——不信任任何客户端输入 代码示范
密钥管理：密钥不能硬编码、不能提交到 Git 工程规范——安全配置需走配置中心/环境变量 强调规范
不同角色不同权限 权限最小化原则——最小授权、职责分离 角色矩阵讲解
ThreadLocal 必须 remove 工程严谨——线程池复用导致用户串号是生产事故 易错点剖析

十、教学评价与反思

10.1 教学评价

  • 过程性评价：课堂互动"两人一组讲解 JWT 流程"（占 30%）、代码跟敲完成度（占 30%）。
  • 结果性评价：课后项目任务提交（JwtUtil + LoginInterceptor + WebMvcConfig + 登录接口改造）（占 40%）。
  • 评价标准：
    • 优秀（90+）：能独立完成全部代码，能口述 JWT 防篡改原理，能排查 Token 过期/格式错误等报错。
    • 良好（75-89）：能完成核心代码，能说明 JWT 三段结构，基本能排查报错。
    • 合格（60-74）：能在指导下完成代码，能说出 JWT 基本概念。
    • 不合格（<60）：无法完成核心代码或概念不清。

10.2 教学反思（课后填写）

10.3 改进方向

  • 若学生基础薄弱，可增加 1 课时实训，专门跟敲 JwtUtil 与 LoginInterceptor。
  • 可引入"JWT 被盗""Token 过期刷新"等进阶话题作为拓展阅读。
  • 下次课 Spring Security 整合 JWT 时，可对比"手写拦截器"与"Spring Security 过滤器链"的差异。
