二、教学目标

2.1 知识目标

  • K13-1 理解 JSR 380（Bean Validation 2.0）规范，掌握 @Valid / @Validated 区别，熟练使用 @NotBlank / @NotNull / @NotEmpty / @Size / @Min / @Max / @Pattern / @Email 等常用校验注解。
  • K13-2 掌握 @RestControllerAdvice + @ExceptionHandler 全局异常处理机制，能够针对 MethodArgumentNotValidException、ConstraintViolationException、MissingServletRequestParameterException、MethodArgumentTypeMismatchException 等异常分别处理。
  • K13-3 掌握自定义业务异常 BusinessException（含 code + message）的设计方法，理解其继承 RuntimeException 的原因，并能被全局异常处理器统一捕获。
  • K13-4 理解 SLF4J 门面模式与 Logback 实现，掌握 @Slf4j 注解、日志级别（TRACE/DEBUG/INFO/WARN/ERROR）、application.yml 日志配置与日志文件输出策略。
  • K13-5 掌握空指针、参数类型不匹配、SQL 异常、404/500 等常见后端错误的排查思路与定位方法。

2.2 能力目标

  • 能够为 CTTS 的 ProjectDTO / TaskDTO 添加合适的校验注解，并实现分组校验。
  • 能够独立创建 GlobalExceptionHandler 全局异常处理器，统一返回 Result<T> 标准响应。
  • 能够设计 BusinessException 并在 Service 层抛出，由全局处理器转换为友好提示。
  • 能够在 Controller / Service 中使用 @Slf4j 输出不同级别日志，并通过 application.yml 配置日志级别与文件输出。
  • 能够根据控制台日志、堆栈信息、Postman 响应快速定位并修复后端常见错误。

2.3 素质目标（课程思政）

  • 系统稳定性意识：异常处理不是"兜底糊弄"，而是对用户、对系统的负责，体现工程师的工匠精神与责任担当。
  • 服务意识：把 500 错误转成"系统繁忙，请稍后重试"是后端对前端、对用户的体贴，体现"以用户为中心"的服务理念。
  • 规范意识：统一异常返回结构、统一日志规范，是团队协作的基础，培养工程化思维与团队契约精神。
  • 底线思维：日志不是"装饰品"，是生产环境排查问题的"黑匣子"，培养严谨、可追溯的工程素养。

三、教学重点与难点

3.1 教学重点

  1. @Valid 与 @Validated 的区别及分组校验的使用场景。
  2. @RestControllerAdvice + @ExceptionHandler 的编写套路与异常匹配优先级。
  3. BusinessException 自定义异常类的设计（code + message + 构造器重载）。
  4. SLF4J + Logback 的配置与 @Slf4j 的使用。
  5. 统一返回 Result<T> 与异常处理的配合，形成完整闭环。

3.2 教学难点

  1. 异常处理的"匹配最近原则"：子类异常优先于父类异常，避免被 Exception "兜底"吃掉。
  2. MethodArgumentNotValidException（表单/JSON 体校验失败）与 ConstraintViolationException（@RequestParam / @PathVariable 校验失败）的区别与处理。
  3. 日志级别选择：什么时候用 INFO、什么时候用 WARN、什么时候用 ERROR，避免日志污染。
  4. 参数校验失败 → 异常处理器 → 统一返回 的完整链路理解。

3.3 重点难点突破策略

  • 对比演示法：先写一个没有校验、没有异常处理的"裸接口"，用 Postman 传入空值/错误类型，让学员直观看到 Spring 默认的 400/500 错误页有多"难看"，再引入校验与全局异常处理，形成强烈反差。
  • 流程图法：用一张"请求 → 校验 → 异常 → 处理器 → Result"完整流程图串起所有知识点。
  • 案例驱动法：以 CTTS 的"创建项目"接口为主线，逐步加校验、加异常处理、加日志，最终形成可上线的工业级代码。
  • 面试快问快答：把高频面试题（@Valid 与 @Validated 区别、全局异常处理原理、日志级别选择）融入课堂，既巩固知识又对接就业。

环节2：K13-1 参数校验（18 分钟）

教学动作：

（1）JSR 380 规范简介（3 分钟）

  • Bean Validation 2.0（JSR 380），Hibernate Validator 是参考实现。
  • Spring Boot 3.x 自动集成 spring-boot-starter-validation。

（2）常用校验注解（8 分钟）—— 对比表格讲解

注解 作用 适用类型 常用场景
@NotNull 非 null 任意类型 对象字段
@NotEmpty 非 null 且非空 Collection/Map/Array/String 集合
@NotBlank 非 null 且去空格后非空 String 字符串
@Size(min,max) 长度范围 String/Collection 字符串长度、集合大小
@Min / @Max 最小/最大值 数字 年龄、进度
@Pattern(regexp) 正则匹配 String 手机号、日期格式
@Email 邮箱格式 String 邮箱字段
@Past / @Future 过去/未来日期 Date/LocalDate 出生日期、截止时间

口诀记忆：NotNull 管对象，@NotEmpty 管集合，@NotBlank 管字符串，三者层层递进。

（3）@Valid 与 @Validated 区别（4 分钟）

对比项 @Valid @Validated
来源 JSR 380（标准） Spring（扩展）
分组校验 不支持 支持
嵌套校验 支持（标注在字段上） 支持
用在方法参数 支持 支持
用在 @RequestParam 不支持 支持（需类上加 @Validated）

（4）CTTS 实战——ProjectDTO 添加校验（3 分钟）

@Data
public class ProjectDTO {
    @NotBlank(message = "项目名称不能为空")
    @Size(min = 2, max = 50, message = "项目名称长度需在2-50之间")
    private String name;

    @Size(max = 200, message = "项目描述不能超过200字")
    private String description;

    @NotNull(message = "负责人ID不能为空")
    @Min(value = 1, message = "负责人ID非法")
    private Long leaderId;
}

Controller 使用：

@PostMapping
public Result<Void> create(@Valid @RequestBody ProjectDTO dto) {
    projectService.create(dto);
    return Result.success();
}

环节3：K13-2 全局异常处理（15 分钟）

教学动作：

（1）流程图讲解（3 分钟）

请求 → Controller @Valid 校验
        ├─ 校验通过 → 业务执行
        └─ 校验失败 → 抛 MethodArgumentNotValidException
                          ↓
                  @RestControllerAdvice 全局捕获
                          ↓
                  @ExceptionHandler 匹配处理
                          ↓
                  返回统一 Result<T>（含 code/message）

（2）@RestControllerAdvice 与 @ExceptionHandler 讲解（4 分钟）

  • @RestControllerAdvice = @ControllerAdvice + @ResponseBody，返回值自动序列化为 JSON。
  • @ExceptionHandler(XxxException.class) 标注在方法上，处理指定类型异常。
  • 匹配原则：子类优先，最近优先，未被捕获的才会落到 Exception 兜底。

（3）GlobalExceptionHandler 完整代码 Live Coding（8 分钟）

@Slf4j
@RestControllerAdvice
public class GlobalExceptionHandler {

    /** 1. @RequestBody 体校验失败 */
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<Void> handleValid(MethodArgumentNotValidException e) {
        String msg = e.getBindingResult().getFieldErrors().stream()
                .map(fe -> fe.getField() + ": " + fe.getDefaultMessage())
                .collect(Collectors.joining("; "));
        log.warn("参数校验失败: {}", msg);
        return Result.fail(400, msg);
    }

    /** 2. @RequestParam/@PathVariable 校验失败 */
    @ExceptionHandler(ConstraintViolationException.class)
    public Result<Void> handleConstraint(ConstraintViolationException e) {
        String msg = e.getConstraintViolations().stream()
                .map(cv -> cv.getMessage())
                .collect(Collectors.joining("; "));
        log.warn("约束校验失败: {}", msg);
        return Result.fail(400, msg);
    }

    /** 3. 参数类型不匹配 */
    @ExceptionHandler(MethodArgumentTypeMismatchException.class)
    public Result<Void> handleTypeMismatch(MethodArgumentTypeMismatchException e) {
        log.warn("参数类型不匹配: {}", e.getMessage());
        return Result.fail(400, "参数类型不匹配: " + e.getName());
    }

    /** 4. 业务异常 */
    @ExceptionHandler(BusinessException.class)
    public Result<Void> handleBusiness(BusinessException e) {
        log.warn("业务异常: code={}, msg={}", e.getCode(), e.getMessage());
        return Result.fail(e.getCode(), e.getMessage());
    }

    /** 5. 兜底异常 */
    @ExceptionHandler(Exception.class)
    public Result<Void> handleException(Exception e) {
        log.error("系统异常", e);
        return Result.fail(500, "系统繁忙，请稍后重试");
    }
}

强调：兜底异常一定不要把堆栈返回给前端（信息泄露），但要 log.error 记录完整堆栈便于排查。

环节4：K13-3 自定义业务异常（10 分钟）

教学动作：

（1）为什么需要自定义异常（2 分钟）

  • 业务错误（如"项目不存在"、"项目名重复"）不是系统异常，不该返回 500。
  • 用 RuntimeException 表达太宽泛，无法携带业务码。
  • BusinessException(code, message) 可以精准表达业务错误，并返回对应码。

（2）BusinessException 设计（4 分钟）

@Getter
public class BusinessException extends RuntimeException {
    private final Integer code;

    public BusinessException(Integer code, String message) {
        super(message);
        this.code = code;
    }

    public BusinessException(String message) {
        this(500, message);
    }
}

讲解要点：

  • 继承 RuntimeException（非受检异常），避免在 Service 方法签名上到处 throws。
  • code 字段携带业务错误码，前端可据此做不同提示（如 40001 跳登录、40002 弹窗）。
  • 提供两个构造器重载，简化使用。

（3）Service 层抛出业务异常（4 分钟）

@Service
@Slf4j
public class ProjectServiceImpl implements ProjectService {

    @Override
    public void create(ProjectDTO dto) {
        // 1. 校验项目名是否重复
        if (projectMapper.existsByName(dto.getName())) {
            log.warn("项目名重复: {}", dto.getName());
            throw new BusinessException(40010, "项目名已存在");
        }
        // 2. 校验负责人是否存在
        if (!userMapper.existsById(dto.getLeaderId())) {
            throw new BusinessException(40011, "负责人不存在");
        }
        // 3. 执行新增
        Project project = new Project();
        BeanUtils.copyProperties(dto, project);
        projectMapper.insert(project);
        log.info("创建项目成功: id={}, name={}", project.getId(), project.getName());
    }
}

环节5：K13-4 日志基础（12 分钟）

教学动作：

（1）SLF4J 与 Logback 关系（3 分钟）

  • SLF4J 是门面（接口），Logback 是实现。
  • Spring Boot 默认集成 Logback，无需额外引入依赖。
  • 门面模式的好处：切换日志实现（如换成 Log4j2）无需改业务代码。

（2）@Slf4j 注解与日志级别（4 分钟）

级别 说明 使用场景
TRACE 最详细 极少使用，调试细粒度流程
DEBUG 调试信息 开发环境，关键变量值
INFO 重要业务信息 上线默认级别，如"创建项目成功"
WARN 警告 可恢复的异常，如"项目名重复"
ERROR 错误 影响业务的异常，如"数据库连接失败" 
@Slf4j
@Service
public class ProjectServiceImpl {
    public void create(ProjectDTO dto) {
        log.debug("开始创建项目, dto={}", dto);
        // ...
        log.info("创建项目成功, id={}", project.getId());
        log.warn("项目名重复: {}", dto.getName());
        log.error("数据库异常", e);
    }
}

口诀：INFO 记业务，WARN 记可恢复，ERROR 记不可恢复，DEBUG 只在开发开。

（3）application.yml 日志配置（5 分钟）

logging:
  level:
    root: INFO
    com.ctts: DEBUG
    com.ctts.mp.mapper: DEBUG
  file:
    name: logs/ctts.log
  logback:
    rollingpolicy:
      max-file-size: 10MB
      max-history: 30
      total-size-cap: 1GB

讲解要点：

  • root: INFO 全局默认 INFO。
  • com.ctts: DEBUG 业务包开 DEBUG，方便排查。
  • com.ctts.mp.mapper: DEBUG 打印 MyBatis-Plus SQL（开发期必备）。
  • 日志文件按 10MB 滚动，保留 30 天，总容量 1GB 上限，避免磁盘爆满。

环节6：K13-5 常见后端错误排查（8 分钟）

教学动作：用表格 + 案例 + 排查口诀讲解

错误现象 可能原因 排查思路
空指针 NPE 对象未初始化 / 查询结果为 null 看堆栈定位行号 → 检查该行对象是否为 null → 加判空或 Optional
参数类型不匹配 400 前端传字符串后端要 Long 看日志 MethodArgumentTypeMismatchException → 检查接口参数类型
SQL 异常 字段名错 / 类型错 / 唯一约束冲突 看日志 SQL 与参数 → 对比表结构 → 检查约束
404 路径错 / 缺 @RestController / 启动类扫描不到 Postman 看 URL → 看 Controller 注解 → 看启动类 @ComponentScan
500 业务异常 / 空指针 / 数据库异常 看日志 ERROR 行 + 堆栈 → 定位代码行 → 修复

排查口诀：先看状态码（4xx 客户端、5xx 服务端）→ 再看日志（级别 + 堆栈）→ 定位代码行 → 复现验证。
