二、教学目标

1. 知识目标

  • K11-1：能准确说出PO/Entity/DTO/VO四类对象的定义、职责与区别，理解"数据库表—Entity—DTO—VO"的数据流转链路。
  • K11-2：能说明统一响应Result的设计动机，掌握code/message/data三字段规范及ok()/fail()静态方法的封装思想。
  • K11-3：能描述对象转换的两种主流方案（BeanUtils.copyProperties手动转换、MapStruct编译期自动映射），并比较其优劣。
  • K11-4：能列出Spring Boot企业级项目的标准包结构（controller/service/serviceImpl/mapper/entity/dto/vo/config/utils/exception），说明各包职责。
  • K11-5：能说出Lombok常用注解（@Data/@Getter/@Setter/@Builder/@AllArgsConstructor/@NoArgsConstructor）的作用与使用场景。

2. 能力目标

  • 能为CTTS项目独立设计ProjectDTO、ProjectVO、TaskSubmissionDTO等数据载体，并正确选择应用场景。
  • 能编写完整的Result统一响应类，含泛型、静态工厂方法、链式setter，并改造既有Controller返回格式。
  • 能使用BeanUtils.copyProperties完成Entity↔︎VO、DTO→Entity的转换，识别属性名不一致导致的拷贝失效问题。
  • 能按企业规范重构CTTS项目的包结构，使controller/service/mapper/entity/dto/vo/config/utils/exception各归其位。
  • 能使用Lombok注解简化实体类代码，避免手写getter/setter/构造器带来的冗余。

3. 素质目标

  • 工程规范意识：体会"良好的结构是可维护性的基础"，养成按分层规范组织代码的习惯。
  • 协作沟通能力：在小组讨论中清晰表达"接口返回格式统一方案"，学会倾听与妥协。
  • 精益求精的工匠精神：通过对象转换与统一响应的细节打磨，培养对代码质量的追求。
  • 抽象建模思维：从"一堆字段"到"按职责分层的数据对象"，提升面向对象的建模能力。

三、主要知识点纲要

编号 知识点 核心内容 重点/难点 学时
K11-1 PO/Entity/DTO/VO的区别与职责 Entity对应数据库表结构；DTO接收请求参数（含校验注解）；VO返回给前端的视图数据（可脱敏/聚合）；PO为持久化对象的统称，在MyBatis-Plus中Entity即充当PO 重点：四者职责边界；难点：DTO与VO何时合并、何时分离 20min
K11-2 统一响应Result设计 三字段code/message/data；泛型T表示data类型；ok()/ok(data)/fail()/fail(code,msg)静态工厂方法；链式setter；常用枚举ResultCode 重点：泛型+静态方法；难点：链式调用与重载设计 18min
K11-3 对象转换 BeanUtils.copyProperties(source,target)按属性名拷贝；Spring与Apache两套BeanUtils对比；MapStruct基于接口注解@Mapper编译期生成实现类，性能高、类型安全 重点：BeanUtils用法；难点：类型不一致、嵌套对象拷贝陷阱 15min
K11-4 项目包结构规范 com.ctts下分controller/service/serviceImpl/mapper/entity/dto/vo/config/utils/exception；service放接口、serviceImpl放实现；config放配置类；exception放自定义异常 重点：分层职责；难点：service与serviceImpl分离的必要性 15min
K11-5 Lombok常用注解 @Data=@Getter+@setter+@toString+@equalsAndHashCode+@RequiredArgsConstructor；@Builder建造者模式；@AllArgsConstructor/@NoArgsConstructor全参无参构造；IDEA需装Lombok插件+开启Annotation Processing 重点：注解组合；难点：@Builder与无参构造的冲突 12min

四、项目任务

任务主题：为CTTS定义DTO/VO/Result，重构包结构，统一Controller返回格式

任务描述

在前序课程已完成的CTTS基础上（sys_user/training_project/task/task_submission/task_review 五张表，已实现基础Controller直接返回Entity），本节课完成三件事：

  1. 定义数据载体：为 training_project（实训项目）创建 ProjectDTO（接收前端新增/修改请求）和 ProjectVO（返回给前端的视图数据，隐藏创建人密码等敏感字段）。
  2. 定义统一响应：创建 Result<T> 类，封装 code/message/data 三字段及 ok()/fail() 静态方法。
  3. 重构包结构与改造返回：按 controller/service/serviceImpl/mapper/entity/dto/vo/config/utils/exception 规范重构包结构，将 ProjectController 中的接口返回值由 Entity/List<Entity> 改为 Result<ProjectVO>/Result<List<ProjectVO>>。

验收标准

  • 包结构符合规范，5张表对应的Entity/Mapper/Service/ServiceImpl/Controller各归其位。
  • ProjectController 的查询/新增/修改/删除接口统一返回 Result<T>，Knife4j文档中可看到统一格式。
  • ProjectDTO 含JSR-303校验注解（@NotBlank/@NotNull等），ProjectVO 不含密码字段。
  • 提交Git commit，message符合规范：refactor: 重构包结构，统一Result响应格式。

五、课堂互动设计

互动主题：接口返回格式统一方案

环节 内容
提出问题 "目前我们的Controller直接返回Entity或List，前端拿到的是裸数据。请讨论：①这种做法有哪些问题？②如果让你设计一套统一的接口返回格式，你会设计哪些字段？③成功和失败如何区分？④分页数据怎么返回？"
组织方式 4~5人一组，共6组，10分钟讨论。每组用大白纸/在线文档列出方案要点，推选1人汇报（每组2分钟）。
学生输出 ①每组一份"统一响应格式设计草案"（字段名+类型+示例）；②至少指出2个直接返回Entity的弊端；③至少给出1种分页方案。
教师点评 ①归纳各组方案的共性：都提到code+message+data，说明业界共识；②指出常见误区：把HTTP状态码和业务code混淆、data直接放List导致扩展困难；③引出Result的标准答案；④表扬有创意的方案（如链式调用、枚举管理错误码）。

互动预期生成物

  • 黑板/PPT汇总6组方案对比表
  • 引出 Result<T> 的标准设计，自然过渡到K11-2讲解

六、课程思政融入点

思政要素 融入方式
工程规范——良好结构是可维护性的基础 通过包结构重构前后对比（混乱包结构 vs 分层包结构），让学生直观感受"代码是写给人看的"。"万里之行始于足下，万行代码始于规范"——一个没有规范的项目，3个月后就没人敢动。
抽象建模——从杂乱到有序的工程思维 PO/DTO/VO的划分本质是"职责分离"原则的体现。类比社会分工：数据库管理员管Entity、前端工程师管VO、后端工程师管DTO，各司其职。培养学生用抽象思维看待复杂系统。
协作精神——契约即信任 统一响应Result是前后端协作的"契约"。一旦约定，双方都遵守，体现工程协作中的诚信与契约精神。"接口文档就是工程师之间的合同"。
工匠精神——细节决定成败 对象转换中一个属性名不一致就导致数据丢失，统一响应少一个字段就让前端崩溃。培养学生对代码细节的敬畏与精益求精。

七、课堂练习

练习时长：约15分钟，紧随K11-2讲解后进行

练习1（基础，5分钟）

在CTTS项目中创建 com.ctts.common.Result<T> 类，要求：

  • 三字段：int code、String message、T data
  • 静态方法：ok()、ok(T data)、fail()、fail(int code, String message)
  • 每个字段提供链式setter（返回this）
  • 使用Lombok的 @Data + @Accessors(chain=true) 或手写链式

练习2（进阶，5分钟）

为 training_project 表编写 ProjectDTO，字段：projectName、description、startTime、endTime、creatorId。要求：

  • 使用Lombok的 @Data
  • projectName加 @NotBlank(message="项目名称不能为空")
  • startTime/endTime加 @NotNull 并加 @JsonFormat(pattern="yyyy-MM-dd")

练习3（综合，5分钟）

编写 ProjectVO，字段：id、projectName、description、startTime、endTime、creatorName（注意不是creatorId，是创建人姓名）、createTime。然后编写一个转换方法，使用 BeanUtils.copyProperties 将 TrainingProject Entity 转为 ProjectVO，并手动补全 creatorName。

练习验收

  • 3名学生上台演示，教师即时点评
  • 重点检查：泛型是否正确、链式调用是否生效、BeanUtils参数顺序（source在前target在后）
