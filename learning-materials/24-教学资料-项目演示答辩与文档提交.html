二、答辩常见问题清单（22题）

覆盖架构设计、技术选型、安全措施、性能优化、代码规范、项目反思六大方向。 每组答辩随机抽取3-4题，教师可追加1题。

A. 架构设计（6题）

Q1. 请简述CTTS项目的整体分层架构，各层职责是什么？

参考答案：Controller层（接收请求、参数校验、返回Result）、Service层（业务逻辑、事务控制）、Mapper层（数据访问）、Entity/DTO/VO（数据模型）、common层（统一返回、全局异常、JWT工具、拦截器）。遵循单一职责，Controller不写业务，Service不写SQL。

Q2. 为什么采用三层架构而不是MVC单层？多层带来的好处和代价？

参考答案：三层分离关注点，提升可维护性与可测试性；Service可被复用，便于后期扩展为RPC服务。代价是类增多、调用链变长。对CTTS规模而言利大于弊。

Q3. CTTS的包结构com.ctts下如何组织？这样设计的原因？

参考答案：按功能模块组织——controller/service/mapper/entity/dto/vo/common/config/interceptor/exception。按职责而非按角色分包，便于横向扩展新模块。

Q4. 统一返回结构Result的设计思路是什么？为什么不直接返回业务对象？

参考答案：Result含code/message/data，统一前后端契约，便于前端按code判断处理；业务对象直接返回无法表达成功/失败语义，且字段不可控。

Q5. DTO、VO、Entity三者区别？在CTTS中如何使用？

参考答案：Entity对应数据库表（如User）；DTO接收前端请求参数（如UserLoginDTO）；VO返回给前端的视图对象（如UserVO，脱敏密码）。分离避免敏感字段泄露与字段污染。

Q6. 全局异常处理器如何实现？解决了什么问题？

参考答案：@RestControllerAdvice + @ExceptionHandler，捕获BusinessException、MethodArgumentNotValidException等，统一转Result返回。解决异常处理散落、返回结构不一致问题。

B. 技术选型（5题）

Q7. 为什么选SpringBoot 3.x而不是2.x？主要差异？

参考答案：3.x基于Spring 6，要求Java 17+，支持Jakarta EE 9+（javax→jakarta），性能与原生镜像支持更好，符合最新生态。CTTS用Java 17，故选3.x。

Q8. MyBatis-Plus相比MyBatis的优势？在CTTS中用了哪些特性？

参考答案：内置CRUD、条件构造器、分页插件、代码生成。CTTS用了BaseMapper通用CRUD、LambdaQueryWrapper条件查询、PaginationInnerInterceptor分页。减少模板代码。

Q9. 为什么用JWT而不是Session？JWT的缺点是什么？

参考答案：JWT无状态、易横向扩展、前后端分离友好。缺点：令牌签发后无法主动失效（需配合黑名单/短有效期）、payload不宜存敏感信息、令牌体积大于session id。

Q10. Knife4j在项目中扮演什么角色？生产环境是否应开放？

参考答案：接口文档与调试工具，基于OpenAPI 3。开发测试期开放便于联调；生产环境应关闭或加权限，避免接口泄露。

Q11. 为什么用Maven而不是Gradle？Maven的核心机制？

参考答案：Maven生态成熟、约定优于配置、依赖管理稳定，适合教学与企业主流。核心机制：POM坐标、依赖传递、生命周期（clean/compile/test/package/install/deploy）。

C. 安全措施（5题）

Q12. 密码在数据库中如何存储？为什么不能明文？

参考答案：BCrypt加密存储（带盐）。明文存储一旦数据库泄露，所有账号暴露；MD5不加盐可被彩虹表破解；BCrypt自带盐且可调强度，更安全。

Q13. JWT令牌如何生成与校验？拦截器如何实现？

参考答案：登录成功后用HS256签名生成JWT（payload含userId、role、exp）。拦截器HandlerInterceptor在preHandle中解析Authorization头，校验签名与过期时间，将用户信息存入ThreadLocal，放行/拒绝。

Q14. 如何实现"学生不能调用教师接口"的权限控制？

参考答案：双层控制——①拦截器校验JWT中role是否匹配接口所需角色；②方法级可用自定义注解@RequireRole + AOP校验。前者统一拦截，后者灵活细粒度。

Q15. SQL注入风险如何防范？MyBatis-Plus是否天然安全？

参考答案：使用预编译（#{}占位符），MyBatis-Plus的Wrapper也参数化。但若用${}拼接或原生SQL拼接仍有风险。CTTS全程使用Wrapper/#{}，无SQL注入。

Q16. 接口参数校验如何做？校验失败如何返回？

参考答案：JSR-303注解（@NotBlank/@Email/@Size等）标注在DTO字段，Controller方法参数加@Valid。校验失败触发MethodArgumentNotValidException，全局异常处理器转Result(code=400, message=字段错误信息)。

D. 性能与规范（4题）

Q17. 分页查询如何实现？为什么不能在内存中分页？

参考答案：MyBatis-Plus分页插件PaginationInnerInterceptor，SQL层面LIMIT。内存分页需查全表，数据量大时OOM且慢；SQL分页只取所需行。

Q18. 项目中哪些场景适合加Redis缓存？CTTS是否引入？

参考答案：高频读、低频写场景，如任务列表、统计数据。CTTS基础版未引入，可作为扩展点。引入需考虑缓存一致性、过期策略、穿透/击穿/雪崩防护。

Q19. 事务用在哪些地方？@Transactional的注意事项？

参考答案：多表写入或需原子性的操作（如审批时更新报名状态+写日志）。注意：只对public方法生效、默认只回滚RuntimeException、同类内调用不生效（代理失效）、传播行为需明确。

Q20. 代码规范如何保证？用了哪些工具？

参考答案：①阿里巴巴Java开发手册约束命名/注释；②Lombok减少样板代码；③统一返回Result；④Controller/Service/Mapper命名一致；⑤可选：Checkstyle/SpotBugs静态扫描。

E. 项目反思与拓展（2题）

Q21. 项目中遇到的最大难点是什么？如何解决？

参考答案（示例）：①JWT拦截器与Spring Web资源冲突——通过excludePathPatterns放行登录/文档；②MyBatis-Plus分页插件不生效——漏配PaginationInnerInterceptor配置类；③多角色权限粒度——用自定义注解+AOP解耦。学生据实回答。

Q22. 如果给你2周时间迭代，你会优化哪些方面？

参考答案（示例）：①引入Redis缓存热点数据；②接入refreshToken机制；③增加操作日志AOP；④完善单元测试与集成测试；⑤Docker化部署；⑥前端联调接口契约。

# CTTS 部署说明

## 一、环境要求
| 组件 | 版本 | 说明 |
|------|------|------|
| JDK | 17+ | 必须，推荐OpenJDK 17 |
| Maven | 3.9+ | 构建工具 |
| MySQL | 8.0+ | 数据库 |
| Redis（可选） | 7.0+ | 缓存，基础版可不装 |

## 二、部署步骤
1. **克隆代码**
   \`\`\`bash
   git clone <仓库地址> ctts-backend
   cd ctts-backend
   \`\`\`
2. **初始化数据库**
   \`\`\`bash
   mysql -uroot -p < db/schema.sql
   mysql -uroot -p ctts < db/data.sql
   \`\`\`
3. **修改配置**
   编辑 `src/main/resources/application.yml`：
   \`\`\`yaml
   spring:
     datasource:
       url: jdbc:mysql://localhost:3306/ctts?useSSL=false&serverTimezone=Asia/Shanghai
       username: root
       password: 你的密码
   ctts:
     jwt:
       secret: your-256-bit-secret-key
       ttl: 3600000
   \`\`\`
4. **编译打包**
   \`\`\`bash
   mvn clean package -DskipTests
   \`\`\`
5. **启动服务**
   \`\`\`bash
   java -jar target/ctts-backend-1.0.0.jar
   # 或后台运行
   nohup java -jar target/ctts-backend-1.0.0.jar > ctts.log 2>&1 &
   \`\`\`
6. **验证**
   访问 http://localhost:8080/doc.html 出现Knife4j文档即成功。

## 三、配置说明
| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| server.port | 8080 | 服务端口 |
| spring.datasource.url | jdbc:mysql://... | 数据库连接 |
| ctts.jwt.secret | - | JWT签名密钥（生产须替换） |
| ctts.jwt.ttl | 3600000 | 令牌有效期（毫秒） |
| logging.level.com.ctts | INFO | 日志级别 |

## 四、常见问题
| 问题 | 解决方案 |
|------|----------|
| 端口被占用 | 修改application.yml中server.port |
| 数据库连接失败 | 检查url/账号密码、MySQL是否启动 |
| JWT签名异常 | 确认secret长度≥32字符 |
| 分页不生效 | 确认MyBatisPlusConfig已注册分页插件 |
| Knife4j 404 | 生产环境profile可能禁用文档，检查profile |

# CTTS校园实训任务管理系统 项目报告
