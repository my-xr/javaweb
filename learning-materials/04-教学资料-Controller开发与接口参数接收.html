二、知识点详解

K4-1 @RestController 与 @Controller 区别

1. 定义

  • @Controller：Spring MVC 传统的控制器注解，标记一个类为控制器。默认返回的是"视图名称"，方法返回的字符串会被 ViewResolver 解析成页面（如 JSP、Thymeleaf）。
  • @RestController：Spring 4.0 引入的组合注解，等同于 @Controller + @ResponseBody。它标记的控制器中所有方法的返回值都会直接被写入 HTTP 响应体（通常序列化为 JSON）。

源码层面：

// Spring 源码：@RestController 的定义
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
@Documented
@Controller            // ← 继承了 @Controller
@ResponseBody          // ← 组合了 @ResponseBody
public @interface RestController {
    @AliasFor(annotation = Controller.class)
    String value() default "";
}

2. 原理

Spring MVC 处理请求返回值时，会遍历 HandlerMethodReturnValueHandler 列表：

  • 如果方法所在类或方法本身标注了 @ResponseBody，则使用 RequestResponseBodyMethodProcessor 处理返回值。
  • 该处理器会调用 HttpMessageConverter（默认 MappingJackson2HttpMessageConverter）把返回对象序列化为 JSON，并写入响应体。
  • 否则使用 ModelAndViewMethodReturnValueHandler，把返回值当作视图名，跳转到页面。

3. 问题/场景

场景 选择
前后端分离项目，接口返回 JSON @RestController
服务端渲染项目，返回页面 @Controller
一个控制器既返回页面又返回 JSON @Controller，在需要返回 JSON 的方法上加 @ResponseBody

CTTS 项目是前后端分离架构，全部使用 @RestController。

4. 完整示例代码

package com.ctts.controller;

import org.springframework.stereotype.Controller;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.ResponseBody;

/**
 * 演示 @Controller 与 @RestController 区别
 * 仅用于教学对比，CTTS 项目不使用该类
 */
@Controller
public class DemoController {

    // 方式1：返回视图名（会跳转到 /WEB-INF/views/hello.jsp）
    @GetMapping("/page/hello")
    public String helloPage() {
        return "hello";
    }

    // 方式2：返回 JSON（需要方法级加 @ResponseBody）
    @GetMapping("/api/hello")
    @ResponseBody
    public String helloJson() {
        return "{\"msg\": \"hello\"}";
    }
}

对应等价的 @RestController 写法：

package com.ctts.controller;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/demo")
public class DemoRestController {

    // 直接返回 JSON，无需 @ResponseBody
    @GetMapping("/hello")
    public String hello() {
        return "{\"msg\": \"hello\"}";
    }
}

6. 易错点

  • 易错点 1：在 @Controller 类中写接口忘了加 @ResponseBody，结果返回值被当成视图名，前端 404。
  • 易错点 2：以为 @RestController 只能返回 JSON，其实它也可以返回 String、Integer、自定义对象，甚至是 ResponseEntity。
  • 易错点 3：在 @RestController 类中又加了 @ResponseBody，虽然不会报错，但属于冗余。
  • 易错点 4：类上忘记加 @RestController，只有方法上的 @GetMapping，Spring 不会识别该类为控制器，接口 404。

7. 小结

@RestController = @Controller + @ResponseBody，前后端分离项目无脑选它。记住一句话："要 JSON 就 RestController，要页面就 Controller"。

K4-2 请求映射注解

1. 定义

Spring MVC 提供了一系列注解用于把 HTTP 请求映射到 Controller 方法上：

注解 说明 常用
@RequestMapping 通用映射，可指定 method 类级别常用
@GetMapping 等价 @RequestMapping(method = GET) ★★★
@PostMapping 等价 @RequestMapping(method = POST) ★★★
@PutMapping 等价 @RequestMapping(method = PUT) ★★
@DeleteMapping 等价 @RequestMapping(method = DELETE) ★★
@PatchMapping 等价 @RequestMapping(method = PATCH) ★

2. 原理

  • @RequestMapping 标注在类上：定义该控制器所有接口的"统一前缀"（base path）。
  • 标注在方法上：定义具体的访问路径。
  • 最终访问路径 = 类上路径 + 方法上路径。

路径参数用 {xxx} 占位，配合 @PathVariable 取值。例如：

@GetMapping("/projects/{id}")
public Project getById(@PathVariable Long id) { ... }

3. 问题/场景

RESTful 风格约定：

操作 HTTP 方法 路径示例
查列表 GET /projects
查单个 GET /projects/{id}
新增 POST /projects
全量更新 PUT /projects/{id}
删除 DELETE /projects/{id}

4. 完整示例代码

package com.ctts.controller;

import com.ctts.entity.Project;
import org.springframework.web.bind.annotation.*;

import java.util.ArrayList;
import java.util.List;

@RestController
@RequestMapping("/projects")   // 类级别：统一前缀
public class ProjectController {

    // GET /projects  查询列表
    @GetMapping
    public List<Project> list() {
        List<Project> list = new ArrayList<>();
        list.add(new Project(1L, "电商实训", "2025 春季"));
        list.add(new Project(2L, "大数据实训", "2025 春季"));
        return list;
    }

    // GET /projects/1  根据 ID 查询
    @GetMapping("/{id}")
    public Project getById(@PathVariable Long id) {
        return new Project(id, "实训项目" + id, "2025 春季");
    }

    // POST /projects  新增
    @PostMapping
    public String add(@RequestBody Project project) {
        return "新增成功：" + project.getName();
    }

    // PUT /projects/1  更新
    @PutMapping("/{id}")
    public String update(@PathVariable Long id, @RequestBody Project project) {
        return "更新项目 " + id + " 成功";
    }

    // DELETE /projects/1  删除
    @DeleteMapping("/{id}")
    public String delete(@PathVariable Long id) {
        return "删除项目 " + id + " 成功";
    }
}

5. 图示

GET    /projects          → list()
GET    /projects/1        → getById(1)
POST   /projects          → add(project)
PUT    /projects/1        → update(1, project)
DELETE /projects/1        → delete(1)
        │
        ▼
  类级别 @RequestMapping("/projects") 提供公共前缀
  方法级别 @GetMapping/@PostMapping 等细化路径与 HTTP 方法

6. 易错点

  • 易错点 1：类上 @RequestMapping 路径以 / 开头，方法上又写 /，例如 /projects + //list。Spring 会自动处理，但建议方法上路径不要重复以 / 开头。
  • 易错点 2：@GetMapping 不支持 method 属性，它已经固定为 GET。
  • 易错点 3：路径参数 {id} 与方法参数名 id 不一致时，必须显式写 @PathVariable("id") Long projectId，否则报 400。
  • 易错点 4：路径参数中包含特殊字符（如 .），Spring 默认会截断后缀，需要在配置中关闭 useSuffixPatternMatch。
  • 易错点 5：同一个类中两个方法映射了相同的路径+方法，启动时报 Ambiguous mapping 异常。

7. 小结

记住 RESTful 五动词：Get 查、Post 增、Put 改、Delete 删。类上加 @RequestMapping 定前缀，方法上加 @XxxMapping 定路径与方法。

K4-3 参数接收：@RequestParam / @PathVariable / @RequestBody / @RequestHeader

1. 定义

注解 参数位置 典型 Content-Type 用途
@RequestParam URL query string 任意 简单参数（分页、过滤条件）
@PathVariable URL 路径段 任意 资源 ID 等关键标识
@RequestBody 请求体 application/json 复杂对象（表单、JSON）
@RequestHeader 请求头 任意 Token、自定义 Header

2. 原理

Spring MVC 通过 HandlerMethodArgumentResolver 解析方法参数：

  • @RequestParam → RequestParamMethodArgumentResolver：从 request.getParameter() 取值。
  • @PathVariable → PathVariableMethodArgumentResolver：从 URL 模板变量取值。
  • @RequestBody → RequestResponseBodyMethodProcessor：调用 HttpMessageConverter 反序列化请求体。
  • @RequestHeader → RequestHeaderMethodArgumentResolver：从 request.getHeader() 取值。

3. 问题/场景——何时用哪种？

场景 选择
查询列表的分页参数 ?page=1&size=10 @RequestParam
路径中的资源 ID /projects/1 @PathVariable
POST 新增一个复杂对象（JSON） @RequestBody
获取请求头中的 Token @RequestHeader
表单提交（form-urlencoded） @RequestParam 或对象绑定

4. 完整示例代码

package com.ctts.controller;

import com.ctts.entity.Project;
import org.springframework.web.bind.annotation.*;

import java.util.List;
import java.util.Map;

@RestController
@RequestMapping("/projects")
public class ProjectController {

    // 1. @RequestParam 接收查询参数
    //    GET /projects/search?keyword=电商&page=1&size=10
    @GetMapping("/search")
    public String search(
            @RequestParam(value = "keyword", required = false, defaultValue = "") String keyword,
            @RequestParam(value = "page", defaultValue = "1") int page,
            @RequestParam(value = "size", defaultValue = "10") int size) {
        return "搜索：" + keyword + "，第" + page + "页，每页" + size + "条";
    }

    // 2. @PathVariable 接收路径参数
    //    GET /projects/1
    @GetMapping("/{id}")
    public Project getById(@PathVariable("id") Long projectId) {
        return new Project(projectId, "实训项目" + projectId, "2025 春季");
    }

    // 3. @RequestBody 接收 JSON 请求体
    //    POST /projects
    //    Body: {"name":"电商实训","semester":"2025春季"}
    @PostMapping
    public String add(@RequestBody Project project) {
        return "新增成功：" + project.getName();
    }

    // 4. @RequestHeader 接收请求头
    //    Header: Authorization: Bearer xxx-token
    @GetMapping("/me")
    public String me(@RequestHeader(value = "Authorization", required = false) String token) {
        if (token == null || token.isEmpty()) {
            return "未登录";
        }
        return "当前 Token：" + token;
    }

    // 5. 用 Map 接收 JSON（不推荐生产用，但灵活）
    @PostMapping("/map")
    public String addByMap(@RequestBody Map<String, Object> body) {
        return "收到 name=" + body.get("name");
    }
}

6. 易错点

  • 易错点 1：@RequestParam 默认 required = true，前端没传该参数会 400。可选参数必须显式写 required = false。
  • 易错点 2：@RequestBody 一个方法只能有一个，且必须用 POST/PUT/PATCH（有请求体）。
  • 易错点 3：GET 请求用 @RequestBody 接收参数——浏览器 GET 不带 body，会拿不到值。
  • 易错点 4：@PathVariable 的名称与方法参数名不一致，又没写 @PathVariable("id")，编译报错或运行时报错。
  • 易错点 5：JSON 字段名与实体类字段名不匹配（如 JSON 是 project_name，实体是 name），需要加 @JsonProperty。
  • 易错点 6：日期格式不对，默认要求 yyyy-MM-dd'T'HH:mm:ss，业务常用 yyyy-MM-dd 需加 @JsonFormat。
  • 易错点 7：@RequestParam 接收 List：?ids=1,2,3 用 @RequestParam List<Long> ids，逗号自动分割。

7. 小结

四句话口诀：

  • 查 query 用 RequestParam
  • 路径里用 PathVariable
  • 复杂 body 用 RequestBody
  • 请求头用 RequestHeader

K4-4 JSON 返回：@ResponseBody、自动序列化、返回 List/Map/自定义对象

1. 定义

  • @ResponseBody：把方法返回值直接写入 HTTP 响应体，而不是当视图名。
  • 自动序列化：Spring Boot 默认集成 Jackson，会把 Java 对象自动转成 JSON 字符串。
  • 可返回类型：String、Integer、Boolean、List<T>、Map<K,V>、自定义实体 T、ResponseEntity<T>。

2. 原理

请求处理流程：

图示 3：结构与流程重绘
方法返回 Java 对象 │ ▼ RequestResponseBodyMethodProcessor │ ▼ 遍历 HttpMessageConverter 列表 │ ▼ MappingJackson2HttpMessageConverter 命中（对象类型 + application/json） │ ▼ ObjectMapper.writeValueAsString(obj) │ ▼ 写入 response.getOutputStream() │ ▼ 设置 Content-Type: application/json

3. 问题/场景

返回类型 JSON 示例
String "hello"
Integer 42
List<Project> [{...},{...}]
Map<String,Object> {"code":0,"data":[...]}
Project（自定义） {"id":1,"name":"电商实训"}

4. 完整示例代码

package com.ctts.controller;

import com.ctts.entity.Project;
import com.fasterxml.jackson.annotation.JsonFormat;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import java.time.LocalDateTime;
import java.util.*;

@RestController
@RequestMapping("/demo/json")
public class JsonDemoController {

    // 1. 返回 String
    @GetMapping("/str")
    public String str() {
        return "hello";
    }

    // 2. 返回 List
    @GetMapping("/list")
    public List<Project> list() {
        List<Project> list = new ArrayList<>();
        list.add(new Project(1L, "电商实训", "2025 春季"));
        list.add(new Project(2L, "大数据实训", "2025 春季"));
        return list;
    }

    // 3. 返回 Map（统一响应格式常用）
    @GetMapping("/map")
    public Map<String, Object> map() {
        Map<String, Object> result = new HashMap<>();
        result.put("code", 200);
        result.put("msg", "success");
        result.put("data", Arrays.asList(
                new Project(1L, "电商实训", "2025 春季"),
                new Project(2L, "大数据实训", "2025 春季")
        ));
        return result;
    }

    // 4. 返回自定义对象（含日期）
    @GetMapping("/obj")
    public Project obj() {
        Project p = new Project(1L, "电商实训", "2025 春季");
        p.setCreateTime(LocalDateTime.now());
        return p;
    }
}

实体类中的日期处理：

package com.ctts.entity;

import com.fasterxml.jackson.annotation.JsonFormat;
import java.time.LocalDateTime;

public class Project {
    private Long id;
    private String name;
    private String semester;

    @JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss", timezone = "GMT+8")
    private LocalDateTime createTime;

    public Project() {}

    public Project(Long id, String name, String semester) {
        this.id = id;
        this.name = name;
        this.semester = semester;
    }

    // getter / setter
    public Long getId() { return id; }
    public void setId(Long id) { this.id = id; }
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
    public String getSemester() { return semester; }
    public void setSemester(String semester) { this.semester = semester; }
    public LocalDateTime getCreateTime() { return createTime; }
    public void setCreateTime(LocalDateTime createTime) { this.createTime = createTime; }
}

6. 易错点

  • 易错点 1：返回 LocalDateTime 没加 @JsonFormat，序列化出来是 [2025,3,15,10,30,0] 数组形式。
  • 易错点 2：实体类没有 getter 方法，Jackson 默认用字段反射，但 Lombok 缺失时返回 {}。
  • 易错点 3：返回 null，前端拿到的是字符串 null，建议用空集合或空对象替代。
  • 易错点 4：循环引用（双向一对多），Jackson 会无限递归，抛 JsonMappingException。
  • 易错点 5：返回 Map 时 key 顺序不可控，需用 LinkedHashMap 保证顺序。
  • 易错点 6：想在序列化时忽略某字段，用 @JsonIgnore。

7. 小结

Spring Boot + Jackson = JSON 全自动。重点掌握：自定义对象、List、Map、日期 @JsonFormat、忽略字段 @JsonIgnore。

K4-5 接口参数设计：何时用 query / path / body

1. 定义

RESTful 接口参数三种位置：

位置 URL 示例 用途
path（路径） /projects/1 资源唯一标识
query（查询串） /projects?page=1&keyword=电商 过滤、分页、排序等非资源标识的可选参数
body（请求体） POST /projects + JSON 创建/更新资源时的完整数据载体

2. 原理（设计原则）

  • path：路径段语义化，参数少（1~2 个），表达"哪个资源"。
  • query：可选、可空、数量较多；表达"如何筛选资源"。
  • body：结构化数据，字段多、嵌套深；只在 POST/PUT/PATCH 使用。

package com.ctts.controller;

import com.ctts.entity.Project;
import com.ctts.service.ProjectService;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.web.bind.annotation.*;

import java.util.List;

@RestController
@RequestMapping("/projects")
public class ProjectController {

    @Autowired
    private ProjectService projectService;

    // 接口1：查询实训项目列表
    // 设计说明：分页与搜索条件为可选过滤参数 → query
    @GetMapping
    public List<Project> list(
            @RequestParam(value = "keyword", required = false) String keyword,
            @RequestParam(value = "page", defaultValue = "1") int page,
            @RequestParam(value = "size", defaultValue = "10") int size) {
        return projectService.list(keyword, page, size);
    }

    // 接口2：根据 ID 查询
    // 设计说明：ID 是资源唯一标识 → path
    @GetMapping("/{id}")
    public Project getById(@PathVariable Long id) {
        return projectService.getById(id);
    }

    // 接口3：新增项目
    // 设计说明：完整数据载体 → body
    @PostMapping
    public Project add(@RequestBody Project project) {
        return projectService.add(project);
    }
}

6. 易错点

  • 易错点 1：把 ID 放到 query（?id=1）而不是 path，违反 RESTful 习惯。
  • 易错点 2：把分页参数塞到 body，导致 GET 请求拿不到。
  • 易错点 3：POST 新增时把字段拆成一堆 @RequestParam，参数多了维护困难，应该用 @RequestBody。
  • 易错点 4：路径参数与方法语义冲突，如 DELETE /projects?id=1 应改为 DELETE /projects/{id}。
  • 易错点 5：query 参数过多（>5 个）时建议封装为 DTO 对象，Spring 能自动绑定。

7. 小结

三句话口诀：

  • 资源标识 → path
  • 筛选过滤 → query
  • 数据载体 → body

package com.ctts.service;

import com.ctts.entity.Project;
import java.util.List;

public interface ProjectService {
    List<Project> list(String keyword, int page, int size);
    Project getById(Long id);
    Project add(Project project);
}
package com.ctts.service.impl;

import com.ctts.entity.Project;
import com.ctts.service.ProjectService;
import org.springframework.stereotype.Service;

import java.util.ArrayList;
import java.util.List;
import java.util.Optional;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.atomic.AtomicLong;
import java.util.stream.Collectors;

@Service
public class ProjectServiceImpl implements ProjectService {

    // 模拟数据库：线程安全 Map
    private static final ConcurrentHashMap<Long, Project> DB = new ConcurrentHashMap<>();
    private static final AtomicLong ID_GEN = new AtomicLong(0);

    static {
        // 初始化两条模拟数据
        Project p1 = new Project(1L, "电商实训", "2025 春季");
        p1.setDescription("搭建小型电商平台，包含商品、订单、支付");
        p1.setInternalRemark("校长牵头");
        DB.put(1L, p1);

        Project p2 = new Project(2L, "大数据实训", "2025 春季");
        p2.setDescription("基于 Hadoop 生态完成离线数仓");
        p2.setInternalRemark("企业合作");
        DB.put(2L, p2);

        ID_GEN.set(2L);
    }

    @Override
    public List<Project> list(String keyword, int page, int size) {
        List<Project> all = new ArrayList<>(DB.values());
        if (keyword != null && !keyword.isEmpty()) {
            all = all.stream()
                    .filter(p -> p.getName().contains(keyword))
                    .collect(Collectors.toList());
        }
        // 简单分页
        int from = (page - 1) * size;
        int to = Math.min(from + size, all.size());
        if (from >= all.size()) {
            return new ArrayList<>();
        }
        return all.subList(from, to);
    }

    @Override
    public Project getById(Long id) {
        return DB.get(id);
    }

    @Override
    public Project add(Project project) {
        long id = ID_GEN.incrementAndGet();
        project.setId(id);
        project.setCreateTime(java.time.LocalDateTime.now());
        if (project.getStatus() == null) {
            project.setStatus(0);
        }
        DB.put(id, project);
        return project;
    }
}

四、拓展阅读

4.1 RESTful API 设计最佳实践

  • 资源用名词复数：/projects 而非 /project 或 /getProjects。
  • HTTP 方法表达动作：GET 查、POST 增、PUT 改、DELETE 删。
  • 状态码规范：200 成功、400 参数错误、401 未认证、403 无权限、404 资源不存在、500 服务器错误。
  • 统一响应格式：建议所有接口返回 {code, msg, data} 结构。

4.2 Spring MVC 参数解析器体系

HandlerMethodArgumentResolver 是 Spring MVC 解析控制器方法参数的核心接口，常见实现：

解析器 对应注解
RequestParamMethodArgumentResolver @RequestParam
PathVariableMethodArgumentResolver @PathVariable
RequestResponseBodyMethodProcessor @RequestBody
RequestHeaderMethodArgumentResolver @RequestHeader
ServletRequestMethodArgumentResolver HttpServletRequest 等
ModelAttributeMethodProcessor 无注解对象绑定

4.3 Jackson 常用注解

注解 作用
@JsonProperty("xxx") 修改序列化后的字段名
@JsonIgnore 序列化时忽略该字段
@JsonFormat(pattern="yyyy-MM-dd") 格式化日期
@JsonInclude(JsonInclude.Include.NON_NULL) null 字段不序列化
@JsonAlias({"a","b"}) 反序列化时接受多个字段名
@JsonSerialize / @JsonDeserialize 自定义序列化器

五、小结与思维导图

5.1 本次课核心要点

  1. @RestController = @Controller + @ResponseBody，前后端分离项目首选。
  2. 请求映射注解：@RequestMapping + @GetMapping/@PostMapping/@PutMapping/@DeleteMapping，类上定前缀，方法上定路径。
  3. 参数接收四件套：
    • @RequestParam：query 参数
    • @PathVariable：路径参数
    • @RequestBody：请求体 JSON
    • @RequestHeader：请求头
  4. JSON 返回：Spring Boot 自动集成 Jackson，可返回 String/List/Map/自定义对象。
  5. 参数位置决策：资源标识→path，筛选过滤→query，数据载体→body。
