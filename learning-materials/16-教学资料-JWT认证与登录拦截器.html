二、知识点详解

知识点 K16-1 JWT 原理与结构

1. 定义

JWT（JSON Web Token） 是一种基于 JSON 的开放标准（RFC 7519），用于在网络应用各方之间以紧凑、自包含的方式安全传递声明（claims）。JWT 本质上是一个由三段 Base64URL 编码字符串通过 . 连接组成的字符串，形如：

xxxxx.yyyyy.zzzzz

在认证场景中，用户登录成功后服务端签发 JWT，客户端将其保存，后续每次请求在 Authorization Header 中携带，服务端解析校验通过即放行。

2. 原理（三段结构图解）

图示 2：JWT 三段结构图解
Header

算法与类型

{ "alg":"HS256", "typ":"JWT" }，Base64URL 编码后形成第一段。

Payload

业务声明

保存 userId、username、role、iat、exp 等声明；只是编码，不等于加密。

Signature

防篡改签名

用 header、payload 和 secret 计算签名，服务端解析时重新计算并比对。

最终 Token 由三段用点号连接：Header.Payload.Signature。

各段说明：

段 内容 编码 是否可逆 是否加密
Header alg（算法）+ typ（类型） Base64URL 可逆 否（任何人可解码）
Payload claims（声明：userId/username/role/exp/iat） Base64URL 可逆 否（任何人可解码）
Signature HMAC-SHA256(base64(header)+"."+base64(payload), secret) Base64URL 不可逆 是（需密钥）

⚠️ 关键认知：JWT 的 Header 和 Payload 是 Base64 编码，不是加密，任何人都能解码看到内容。绝不能在 Payload 中放密码、身份证号等敏感信息。JWT 的安全性来自 Signature——任何人没有密钥就无法伪造合法签名。

HS256 签名算法：

HMAC（Hash-based Message Authentication Code）= 哈希 + 密钥

Signature = HMACSHA256(
    base64UrlEncode(header) + "." + base64UrlEncode(payload),
    secret
)
  • HMAC：一种使用密钥的消息认证码算法，"哈希 + 密钥"共同决定输出。
  • SHA-256：哈希函数，输出 256 位（32 字节）摘要。
  • 对称：签发与验证使用同一密钥（与 RS256 非对称不同）。

防篡改原理：攻击者修改 Payload 中的 role 从 STUDENT 改成 ADMIN 后，由于没有密钥，无法生成正确的 Signature；服务端用密钥重新计算签名会发现不匹配，校验失败。

3. 问题

Q1：为什么用 Base64URL 而不是标准 Base64？ 标准 Base64 中可能出现 +、/、=，这些字符在 URL/HTTP Header 中有特殊含义（+ 可能被解析为空格、/ 是路径分隔符）。Base64URL 用 - 替换 +、_ 替换 /、去掉 = 填充，保证 JWT 可安全放在 URL/Header/Cookie 中。

Q2：JWT 与 Session 的本质区别？

  • Session：状态存在服务端，客户端只存 SessionID（通过 Cookie）。服务端需维护 Session 存储，扩展时需解决 Session 共享。
  • JWT：状态存在 Token 中（自包含），服务端不存任何状态（无状态）。扩展时只需多实例共享同一个密钥即可。

Q3：Token 被偷了怎么办？ JWT 一旦签发，在过期前一直有效。若 Token 被盗，攻击者可冒充用户。常见对策：

  • 使用 HTTPS 防止中间人窃听。
  • 设置较短过期时间（如 2 小时）。
  • 引入 Refresh Token 机制（短期 Access Token + 长期 Refresh Token）。
  • 关键操作要求二次验证（如支付密码/短信验证码）。
  • 服务端维护 Token 黑名单（牺牲无状态性）。

Q4：JWT 适合放在 Cookie 还是 LocalStorage？

  • LocalStorage：易受 XSS 攻击窃取，但可跨域。
  • HttpOnly Cookie：防 XSS 读取，但易受 CSRF 攻击（需配合 SameSite）。 业界通常：Access Token 放内存（vuex/redux），Refresh Token 放 HttpOnly Cookie。

4. 完整代码

本小节先给出 JWT 三段结构的可观察代码，K16-2 会给出完整 JwtUtil。

// 演示：手动构造一段 JWT 的 Header 与 Payload（仅用于理解结构，生产请用 jjwt）
import java.nio.charset.StandardCharsets;
import java.util.Base64;
import java.util.Map;

public class JwtStructureDemo {
    // Base64URL 编码（去掉 = 填充，+ 换 -，/ 换 _）
    public static String base64UrlEncode(String input) {
        return Base64.getUrlEncoder().withoutPadding()
                .encodeToString(input.getBytes(StandardCharsets.UTF_8));
    }

    public static void main(String[] args) {
        String header  = "{\"alg\":\"HS256\",\"typ\":\"JWT\"}";
        String payload = "{\"userId\":1,\"username\":\"admin\",\"role\":\"ADMIN\"}";
        String h = base64UrlEncode(header);
        String p = base64UrlEncode(payload);
        System.out.println("Header  编码: " + h);
        System.out.println("Payload 编码: " + p);
        System.out.println("拼接（无签名）: " + h + "." + p + ".");
        // 真正的 Signature 需用 HMAC-SHA256，见 K16-2 JwtUtil
    }
}

6. 易错点

易错点 后果 正确做法
在 Payload 中放密码 任何人可解码看到，密码泄露 绝不放敏感信息，只放 userId/username/role
误以为 Payload 是加密的 错觉安全，实际任何人可读 知道 Payload 仅 Base64 编码
用 MD5/SHA-256 直接哈希做签名 无密钥，任何人可伪造 必须用 HMAC-SHA256（HS256）带密钥
密钥太短（< 32 字节） jjwt 抛 WeakKeyException HS256 密钥至少 256 位（32 字节）
把 JWT 当作"加密存储"使用 误解 JWT 用途 JWT 用于传递声明，不是加密容器

7. 小结

  • JWT = Header（算法/类型）+ Payload（声明）+ Signature（签名），三段用 . 连接。
  • Header 和 Payload 是 Base64URL 编码（可逆、非加密）；Signature 是 HMAC-SHA256（需密钥、防篡改）。
  • HS256 是对称算法，签发与校验用同一密钥。
  • JWT 自包含、无状态，适合前后端分离与分布式场景。
  • 安全性来自签名密钥保密，不在 Payload 放敏感信息。

知识点 K16-2 jjwt 生成与解析 Token

1. 定义

jjwt 是 Java 生态最流行的 JWT 库（github.com/jwtk/jjwt），提供 fluent API 生成、解析、验证 JWT。本课使用 0.12.x 版本（API 与 0.11.x 有差异，注意区分）。

2. 原理

jjwt 0.12.x 核心 API：

用途 API 说明
生成 Token Jwts.builder() 返回 JwtBuilder，链式调用
设置 claims .claims(claimsMap) 或 .claim(k, v) 自定义声明
设置过期 .expiration(Date) 标准注册声明 exp
设置签发时间 .issuedAt(Date) 标准注册声明 iat
设置主题 .subject(username) 标准注册声明 sub
签名 .signWith(SecretKey) 传入 HS256 密钥
压缩输出 .compact() 返回最终 JWT 字符串
解析 Token Jwts.parser().verifyWith(key).build().parseSignedClaims(token) 返回 Jws<Claims>
获取 claims jws.getPayload() 返回 Claims（继承 Map）
验证过期 jjwt 自动校验 exp，过期抛 ExpiredJwtException 无需手动判断

密钥生成：HS256 要求密钥 ≥ 256 位（32 字节）。可用：

  • Keys.secretKeyFor(SignatureAlgorithm.HS256)（0.11.x）或 Keys.hmacShaKeyFor(byte[])（推荐，可从配置读密钥字符串）。
  • Keys.hmacShaKeyFor(secret.getBytes())：要求 secret 至少 32 字节。

3. 问题

Q1：jjwt 0.12.x 与 0.11.x API 有何不同？ 0.12.x 大幅重构：

  • Jwts.parserBuilder() → Jwts.parser()
  • setSigningKey(key) → verifyWith(key)
  • parseClaimsJws(token) → parseSignedClaims(token)
  • getBody() → getPayload() 建议直接学 0.12.x，老项目用 0.11.x 时查阅对应文档。

Q2：为什么 jjwt 拆成三个依赖？

jjwt-api     —— API 接口（编译期需要）
jjwt-impl    —— 运行时实现（运行期需要，不能被下游传递）
jjwt-jackson —— JSON 序列化（运行期需要，可选 gson 替代）

这是"API/实现分离"设计，类似 SLF4J 与 Logback 的关系。三个都要加，且 jjwt-impl 和 jjwt-jackson 用 runtime scope。

Q3：密钥该写死在代码里还是放配置文件？ 绝对不能写死在代码里（会被提交到 Git，泄露即全盘崩溃）。应放 application.yml 并用环境变量覆盖：

ctts:
  jwt:
    secret: ${CTTS_JWT_SECRET:your-256-bit-secret-key-at-least-32-bytes-please-change-in-prod}
    expiration: 7200000   # 2小时，单位毫秒

生产环境通过环境变量 CTTS_JWT_SECRET 注入真实密钥。

③ JwtUtil 工具类（完整可运行）：

package com.ctts.common.jwt;

import io.jsonwebtoken.Claims;
import io.jsonwebtoken.ExpiredJwtException;
import io.jsonwebtoken.JwtException;
import io.jsonwebtoken.Jwts;
import io.jsonwebtoken.security.Keys;
import jakarta.annotation.PostConstruct;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;

import javax.crypto.SecretKey;
import java.nio.charset.StandardCharsets;
import java.util.Date;
import java.util.HashMap;
import java.util.Map;

/**
 * JWT 工具类
 * 功能：生成 Token / 解析 Token / 验证 Token
 * 算法：HS256（HMAC-SHA-256）
 */
@Component
public class JwtUtil {

    private static final Logger log = LoggerFactory.getLogger(JwtUtil.class);

    /** 标准 claim：签发时间 */
    public static final String CLAIM_IAT = "iat";
    /** 标准 claim：过期时间 */
    public static final String CLAIM_EXP = "exp";
    /** 私有 claim：用户 ID */
    public static final String CLAIM_USER_ID = "userId";
    /** 私有 claim：用户名 */
    public static final String CLAIM_USERNAME = "username";
    /** 私有 claim：角色（STUDENT / TEACHER / ADMIN） */
    public static final String CLAIM_ROLE = "role";

    @Value("${ctts.jwt.secret}")
    private String secret;

    @Value("${ctts.jwt.expiration}")
    private long expiration;

    private SecretKey key;

    @PostConstruct
    public void init() {
        // 将密钥字符串转为 SecretKey，要求字节数 >= 32
        byte[] keyBytes = secret.getBytes(StandardCharsets.UTF_8);
        if (keyBytes.length < 32) {
            throw new IllegalStateException(
                "JWT secret 长度不足 32 字节，当前 " + keyBytes.length + " 字节，HS256 要求至少 256 位");
        }
        this.key = Keys.hmacShaKeyFor(keyBytes);
        log.info("JwtUtil 初始化完成，密钥长度 {} 字节", keyBytes.length);
    }

    /**
     * 生成 JWT Token
     *
     * @param userId   用户 ID
     * @param username 用户名
     * @param role     角色（STUDENT / TEACHER / ADMIN）
     * @return JWT 字符串
     */
    public String generateToken(Long userId, String username, String role) {
        Date now = new Date();
        Date expiryDate = new Date(now.getTime() + expiration);

        Map<String, Object> claims = new HashMap<>();
        claims.put(CLAIM_USER_ID, userId);
        claims.put(CLAIM_USERNAME, username);
        claims.put(CLAIM_ROLE, role);

        return Jwts.builder()
                .claims(claims)                          // 自定义声明
                .subject(username)                       // 标准声明 sub
                .issuedAt(now)                           // 标准声明 iat
                .expiration(expiryDate)                  // 标准声明 exp
                .signWith(key)                           // 签名（默认 HS256）
                .compact();
    }

    /**
     * 解析 Token，返回 Claims
     * 若 Token 无效/过期/被篡改，抛出 JwtException
     */
    public Claims parseToken(String token) {
        return Jwts.parser()
                .verifyWith(key)                        // 验签密钥
                .build()
                .parseSignedClaims(token)               // 解析并校验签名
                .getPayload();                          // 获取 Claims
    }

    /**
     * 校验 Token 是否有效（签名正确 + 未过期）
     */
    public boolean validateToken(String token) {
        try {
            parseToken(token);
            return true;
        } catch (ExpiredJwtException e) {
            log.warn("Token 已过期: {}", e.getMessage());
        } catch (JwtException e) {
            log.warn("Token 无效: {}", e.getMessage());
        } catch (IllegalArgumentException e) {
            log.warn("Token 为空或格式错误: {}", e.getMessage());
        }
        return false;
    }

    /** 从 Token 中提取 userId */
    public Long getUserId(String token) {
        return parseToken(token).get(CLAIM_USER_ID, Long.class);
    }

    /** 从 Token 中提取 username */
    public String getUsername(String token) {
        return parseToken(token).get(CLAIM_USERNAME, String.class);
    }

    /** 从 Token 中提取 role */
    public String getRole(String token) {
        return parseToken(token).get(CLAIM_ROLE, String.class);
    }

    /** 判断 Token 是否过期（不抛异常，返回 boolean） */
    public boolean isExpired(String token) {
        try {
            Date exp = parseToken(token).getExpiration();
            return exp.before(new Date());
        } catch (ExpiredJwtException e) {
            return true;
        }
    }
}

6. 易错点

易错点 现象 解决
密钥 < 32 字节 启动报 WeakKeyException 密钥至少 32 字节（256 位）
用 0.11.x API 调 0.12.x 库 编译报错 parserBuilder 不存在 用 0.12.x 新 API：Jwts.parser().verifyWith()
忘加 jjwt-impl/jjwt-jackson 运行时抛 ClassNotFoundException 三个依赖都加，后两个 runtime scope
密钥硬编码在代码 提交 Git 后泄露 放 application.yml + 环境变量覆盖
把 parseToken 异常吞掉返回 null 调用方拿到 null 又不判空 NPE 用 validateToken 返回 boolean，或抛业务异常
多次调用 parseToken 性能浪费（每次都验签解析） 在拦截器中解析一次，存入 ThreadLocal

7. 小结

  • jjwt 0.12.x 三件套：jjwt-api（编译）+ jjwt-impl（运行）+ jjwt-jackson（运行）。
  • 生成：Jwts.builder().claims().signWith(key).compact()。
  • 解析：Jwts.parser().verifyWith(key).build().parseSignedClaims(token).getPayload()。
  • 密钥 ≥ 32 字节，放配置不放代码。
  • 过期/篡改会抛 ExpiredJwtException/JwtException，需捕获处理。

知识点 K16-3 HandlerInterceptor 登录拦截器

1. 定义

HandlerInterceptor（处理器拦截器）是 Spring MVC 提供的接口，用于在 Controller 方法执行前后插入自定义逻辑。登录拦截器利用 preHandle 方法在请求到达 Controller 之前校验 Token，校验失败返回 401，校验通过放行并将当前用户存入 ThreadLocal。

2. 原理

HandlerInterceptor 接口三个方法：

public interface HandlerInterceptor {
    default boolean preHandle(HttpServletRequest request, HttpServletResponse response,
                              Object handler) throws Exception {
        return true;   // 返回 true 放行，false 拦截
    }
    default void postHandle(HttpServletRequest request, HttpServletResponse response,
                            Object handler, @Nullable ModelAndView modelAndView) throws Exception {
    }
    default void afterCompletion(HttpServletRequest request, HttpServletResponse response,
                                 Object handler, @Nullable Exception ex) throws Exception {
    }
}

收尾

postHandle 后处理，afterCompletion 清理 ThreadLocal。

handler 参数：实际是 HandlerMethod 对象，封装了要执行的 Controller 方法。可用于：

  • 判断目标方法是否有某注解（注解式权限控制）。
  • 获取方法名、参数等元信息。

3. 问题

Q1：拦截器与 Filter 的区别？

维度 Filter HandlerInterceptor
规范 Servlet 规范 Spring MVC
作用域 所有请求（含静态资源） 仅 Controller 请求
执行时机 DispatcherServlet 之前 DispatcherServlet 之后、Controller 之前
能否访问 Controller 信息 否 能（HandlerMethod）
配置方式 @WebFilter/FilterRegistrationBean WebMvcConfigurer.addInterceptors
Spring Bean 注入 需 @Component + FilterRegistrationBean 直接 @Component

JWT 校验二者皆可，拦截器更 Spring 风格、能拿到 HandlerMethod 做注解式权限，本课选拦截器。

Q2：为什么用 Bearer 前缀？ Authorization: <scheme> <credentials> 是 HTTP 标准（RFC 7235）。Bearer 表示"持有者"——谁持有这个 Token 谁就是合法用户。前缀的作用：

  • 区分认证方案（Basic/Digest/Bearer/...）。
  • 服务端剥离前缀后得到真正的凭证。

Q3：为什么必须 afterCompletion 里 remove ThreadLocal？ Spring Boot 默认用 Tomcat 线程池处理请求，线程会被复用。若不 remove：

  • 用户 A 请求后 ThreadLocal 残留 A 的信息。
  • 线程复用给用户 B，但 B 没有 Token，ThreadLocal 却是 A 的数据 → 用户串号，严重安全事故。
  • afterCompletion 无论 Controller 是否抛异常都会执行，是清理 ThreadLocal 的可靠位置。

③ LoginInterceptor（登录拦截器完整实现）：

package com.ctts.common.interceptor;

import com.ctts.common.context.CurrentUserContext;
import com.ctts.common.context.LoginUser;
import com.ctts.common.jwt.JwtUtil;
import com.fasterxml.jackson.databind.ObjectMapper;
import io.jsonwebtoken.Claims;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.http.HttpStatus;
import org.springframework.http.MediaType;
import org.springframework.stereotype.Component;
import org.springframework.web.servlet.HandlerInterceptor;

import java.nio.charset.StandardCharsets;
import java.util.HashMap;
import java.util.Map;

/**
 * 登录拦截器：校验 JWT Token
 * 流程：取 Authorization Header → 剥离 Bearer → 解析校验 → 存入 ThreadLocal → 放行/拒绝
 */
@Component
public class LoginInterceptor implements HandlerInterceptor {

    private static final Logger log = LoggerFactory.getLogger(LoginInterceptor.class);
    private static final String AUTH_HEADER = "Authorization";
    private static final String BEARER_PREFIX = "Bearer ";
    private static final ObjectMapper MAPPER = new ObjectMapper();

    @Autowired
    private JwtUtil jwtUtil;

    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response,
                             Object handler) throws Exception {
        // 1. 从 Header 取 Authorization
        String authHeader = request.getHeader(AUTH_HEADER);
        if (authHeader == null || authHeader.isBlank()) {
            return writeUnauthorized(response, "未携带 Token，请先登录", request.getRequestURI());
        }

        // 2. 校验 Bearer 前缀
        if (!authHeader.startsWith(BEARER_PREFIX)) {
            return writeUnauthorized(response, "Token 格式错误，应为 'Bearer <token>'", request.getRequestURI());
        }

        // 3. 剥离前缀得到纯 Token
        String token = authHeader.substring(BEARER_PREFIX.length()).trim();

        // 4. 解析校验 Token
        Claims claims;
        try {
            claims = jwtUtil.parseToken(token);
        } catch (Exception e) {
            return writeUnauthorized(response, "Token 无效或已过期: " + e.getMessage(), request.getRequestURI());
        }

        // 5. 提取用户信息并存入 ThreadLocal
        Long userId = claims.get(JwtUtil.CLAIM_USER_ID, Long.class);
        String username = claims.get(JwtUtil.CLAIM_USERNAME, String.class);
        String role = claims.get(JwtUtil.CLAIM_ROLE, String.class);
        CurrentUserContext.set(new LoginUser(userId, username, role));

        log.debug("认证通过: userId={}, username={}, role={}, uri={}",
                userId, username, role, request.getRequestURI());
        return true;
    }

    @Override
    public void afterCompletion(HttpServletRequest request, HttpServletResponse response,
                                Object handler, Exception ex) {
        // 必须 remove，防止线程池复用导致用户串号
        CurrentUserContext.remove();
    }

    /**
     * 统一写 401 响应
     */
    private boolean writeUnauthorized(HttpServletResponse response, String message, String path) throws Exception {
        response.setStatus(HttpStatus.UNAUTHORIZED.value());
        response.setContentType(MediaType.APPLICATION_JSON_VALUE);
        response.setCharacterEncoding(StandardCharsets.UTF_8.name());
        Map<String, Object> body = new HashMap<>();
        body.put("code", HttpStatus.UNAUTHORIZED.value());
        body.put("message", message);
        body.put("path", path);
        response.getWriter().write(MAPPER.writeValueAsString(body));
        return false;   // 返回 false 拦截请求
    }
}

6. 易错点

易错点 后果 解决
忘记 afterCompletion 里 remove 线程复用 → 用户串号 必须在 afterCompletion 调 CurrentUserContext.remove()
preHandle 返回 false 后没写响应 客户端收到空响应 返回 false 前用 response.getWriter().write(...) 写错误信息

  • HandlerInterceptor 三方法：preHandle（前）/postHandle（后）/afterCompletion（最终）。
  • preHandle 返回 true 放行、false 拦截。
  • 登录拦截器流程：取 Header → 剥 Bearer → 解析 Token → 存 ThreadLocal → 放行。
  • afterCompletion 必须 remove ThreadLocal，防用户串号。
  • 拦截器异常不进 @RestControllerAdvice，需自己写 401 响应。

知识点 K16-4 WebMvcConfigurer 注册拦截器

1. 定义

WebMvcConfigurer 是 Spring MVC 的配置接口，通过实现 addInterceptors(InterceptorRegistry registry) 方法将自定义拦截器注册到 Spring MVC，并配置拦截路径与排除路径。

2. 原理

@Configuration
public class WebMvcConfig implements WebMvcConfigurer {
    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(loginInterceptor)
                .addPathPatterns("/**")           // 拦截所有路径
                .excludePathPatterns("/api/auth/**", "/doc.html", ...);  // 排除
    }
}

路径匹配规则（Spring MVC Ant 风格）：

模式 匹配 说明
/** 任意多级路径 拦截全部
/api/* /api/xxx 单级
/api/** /api/xxx、/api/x/y 多级
/api/auth/** /api/auth/login、/api/auth/register 多级

优先级：excludePathPatterns 优先于 addPathPatterns。即先匹配排除，排除命中则不拦截。

必须放行的路径：

  • /api/auth/login、/api/auth/register：登录注册本身不需要 Token。
  • /doc.html、/swagger-ui/**、/v3/api-docs/**、/webjars/**：Knife4j/Swagger 接口文档。
  • /error：Spring Boot 错误页。
  • 静态资源：/static/**、/public/**（若有）。

3. 问题

Q1：为什么拦截器配置类要加 @Configuration 而不是 @Component？ @Configuration 是全模式配置类，Spring 会用 CGLIB 代理，保证 @Bean 方法间依赖调用走容器单例。WebMvcConfigurer 实现类推荐用 @Configuration。

Q2：addInterceptor 传入的拦截器实例从哪来？ 两种方式：

  • @Autowired 注入（拦截器本身是 @Component，推荐）。
  • new LoginInterceptor()（不推荐，内部 @Autowired 失效）。

Q3：为什么 /error 也要放行？ Spring Boot 出错时会转发到 /error，若 /error 被拦截，且此时 ThreadLocal 已被清空，会再次 401，导致错误页无法渲染。

Q4：拦截器配置多个时执行顺序？ 按 addInterceptor 调用顺序，先注册的先执行 preHandle，后注册的先执行 afterCompletion（栈结构）。可用 registry.addInterceptor(x).order(1) 指定。

4. 完整代码

package com.ctts.common.config;

import com.ctts.common.interceptor.LoginInterceptor;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.InterceptorRegistry;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

/**
 * Web MVC 配置：注册登录拦截器
 */
@Configuration
public class WebMvcConfig implements WebMvcConfigurer {

    @Autowired
    private LoginInterceptor loginInterceptor;

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(loginInterceptor)
                .addPathPatterns("/**")          // 拦截所有路径
                .excludePathPatterns(            // 排除路径（放行）
                        "/api/auth/login",        // 登录
                        "/api/auth/register",     // 注册
                        "/api/auth/refresh",      // 刷新 Token
                        "/doc.html",              // Knife4j 文档入口
                        "/swagger-ui/**",         // Swagger UI
                        "/v3/api-docs/**",        // OpenAPI 3 文档
                        "/webjars/**",            // 静态资源（Knife4j 依赖）
                        "/favicon.ico",           // 图标
                        "/error"                  // Spring Boot 错误页
                )
                .order(1);                        // 拦截器顺序（多个拦截器时）
    }
}

  • 拦截器实例用 @Autowired 注入，配置类加 @Configuration。
  • 别忘放行 /error 与 Knife4j 全套。

知识点 K16-5 简单角色权限控制

1. 定义

角色权限控制是在认证（你是谁）基础上进一步做授权（你能做什么）。本课实现简单方案：JWT 的 Payload 中携带 role 字段，拦截器或自定义注解根据 role 判断是否有权访问某接口。

CTTS 三角色权限矩阵：

接口 STUDENT TEACHER ADMIN
GET /api/tasks 查看自己 查看本班 查看全部
POST /api/tasks × 发布任务 全部
DELETE /api/tasks/{id} × 删除自己的 全部
GET /api/users × × 全部
POST /api/users × × 创建用户

2. 原理

方案一：拦截器中按路径前缀校验（简单粗暴）

if (request.getRequestURI().startsWith("/api/admin") && !"ADMIN".equals(role)) {
    return writeForbidden(response, "需要管理员权限");
}

缺点：路径与权限硬耦合，难以维护。

方案二：自定义注解 + 拦截器解析注解（推荐）

@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface RequireRole {
    String[] value();   // 允许的角色
}

Controller 方法标注：

@RequireRole({"ADMIN"})
@DeleteMapping("/users/{id}")
public Result<Void> delete(@PathVariable Long id) { ... }

拦截器中读取注解决定是否放行：

HandlerMethod hm = (HandlerMethod) handler;
RequireRole anno = hm.getMethodAnnotation(RequireRole.class);
if (anno != null) {
    String role = CurrentUserContext.getRole();
    if (!Arrays.asList(anno.value()).contains(role)) {
        return writeForbidden(response, "权限不足");
    }
}

3. 问题

Q1：注解式权限控制为什么要判断 handler instanceof HandlerMethod？ handler 不一定是 HandlerMethod（如静态资源、ResourceHttpRequestHandler），强转前必须判断，否则 ClassCastException。

Q2：注解放在方法上还是类上？ 支持方法级与类级。通常方法级更细粒度；类级可设默认权限，方法级覆盖。可同时扫描二者：

RequireRole methodAnno = hm.getMethodAnnotation(RequireRole.class);
RequireRole classAnno = hm.getBeanType().getAnnotation(RequireRole.class);

Q3：与 Spring Security 的 @PreAuthorize 有何区别？ @PreAuthorize 是 Spring Security 提供，基于 SpEL，功能强大但需引入 Spring Security 全套。本课手写注解是轻量方案，适合教学项目；生产项目建议直接用 Spring Security。

4. 完整代码

① @RequireRole 注解：

package com.ctts.common.annotation;

import java.lang.annotation.ElementType;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;

/**
 * 角色权限注解（标注在 Controller 方法或类上）
 * 拦截器解析此注解，校验当前用户角色是否在允许列表中
 */
@Target({ElementType.METHOD, ElementType.TYPE})
@Retention(RetentionPolicy.RUNTIME)
public @interface RequireRole {
    /** 允许访问的角色，如 {"ADMIN"} 或 {"TEACHER","ADMIN"} */
    String[] value();

    /** 逻辑：AND（同时具备）还是 OR（任一即可），默认 OR */
    Logical logical() default Logical.OR;

    enum Logical { AND, OR }
}

② RoleInterceptor（角色拦截器）：

package com.ctts.common.interceptor;

import com.ctts.common.annotation.RequireRole;
import com.ctts.common.context.CurrentUserContext;
import com.ctts.common.context.LoginUser;
import com.fasterxml.jackson.databind.ObjectMapper;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import org.springframework.http.HttpStatus;
import org.springframework.http.MediaType;
import org.springframework.stereotype.Component;
import org.springframework.web.method.HandlerMethod;
import org.springframework.web.servlet.HandlerInterceptor;

import java.nio.charset.StandardCharsets;
import java.util.Arrays;
import java.util.HashMap;
import java.util.Map;

/**
 * 角色权限拦截器：解析 @RequireRole 注解校验角色
 * 必须在 LoginInterceptor 之后执行（依赖 CurrentUserContext）
 */
@Component
public class RoleInterceptor implements HandlerInterceptor {

    private static final ObjectMapper MAPPER = new ObjectMapper();

    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response,
                             Object handler) throws Exception {
        // 非 Controller 方法（如静态资源）直接放行
        if (!(handler instanceof HandlerMethod hm)) {
            return true;
        }

        // 优先读方法注解，再读类注解
        RequireRole anno = hm.getMethodAnnotation(RequireRole.class);
        if (anno == null) {
            anno = hm.getBeanType().getAnnotation(RequireRole.class);
        }
        if (anno == null) {
            return true;   // 无注解，不需要角色校验
        }

        LoginUser user = CurrentUserContext.get();
        if (user == null) {
            return writeForbidden(response, "未登录，无法校验角色");
        }

        String currentRole = user.getRole();
        String[] allowed = anno.value();
        boolean pass;
        if (anno.logical() == RequireRole.Logical.AND) {
            pass = Arrays.asList(allowed).contains(currentRole)
                    && allowed.length == Arrays.stream(allowed)
                        .filter(r -> r.equals(currentRole)).count();
            // AND 较少用，这里简化为：当前角色必须等于所有要求（实际多用 OR）
            pass = allowed.length == 1 && allowed[0].equals(currentRole);
        } else {
            pass = Arrays.asList(allowed).contains(currentRole);
        }

        if (!pass) {
            return writeForbidden(response,
                "权限不足，需要角色: " + Arrays.toString(allowed) + "，当前角色: " + currentRole);
        }
        return true;
    }

    private boolean writeForbidden(HttpServletResponse response, String message) throws Exception {
        response.setStatus(HttpStatus.FORBIDDEN.value());
        response.setContentType(MediaType.APPLICATION_JSON_VALUE);
        response.setCharacterEncoding(StandardCharsets.UTF_8.name());
        Map<String, Object> body = new HashMap<>();
        body.put("code", HttpStatus.FORBIDDEN.value());
        body.put("message", message);
        response.getWriter().write(MAPPER.writeValueAsString(body));
        return false;
    }
}

import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

@Configuration
public class WebMvcConfig implements WebMvcConfigurer {

    @Autowired
    private LoginInterceptor loginInterceptor;

    @Autowired
    private RoleInterceptor roleInterceptor;

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        // 登录拦截器：先执行（order=1）
        registry.addInterceptor(loginInterceptor)
                .addPathPatterns("/**")
                .excludePathPatterns(
                        "/api/auth/login",
                        "/api/auth/register",
                        "/api/auth/refresh",
                        "/doc.html",
                        "/swagger-ui/**",
                        "/v3/api-docs/**",
                        "/webjars/**",
                        "/favicon.ico",
                        "/error"
                )
                .order(1);

        // 角色拦截器：后执行（order=2，依赖 CurrentUserContext）
        registry.addInterceptor(roleInterceptor)
                .addPathPatterns("/**")
                .excludePathPatterns(
                        "/api/auth/**",
                        "/doc.html",
                        "/swagger-ui/**",
                        "/v3/api-docs/**",
                        "/webjars/**",
                        "/favicon.ico",
                        "/error"
                )
                .order(2);
    }
}

6. 易错点

易错点 后果 解决
不判 handler instanceof HandlerMethod 直接强转 静态资源请求 ClassCastException 必须先 instanceof 判断
RoleInterceptor 在 LoginInterceptor 之前执行 CurrentUserContext.get() 为 null 用 order(1)/order(2) 控制顺序
注解只读方法注解，忘读类注解 类级注解失效 方法注解优先，方法无则读类注解
AND 逻辑写错 多角色场景权限判断错 多数场景用 OR（任一角色即可）
角色字符串大小写不一致 "admin" vs "ADMIN" 不匹配 统一用大写常量或枚举

7. 小结

  • 简单角色控制：JWT 携带 role，拦截器校验。
  • 推荐注解式：@RequireRole({"ADMIN"}) 标注方法/类，RoleInterceptor 解析注解。
  • 拦截器顺序：LoginInterceptor 在前（认证），RoleInterceptor 在后（授权）。
  • handler instanceof HandlerMethod 必判，避免静态资源强转错。
  • 生产项目可用 Spring Security @PreAuthorize 替代。

3.1 登录接口改造（返回 JWT Token）

承接第15次课的登录接口，本课在密码校验通过后用 JwtUtil.generateToken 生成 JWT 返回。

package com.ctts.controller;

import com.ctts.common.context.CurrentUserContext;
import com.ctts.common.jwt.JwtUtil;
import com.ctts.common.response.Result;
import com.ctts.dto.LoginDTO;
import com.ctts.entity.User;
import com.ctts.service.UserService;
import jakarta.validation.Valid;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.web.bind.annotation.*;

import java.util.HashMap;
import java.util.Map;

@RestController
@RequestMapping("/api/auth")
public class AuthController {

    private static final Logger log = LoggerFactory.getLogger(AuthController.class);

    @Autowired
    private UserService userService;

    @Autowired
    private JwtUtil jwtUtil;

    /**
     * 登录接口：校验密码成功后返回 JWT Token
     * 该路径在 WebMvcConfig 中被 excludePathPatterns 放行
     */
    @PostMapping("/login")
    public Result<Map<String, Object>> login(@Valid @RequestBody LoginDTO dto) {
        log.info("用户登录: username={}", dto.getUsername());

        // 1. 查询用户
        User user = userService.findByUsername(dto.getUsername());
        if (user == null) {
            return Result.fail(401, "用户名或密码错误");
        }

        // 2. 校验密码（BCrypt）
        if (!userService.checkPassword(dto.getPassword(), user.getPassword())) {
            return Result.fail(401, "用户名或密码错误");
        }

        // 3. 校验账号状态
        if (user.getStatus() != 1) {
            return Result.fail(403, "账号已被禁用，请联系管理员");
        }

        // 4. 生成 JWT Token
        String token = jwtUtil.generateToken(
                user.getId(),
                user.getUsername(),
                user.getRole()   // STUDENT / TEACHER / ADMIN
        );

        // 5. 组装返回
        Map<String, Object> data = new HashMap<>();
        data.put("token", token);
        data.put("userId", user.getId());
        data.put("username", user.getUsername());
        data.put("role", user.getRole());
        data.put("nickname", user.getNickname());

        log.info("登录成功: userId={}, role={}", user.getId(), user.getRole());
        return Result.success(data);
    }

    /**
     * 获取当前登录用户信息（需 Token）
     */
    @GetMapping("/me")
    public Result<Map<String, Object>> me() {
        Map<String, Object> data = new HashMap<>();
        data.put("userId", CurrentUserContext.getUserId());
        data.put("username", CurrentUserContext.getUsername());
        data.put("role", CurrentUserContext.getRole());
        return Result.success(data);
    }

    /**
     * 登出（客户端清除 Token 即可，服务端无状态）
     * 若引入 Token 黑名单，可在此记录
     */
    @PostMapping("/logout")
    public Result<Void> logout() {
        log.info("用户登出: userId={}", CurrentUserContext.getUserId());
        return Result.success();
    }
}

四、拓展阅读

4.1 JWT 算法对比

算法 类型 密钥 适用场景
HS256 对称（HMAC） 共享密钥 单体应用、内部服务
RS256 非对称（RSA） 公钥验签/私钥签发 微服务、开放平台
ES256 非对称（ECDSA） 公钥验签/私钥签发 移动端、物联网
none 无签名 无 ❌ 禁用，安全漏洞

微服务场景：认证中心用私钥签发（RS256），各业务服务用公钥验签，无需共享私钥。

4.2 Refresh Token 机制

短期 Access Token（2h）+ 长期 Refresh Token（7d）：

  • Access Token 过期后，客户端用 Refresh Token 换新 Access Token。
  • Refresh Token 通常存数据库或 Redis，可主动吊销。
  • 减少用户重新登录频率，又控制 Access Token 泄露风险。

4.3 JWT 与 OAuth2 的关系

  • JWT 是 Token 格式标准；OAuth2 是授权框架。
  • OAuth2 可以用 JWT 作为 Access Token 的格式（最常见组合）。
  • 本课的 JWT 是"自签发自校验"的简单方案，OAuth2 涉及授权码、客户端、授权服务器等完整流程。
