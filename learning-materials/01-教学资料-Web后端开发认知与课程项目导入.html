二、知识点详解

知识点 K1-1：什么是 Web 后端开发

定义

Web 后端开发是指开发运行在服务器端的程序，负责接收客户端（浏览器/APP）发来的请求，处理业务逻辑，访问数据库，并将结果返回给客户端。

一句话概括后端的核心职责：

接收请求 → 处理业务 → 访问数据 → 返回结果

原理

一个 Web 系统通常由三部分组成：

图示 1：结构与流程重绘
┌──────────┐ HTTP请求 ┌──────────┐ SQL/数据 ┌──────────┐ │ 前端 │ ──────────▶ │ 后端 │ ──────────▶ │ 数据库 │ │ (浏览器) │ ◀────────── │ (服务器) │ ◀────────── │ (MySQL) │ └──────────┘ HTTP响应 └──────────┘ 数据结果 └──────────┘

已由原 Markdown 字符图转换为网页图示，保留原有逻辑关系并优化阅读效果。

  • 前端：用户看到的界面（HTML/CSS/JS），负责展示与交互。
  • 后端：运行在服务器上的程序，负责业务逻辑与数据处理。
  • 数据库：持久化存储数据（如 MySQL）。

后端开发关注的是中间这一层：如何接收请求、如何处理业务、如何读写数据、如何返回结果。

问题 / 场景

问：后端开发和前端开发有什么区别？

  • 前端关注"用户看到什么"，后端关注"数据从哪来、业务怎么算、结果对不对"。
  • 前端代码运行在浏览器，后端代码运行在服务器。

问：后端开发就是写 SQL 吗？

  • 不是。SQL 只是后端访问数据库的工具之一。后端更核心的是业务逻辑处理——比如"学生提交任务后，状态要更新为已提交，且要在评审表中生成待评审记录"，这是业务逻辑，不只是 SQL。

完整示例代码

下面是一个现代后端接口的代码示例（使用 Spring Boot，后续课程会详细学习）。现在只需看懂它的结构，不用深究语法：

// 这是一个"查询实训项目列表"的后端接口（Spring Boot 写法）
@RestController
@RequestMapping("/api/projects")
public class ProjectController {

    @GetMapping("/list")
    public List<Project> listProjects() {
        // 1. 接收请求（这里没有参数，直接查询全部）
        // 2. 调用业务逻辑，查询数据库
        List<Project> projects = projectService.findAll();
        // 3. 返回结果（自动转成 JSON）
        return projects;
    }
}

易错点

  1. ❌ 误认为"后端 = 写 SQL"。✅ 后端核心是业务逻辑，SQL 只是工具。
  2. ❌ 误认为"后端运行在用户电脑上"。✅ 后端运行在服务器上，用户通过浏览器访问。
  3. ❌ 误认为"前端和后端用同一种语言"。✅ 前端用 HTML/CSS/JS，后端用 Java/Python/Go 等。

小结

后端开发 = 服务器端程序开发，核心职责是"接收请求 → 处理业务 → 访问数据 → 返回结果"。本课程学的就是用 Java（Spring Boot）来做这件事。

知识点 K1-2：B/S 架构与 C/S 架构

定义

  • B/S 架构（Browser/Server）：客户端是浏览器，用户通过浏览器访问服务器上的应用。如：淘宝网页版、教务系统网页版。
  • C/S 架构（Client/Server）：客户端是专门的桌面程序或 APP，需要安装后才能使用。如：微信 PC 版、手机银行 APP。

原理

对比项 B/S 架构 C/S 架构
客户端 浏览器（无需安装应用） 专用客户端程序（需安装）
升级维护 服务器更新即可，客户端自动生效 客户端需重新下载安装更新
跨平台 浏览器即可，天然跨平台 需为不同系统开发不同客户端
性能 受浏览器限制 可充分利用本机性能
典型代表 淘宝网页、教务系统、在线文档 微信 PC 版、手机银行 APP、QQ

现代 Web 后端开发主要针对 B/S 架构。本课程的项目 CTTS 也是 B/S 架构。

问题 / 场景

问：手机 APP 是 B/S 还是 C/S？

  • 手机 APP 本身是 C/S 的客户端（需安装），但它与服务器之间的通信方式（HTTP + JSON）和 B/S 后端是一样的。所以"后端开发"的技能在 B/S 和 C/S 中是通用的。

问：B/S 架构有没有缺点？

  • 有。浏览器对本地文件、硬件访问受限；离线能力弱；复杂交互体验不如原生客户端。所以现在很多产品同时提供网页版和 APP 版。

完整示例代码

判断一个软件是 B/S 还是 C/S，看客户端是否需要安装专用程序：

微信 PC 版           专用程序（需安装）  C/S
教务系统（网页）       浏览器            B/S
手机银行 APP          专用程序（需安装）  C/S
腾讯文档（网页）       浏览器            B/S

易错点

  1. ❌ 误认为"B/S 架构就是前后端分离"。✅ B/S 只是指客户端是浏览器；JSP 也是 B/S，但前后端没有分离（见 K1-3）。
  2. ❌ 误认为"C/S 架构已经过时"。✅ C/S 在性能要求高的场景（如游戏、银行）仍是主流，很多产品 B/S + C/S 并存。

小结

B/S 用浏览器访问、免安装、易维护，是 Web 开发主流。本课程聚焦 B/S 架构的后端开发。

知识点 K1-3：前后端分离

定义

前后端分离是一种开发模式：前端和后端各自独立开发、独立部署，通过 API（通常返回 JSON 数据） 进行通信。前端只负责界面展示与交互，后端只负责数据与业务，二者不再混合在同一套代码中。

原理

对比两种模式：

传统 JSP 模式（未分离）：

图示 5：结构与流程重绘
浏览器 ──请求──▶ 服务器(JSP) ──SQL──▶ 数据库 │ ▼ JSP 中混合 HTML + Java 代码 在服务器端拼装出完整 HTML 页面 返回给浏览器直接显示

已由原 Markdown 字符图转换为网页图示，保留原有逻辑关系并优化阅读效果。

前后端分离模式：

图示 6：结构与流程重绘
浏览器(JS前端) ──请求API──▶ 后端(Java) ──SQL──▶ 数据库 │ ▼ 后端只返回 JSON 数据 （不含任何 HTML） │ 浏览器(JS前端) ◀──JSON数据───┘ 前端拿到数据后，自己渲染成界面

已由原 Markdown 字符图转换为网页图示，保留原有逻辑关系并优化阅读效果。

问题 / 场景

问：为什么要前后端分离？

  • 分工清晰：前端工程师专注界面，后端工程师专注业务。
  • 并行开发：前后端约定好接口后可同时开发，提升效率。
  • 复用性强：同一套后端 API 可同时服务网页版、APP 版、小程序。
  • 体验更好：前端可做局部刷新（无刷新更新数据），类似原生应用体验。

问：前后端分离后，后端返回什么？

  • 返回 JSON 格式的数据，不返回 HTML 页面。例如：
{
  "code": 200,
  "message": "success",
  "data": {"id": 1, "title": "JavaWeb 实训"}
}

完整示例代码

未分离（JSP，了解即可，本课程不写）：

<%@ page contentType="text/html;charset=UTF-8" %>
<%
  // JSP 中直接写 Java 代码查数据库
  List<Project> projects = projectDao.findAll();
%>
<html>
<body>
  <ul>
  <% for(Project p : projects) { %>
    <li><%= p.getTitle() %></li>
  <% } %>
  </ul>
</body>
</html>

问题：HTML 和 Java 混在一起，难以维护，前后端无法分离开发。

前后端分离（现代后端，本课程学习）：

// 后端：只返回数据，不关心界面长什么样
@RestController
@RequestMapping("/api/projects")
public class ProjectController {
    @GetMapping("/list")
    public List<Project> list() {
        return projectService.findAll();  // 自动转 JSON 返回
    }
}
// 后端返回的内容（JSON），前端拿到后自己渲染界面
[
  {"id": 1, "title": "JavaWeb 实训", "status": "进行中"},
  {"id": 2, "title": "数据库实训", "status": "已结束"}
]

传统 JSP（未分离） 前后端分离 ┌─────────────────────┐ ┌──────────┐ ┌──────────┐ │ 服务器 │ │ 前端 │ API │ 后端 │ │ ┌───────────────┐ │ │ (JS渲染) │◀──────▶│ (Java) │ │ │JSP:HTML+Java │ │ └──────────┘ JSON └──────────┘ │ │混合，拼装HTML │ │ 独立开发部署 独立开发部署 │ └───────────────┘ │ └─────────────────────┘ 前后端耦合在一起 前后端解耦，各司其职

易错点

  1. ❌ 误认为"B/S = 前后端分离"。✅ B/S 是架构模式（客户端用浏览器），前后端分离是开发模式。JSP 是 B/S 但未分离。
  2. ❌ 误认为"前后端分离后后端就不返回 HTML 了，那 HTML 谁写"。✅ HTML 由前端写，后端只返回 JSON 数据。
  3. ❌ 误认为"前后端分离就是用两台服务器"。✅ 分离是指代码与职责分离，不是物理服务器分离。

小结

前后端分离 = 前端管界面、后端管数据、二者通过 JSON API 通信。这是现代 Web 开发主流模式，也是本课程的目标模式。

知识点 K1-4：后端开发岗位与企业项目流程

定义

Java 后端开发工程师是企业研发团队中的核心岗位，负责服务器端业务逻辑、接口开发、数据库访问、系统稳定性等工作。

原理

典型岗位职责：

  1. 根据需求设计数据库表与接口。
  2. 编写后端代码（Controller/Service/Mapper）实现业务功能。
  3. 编写与维护接口文档，与前端联调。
  4. 处理异常、保证数据安全与系统稳定。
  5. 参与代码评审、测试、部署与运维。

知识点 K1-5：Servlet + JSP 历史背景（背景讲解）

定义

Servlet 是 Java 早期的 Web 服务器端技术，用 Java 代码处理 HTTP 请求；JSP 是在 HTML 中嵌入 Java 代码生成动态页面的技术。二者是早期 JavaWeb 开发的主流方式。

原理

早期 JavaWeb 开发流程（了解即可，本课程不深入）：

图示 10：结构与流程重绘
浏览器 ──请求──▶ Tomcat(Web服务器) ──▶ Servlet(处理请求,写Java) │ ▼ JSP(HTML+Java,拼页面) │ 浏览器 ◀──HTML页面─── Tomcat ◀────────────┘

已由原 Markdown 字符图转换为网页图示，保留原有逻辑关系并优化阅读效果。

为什么现代项目不再用 Servlet/JSP 作为主线？

痛点 说明
配置繁琐 web.xml 大量配置，容易出错
前后端耦合 JSP 中 HTML+Java 混写，无法分离开发
开发效率低 一个简单功能要写 Servlet + 配置 + JSP，步骤多
难以维护 业务逻辑、页面展示、数据访问混在一起
不契合前后端分离 JSP 本质是服务端渲染页面，与现代 JSON API 模式不符

现代替代方案：Spring Boot 简化了配置，天然支持前后端分离（返回 JSON），开发效率高，是企业主流。

问题 / 场景

问：既然 Servlet 过时了，为什么还要了解？

  • Servlet 是 JavaWeb 的底层规范，Spring Boot 底层仍基于 Servlet。了解 Servlet 有助于理解 Spring Boot 的原理。但本课程不深讲 Servlet 编码，只作背景。

问：Spring MVC / Spring Boot 和 Servlet 是什么关系？

  • Spring MVC 封装了 Servlet，Spring Boot 又封装了 Spring MVC 并简化配置。关系：Servlet（底层）→ Spring MVC（封装）→ Spring Boot（再封装+简化）。

完整示例代码

早期 Servlet 写法（了解，不要求掌握）：

// 早期：写一个接口要继承 HttpServlet，配置 web.xml，步骤繁琐
public class HelloServlet extends HttpServlet {
    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {
        resp.setContentType("text/html;charset=UTF-8");
        resp.getWriter().write("<h1>Hello, Servlet!</h1>");  // 手动拼 HTML
    }
}
// 还需在 web.xml 中配置路由映射，非常繁琐

现代 Spring Boot 写法（本课程学习）：

// 现代：一个注解 + 一个方法，无需配置 XML
@RestController
public class HelloController {
    @GetMapping("/hello")
    public String hello() {
        return "Hello, Spring Boot!";  // 自动返回，无需手动拼 HTML
    }
}

📌 对比可见，Spring Boot 写法简洁得多。这就是为什么现代项目选择 Spring Boot。

  2. ❌ 误认为"本课程要学 JSP"。✅ 本课程不学 JSP 编码，JSP 仅作历史背景了解。

Servlet/JSP 是 JavaWeb 早期技术，配置繁琐、前后端耦合，已被 Spring Boot 等现代框架替代。本课程以 Spring Boot 为主线，Servlet/JSP 仅作背景帮助理解原理。

知识点 K1-6：课程项目导入 — 校园实训任务管理系统（CTTS）

定义

校园实训任务管理系统（Campus Training Task System，CTTS） 是贯穿本课程的实战项目。我们将用 24 次课逐步构建这个系统的后端，最终交付一个可运行、可演示、可部署的项目。

原理

业务背景： 高校实训管理中常存在痛点：任务下发靠群里通知易遗漏、学生提交成果靠邮件难统计、教师评审靠 Excel 难追溯、成绩汇总靠手工易出错。CTTS 用一个 Web 系统解决这些问题。

三种角色与核心功能：

角色 核心功能
管理员 用户管理（增删改查、分配角色）、实训项目管理、系统统计
教师 创建/维护实训项目、发布任务、评审学生提交、查询进度
学生 查看实训项目与任务、提交任务成果、查看评审反馈、查询个人成绩

五张核心数据表（第 18 次课详细设计）：

表名 说明
sys_user 用户表（学生/教师/管理员）
training_project 实训项目表
task 任务表（属于某项目）
task_submission 学生任务提交表
task_review 教师评审记录表
