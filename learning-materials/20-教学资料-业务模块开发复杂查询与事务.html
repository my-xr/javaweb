二、知识点详解

K20-1 复杂条件查询

2.1.1 定义

复杂条件查询：在一张或多张表上，根据用户输入的多个可变条件（可能为空、可能组合）动态拼接 SQL WHERE 子句的查询方式。

典型场景：CTTS 后台"提交记录查询"页面，用户可能按学号、姓名、任务标题、提交状态、提交时间范围任意组合筛选。

2.1.2 原理

MyBatis-Plus 的 QueryWrapper 采用链式 API 拼 WHERE 子句，每个 and(Predicate) / or(Predicate) 接收一个 Lambda，内部会自动加括号保证优先级。

条件拼接的优先级问题：SQL 中 AND 优先级高于 OR，所以 A AND B OR C 实际是 (A AND B) OR C，与直觉中的 A AND (B OR C) 不同。用 nested 或 and(lambda) 显式加括号是避免歧义的关键。

2.1.3 问题

典型错误写法（丢括号导致语义偏差）：

// 需求：查询"张三"或"李四"的、状态为"已提交"的记录
QueryWrapper<Submission> wrapper = new QueryWrapper<>();
wrapper.eq("status", 2)
       .eq("student_name", "张三")
       .or().eq("student_name", "李四");
// 生成的 SQL：WHERE status = 2 AND student_name = '张三' OR student_name = '李四'
// 实际语义：(status=2 AND student_name='张三') OR student_name='李四'
// 即"李四"的所有记录都会被查出，与需求不符！

2.1.4 完整代码

正确写法：嵌套条件 + 动态拼接

package com.ctts.service.impl;

import com.baomidou.mybatisplus.core.conditions.query.QueryWrapper;
import com.ctts.dto.SubmissionQueryDTO;
import com.ctts.entity.Submission;
import com.ctts.mapper.SubmissionMapper;
import com.ctts.service.SubmissionService;
import com.ctts.vo.SubmissionVO;
import org.springframework.stereotype.Service;
import org.springframework.util.StringUtils;

import java.util.List;

@Service
public class SubmissionServiceImpl implements SubmissionService {

    private final SubmissionMapper submissionMapper;

    public SubmissionServiceImpl(SubmissionMapper submissionMapper) {
        this.submissionMapper = submissionMapper;
    }

    /**
     * 复杂条件查询：多条件动态组合 + 嵌套 or/and
     * 需求：按学生姓名/学号、任务标题、状态、时间范围筛选提交记录
     */
    public List<SubmissionVO> querySubmissions(SubmissionQueryDTO dto) {
        QueryWrapper<SubmissionVO> wrapper = new QueryWrapper<>();

        // 1) 动态条件：只在字段非空时拼接（避免拼出 WHERE ... AND null）
        wrapper.eq(StringUtils.hasText(dto.getStudentNo()),
                   "s.student_no", dto.getStudentNo());
        wrapper.like(StringUtils.hasText(dto.getTaskTitle()),
                     "t.title", dto.getTaskTitle());
        wrapper.eq(dto.getStatus() != null, "sub.status", dto.getStatus());
        wrapper.ge(dto.getStartTime() != null, "sub.submit_time", dto.getStartTime());
        wrapper.le(dto.getEndTime() != null, "sub.submit_time", dto.getEndTime());

        // 2) 嵌套 or 条件：姓名模糊匹配"张三"或"李四"（用 and(lambda) 显式加括号）
        //    最终生成：AND ( s.name LIKE '%张三%' OR s.name LIKE '%李四%' )
        if (StringUtils.hasText(dto.getStudentName())) {
            wrapper.and(w -> w.like("s.name", dto.getStudentName())
                              .or().like("s.name", "李四"));
        }

        // 3) 排序
        wrapper.orderByDesc("sub.submit_time");

        return submissionMapper.selectSubmissionList(wrapper);
    }
}

对应 Mapper（多表 JOIN + 用 Wrapper 接收动态条件）：

package com.ctts.mapper;

import com.baomidou.mybatisplus.core.conditions.query.QueryWrapper;
import com.ctts.entity.Submission;
import com.baomidou.mybatisplus.core.mapper.BaseMapper;
import com.ctts.vo.SubmissionVO;
import org.apache.ibatis.annotations.Param;
import org.apache.ibatis.annotations.Select;

import java.util.List;

public interface SubmissionMapper extends BaseMapper<Submission> {

    /**
     * 多表关联 + 动态条件查询
     * 注意：${ew.customSqlSegment} 是 MyBatis-Plus 的占位符，
     *       会把 QueryWrapper 拼出的 WHERE 子句原样注入
     */
    @Select("""
        SELECT sub.id, sub.task_id, sub.student_id, sub.status,
               sub.submit_time, sub.content,
               s.name AS student_name, s.student_no,
               t.title AS task_title
        FROM submission sub
        INNER JOIN student s ON sub.student_id = s.id
        INNER JOIN task t ON sub.task_id = t.id
        ${ew.customSqlSegment}
        """)
    List<SubmissionVO> selectSubmissionList(@Param("ew") QueryWrapper<SubmissionVO> wrapper);
}

2.1.6 易错点

易错点 错误写法 正确写法
or 优先级错乱 wrapper.eq(A).eq(B).or().eq(C) wrapper.and(w -> w.eq(A).or().eq(C)).eq(B)
动态条件拼空 wrapper.like(name != null, ...) 漏判空字符串 用 StringUtils.hasText()
多表字段重名 wrapper.eq("id", 1) 三张表都有 id 加表别名前缀 t.id
Lambda 写法丢括号 wrapper.eq(A).or().eq(B).eq(C) wrapper.and(w -> w.eq(A).or().eq(B)).eq(C)

2.1.7 小结

  • 多条件动态拼接用 condition 参数版本（eq(boolean condition, ...)）。
  • 涉及 or 的组合一律用 and(lambda) 或 or(lambda) 显式加括号。
  • 多表查询字段必须加表别名前缀。
  • 永远打印 SQL 日志验证 WHERE 子句是否正确。

K20-2 统计查询

2.2.1 定义

统计查询：使用 SQL 聚合函数（COUNT / SUM / AVG / MAX / MIN）配合 GROUP BY 对数据进行分组汇总的查询。

典型场景：CTTS 教师端"成绩统计"页面——每个学生平均分、每个任务提交数、各状态提交占比。

2.2.2 原理

  • COUNT(*) 统计行数；COUNT(字段) 忽略 NULL。
  • GROUP BY 按字段分组，SELECT 只能出现分组字段或聚合函数。
  • HAVING 对分组结果过滤（区别于 WHERE 对原始行过滤）。
  • MyBatis-Plus 提供 selectMaps / selectCount / selectMapsPage 简化统计。

2.2.3 问题

直接用 selectList 查统计结果会丢失聚合列——因为实体类没有"avg_score"字段。解决方案：用 selectMaps（返回 List<Map>）或自定义 SQL 映射到 VO。

2.2.4 完整代码

方式一：MyBatis-Plus selectMaps + QueryWrapper

package com.ctts.service.impl;

import com.baomidou.mybatisplus.core.conditions.query.QueryWrapper;
import com.ctts.entity.Submission;
import com.ctts.mapper.SubmissionMapper;
import org.springframework.stereotype.Service;

import java.util.List;
import java.util.Map;

@Service
public class StatServiceImpl implements StatService {

    private final SubmissionMapper submissionMapper;

    public StatServiceImpl(SubmissionMapper submissionMapper) {
        this.submissionMapper = submissionMapper;
    }

    /**
     * 统计每个任务下的提交数（用 selectMaps）
     * SQL: SELECT task_id, COUNT(*) AS cnt FROM submission GROUP BY task_id
     */
    public List<Map<String, Object>> countByTask() {
        QueryWrapper<Submission> wrapper = new QueryWrapper<>();
        wrapper.select("task_id", "COUNT(*) AS cnt")
               .groupBy("task_id");
        return submissionMapper.selectMaps(wrapper);
    }

    /**
     * 统计某任务各状态的提交数
     * SQL: SELECT status, COUNT(*) AS cnt FROM submission
     *      WHERE task_id = ? GROUP BY status
     */
    public List<Map<String, Object>> countStatusByTask(Long taskId) {
        QueryWrapper<Submission> wrapper = new QueryWrapper<>();
        wrapper.select("status", "COUNT(*) AS cnt")
               .eq("task_id", taskId)
               .groupBy("status");
        return submissionMapper.selectMaps(wrapper);
    }
}

方式二：自定义 SQL + VO（推荐，类型安全）

// VO
package com.ctts.vo;

import lombok.Data;
import java.math.BigDecimal;

@Data
public class StudentStatVO {
    private Long studentId;
    private String studentName;
    private Integer submitCount;     // 提交次数
    private BigDecimal avgScore;     // 平均成绩
    private BigDecimal maxScore;     // 最高分
}
// Mapper
package com.ctts.mapper;

import com.ctts.vo.StudentStatVO;
import org.apache.ibatis.annotations.Select;
import java.util.List;

public interface ReviewMapper extends com.baomidou.mybatisplus.core.mapper.BaseMapper<com.ctts.entity.Review> {

    /**
     * 统计每个学生的平均成绩、最高分、提交数
     * 三表关联：submission + review + student
     */
    @Select("""
        SELECT s.id              AS studentId,
               s.name            AS studentName,
               COUNT(r.id)       AS submitCount,
               AVG(r.score)      AS avgScore,
               MAX(r.score)      AS maxScore
        FROM submission sub
        INNER JOIN student s  ON sub.student_id = s.id
        LEFT  JOIN review r   ON r.submission_id = sub.id
        WHERE sub.status = 3
        GROUP BY s.id, s.name
        HAVING COUNT(r.id) > 0
        ORDER BY avgScore DESC
        """)
    List<StudentStatVO> statStudentScore();
}

2.2.6 易错点

易错点 说明 解决
SELECT 字段不在 GROUP BY 中 报 SQL 语法错 只选分组字段或聚合字段
COUNT(字段) vs COUNT(*) 字段为 NULL 不计 数行数用 COUNT(*)
AVG 保留小数 默认返回 BigDecimal，注意精度 用 BigDecimal.setScale(2, HALF_UP)
HAVING vs WHERE 混用 WHERE 不能用聚合函数 先 WHERE 过滤行，再 HAVING 过滤组
selectMaps 字段名 返回 Map 的 key 是 SQL 中的列别名 用 AS xxx 显式起别名

2.2.7 小结

  • 简单分组统计用 selectMaps + QueryWrapper。
  • 类型安全的多表统计用自定义 @Select + VO。
  • 统计总数用 selectCount。
  • 区分 WHERE / HAVING / ON 三种过滤位置。

K20-3 事务管理深入

2.3.1 定义

事务（Transaction）：一组不可分割的操作序列，要么全部成功，要么全部失败回滚。事务的四大特性（ACID）：

  • Atomicity 原子性：全部成功或全部回滚
  • Consistency 一致性：执行前后数据满足约束
  • Isolation 隔离性：并发事务互不干扰
  • Durability 持久性：提交后永久保存

@Transactional：Spring 提供的声明式事务注解，加在方法或类上，由 Spring AOP 在方法执行前后织入事务管理逻辑。

2.3.2 原理

Spring 声明式事务的本质：基于 AOP 代理。

图示 4：Spring 事务代理提交与回滚流程

调用方

调用事务方法。

→

代理对象

Spring AOP 开启事务。

→

目标方法

执行业务与数据库操作。

正常返回

提交事务。

抛出异常

判断 rollbackFor，匹配则回滚事务。

@Transactional 核心属性：

属性 默认值 说明
propagation REQUIRED 事务传播行为，见下表
isolation 数据库默认 隔离级别（READ_COMMITTED / REPEATABLE_READ / SERIALIZABLE）
timeout -1（不超时） 事务超时秒数
readOnly false 是否只读事务
rollbackFor RuntimeException.class 遇到哪些异常回滚
noRollbackFor {} 遇到哪些异常不回滚

7 种传播行为：

传播行为 当前有事务 当前无事务 典型场景
REQUIRED（默认） 加入当前事务 新建事务 99% 业务方法
REQUIRES_NEW 挂起当前事务，新建独立事务 新建事务 日志记录（不受主事务回滚影响）
NESTED 在当前事务内建保存点，部分回滚 新建事务 子操作可独立回滚但不影响主事务
SUPPORTS 加入当前事务 非事务执行 查询方法
NOT_SUPPORTED 挂起当前事务 非事务执行 不需要事务的操作
MANDATORY 加入当前事务 抛异常 强制要求被事务调用
NEVER 抛异常 非事务执行 强制不能在事务中

2.3.3 问题

问题1：rollbackFor 默认值陷阱

// ❌ 反例：默认只回滚 RuntimeException，受检异常不回滚
@Transactional
public void submitTask(Long submissionId) throws IOException {
    submissionMapper.updateStatus(submissionId, 2);   // 已提交
    saveFile();                                       // 抛 IOException
    // 文件保存失败，但 status 已更新且不会回滚！
}

private void saveFile() throws IOException {
    throw new IOException("磁盘满");
}

问题2：自调用导致事务失效

// ❌ 反例：内部方法调用，AOP 代理被绕过
@Service
public class SubmissionServiceImpl implements SubmissionService {

    public void submitAndReview(Long submissionId) {
        this.doSubmit(submissionId);   // ← 直接 this 调用，不走代理！
        this.doReview(submissionId);
    }

    @Transactional
    public void doSubmit(Long submissionId) {
        // 事务注解在这里完全失效
    }
}

问题3：异常被 catch 吞掉

// ❌ 反例：异常被 catch，AOP 看不到异常，不回滚
@Transactional
public void submitTask(Long submissionId) {
    try {
        submissionMapper.updateStatus(submissionId, 2);
        throw new RuntimeException("模拟异常");
    } catch (Exception e) {
        log.error("提交失败", e);   // 异常被吞，事务不回滚
    }
}

问题4：non-public 方法

// ❌ 反例：private 方法，Spring AOP 默认只代理 public

package com.ctts.service.impl;

import com.ctts.entity.Review;
import com.ctts.entity.Submission;
import com.ctts.enums.SubmissionStatus;
import com.ctts.mapper.ReviewMapper;
import com.ctts.mapper.SubmissionMapper;
import com.ctts.service.TaskBusinessService;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.time.LocalDateTime;

@Service
public class TaskBusinessServiceImpl implements TaskBusinessService {

    private final SubmissionMapper submissionMapper;
    private final ReviewMapper reviewMapper;

    public TaskBusinessServiceImpl(SubmissionMapper submissionMapper,
                                   ReviewMapper reviewMapper) {
        this.submissionMapper = submissionMapper;
        this.reviewMapper = reviewMapper;
    }

    /**
     * 提交任务：更新提交状态为"已提交" + 记录提交时间
     * rollbackFor = Exception.class：受检异常也回滚
     * propagation = REQUIRED：当前无事务则新建，有则加入
     */
    @Transactional(rollbackFor = Exception.class, propagation = Propagation.REQUIRED)
    public void submitTask(Long submissionId, String content, String fileUrl) {
        // 1) 校验提交状态（必须是"进行中"才能提交）
        Submission submission = submissionMapper.selectById(submissionId);
        if (submission == null) {
            throw new IllegalArgumentException("提交记录不存在");
        }
        if (!SubmissionStatus.IN_PROGRESS.getCode().equals(submission.getStatus())) {
            throw new IllegalStateException("当前状态不允许提交");
        }

        // 2) 更新提交记录
        submission.setStatus(SubmissionStatus.SUBMITTED.getCode());
        submission.setContent(content);
        submission.setFileUrl(fileUrl);
        submission.setSubmitTime(LocalDateTime.now());
        submissionMapper.updateById(submission);
        // 至此 status 已变 2
    }

    /**
     * 评审任务：创建评审记录 + 更新提交状态为"已评审"
     * 一个事务内完成两步操作，任一失败全部回滚
     */
    @Transactional(rollbackFor = Exception.class, propagation = Propagation.REQUIRED)
    public void reviewTask(Long submissionId, Long teacherId,
                           java.math.BigDecimal score, String comment) {
        // 1) 创建评审记录
        Review review = new Review();
        review.setSubmissionId(submissionId);
        review.setTeacherId(teacherId);
        review.setScore(score);
        review.setComment(comment);
        review.setReviewTime(LocalDateTime.now());
        reviewMapper.insert(review);

        // 2) 更新提交状态为"已评审"
        Submission submission = submissionMapper.selectById(submissionId);
        if (!SubmissionStatus.SUBMITTED.getCode().equals(submission.getStatus())) {
            throw new IllegalStateException("当前状态不允许评审");
        }
        submission.setStatus(SubmissionStatus.REVIEWED.getCode());
        submissionMapper.updateById(submission);

        // 3) 模拟异常：上面两步会一起回滚
        // if (score.compareTo(new java.math.BigDecimal("100")) > 0) {
        //     throw new IllegalArgumentException("成绩不能超过100");
        // }
    }
}

import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

/**

public class BadTransactionDemo {

        this.innerMethod(id);   // ❌ this 调用绕过代理，事务失效
    }

    @Transactional(rollbackFor = Exception.class)
    public void innerMethod(Long id) {
        // 事务注解在此处不生效
    }

    // 修复方案1：注入自己
    // @Autowired @Lazy private BadTransactionDemo self;
    // public void outerMethod(Long id) { self.innerMethod(id); }
    //
    // 修复方案2：从 ApplicationContext 取代理
    // 修复方案3：拆到两个 Service

    // ========== 宗罪2：异常被 catch ==========
    @Transactional(rollbackFor = Exception.class)
    public void swallowException(Long id) {
        try {
            // 业务操作
            throw new RuntimeException("数据库异常");
        } catch (Exception e) {
            // ❌ 异常被吞，Spring 看不到异常，不回滚
            System.err.println("出错啦：" + e.getMessage());
        }
    }
    // 修复方案：catch 后手动 rethrow，或用 TransactionAspectSupport.currentTransactionStatus().setRollbackOnly()

    // ========== 宗罪3：non-public 方法 ==========
    @Transactional(rollbackFor = Exception.class)
    void packageMethod(Long id) {   // ❌ 包级私有，AOP 默认不代理
    }
    // 修复方案：改为 public

    // ========== 宗罪4：rollbackFor 默认只回 RuntimeException ==========
    @Transactional   // ❌ 默认 rollbackFor = RuntimeException.class
    public void ioOperation() throws java.io.IOException {
        // 抛 IOException 不会回滚
        throw new java.io.IOException("磁盘满");
    }

  • 子操作可部分回滚用 NESTED。
  • 牢记事务失效四宗罪：自调用、catch 吞异常、non-public、rollbackFor 默认值。

K20-4 业务状态流转

2.4.1 定义

业务状态流转：用一个状态字段记录业务对象当前所处的阶段，并通过规则约束状态之间的合法转换路径。

CTTS 提交任务的 4 个状态： | 状态码 | 状态名 | 说明 | |--------|--------|------| | 0 | 未开始 | 学生未开始做任务 | | 1 | 进行中 | 学生正在编辑提交内容 | | 2 | 已提交 | 学生已提交，等待评审 | | 3 | 已评审 | 教师已完成评审，有成绩 |

2.4.2 原理

状态机三要素：

  • 状态（State）：业务对象在某一时刻所处的情况
  • 事件（Event）：触发状态转换的动作
  • 转换（Transition）：状态→事件→新状态的映射规则

合法流转：

图示 7：未开始 (开始) → 进行中 (提交) → 已提交 (评审) → 已评审

未开始 (开始)

→

进行中 (提交)

→

已提交 (评审)

→

已评审

非法流转（必须拦截）：

  • 未开始 → 已提交（跳过开始）
  • 已评审 → 已提交（评审后不能改）
  • 任意状态 → 前置状态（不能回退，除特殊业务流程）

2.4.3 问题

如果不做状态校验：

  • 学生重复提交会覆盖已评审的成绩
  • 已评审的记录被再次"提交"导致评审记录与提交状态不一致
  • 出现脏数据，统计结果失真

package com.ctts.enums;

import lombok.AllArgsConstructor;
import lombok.Getter;

@Getter
@AllArgsConstructor
public enum SubmissionStatus {
    NOT_STARTED(0, "未开始"),
    IN_PROGRESS(1, "进行中"),
    SUBMITTED(2, "已提交"),
    REVIEWED(3, "已评审");

    private final Integer code;
    private final String desc;

    public static SubmissionStatus of(Integer code) {
        for (SubmissionStatus s : values()) {
            if (s.code.equals(code)) return s;
        }
        throw new IllegalArgumentException("未知提交状态: " + code);
    }

状态转换规则：

package com.ctts.enums;

import java.util.EnumMap;
import java.util.Map;
import java.util.Set;

/**
 * 提交状态机：定义合法流转
 */
public class SubmissionStateMachine {

    private static final Map<SubmissionStatus, Set<SubmissionStatus>> TRANSITIONS;

    static {
        TRANSITIONS = new EnumMap<>(SubmissionStatus.class);
        TRANSITIONS.put(SubmissionStatus.NOT_STARTED, Set.of(SubmissionStatus.IN_PROGRESS));
        TRANSITIONS.put(SubmissionStatus.IN_PROGRESS, Set.of(SubmissionStatus.SUBMITTED));
        TRANSITIONS.put(SubmissionStatus.SUBMITTED, Set.of(SubmissionStatus.REVIEWED, SubmissionStatus.IN_PROGRESS)); // 允许退回修改
        TRANSITIONS.put(SubmissionStatus.REVIEWED, Set.of()); // 终态
    }

    /**
     * 判断状态转换是否合法
     */
    public static boolean canTransit(SubmissionStatus from, SubmissionStatus to) {
        return TRANSITIONS.getOrDefault(from, Set.of()).contains(to);
    }

    /**
     * 校验并抛异常
     */
    public static void check(SubmissionStatus from, SubmissionStatus to) {
        if (!canTransit(from, to)) {
            throw new IllegalStateException(
                "非法状态流转: " + from.getDesc() + " → " + to.getDesc());
        }
    }
}

K20-5 综合业务实现

2.5.1 定义

把 K20-1 ~ K20-4 串起来，实现 CTTS 的核心业务链： 任务提交 → 状态更新（进行中→已提交） → 评审 → 状态更新（已提交→已评审） → 成绩统计

2.5.2 原理

业务链的每一步都是独立的事务方法，但每步内部需要事务保障。整条链路的设计原则：

  • 单步操作用 REQUIRED 事务。
  • 跨步操作（如批量评审）整体用 REQUIRED，内部方法加入外层事务。
  • 日志记录用 REQUIRES_NEW，独立提交。
  • 状态流转每步用 StateMachine.check 校验。

2.5.3 问题

整条链路涉及 4 张表（submission / review / student / operation_log）、5 个操作、3 次状态变更，任何一步失败都需要明确的事务边界与回滚策略。

业务链主方法：

package com.ctts.service.impl;

import com.ctts.entity.Review;
import com.ctts.entity.Submission;
import com.ctts.enums.SubmissionStatus;
import com.ctts.enums.SubmissionStateMachine;
import com.ctts.mapper.ReviewMapper;
import com.ctts.mapper.SubmissionMapper;
import com.ctts.service.TaskBusinessService;
import com.ctts.vo.StudentStatVO;
import org.springframework.context.ApplicationContext;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Propagation;
import org.springframework.transaction.annotation.Transactional;

import java.math.BigDecimal;
import java.time.LocalDateTime;
import java.util.List;

@Service
public class TaskBusinessServiceImpl implements TaskBusinessService {

    private final SubmissionMapper submissionMapper;
    private final ReviewMapper reviewMapper;
    private final StatService statService;
    private final LogService logService;

    // 用 ApplicationContext 解决自调用问题
    private final ApplicationContext ctx;

    public TaskBusinessServiceImpl(SubmissionMapper submissionMapper,
                                   ReviewMapper reviewMapper,
                                   StatService statService,
                                   LogService logService,
                                   ApplicationContext ctx) {
        this.submissionMapper = submissionMapper;
        this.reviewMapper = reviewMapper;
        this.statService = statService;
        this.logService = logService;
        this.ctx = ctx;
    }

    /**
     * 业务链第1步：开始任务（未开始 → 进行中）
     */
    @Transactional(rollbackFor = Exception.class)
    public void startTask(Long submissionId) {
        Submission sub = submissionMapper.selectById(submissionId);
        SubmissionStatus from = SubmissionStatus.of(sub.getStatus());
        SubmissionStateMachine.check(from, SubmissionStatus.IN_PROGRESS);

        sub.setStatus(SubmissionStatus.IN_PROGRESS.getCode());
        submissionMapper.updateById(sub);

        // 日志独立事务（REQUIRES_NEW）
        logService.log(submissionId, "START", "开始任务");
    }

    /**
     * 业务链第2步：提交任务（进行中 → 已提交）
     */
    @Transactional(rollbackFor = Exception.class)
    public void submitTask(Long submissionId, String content, String fileUrl) {
        Submission sub = submissionMapper.selectById(submissionId);
        SubmissionStatus from = SubmissionStatus.of(sub.getStatus());
        SubmissionStateMachine.check(from, SubmissionStatus.SUBMITTED);

        sub.setStatus(SubmissionStatus.SUBMITTED.getCode());
        sub.setContent(content);
        sub.setFileUrl(fileUrl);
        sub.setSubmitTime(LocalDateTime.now());
        submissionMapper.updateById(sub);

        logService.log(submissionId, "SUBMIT", "提交任务");
    }

    /**
     * 业务链第3步：评审任务（已提交 → 已评审）+ 创建评审记录
     * 一个事务内完成：插入 review + 更新 submission 状态
     */
    @Transactional(rollbackFor = Exception.class)
    public void reviewTask(Long submissionId, Long teacherId,
                           BigDecimal score, String comment) {
        // 1) 创建评审记录
        Review review = new Review();
        review.setSubmissionId(submissionId);
        review.setTeacherId(teacherId);
        review.setScore(score);
        review.setComment(comment);
        review.setReviewTime(LocalDateTime.now());
        reviewMapper.insert(review);

        // 2) 状态校验 + 更新
        Submission sub = submissionMapper.selectById(submissionId);
        SubmissionStatus from = SubmissionStatus.of(sub.getStatus());
        SubmissionStateMachine.check(from, SubmissionStatus.REVIEWED);
        sub.setStatus(SubmissionStatus.REVIEWED.getCode());
        submissionMapper.updateById(sub);

        logService.log(submissionId, "REVIEW", "评审完成，成绩：" + score);
    }

    /**
     * 业务链第4步：成绩统计（查询，无需事务）
     */
    public List<StudentStatVO> statScore() {
        return statService.statStudentScore();
    }

    /**
     * 综合业务：完整业务链演示（批量评审一个班的所有提交）
     * 一个外层事务包裹整个批量操作，任一失败全部回滚
     */
    @Transactional(rollbackFor = Exception.class)
    public void batchReviewByTask(Long taskId, Long teacherId,
                                  List<ReviewDTO> reviewList) {
        // 注意：这里调用本类的 reviewTask 会自调用失效！
        // 必须通过代理对象调用
        TaskBusinessService self = ctx.getBean(TaskBusinessService.class);
        for (ReviewDTO dto : reviewList) {
            // 通过代理调用，事务才会生效
            self.reviewTask(dto.getSubmissionId(), teacherId,
                            dto.getScore(), dto.getComment());
        }
    }
}

public List<SubmissionVO> query(SubmissionQueryDTO dto) {
    QueryWrapper<SubmissionVO> w = new QueryWrapper<>();
    w.eq(StringUtils.hasText(dto.getStudentNo()), "s.student_no", dto.getStudentNo());
    w.like(StringUtils.hasText(dto.getTaskTitle()), "t.title", dto.getTaskTitle());
    w.eq(dto.getStatus() != null, "sub.status", dto.getStatus());
    w.ge(dto.getStartTime() != null, "sub.submit_time", dto.getStartTime());
    w.le(dto.getEndTime() != null, "sub.submit_time", dto.getEndTime());
    if (StringUtils.hasText(dto.getStudentName())) {
        w.and(x -> x.like("s.name", dto.getStudentName())
                    .or().like("s.name", "李四"));
    }
    w.orderByDesc("sub.submit_time");
    return submissionMapper.selectSubmissionList(w);
}

Step 3：添加事务

任务：在 reviewTask 方法上加 @Transactional，确保插入评审记录 + 更新提交状态原子性。

@Transactional(rollbackFor = Exception.class, propagation = Propagation.REQUIRED)
public void reviewTask(Long submissionId, Long teacherId,
                       BigDecimal score, String comment) {
    Review review = new Review();
    review.setSubmissionId(submissionId);
    review.setTeacherId(teacherId);
    review.setScore(score);
    review.setComment(comment);
    review.setReviewTime(LocalDateTime.now());
    reviewMapper.insert(review);

    Submission sub = submissionMapper.selectById(submissionId);
    SubmissionStateMachine.check(
        SubmissionStatus.of(sub.getStatus()),
        SubmissionStatus.REVIEWED);
    sub.setStatus(SubmissionStatus.REVIEWED.getCode());
    submissionMapper.updateById(sub);
}

隔离级别 脏读 不可重复读 幻读

4.3 分布式事务简介

  • 本地事务：单个数据源，Spring @Transactional 即可。
  • 分布式事务：多数据源 / 微服务，需要 Seata、XA、TCC、Saga 等方案。
  • 本课不展开，但要知道 @Transactional 只能管一个数据源。
