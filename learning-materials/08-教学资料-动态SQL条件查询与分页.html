二、知识点详解

K8-1 MyBatis 动态 SQL 标签

1.1 定义

动态 SQL 是 MyBatis 的核心特性之一：允许在 XML 映射文件中通过 XML 标签（如 <if>、<where>、<foreach>、<choose>、<set> 等）根据传入参数的值动态拼接 SQL 字符串，从而生成不同的最终 SQL。

1.2 原理

MyBatis 在启动时会解析 XML 映射文件，把每条 <select>/<update> 语句编译成一棵 SqlNode 树。执行时：

  1. 根据入参遍历 SqlNode 树，每个标签节点判断自身条件是否成立；
  2. 成立则把内部 SQL 片段拼入 DynamicContext；
  3. 不成立则跳过；
  4. 最终生成一条完整的 SQL 字符串，再交给 JDBC 执行。

整个过程相当于在运行时"按需裁剪"SQL，避免硬编码多种查询分支。

1.3 问题 / 场景

场景一：多条件查询，条件可空

任务查询接口允许只传 status、或只传 projectId、或同时传多个条件。如果用传统字符串拼接，要写一堆 if (!"".equals(status)) { sql += " AND status=" + status; }，极易出错（多一个 AND、少一个空格都会报错）。

场景二：IN 查询，集合长度不固定

按多个状态查询任务：WHERE status IN (1, 2, 3)。集合长度运行时才确定，无法直接写死。

场景三：更新字段可空

更新任务时只想改 title，不想把 status 也覆盖。需要动态生成 SET title = ? 而不是 SET title = ?, status = ?。

步骤 3：动态 SQL XML 映射文件 TaskMapper.xml

<?xml version="1.0" encoding="UTF-8" ?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="com.ctts.mapper.TaskMapper">

    <!-- 多条件查询：项目ID、状态、标题模糊、优先级范围、状态集合 -->
    <select id="selectByConditions" resultType="com.ctts.entity.Task">
        SELECT id, title, description, project_id, assignee_id,
               status, priority, create_time, update_time
          FROM task
         <where>
            deleted = 0
            <if test="projectId != null">
                AND project_id = #{projectId}
            </if>
            <if test="status != null">
                AND status = #{status}
            </if>
            <if test="title != null and title != ''">
                AND title LIKE CONCAT('%', #{title}, '%')
            </if>
            <if test="minPriority != null">
                AND priority &gt;= #{minPriority}
            </if>
            <if test="statusList != null and statusList.size() > 0">
                AND status IN
                <foreach collection="statusList" item="st" open="(" separator="," close=")">
                    #{st}
                </foreach>
            </if>
         </where>
         ORDER BY create_time DESC
    </select>

    <!-- 动态更新：只更新非空字段 -->
    <update id="updateSelective">
        UPDATE task
        <set>
            <if test="title != null and title != ''">
                title = #{title},
            </if>
            <if test="status != null">
                status = #{status},
            </if>
            <if test="assigneeId != null">
                assignee_id = #{assigneeId},
            </if>
            <if test="priority != null">
                priority = #{priority},
            </if>
        </set>
        WHERE id = #{id} AND deleted = 0
    </update>

    <!-- choose-when-otherwise：优先级动态排序 -->
    <select id="selectWithOrder" resultType="com.ctts.entity.Task">
        SELECT * FROM task
        <where>
            deleted = 0
            <choose>
                <when test="orderField == 'createTime'">
                    ORDER BY create_time
                    <if test="asc">ASC</if>
                    <if test="!asc">DESC</if>
                </when>
                <when test="orderField == 'priority'">
                    ORDER BY priority DESC
                </when>
                <otherwise>
                    ORDER BY id DESC
                </otherwise>
            </choose>
        </where>
    </select>

</mapper>

1.6 易错点

编号 易错点 后果 正确做法
1 <if> 中 status != null 写成 status != '' 对数字判断 数字为 0 时被误判为空字符串等价 数字类型只判 != null；字符串类型同时判 != ''
2 <if> 中 AND 写成小写 and MyBatis 默认不识别，可能拼出非法 SQL 标签内统一大写 AND / OR
3 <where> 内首个条件硬编码 WHERE 关键字 SQL 出现 WHERE WHERE ... <where> 标签会自动加 WHERE，不要再手写
4 <foreach> 的 collection 写错 报错 There is no getter for property named 'xxx' 用 @Param 指定参数名，或默认 list/array
5 XML 中 < > 直接写 XML 解析器当成标签开始/结束 用 &lt; &gt; 或 <![CDATA[ ... ]]> 包裹
6 <set> 标签内末尾多逗号 SQL 报语法错误 <set> 会自动去掉末尾多余逗号，但不要依赖它兜底，注意书写规范
7 <choose> 内多个 <when> 条件同时成立 只执行第一个匹配的 <when> 理解为 Java 的 switch-case，最多走一个分支

1.7 小结

  • 动态 SQL 通过 XML 标签运行时裁剪SQL，避免硬编码；
  • <if> 做条件判断、<where> 处理 AND 前缀、<foreach> 遍历集合；
  • <choose>/<when>/<otherwise> 是 if-else if-else 结构；
  • <set> 用于动态更新，自动去末尾逗号；
  • XML 中比较符号要转义或用 CDATA。

K8-2 QueryWrapper 条件构造器

2.1 定义

QueryWrapper 是 MyBatis-Plus 提供的条件构造器，继承自 AbstractWrapper。它以链式调用的方式构造 WHERE 条件，最终由 MyBatis-Plus 自动生成对应 SQL，无需手写 XML。

2.2 原理

QueryWrapper 内部维护一个 MergeSegments 对象，每次调用 eq / like / in 等方法时，会把条件片段追加到内部列表中。执行 SQL 时：

  1. MyBatis-Plus 拦截 BaseMapper.selectList / selectPage 等方法；
  2. 从参数中提取 Wrapper；
  3. 调用 getCustomSqlSegment() 生成 WHERE ... ORDER BY ... SQL 片段；
  4. 与原始 SQL 拼接，绑定参数后执行。

2.3 问题 / 场景

场景： 业务层需要按多种条件组合查询，但不想为每种组合写一个 XML。例如：

  • 查"项目1下、状态为进行中"的任务；
  • 查"标题包含'需求'、优先级≥2"的任务；
  • 查"指派给某用户、状态IN(1,2)"的任务。

使用 QueryWrapper 可以用 5 行代码完成，比 XML 更轻量。

2.4 完整示例代码

package com.ctts.service.impl;

import com.baomidou.mybatisplus.core.conditions.query.QueryWrapper;
import com.ctts.entity.Task;
import com.ctts.mapper.TaskMapper;
import com.ctts.service.TaskService;
import org.springframework.stereotype.Service;
import java.util.List;

@Service
public class TaskQueryWrapperDemo {

    private final TaskMapper taskMapper;
    public TaskQueryWrapperDemo(TaskMapper taskMapper) {
        this.taskMapper = taskMapper;
    }

    /** 演示 eq / like / in / between / ge / le / orderByDesc 链式调用 */
    public List<Task> queryByWrapper(Long projectId, Integer status,
                                     String title, Integer minPri, Integer maxPri) {
        QueryWrapper<Task> wrapper = new QueryWrapper<>();
        wrapper.eq(projectId != null, "project_id", projectId)        // eq(condition, column, val)
               .eq(status != null, "status", status)
               .like(title != null && !title.isEmpty(), "title", title)
               .ge(minPri != null, "priority", minPri)
               .le(maxPri != null, "priority", maxPri)
               .orderByDesc("create_time")
               .orderByAsc("id");
        return taskMapper.selectList(wrapper);
    }

    /** IN 查询：状态在指定集合内 */
    public List<Task> queryByStatusIn(List<Integer> statusList) {
        QueryWrapper<Task> wrapper = new QueryWrapper<>();
        wrapper.in(statusList != null && !statusList.isEmpty(),
                   "status", statusList.toArray())
               .orderByDesc("create_time");
        return taskMapper.selectList(wrapper);
    }

    /** BETWEEN 查询：创建时间在区间内 */
    public List<Task> queryByCreateTimeRange(String start, String end) {
        QueryWrapper<Task> wrapper = new QueryWrapper<>();
        wrapper.between("create_time", start, end)
               .eq("deleted", 0);
        return taskMapper.selectList(wrapper);
    }

    /** 条件为 false 时不拼接：演示 condition 参数 */
    public List<Task> queryWithConditionFlag(boolean onlyHighPriority) {
        QueryWrapper<Task> wrapper = new QueryWrapper<>();
        wrapper.eq(true, "deleted", 0)
               .ge(onlyHighPriority, "priority", 3);  // onlyHighPriority为false时此条件不拼接
        return taskMapper.selectList(wrapper);
    }
}

2.6 易错点

编号 易错点 后果 正确做法
1 列名写字符串"project_id"打错 SQL 报"未知列" 字段名要严格对应数据库列名；或用 LambdaQueryWrapper 避免此问题
2 eq(condition, column, val) 第一个参数漏写 永远拼接条件，与"可空"语义相悖 用三参重载，第一参控制是否拼接
3 like 第三个参数自带 % 实际生成 LIKE %需求% 与字符串内的 % 叠加 like 会自动加两侧 %，调用方只传原文
4 in 传入空集合 生成 IN () 报语法错 用三参重载 + condition 判断非空
5 链式调用漏写 . 编译错或条件丢失 每次返回 this，必须用 . 续接
6 查询条件包含逻辑删除字段 未删除的任务被过滤掉看不到 MyBatis-Plus 已自动加 deleted = 0，无需重复写

2.7 小结

  • QueryWrapper 用链式调用构造 WHERE，比 XML 轻量；
  • eq/ne/gt/ge/lt/le/like/in/between 是最常用方法；
  • 三参重载 eq(condition, col, val) 实现"条件可空"；
  • 列名是字符串，编译期不检查，是主要风险点。

K8-3 LambdaQueryWrapper 类型安全构造器

3.1 定义

LambdaQueryWrapper<T> 是 QueryWrapper 的类型安全版本。它通过 方法引用（如 Task::getTitle）替代字符串列名，让字段名在编译期就被检查，重构实体类时不会漏改。

3.2 原理

LambdaQueryWrapper 内部通过 LambdaUtils.extract(SFunction<T, ?>) 解析方法引用：

  1. 拿到方法引用对应的 SerializedLambda 对象；
  2. 从 implMethodName 推断属性名（getTitle → title）；
  3. 通过实体类的 @TableField 注解或驼峰转下划线得到数据库列名 title。

整个过程在运行时完成，但因为是方法引用，编译期就会检查 Task 是否有 getTitle 方法，字段重命名时 IDE 会同步提示。

3.3 问题 / 场景

场景： 项目进入重构期，Task.title 字段被重命名为 taskName。使用字符串 "title" 的 QueryWrapper 在运行时才会报"未知列"，而 LambdaQueryWrapper 在编译期 IDE 就标红提示。

3.4 完整示例代码

package com.ctts.service.impl;

import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.ctts.entity.Task;
import com.ctts.mapper.TaskMapper;
import org.springframework.stereotype.Service;
import java.util.List;

@Service
public class TaskLambdaDemo {

    private final TaskMapper taskMapper;
    public TaskLambdaDemo(TaskMapper taskMapper) {
        this.taskMapper = taskMapper;
    }

    /** 类型安全的多条件查询 */
    public List<Task> queryByLambda(Long projectId, Integer status, String title) {
        LambdaQueryWrapper<Task> wrapper = new LambdaQueryWrapper<>();
        wrapper.eq(projectId != null, Task::getProjectId, projectId)
               .eq(status != null, Task::getStatus, status)
               .like(title != null && !title.isEmpty(), Task::getTitle, title)
               .orderByDesc(Task::getCreateTime)
               .orderByAsc(Task::getId);
        return taskMapper.selectList(wrapper);
    }

    /** between + in 组合 */
    public List<Task> queryByPriorityRangeAndStatus(Integer minPri, Integer maxPri,
                                                    List<Integer> statusList) {
        LambdaQueryWrapper<Task> wrapper = new LambdaQueryWrapper<>();
        wrapper.between(minPri != null && maxPri != null,
                        Task::getPriority, minPri, maxPri)
               .in(statusList != null && !statusList.isEmpty(),
                   Task::getStatus, statusList)
               .orderByDesc(Task::getPriority);
        return taskMapper.selectList(wrapper);
    }

    /** select 选择字段，避免大字段（如 description）回填 */
    public List<Task> queryLite(Long projectId) {
        LambdaQueryWrapper<Task> wrapper = new LambdaQueryWrapper<>();
        wrapper.select(Task::getId, Task::getTitle, Task::getStatus, Task::getPriority)
               .eq(Task::getProjectId, projectId);
        return taskMapper.selectList(wrapper);
    }
}

K8-4 分页查询

4.1 定义

MyBatis-Plus 通过 MybatisPlusInterceptor 拦截器 + PaginationInnerInterceptor 分页插件，自动把原始 SQL 改写为分页 SQL（MySQL 下追加 LIMIT offset, size），并执行一条 COUNT(*) 查询返回总数，无需手写两条 SQL。

4.2 原理

用户调用 taskMapper.selectPage(page, wrapper)
            │
            ▼
   MybatisPlusInterceptor 拦截 Executor.query
            │
            ├─── 1. 解析 Page 参数 (current=1, size=10)
            │
            ├─── 2. 改写原始 SQL:
            │     原SQL: SELECT * FROM task WHERE ...
            │     改写:  SELECT * FROM task WHERE ... LIMIT 0, 10
            │
            ├─── 3. 自动执行 COUNT:
            │     SELECT COUNT(*) FROM task WHERE ...
            │
            ├─── 4. 把 records 填入 Page.records
            │       把 total  填入 Page.total
            │       计算 pages = ceil(total/size)
            │
            ▼
   返回 IPage<Task> (含 records + total + size + current + pages)

4.3 问题 / 场景

场景： 任务表中有 1 万条数据，前端要分页展示，每页 10 条。若不分页，一次返回 1 万条记录会：

  • 拖慢数据库（IO 与内存压力）；
  • 占满 JVM 堆（OOM 风险）；
  • 网络传输几秒，前端体验差。

需要分页插件自动改写 SQL，无需开发者手写 LIMIT 与 COUNT。

4.4 完整示例代码

步骤 1：分页插件配置类

package com.ctts.config;

import com.baomidou.mybatisplus.annotation.DbType;
import com.baomidou.mybatisplus.extension.plugins.MybatisPlusInterceptor;
import com.baomidou.mybatisplus.extension.plugins.inner.PaginationInnerInterceptor;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class MyBatisPlusConfig {

    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        // 添加分页内部拦截器，指定数据库类型为 MySQL
        PaginationInnerInterceptor pageInterceptor = new PaginationInnerInterceptor(DbType.MYSQL);
        pageInterceptor.setMaxLimit(500L);          // 单页最大 500 条，防止恶意请求
        pageInterceptor.setOverflow(false);         // 页码越界不自动回到第 1 页
        interceptor.addInnerInterceptor(pageInterceptor);
        return interceptor;
    }
}

步骤 2：Service 层

package com.ctts.service;

import com.baomidou.mybatisplus.core.metadata.IPage;
import com.ctts.dto.TaskQueryDto;
import com.ctts.entity.Task;

public interface TaskService {
    /** 多条件分页查询任务 */
    IPage<Task> queryPage(TaskQueryDto dto);
}
package com.ctts.service.impl;

import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.baomidou.mybatisplus.core.metadata.IPage;
import com.baomidou.mybatisplus.extension.plugins.pagination.Page;
import com.ctts.dto.TaskQueryDto;
import com.ctts.entity.Task;
import com.ctts.mapper.TaskMapper;
import com.ctts.service.TaskService;
import org.springframework.stereotype.Service;
import org.springframework.util.StringUtils;

@Service
public class TaskServiceImpl implements TaskService {

    private final TaskMapper taskMapper;
    public TaskServiceImpl(TaskMapper taskMapper) {
        this.taskMapper = taskMapper;
    }

    @Override
    public IPage<Task> queryPage(TaskQueryDto dto) {
        // 1. 构建 Page 对象：当前页、每页大小
        Page<Task> page = new Page<>(dto.getPage(), dto.getSize());

        // 2. 构造条件
        LambdaQueryWrapper<Task> wrapper = new LambdaQueryWrapper<>();
        wrapper.eq(dto.getProjectId() != null, Task::getProjectId, dto.getProjectId())
               .eq(dto.getStatus() != null, Task::getStatus, dto.getStatus())
               .like(StringUtils.hasText(dto.getTitle()), Task::getTitle, dto.getTitle())
               .ge(dto.getMinPriority() != null, Task::getPriority, dto.getMinPriority())
               .orderByDesc(Task::getCreateTime);

        // 3. 执行分页查询
        return taskMapper.selectPage(page, wrapper);
    }
}

4.6 易错点

编号 易错点 后果 正确做法
1 忘记配置 MybatisPlusInterceptor selectPage 不分页，返回全部数据 必须配置分页拦截器 Bean
2 Page 当前页传 0 或负数 报错或查不到数据 前端 page 从 1 开始；后端可校验 Math.max(page, 1)
3 PaginationInnerInterceptor 未指定 DbType 默认走 MySQL，但其他数据库 SQL 错 显式指定 DbType.MYSQL 等
4 自定义 XML SQL + selectPage 不分页 拦截器拦截不到，需在 SQL 末尾加 ${page} 或用 IPage 参数 自定义查询分页：方法第一个参数为 IPage，XML 写普通 SQL 即可
5 不限制 size 上限 恶意请求 size=100000 拖垮数据库 配置 pageInterceptor.setMaxLimit(500L)
6 越界页码返回空列表 用户感到困惑 设置 setOverflow(true) 自动回首页，或返回友好提示

4.7 小结

  • 分页插件通过拦截器机制自动改写 SQL，无需手写 LIMIT；
  • Page<T> 对象封装 current/size，IPage<T> 返回 records/total/pages；
  • 必须配置 MybatisPlusInterceptor + PaginationInnerInterceptor Bean；
  • 单页上限要限制，防止恶意请求。

K8-5 排序

5.1 定义

排序是查询结果按某字段升序或降序排列的能力。MyBatis-Plus 提供 orderByAsc / orderByDesc 方法，在 QueryWrapper 与 LambdaQueryWrapper 中均可使用。

5.2 原理

orderByAsc(col) 在内部 sqlSegment 末尾追加 ORDER BY col ASC，orderByDesc 同理。多个排序字段按调用顺序追加，生成 ORDER BY a DESC, b ASC。

5.3 问题 / 场景

场景： 任务列表需要"按创建时间倒序"，同一天的再"按优先级倒序"，确保最新最高优先级的任务在最上面。

5.4 完整示例代码

// 字符串列名方式
QueryWrapper<Task> w1 = new QueryWrapper<>();
w1.orderByDesc("create_time")
  .orderByDesc("priority")
  .orderByAsc("id");

// Lambda 方式（推荐）
LambdaQueryWrapper<Task> w2 = new LambdaQueryWrapper<>();
w2.orderByDesc(Task::getCreateTime)
  .orderByDesc(Task::getPriority)
  .orderByAsc(Task::getId);

// 条件排序：参数控制升降序
public List<Task> queryByOrder(String field, boolean asc) {
    LambdaQueryWrapper<Task> w = new LambdaQueryWrapper<>();
    if ("createTime".equals(field)) {
        if (asc) w.orderByAsc(Task::getCreateTime);
        else     w.orderByDesc(Task::getCreateTime);
    } else if ("priority".equals(field)) {
        if (asc) w.orderByAsc(Task::getPriority);
        else     w.orderByDesc(Task::getPriority);
    } else {
        w.orderByDesc(Task::getId);   // 默认按 ID 倒序
    }
    return taskMapper.selectList(w);
}

生成 SQL：

SELECT * FROM task
 WHERE deleted = 0
 ORDER BY create_time DESC, priority DESC, id ASC

5.6 易错点

编号 易错点 后果 正确做法
1 排序字段未建索引 大数据量下慢查询 高频排序字段加索引
2 多次调用 orderByDesc 顺序乱 排序结果不符合预期 调用顺序就是 SQL 中 ORDER BY 顺序
3 用字符串拼接构造字段名 SQL 注入风险 用白名单或 Lambda
4 排序字段含 NULL 值 MySQL 默认 NULL 在前 用 isNull 条件或 ORDER BY col IS NULL, col DESC

5.7 小结

  • orderByAsc / orderByDesc 在 wrapper 末尾追加 ORDER BY；
  • 多字段排序按调用顺序生成；
  • 推荐用 Lambda 方式类型安全；
  • 排序字段建议加索引提升性能。

四、拓展阅读

4.1 QueryWrapper 与 LambdaQueryWrapper 选型建议

维度 QueryWrapper LambdaQueryWrapper
类型安全 否（字符串列名） 是（方法引用）
重构友好 否 是
性能 略快（无 Lambda 解析） 略慢（首次解析有反射开销，但有缓存）
动态表名 支持 不支持
复杂 SQL 灵活 略受限

结论： 99% 业务场景用 LambdaQueryWrapper；只有涉及动态表名、复杂子查询时才用 QueryWrapper。

4.2 分页插件原理深入

  • 拦截器基于 MyBatis 的 Interceptor 接口，签名 @Intercepts({@Signature(type=StatementHandler.class, method="prepare", args={Connection.class, Integer.class})})；
  • 通过反射拿到 BoundSql，再通过 JsqlParser 解析并改写 SQL；
  • MySQL 下追加 LIMIT ?, ?，Oracle 用 ROWNUM，PostgreSQL 用 LIMIT ... OFFSET ...；
  • COUNT 语句是去除原 SQL 的 select 字段、order by 后生成的 SELECT COUNT(*) FROM (...) t。

4.3 性能优化提示

  1. 深分页问题： LIMIT 100000, 10 会扫描 100010 行，应用"游标分页"或"延迟关联"优化；
  2. COUNT 慢查询： 大表 COUNT 慢时，可禁用 count（page.setSearchCount(false)），或用缓存估算；
  3. 索引覆盖： 高频查询字段与排序字段组合建联合索引，例如 idx_project_status_create(project_id, status, create_time)。
