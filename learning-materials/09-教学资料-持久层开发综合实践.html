步骤 1：建表（CREATE TABLE SQL）

1.1 task 表（任务表）

-- ============================================
-- 任务表：存储实训项目下的具体任务
-- ============================================
DROP TABLE IF EXISTS `task`;
CREATE TABLE `task` (
  `id`          BIGINT       NOT NULL AUTO_INCREMENT COMMENT '任务主键ID',
  `project_id`  BIGINT       NOT NULL                COMMENT '所属项目ID（外键→training_project.id）',
  `title`       VARCHAR(200) NOT NULL                COMMENT '任务标题',
  `description` TEXT                                 COMMENT '任务描述',
  `priority`    TINYINT      NOT NULL DEFAULT 2      COMMENT '优先级：1高 2中 3低',
  `status`      TINYINT      NOT NULL DEFAULT 0      COMMENT '状态：0未开始 1进行中 2已完成 3已取消',
  `start_time`  DATETIME                             COMMENT '开始时间',
  `end_time`    DATETIME                             COMMENT '截止时间',
  `create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `deleted`     TINYINT      NOT NULL DEFAULT 0      COMMENT '逻辑删除：0未删除 1已删除',
  PRIMARY KEY (`id`),
  KEY `idx_project_id` (`project_id`),
  KEY `idx_status`     (`status`),
  CONSTRAINT `fk_task_project` FOREIGN KEY (`project_id`)
    REFERENCES `training_project` (`id`) ON DELETE RESTRICT ON UPDATE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='任务表';

步骤 2：建实体类

实体类统一放在 com.ctts.entity 包下。

2.1 Task 实体类

package com.ctts.entity;

import com.baomidou.mybatisplus.annotation.*;
import lombok.Data;
import java.time.LocalDateTime;

/**
 * 任务实体类
 * 对应数据库表 task
 */
@Data
@TableName("task")
public class Task {

    @TableId(type = IdType.AUTO)
    private Long id;

    /** 所属项目ID */
    private Long projectId;

    /** 任务标题 */
    private String title;

    /** 任务描述 */
    private String description;

    /** 优先级：1高 2中 3低 */
    private Integer priority;

    /** 状态：0未开始 1进行中 2已完成 3已取消 */
    private Integer status;

    /** 开始时间 */
    private LocalDateTime startTime;

    /** 截止时间 */
    private LocalDateTime endTime;

    /** 创建时间（插入时自动填充） */
    @TableField(fill = FieldFill.INSERT)
    private LocalDateTime createTime;

    /** 更新时间（插入和更新时自动填充） */
    @TableField(fill = FieldFill.INSERT_UPDATE)
    private LocalDateTime updateTime;

    /** 逻辑删除标志 */
    @TableLogic
    @TableField(select = false)
    private Integer deleted;
}

2.3 TaskReview 实体类

package com.ctts.entity;

import com.baomidou.mybatisplus.annotation.*;
import lombok.Data;
import java.math.BigDecimal;
import java.time.LocalDateTime;

/**
 * 任务评审实体类
 * 对应数据库表 task_review
 */
@Data
@TableName("task_review")
public class TaskReview {

    @TableId(type = IdType.AUTO)
    private Long id;

    /** 提交ID */
    private Long submissionId;

    /** 评审教师ID */
    private Long reviewerId;

    /** 评分（0~100） */
    private BigDecimal score;

    /** 评审意见 */
    private String comment;

    /** 评审状态：0待评审 1已评审 2已申诉 */
    private Integer reviewStatus;

    /** 评审时间 */
    private LocalDateTime reviewTime;

    @TableField(fill = FieldFill.INSERT)
    private LocalDateTime createTime;

    @TableField(fill = FieldFill.INSERT_UPDATE)
    private LocalDateTime updateTime;

    @TableLogic
    @TableField(select = false)
    private Integer deleted;
}

说明：

  • @TableId(type = IdType.AUTO) 表示主键自增；
  • @TableField(fill = FieldFill.INSERT) 配合 MetaObjectHandler 实现自动填充；
  • @TableLogic 标记逻辑删除字段，MyBatis-Plus 会自动在查询时追加 WHERE deleted = 0；
  • @TableField(select = false) 表示默认查询时不返回该字段；
  • 数据库下划线命名（project_id）会自动映射为驼峰（projectId），无需手动写 @TableField("project_id")（前提是开启了 map-underscore-to-camel-case，MyBatis-Plus 默认开启）。

预期结果：项目编译通过，无报错。三个实体类字段与数据库表字段一一对应。

步骤 4：编写条件构造器与分页查询

本步骤演示在 Service / 测试类中如何用 条件构造器（QueryWrapper / LambdaQueryWrapper） 和 分页对象（Page） 调用 BaseMapper 提供的方法，无需写 XML。

4.1 QueryWrapper 多条件查询

// 场景：查询项目1下、状态为进行中、标题含"接口"的任务
QueryWrapper<Task> wrapper = new QueryWrapper<>();
wrapper.eq("project_id", 1L)
       .eq("status", 1)
       .like("title", "接口")
       .orderByDesc("create_time");
List<Task> tasks = taskMapper.selectList(wrapper);

4.2 LambdaQueryWrapper 类型安全查询

// 场景：同上，但用 Lambda 引用字段名，避免硬编码字符串
LambdaQueryWrapper<Task> wrapper = new LambdaQueryWrapper<Task>()
        .eq(Task::getProjectId, 1L)
        .eq(Task::getStatus, 1)
        .like(Task::getTitle, "接口")
        .orderByDesc(Task::getCreateTime);
List<Task> tasks = taskMapper.selectList(wrapper);

4.3 分页查询

// 场景：分页查询任务，第1页，每页10条
Page<Task> page = new Page<>(1, 10);
LambdaQueryWrapper<Task> wrapper = new LambdaQueryWrapper<Task>()
        .eq(Task::getStatus, 1)
        .orderByDesc(Task::getCreateTime);
IPage<Task> result = taskMapper.selectPage(page, wrapper);

// 结果
result.getRecords();   // 当前页数据 List<Task>
result.getTotal();     // 总记录数
result.getPages();     // 总页数
result.getCurrent();   // 当前页码
result.getSize();      // 每页条数

前提：必须在配置类中注册分页插件，否则 selectPage 不会生效（会查出全部数据）。

@Configuration
public class MybatisPlusConfig {
    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        interceptor.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));
        return interceptor;
    }
}

预期结果：调用 selectList(wrapper) 返回符合条件的任务列表；调用 selectPage 返回分页对象，getRecords() 大小不超过每页条数，getTotal() 等于满足条件的总记录数。

步骤 5：编写 XML 映射文件

XML 文件统一放在 src/main/resources/mapper/ 目录下。

5.1 TaskMapper.xml

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="com.ctts.mapper.TaskMapper">

    <!-- 通用结果映射 -->
    <resultMap id="TaskResultMap" type="com.ctts.entity.Task">
        <id     column="id"          property="id"/>
        <result column="project_id"  property="projectId"/>
        <result column="title"       property="title"/>
        <result column="description" property="description"/>
        <result column="priority"    property="priority"/>
        <result column="status"      property="status"/>
        <result column="start_time"  property="startTime"/>
        <result column="end_time"    property="endTime"/>
        <result column="create_time" property="createTime"/>
        <result column="update_time" property="updateTime"/>
    </resultMap>

    <!-- 按项目ID查询 -->

四、综合示例：多表关联查询剖析

本节聚焦本次课的"压轴题"——查询某学生的所有提交及对应任务信息，把 resultMap 嵌套映射讲透。

4.1 业务需求

学生在 CTTS 个人中心查看"我的提交"页面，需要展示：

列 来源字段 说明
提交ID task_submission.id 主键
任务标题 task.title 来自 task 表
任务截止时间 task.end_time 来自 task 表
提交内容 task_submission.content 本表
附件 task_submission.file_url 本表
提交状态 task_submission.status 本表
提交时间 task_submission.submit_time 本表

一条提交对应一条任务，是典型的"多对一"关系，用 <association> 嵌套映射。

4.2 SQL 分析

SELECT s.id, s.task_id, s.student_id, s.content, s.file_url,
       s.status, s.submit_time, s.create_time,
       t.id, t.project_id, t.title, t.priority, t.status, t.end_time
  FROM task_submission s
  INNER JOIN task t ON s.task_id = t.id
 WHERE s.student_id = ?
   AND s.deleted = 0
   AND t.deleted = 0
 ORDER BY s.submit_time DESC

为什么用 INNER JOIN 而不是 LEFT JOIN：业务上每条提交必然有对应任务（外键约束保证），用 INNER JOIN 性能略优。若存在"任务被删但提交还在"的脏数据，LEFT JOIN 能让提交仍被查出，但 task 字段为 null——这取决于业务取舍。

4.3 列别名与 resultMap 映射

JOIN 后两表都有 id、status 等同名字段，必须用别名区分，否则 MyBatis 无法正确映射：

图示 3：s.id AS s_id → submission.id

s.id AS s_id

→

submission.id s.status AS s_status

→

submission.status t.id AS t_id

→

submission.task.id t.status AS t_status

→

submission.task.status

resultMap 配置（关键部分）：

<resultMap id="SubmissionWithTaskMap" type="com.ctts.vo.TaskSubmissionVO">
    <id     column="s_id"          property="id"/>
    <result column="s_task_id"     property="taskId"/>
    <result column="s_status"      property="status"/>
    ...
    <association property="task" javaType="com.ctts.entity.Task">
        <id     column="t_id"      property="id"/>
        <result column="t_title"   property="title"/>
        <result column="t_status"  property="status"/>
        ...
    </association>
</resultMap>

要点：

  • <association> 用于"一对一"或"多对一"关系嵌套；
  • property 是外层 VO 中的属性名，javaType 是该属性的类型；
  • 内层用 <id> 和 <result> 映射关联对象的字段；
  • <id> 标签不仅是主键映射，还影响 MyBatis 的对象聚合行为（同一主键的多行数据会被合并到一个对象）。

4.4 嵌套映射的两种写法对比

写法 说明 优劣
嵌套结果（association + JOIN） 一次 SQL 查出所有字段，在内存中组装对象 SQL 次数少，适合一对一；本次示例采用
嵌套查询（association + select） 先查主表，再对每行主表数据发一条子查询 SQL 次数多（N+1 问题），适合一对多且子查询可复用

本次示例用 JOIN + 嵌套结果，一条 SQL 搞定，避免 N+1 问题。

五、常见问题排查

# 问题现象 可能原因 解决方案
1 Invalid bound statement (not found) XML 未被加载 / namespace 写错 / 方法名对不上 检查 application.yml 的 mapper-locations；XML namespace 必须等于 Mapper 接口全限定名；<select id> 必须等于方法名
2 分页查询返回全部数据，total 等于当前页条数 未注册分页插件 在配置类中注册 MybatisPlusInterceptor + PaginationInnerInterceptor
3 多表 JOIN 后 task 对象字段全部为 null resultMap 未用别名，同名字段被覆盖 给 JOIN 两表的同名字段加别名（s_id/t_id），resultMap 用别名 column
4 <association> 嵌套对象为 null javaType 写错 / property 名与 VO 字段不一致 / column 写错 检查 javaType 全限定名；property 与 VO 字段名一致；column 与 SQL 别名一致
5 @TableLogic 失效，删除后数据被物理删除 未配置逻辑删除全局值 application.yml 中配置 logic-delete-field、logic-delete-value、logic-not-delete-value；或在字段上用 @TableLogic
6 逻辑删除字段 deleted 仍被查出来 未加 @TableField(select = false) 在 deleted 字段上加 @TableField(select = false)
7 @TableField(fill = FieldFill.INSERT) 不生效，createTime 为 null 未注册 MetaObjectHandler 写一个 MetaObjectHandler 实现类，重写 insertFill / updateFill
8 <if test="status != null and status != ''"> 数字字段判断异常 数字类型用了空字符串判断 数字类型只判 != null：<if test="status != null">
9 LambdaQueryWrapper 启动报错 Cannot find method 实体类未编译 / 字段名写错 重新编译；检查 Task::getProjectId 方法名与实体类字段一致
10 外键约束报错 Cannot add or update a child row 插入时外键值在父表不存在 先插入父表数据（training_project / task / sys_user），再插子表
11 @Select 注解 SQL 中文乱码 数据库或连接编码非 utf8mb4 数据库建库 CHARSET=utf8mb4；连接串加 useUnicode=true&characterEncoding=utf8
12 XML 中 < 号报错 The content of elements must consist of well-formed markup XML 解析器把 < 当标签起始 用 &lt; 或 <![CDATA[<]]> 包裹
