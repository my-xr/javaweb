二、知识点详解

知识点 K3-1：Spring Boot 特性

定义

Spring Boot 是基于 Spring 框架的二次封装框架，它通过自动配置、起步依赖、内嵌 Servlet 容器等特性，让开发者能够"开箱即用"地构建独立的、生产级的 Spring 应用，几乎不需要写 XML 配置。

一句话理解：Spring 是"发动机"，Spring Boot 是"整车"——发动机已经装好、油路接好、钥匙给你，你拧钥匙就能开走。

原理

Spring Boot 的四大核心特性：

特性 含义 解决的痛点
自动配置（Auto-Configuration） 根据classpath中存在的依赖，自动创建并注入常用的Bean 以前要在XML里手写大量<bean>配置
起步依赖（Starter） 把某一场景所需的多个依赖打包成一个starter 以前要自己挑版本、自己加十几个jar
内嵌Web容器（Embedded Container） 内嵌Tomcat/Jetty/Undertow，无需部署WAR包到外部容器 以前要装Tomcat、打包WAR、拷贝到webapps
约定优于配置（Convention over Configuration） 提供合理的默认值（默认端口8080、默认配置文件名等） 以前一切都要手动配置

Spring Boot 与 Spring 的关系：

图示 2：Spring Boot 与 Spring Framework 的层级关系
你的应用代码（CTTS）：Controller / Service / Mapper / Entity
Spring Boot：自动配置、Starter 起步依赖、内嵌 Servlet 容器
Spring Framework：IoC / AOP / MVC / Beans 等核心能力
底层运行环境：JDK、Maven 依赖、内嵌 Tomcat
Spring Boot 不是替代 Spring，而是在 Spring 之上提供“约定优于配置”的工程化封装。
  • Spring Boot 不是取代 Spring，而是简化 Spring 应用的搭建。
  • Spring Boot 底层就是 Spring，你在 Spring 里学的 @Component、@Service、@Autowired、@RequestMapping 全部照样能用。

自动配置的工作流程（简化版）：

启动类 @SpringBootApplication
        │
        ▼
@EnableAutoConfiguration  ← 开启自动配置
        │
        ▼
扫描 classpath 下的 META-INF/spring/...imports 文件
        │
        ▼
加载若干 AutoConfiguration 类（如 DataSourceAutoConfiguration）
        │
        ▼
通过 @ConditionalOnClass / @ConditionalOnMissingBean 判断
        │
        ▼
"如果你引入了MySQL驱动，又没自己配DataSource，我就帮你配一个"

问题 / 场景

问：没有 Spring Boot 之前，搭一个 Spring Web 项目有多麻烦？

  • 要手写 web.xml 注册 DispatcherServlet；
  • 要写 applicationContext.xml 配置组件扫描、数据源、事务管理器；
  • 要自己挑 Spring MVC、Jackson、Hibernate Validator 的版本并保证兼容；
  • 要安装外部 Tomcat，把项目打成 WAR 部署进去。 Spring Boot 把这些步骤都省掉了。

问：自动配置会不会"乱配"导致冲突？

  • 不会。自动配置类大量使用 @Conditional 系列注解，只有满足条件才生效；并且"用户自定义的 Bean 优先"，如果你自己配了一个 DataSource，Spring Boot 的自动配置会自动退让。

完整示例代码

最小可运行的 Spring Boot 应用（本节后续 K3-5 会展开）：

package com.ctts;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class CttsApplication {
    public static void main(String[] args) {
        SpringApplication.run(CttsApplication.class, args);
    }
}

易错点

  1. 把 Spring Boot 当成"新框架"：它本质是 Spring 的封装，Spring 的注解和原理仍然适用。
  2. 以为自动配置是"万能的"：自动配置只覆盖"约定场景"，定制化需求仍需自己写配置类。
  3. 认为内嵌 Tomcat 性能不如外部 Tomcat：内嵌 Tomcat 与外部 Tomcat 是同一份代码，性能无差异，部署方式不同而已。

小结

Spring Boot 通过自动配置 + 起步依赖 + 内嵌容器 + 约定优于配置四大特性，把 Spring 应用从"配置地狱"中解放出来。它不是新框架，而是 Spring 的"快捷启动器"。理解这四大特性，是后续一切 Spring Boot 开发的基础。

知识点 K3-2：Spring Boot 项目结构

定义

Spring Boot 项目结构 是指一个基于 Maven 的 Spring Boot 工程在文件系统中的标准目录组织方式。它遵循 Maven 的"约定目录结构"，并在其上增加 Spring Boot 的约定（如配置文件放 src/main/resources）。

原理

Maven 约定的标准目录结构：

图示 4：CTTS 标准项目目录结构
  • ctts/
    • pom.xml 项目对象模型文件：依赖与构建配置
    • src/main/java/com/ctts/
      • CttsApplication.java 启动类
      • controller/ 控制层，后续课程添加
      • service/ 业务层，后续课程添加
      • mapper/ 数据访问层，后续课程添加
      • entity/ 实体类，后续课程添加
      • common/ 通用工具，后续课程添加
    • src/main/resources/
      • application.yml 主配置文件
      • application-dev.yml 环境配置，可选
      • mapper/ MyBatis SQL 映射文件
      • static/ 静态资源，前后端分离项目一般少用
    • src/test/java/com/ctts/
      • CttsApplicationTests.java 测试类
    • target/ 编译输出目录，自动生成

各目录职责：

目录/文件 职责 是否必须
pom.xml Maven 项目对象模型，声明依赖与构建方式 必须
src/main/java 存放 Java 源代码 必须
src/main/resources 存放配置文件、静态资源、模板等 必须
application.yml Spring Boot 主配置文件 强烈建议
src/test/java 存放单元测试代码 建议
target/ 编译输出目录，由 Maven 自动生成，不要手动改 自动
src/main/resources/mapper/ MyBatis 的 XML 映射文件 后续课程用

包结构约定（以 com.ctts 为根包）：

图示 5：com.ctts 根包与分层包职责

CttsApplication

启动类必须放在根包或父包上，保证组件扫描覆盖业务代码。

controller

接收 HTTP 请求，调用 Service，返回响应。

service / impl

承载业务逻辑，接口与实现分离。

mapper

访问数据库，执行 SQL 或 MyBatis 映射。

entity / dto / vo

Entity 对应表，DTO 接收入参，VO 返回给前端。

common / config

Result、异常、工具类和配置类等通用能力。

⚠️ 启动类位置很关键：@SpringBootApplication 默认扫描"启动类所在包及其子包"。所以启动类必须放在根包（com.ctts）下，否则 controller/service 等组件扫描不到。

问题 / 场景

问：为什么配置文件要叫 application.yml？叫别的名字不行吗？

  • Spring Boot 约定配置文件名为 application（扩展名可以是 .properties / .yml / .yaml）。叫别的名字默认不会被加载，需要在启动时额外指定。

问：target/ 目录为什么有时候没看到？

  • target/ 是 Maven 编译时生成的，只有在执行过 mvn compile 或运行过项目后才会出现。可以随时删除，重新编译会再生成。一般加入 .gitignore。

问：启动类能不能放在 com.ctts.controller 包下？

  • 不建议。如果启动类放在 com.ctts.controller，组件扫描默认只扫描 com.ctts.controller.*，service、mapper 等同级包不会被扫描，会导致依赖注入失败。

易错点

  1. 把启动类放错包：放在 com.ctts.controller 等子包下，导致其他包扫描不到。
  2. 在 target/ 里改代码：target/ 是编译输出，改了下次编译会被覆盖，源码在 src/main/java。
  3. 把配置文件放错位置：application.yml 必须在 src/main/resources/ 根下，放子目录里默认读不到。
  4. 包名不一致：创建项目时填的 Package 是 com.ctts，但后续手动建类时写成 com.ctts.controller（正确），写成 ctts.controller（错误，缺 com）就会扫描不到。

小结

Spring Boot 项目遵循 Maven 约定目录结构：src/main/java 放源码、src/main/resources 放配置、src/test/java 放测试、pom.xml 管依赖。启动类必须放在根包下以保证组件扫描覆盖整个项目。

知识点 K3-3：Maven 依赖管理

定义

Maven 是 Java 生态最主流的项目构建与依赖管理工具。它通过一个名为 pom.xml（Project Object Model）的 XML 文件描述项目的基本信息、依赖的第三方库以及构建方式，由 Maven 自动从远程仓库下载这些依赖到本地仓库。

一句话理解：Maven 就像"程序员的外卖 App"——你在 pom.xml 里点菜（声明依赖），Maven 自动去中央仓库取餐、缓存到你家冰箱（本地仓库），再端到你的项目里。

原理

Maven 三坐标（GAV）：每个依赖在 Maven 世界里通过三个坐标唯一定位。

坐标 含义 示例
groupId 组织/公司/项目的反向域名 com.ctts、org.springframework.boot
artifactId 模块/项目名 ctts、spring-boot-starter-web
version 版本号 3.2.5、1.0.0

三个坐标组合起来唯一确定一个 jar 包，例如：

org.springframework.boot : spring-boot-starter-web : 3.2.5

Maven 仓库体系：

图示 8：Maven 依赖查找顺序

pom.xml 声明依赖

项目需要某个 jar。

→

pom.xml 的核心结构：

<project ...>
    <!-- 1. 项目坐标 -->
    <groupId>com.ctts</groupId>
    <artifactId>ctts</artifactId>
    <version>1.0.0</version>
    <packaging>jar</packaging>   <!-- Spring Boot 默认打 jar -->

    <!-- 2. 父项目（Spring Boot 起步必备） -->
    <parent>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-parent</artifactId>
        <version>3.2.5</version>
        <relativePath/>
    </parent>

    <!-- 3. 属性（版本号集中管理） -->
    <properties>
        <java.version>17</java.version>
        <mybatis-plus.version>3.5.5</mybatis-plus.version>
    </properties>

    <!-- 4. 依赖 -->
    <dependencies>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-web</artifactId>
        </dependency>
        <!-- 更多依赖... -->
    </dependencies>

    <!-- 5. 构建 -->
    <build>
        <plugins>
            <plugin>
                <groupId>org.springframework.boot</groupId>
                <artifactId>spring-boot-maven-plugin</artifactId>
            </plugin>
        </plugins>
    </build>
</project>

Spring Boot 起步依赖（Starter）：

Starter 用途 包含的典型依赖
spring-boot-starter-web Web 开发 spring-webmvc、spring-web、tomcat、jackson
spring-boot-starter-test 测试 junit-jupiter、mockito、spring-test
spring-boot-starter-validation 参数校验 hibernate-validator
mybatis-plus-boot-starter MyBatis-Plus mybatis-plus、mybatis-spring

为什么不用写版本号？ —— 因为 spring-boot-starter-parent 已经在 <dependencyManagement> 中声明了所有官方推荐的版本，子项目继承后直接用即可。这就是"版本由父 POM 统一管理"的好处。

问题 / 场景

问：spring-boot-starter-web 和 spring-web 有什么区别？

  • spring-web 是 Spring Framework 的一个底层模块，只有基础类；
  • spring-boot-starter-web 是 Spring Boot 的"打包"，把 web 开发需要的所有依赖（spring-web、spring-webmvc、tomcat、jackson）一次性都引入了，这才是我们要用的。

问：为什么下载依赖特别慢？

  • Maven 默认从国外的中央仓库下载，国内访问慢。解决方法：在 ~/.m2/settings.xml 中配置阿里云镜像。

问：依赖冲突怎么办？

  • Maven 自动处理依赖冲突，原则是"最短路径优先"。如果 A 依赖 B 的 v1，C 依赖 B 的 v2，Maven 会选择路径更短的那个。IDEA 有 Maven 依赖图可视化工具帮助排查。

知识点 K3-4：配置文件 application.yml

定义

application.yml 是 Spring Boot 的主配置文件，位于 src/main/resources/ 下，用于配置服务器端口、数据源、日志、自定义属性等。它是 .properties 文件的替代方案，使用 YAML 格式，支持层级结构，更清晰。

原理

YAML 语法规则：

  1. 使用缩进表示层级关系（只能用空格，不能用 Tab）；
  2. 同级元素左侧缩进必须一致；
  3. 键值对用 : 分隔，冒号后必须有一个空格；
  4. # 表示注释。

对比 .properties 与 .yml：

# .properties 写法（扁平）
server.port=8080
server.servlet.context-path=/api
spring.datasource.url=jdbc:mysql://localhost:3306/ctts
spring.datasource.username=root
spring.datasource.password=123456
# .yml 写法（层级清晰）
server:
  port: 8080
  servlet:
    context-path: /api

spring:
  datasource:
    url: jdbc:mysql://localhost:3306/ctts
    username: root
    password: 123456

Spring Boot 常用配置项：

配置项 含义 默认值
server.port 服务器端口 8080
server.servlet.context-path 上下文路径（URL 前缀） /
spring.application.name 应用名 -
spring.datasource.url 数据库连接 URL -
spring.datasource.username 数据库用户名 -
spring.datasource.password 数据库密码 -
spring.datasource.driver-class-name 驱动类名 自动推断
mybatis-plus.mapper-locations Mapper XML 路径 -
logging.level.com.ctts 日志级别 INFO

配置文件加载顺序（高优先级覆盖低优先级）：

1. 命令行参数 --server.port=9090                (最高)
2. JNDI 属性
3. Java 系统属性
4. OS 环境变量
5. application-{profile}.yml（如 application-dev.yml）
6. application.yml                              (默认)
7. 默认值                                       (最低)

多环境配置：

application.yml          ← 主配置，通用内容 + 激活哪个环境
application-dev.yml      ← 开发环境
application-prod.yml     ← 生产环境

主配置中切换：

spring:
  profiles:
    active: dev   # 激活 dev 环境

问题 / 场景

问：8080 端口被占用了怎么办？

  • 改 server.port: 8081（或其他空闲端口），或者用命令行 java -jar ctts.jar --server.port=8081 临时指定。

问：context-path 是干什么的？

  • 它是所有接口的 URL 前缀。设置 server.servlet.context-path=/api 后，原本 localhost:8080/tasks 会变成 localhost:8080/api/tasks。前后端联调时统一前缀，便于反向代理。

问：.yml 和 .properties 哪个更好？

  • 都能用，但 .yml 层级结构清晰，适合复杂配置；.properties 简单扁平。Spring Boot 项目推荐 .yml。

问：YAML 里 : 后面没空格会怎样？

  • 报错！server:8080（错）会被识别成字符串 "server:8080"，而不是键值对。必须写成 server: 8080。

完整示例代码

CTTS 项目 application.yml（开发阶段完整版）：

图示 10：YAML 缩进表达层级关系
配置文本
server:
  port: 8080

    context-path: /api
spring:

层级含义
server.port服务端口 8080。
server.servlet.context-path统一访问前缀 /api。
spring.application.name应用名称 ctts。
spring.datasource数据库连接地址、用户名和密码。
YAML 的缩进就是包含关系，缩进错了，配置含义就会变。

易错点

  1. 用 Tab 缩进：YAML 不允许 Tab，必须用空格。IDEA 默认会把 Tab 转空格，但要从其他编辑器粘贴时要注意。
  2. 冒号后没空格：server:8080 错，server: 8080 对。
  3. 密码含特殊字符不引号：如密码是 p@ss#word，建议加引号 password: "p@ss#word"，避免被解析成引用。
  4. URL 中的 & 不转义：JDBC URL 里的 & 在 YAML 里其实可以直接写，但建议用引号包裹整个 URL，避免歧义。
  5. 改了配置不重启：默认配置文件改了必须重启项目才生效（devtools 可以热重载，但本节先不用）。
  6. 把 context-path 写成 contextPath：Spring Boot 配置项采用"烤串命名"（kebab-case），全小写连字符分隔。

小结

application.yml 是 Spring Boot 主配置文件，用 YAML 层级结构组织配置。常用配置：server.port 改端口、server.servlet.context-path 加前缀、spring.datasource.* 配数据源、mybatis-plus.* 配 MyBatis。注意缩进用空格、冒号后空格、配置项用烤串命名。

知识点 K3-5：启动类与 @SpringBootApplication

定义

启动类是 Spring Boot 应用的入口，包含 main 方法和 @SpringBootApplication 注解。它通过 SpringApplication.run() 启动 Spring 容器、初始化自动配置、启动内嵌 Tomcat。

原理

@SpringBootApplication 注解的"三合一"：

@SpringBootApplication 是一个组合注解，等价于：

@SpringBootConfiguration       // = @Configuration，标记配置类
@EnableAutoConfiguration       // 开启自动配置
@ComponentScan                 // 组件扫描（默认扫启动类所在包及子包）
public class CttsApplication { ... }
注解 作用
@SpringBootConfiguration 标记这是一个配置类，里面可以写 @Bean 方法
@EnableAutoConfiguration 开启自动配置机制，根据 classpath 自动装配 Bean
@ComponentScan 自动扫描 @Component、@Service、@Controller、@Repository 等注解

SpringApplication.run() 做了什么：

图示 11：SpringApplication.run 启动流程

创建 SpringApplication 实例。

推断应用类型：SERVLET / REACTIVE / NONE。

加载 spring.factories / AutoConfiguration.imports。

创建 ApplicationContext（Spring 容器）。

refresh() 容器：注册 Bean 定义，执行自动配置。

Web 应用启动内嵌 Tomcat。

发布 ApplicationStartedEvent / ApplicationReadyEvent。

控制台打印 banner，返回 ApplicationContext。

组件扫描范围：

启动类位置：com.ctts.CttsApplication

默认扫描范围：
✅ com.ctts                  （启动类所在包）
✅ com.ctts.controller       （子包）
✅ com.ctts.service          （子包）
✅ com.ctts.mapper           （子包）
✅ com.ctts.entity           （子包）
✅ com.ctts.common           （子包）

❌ com.example               （不会被扫描）
❌ org.springframework       （Spring自己的，由它自己处理）

问题 / 场景

问：启动类能不能改名，比如叫 App.java 而不是 CttsApplication.java？

  • 可以。类名随意，但约定叫 XxxApplication，便于识别。

问：@SpringBootApplication 后面能不能加参数？

  • 可以。例如 @SpringBootApplication(scanBasePackages = {"com.ctts", "com.common"}) 可以扩大扫描范围；exclude = {DataSourceAutoConfiguration.class} 可以排除某个自动配置。

问：为什么有时候启动报错 "No qualifying bean of type 'xxx'"？

  • 常见原因：① 该类没加 @Service/@Component 等注解；② 该类不在扫描包范围内；③ 启动类位置放错了。

问：能不能不用 @SpringBootApplication，而是拆开写三个注解？

  • 可以，效果完全等价。但 @SpringBootApplication 更简洁，是约定写法。

完整示例代码

CTTS 启动类 CttsApplication.java：

package com.ctts;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

/**
 * CTTS 校园实训任务管理系统 - 启动类
 *
 * @SpringBootApplication 是组合注解：
 *   - @SpringBootConfiguration
 *   - @EnableAutoConfiguration
 *   - @ComponentScan (扫描 com.ctts 及其子包)
 */
@SpringBootApplication
public class CttsApplication {

    public static void main(String[] args) {
        SpringApplication.run(CttsApplication.class, args);
    }
}

变体：排除自动配置（启动时不想用数据源自动配置，比如还没配数据库）：

package com.ctts;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.boot.autoconfigure.jdbc.DataSourceAutoConfiguration;

@SpringBootApplication(exclude = {DataSourceAutoConfiguration.class})
public class CttsApplication {
    public static void main(String[] args) {
        SpringApplication.run(CttsApplication.class, args);
    }
}

变体：扩大扫描范围：

@SpringBootApplication(scanBasePackages = {"com.ctts", "com.common.utils"})
public class CttsApplication { ... }

易错点

  1. 启动类不在根包：放在 com.ctts.controller.CttsApplication，导致 service、mapper 扫描不到。
  2. 忘记 @SpringBootApplication：只有 main 方法没有注解，启动后 Spring 容器是空的。
  3. main 方法签名错误：必须是 public static void main(String[] args)，少了 static 或参数类型写错都启动不了。
  4. 包名拼写错误：com.ctts 写成 com.cts 或 com.CTTS（Java 包名区分大小写，约定全小写）。
  5. 引入了不需要的自动配置：比如没配数据库但引入了 MyBatis-Plus，启动会报错，可以用 exclude 排除。

小结

启动类是 Spring Boot 应用的入口，通过 @SpringBootApplication（组合了 @SpringBootConfiguration + @EnableAutoConfiguration + @ComponentScan）开启自动配置与组件扫描，通过 SpringApplication.run() 启动容器和内嵌 Tomcat。启动类必须放在根包下，否则扫描不到其他组件。

问题 / 场景

问：Type 选 Maven 还是 Gradle？

问：Java 版本选 17 还是 21？

  • Spring Boot 3.x 最低 Java 17。本课程统一 Java 17（LTS 长期支持版）。

问：Packaging 选 Jar 还是 War？

  • 默认 Jar。内嵌 Tomcat 的 Spring Boot 应用直接 java -jar 运行；War 是部署到外部 Tomcat 用的，本课程不用。

易错点

  1. 路径含中文或空格：D:\我的项目\ctts 或 D:\Program Files\ctts 可能导致 Maven 编译异常，建议放纯英文路径。
  2. Spring Boot 版本选 SNAPSHOT：快照版不稳定，新手选正式版（不带 SNAPSHOT/M1/RC 后缀）。
  3. 勾依赖时勾了一堆用不上的：增加项目体积和下载时间，按需勾选。
  4. 忘记配 JDK：IDEA 没配 JDK 17 时，创建项目会报错或用 JDK 8 编译失败。File → Project Structure → Project SDK 配置。
  5. 改 pom.xml 不刷新 Maven：依赖不会自动生效，需要手动点 Maven 刷新按钮。
  6. 用 Eclipse 风格的目录：Spring Boot 项目就是标准 Maven 目录，不要建 WebContent、WEB-INF 这种老式目录。

小结

使用 IDEA 的 Spring Initializr 创建项目分 8 步：新建 → 选类型 → 填元数据 → 选依赖 → Finish → 补 pom → 写 yml → 启动验证。注意路径无中文、JDK 17+、版本选稳定版、改完 pom 要刷新 Maven。

五、本节小结与知识结构图

5.1 核心要点回顾

  1. Spring Boot = Spring + 自动配置 + 起步依赖 + 内嵌容器，让开发"开箱即用"。
  2. 项目结构遵循 Maven 约定：src/main/java（源码）+ src/main/resources（配置）+ src/test/java（测试）+ pom.xml（依赖）。
  3. Maven 三坐标：groupId + artifactId + version 唯一确定依赖；起步依赖把场景依赖打包。
  4. application.yml 用 YAML 层级结构组织配置；常用 server.port、context-path、datasource.*。
  5. 启动类 @SpringBootApplication 是三合一注解，必须放在根包保证扫描范围；SpringApplication.run() 启动容器与 Tomcat。
  6. IDEA 创建流程：File → New → Project → Spring Initializr → 填元数据 → 勾依赖 → Finish → 补 pom → 写 yml → 启动验证。
