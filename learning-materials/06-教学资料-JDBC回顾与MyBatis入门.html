二、知识点详解

K6-1 JDBC核心步骤

定义

JDBC（Java Database Connectivity） 是 Java 平台提供的一套独立于具体数据库的访问标准 API，位于 java.sql 与 javax.sql 包下。它由一组 Java 类和接口组成，为 Java 开发者提供了一种统一的数据库访问方式——无论底层是 MySQL、Oracle 还是 SQL Server，JDBC API 的写法完全一致，只是驱动不同。

原理

JDBC 通过"驱动管理器 + 驱动"的两层结构屏蔽了不同数据库的差异：

Java 应用程序
      ↓ 调用 JDBC API（Connection / Statement / ResultSet）
JDBC DriverManager（驱动管理器）
      ↓ 根据url选择对应驱动
具体数据库驱动（mysql-connector-j）
      ↓ 通过 TCP 协议
MySQL 数据库服务器

JDBC 操作数据库的核心六步流程：

图示 3：JDBC 编程六步流程

加载驱动：Class.forName("com.mysql.cj.jdbc.Driver")。

获取连接：DriverManager.getConnection(url, user, password)。

创建 PreparedStatement：conn.prepareStatement(sql)。

执行 SQL：executeQuery() / executeUpdate()。

处理结果集：while(rs.next()) 读取字段。

关闭资源：try-with-resources 自动关闭 rs、pstmt、conn。

问题/场景

场景：CTTS 项目需要查询 sys_user 表中所有用户信息，展示在用户列表页。在没有 MyBatis-Plus 的情况下，必须使用原生 JDBC 完成。

问题：原生 JDBC 代码冗长，开发者必须严格按照六步流程编写，任何一步遗漏都会导致资源泄漏或 SQL 异常。

完整示例代码

下面是一段完整的、规范的 JDBC 查询代码，使用 PreparedStatement + try-with-resources，查询 sys_user 表中所有用户：

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;

/**
 * JDBC 完整示例：查询 sys_user 表所有用户
 * 演示 JDBC 核心六步流程
 */
public class JdbcQueryDemo {

    // 数据库连接信息
    private static final String URL =
            "jdbc:mysql://localhost:3306/ctts?useSSL=false&serverTimezone=Asia/Shanghai&characterEncoding=utf8";
    private static final String USER = "root";
    private static final String PASSWORD = "123456";
    private static final String DRIVER = "com.mysql.cj.jdbc.Driver";

    public static void main(String[] args) {
        // 步骤1：加载驱动
        try {
            Class.forName(DRIVER);
        } catch (ClassNotFoundException e) {
            System.err.println("MySQL 驱动加载失败：" + e.getMessage());
            return;
        }

        // 步骤2~6：使用 try-with-resources 自动关闭资源
        // 注意：资源声明顺序应为 ResultSet → PreparedStatement → Connection
        String sql = "SELECT id, username, password, name, role, phone, create_time FROM sys_user";

        try (Connection conn = DriverManager.getConnection(URL, USER, PASSWORD);
             PreparedStatement pstmt = conn.prepareStatement(sql);
             ResultSet rs = pstmt.executeQuery()) {

            // 步骤5：处理结果集
            System.out.println("ID\t用户名\t姓名\t角色\t电话");
            System.out.println("─────────────────────────────────────");
            while (rs.next()) {
                Long id = rs.getLong("id");
                String username = rs.getString("username");
                // password 不打印，避免泄露
                String name = rs.getString("name");
                String role = rs.getString("role");
                String phone = rs.getString("phone");
                java.sql.Timestamp createTime = rs.getTimestamp("create_time");

                System.out.printf("%d\t%s\t%s\t%s\t%s%n",
                        id, username, name, role, phone);
            }
        } catch (SQLException e) {
            System.err.println("数据库操作异常：" + e.getMessage());
            e.printStackTrace();
        }
        // 步骤6：try-with-resources 自动调用 close()，无需手动关闭
    }
}

带参数的查询示例（按用户名查询）：

/**
 * 按用户名查询用户（演示 PreparedStatement 参数绑定，防止SQL注入）
 */
public static User findByUsername(String username) {
    String sql = "SELECT id, username, password, name, role, phone, create_time " +
                 "FROM sys_user WHERE username = ?";

    try (Connection conn = DriverManager.getConnection(URL, USER, PASSWORD);
         PreparedStatement pstmt = conn.prepareStatement(sql)) {

        // 设置参数（下标从1开始）
        pstmt.setString(1, username);

        try (ResultSet rs = pstmt.executeQuery()) {
            if (rs.next()) {
                User user = new User();
                user.setId(rs.getLong("id"));
                user.setUsername(rs.getString("username"));
                user.setPassword(rs.getString("password"));
                user.setName(rs.getString("name"));
                user.setRole(rs.getString("role"));
                user.setPhone(rs.getString("phone"));
                user.setCreateTime(rs.getTimestamp("create_time"));
                return user;
            }
        }
    } catch (SQLException e) {
        e.printStackTrace();
    }
    return null;
}

新增用户示例（演示 executeUpdate）：

/**
 * 新增用户（演示 executeUpdate 返回受影响行数）
 */
public static int insertUser(User user) {
    String sql = "INSERT INTO sys_user(username, password, name, role, phone, create_time) " +
                 "VALUES (?, ?, ?, ?, ?, NOW())";

    try (Connection conn = DriverManager.getConnection(URL, USER, PASSWORD);
         PreparedStatement pstmt = conn.prepareStatement(sql)) {

        pstmt.setString(1, user.getUsername());
        pstmt.setString(2, user.getPassword());
        pstmt.setString(3, user.getName());
        pstmt.setString(4, user.getRole());
        pstmt.setString(5, user.getPhone());

        // executeUpdate 返回受影响行数
        return pstmt.executeUpdate();
    } catch (SQLException e) {
        e.printStackTrace();
        return 0;
    }
}

图示

图示 4：JDBC 核心六步流程

加载驱动

Class.forName("com.mysql.cj.jdbc.Driver")，让 MySQL 驱动进入 JVM。

获取连接

DriverManager.getConnection(url, user, password) 返回 Connection。

创建语句对象

conn.prepareStatement(sql) 预编译 SQL，用 ? 承载参数。

执行 SQL

executeQuery() 返回结果集；executeUpdate() 返回影响行数。

处理结果集

while(rs.next()) 移动游标，并按字段读取数据。

关闭资源

使用 try-with-resources 自动关闭 ResultSet、PreparedStatement、Connection。

易错点

  1. 驱动类名写错：

    • 错误：com.mysql.jdbc.Driver（MySQL 5.x 旧类名，已废弃）
    • 正确：com.mysql.cj.jdbc.Driver（MySQL 8.x 新类名，必带 cj）

  2. URL 漏写时区参数：

    • 错误：jdbc:mysql://localhost:3306/ctts
    • 正确：jdbc:mysql://localhost:3306/ctts?serverTimezone=Asia/Shanghai
    • 不写时区会报 The server time zone value 'xxx' is unrecognized

  3. Statement vs PreparedStatement 混用：

    • Statement 用于无参数的静态 SQL，存在 SQL 注入风险
    • PreparedStatement 用于带参数的预编译 SQL，强烈推荐始终使用

  4. 参数下标从 1 开始（不是 0）：

    • 正确：pstmt.setString(1, username)
    • 错误：pstmt.setString(0, username) → 报 Parameter index out of range

  5. ResultSet 取值列名要一致：

    • 列名是 create_time（下划线），不是 createTime（驼峰）
    • 数据库列名是下划线命名，Java 属性是驼峰命名，JDBC 不会自动转换

  6. try-with-resources 资源声明顺序：

    • 顺序应为 Connection → PreparedStatement → ResultSet（按依赖关系，外层先声明）
    • 关闭时反向：ResultSet → PreparedStatement → Connection（自动处理）

  7. executeQuery 与 executeUpdate 不能混用：

    • SELECT 必须用 executeQuery() 返回 ResultSet
    • INSERT/UPDATE/DELETE 必须用 executeUpdate() 返回 int

  8. 加载驱动可以省略但建议保留：

    • JDBC 4.0 之后驱动会自动加载（SPI 机制），Class.forName 可省略
    • 但教学场景建议保留，便于理解；生产代码常省略

小结

JDBC 是 Java 访问数据库的最底层标准 API，所有上层框架（MyBatis、MyBatis-Plus、JPA）底层都是基于 JDBC 实现的。掌握 JDBC 六步流程是理解持久层框架原理的基础——框架只是把"加载驱动、获取连接、关闭资源"这些重复工作自动化了。下次遇到框架报错，回归 JDBC 思路往往能快速定位问题。

K6-2 JDBC痛点

定义

JDBC 虽然是 Java 数据库访问的标准 API，但在实际企业项目开发中存在四大痛点，导致开发者长期编写大量冗余、易错的模板代码。

原理（四大痛点详解）

图示 5：原生 JDBC 的四个主要痛点
痛点 1

代码繁琐

每次访问数据库都要重复六步流程，还要手动把字段装配成对象。

痛点 2

资源易泄漏

忘记关闭连接、语句或结果集，异常分支也可能跳过关闭逻辑。

痛点 3

SQL 硬编码

SQL 散落在 Java 文件中，难以集中维护、复用和审查。

痛点 4

手动映射

rs.getString("name") 到 user.setName() 的映射重复且易错。

问题/场景

场景：假设 CTTS 项目需要实现"用户登录"接口，要求根据用户名密码查询 sys_user 表。如果用原生 JDBC 实现，代码会非常冗长：

public User login(String username, String password) {
    Connection conn = null;
    PreparedStatement pstmt = null;
    ResultSet rs = null;
    User user = null;
    try {
        Class.forName("com.mysql.cj.jdbc.Driver");
        conn = DriverManager.getConnection(URL, USER, PASSWORD);
        String sql = "SELECT id, username, password, name, role, phone, create_time " +
                     "FROM sys_user WHERE username = ? AND password = ?";
        pstmt = conn.prepareStatement(sql);
        pstmt.setString(1, username);
        pstmt.setString(2, password);
        rs = pstmt.executeQuery();
        if (rs.next()) {
            user = new User();
            user.setId(rs.getLong("id"));
            user.setUsername(rs.getString("username"));
            user.setPassword(rs.getString("password"));
            user.setName(rs.getString("name"));
            user.setRole(rs.getString("role"));
            user.setPhone(rs.getString("phone"));
            user.setCreateTime(rs.getTimestamp("create_time"));
        }
    } catch (Exception e) {
        e.printStackTrace();
    } finally {
        // 必须按顺序关闭：rs → pstmt → conn
        if (rs != null) try { rs.close(); } catch (SQLException e) {}
        if (pstmt != null) try { pstmt.close(); } catch (SQLException e) {}
        if (conn != null) try { conn.close(); } catch (SQLException e) {}
    }
    return user;
}

问题：上述代码 30 多行，只完成了"一个用户名密码查询"。如果 CTTS 项目有 20 个类似的查询接口，就要重复写 600 多行模板代码。

完整示例代码（痛点对比）

下面对比展示"原生 JDBC 写法"与"MyBatis-Plus 写法"实现同一个功能：

// ============ 原生JDBC写法（30+行） ============
public User findByUsernameJdbc(String username) {
    String sql = "SELECT * FROM sys_user WHERE username = ?";
    try (Connection conn = DriverManager.getConnection(URL, USER, PASSWORD);
         PreparedStatement pstmt = conn.prepareStatement(sql)) {
        pstmt.setString(1, username);
        try (ResultSet rs = pstmt.executeQuery()) {
            if (rs.next()) {
                User user = new User();
                user.setId(rs.getLong("id"));
                user.setUsername(rs.getString("username"));
                user.setPassword(rs.getString("password"));
                user.setName(rs.getString("name"));
                user.setRole(rs.getString("role"));
                user.setPhone(rs.getString("phone"));
                user.setCreateTime(rs.getTimestamp("create_time"));
                return user;
            }
        }
    } catch (SQLException e) {
        e.printStackTrace();
    }
    return null;
}

// ============ MyBatis-Plus写法（1行） ============
public User findByUsernameMp(String username) {
    // BaseMapper内置方法 + 条件构造器
    return userMapper.selectOne(
        new QueryWrapper<User>().eq("username", username)
    );
}

图示

图示 6：JDBC 痛点与 MyBatis-Plus 解决方式

代码繁琐

JDBC 六步流程重复。

解决：BaseMapper 内置 CRUD。

资源易泄漏

忘记 close 或异常中断。

解决：SqlSession / 连接池托管。

SQL 硬编码

SQL 分散在 Java 文件中。

解决：XML / 注解集中管理 SQL。

手动映射

ResultSet 到对象字段重复劳动。

解决：驼峰映射与 ResultMap。

易错点

  1. 资源泄漏问题常被忽视：初学者常把 rs.close()、pstmt.close()、conn.close() 写在 try 块中而不写在 finally 中，一旦中间代码抛异常，资源永远不会关闭，最终耗尽数据库连接池。
  2. 手动映射容易遗漏字段：表新增字段后，Java 代码必须同步添加 user.setXxx(rs.getString("xxx"))，遗漏会导致数据丢失。
  3. SQL 硬编码不利于维护：SQL 写在 Java 文件中，修改 SQL 必须重新编译打包，无法做到热更新；且 Java 代码中混杂 SQL 字符串可读性差。
  4. SQL 注入风险：使用 Statement 拼接 SQL 容易被注入，例如 "... WHERE username = '" + username + "'"，若 username = "admin' OR '1'='1"，会返回所有用户。必须使用 PreparedStatement 参数绑定。

小结

JDBC 痛点的本质是**"重复代码"与"业务无关"**——每个查询都要写一遍加载驱动、获取连接、关闭资源的代码，这些代码与业务逻辑毫无关系，却占了总代码量的大头。MyBatis 与 MyBatis-Plus 的出现正是为了解决这些痛点：把模板代码交给框架，让开发者专注业务 SQL 与 Java 对象的映射。

K6-3 MyBatis简介

定义

MyBatis 是一款优秀的半自动 ORM（Object-Relational Mapping）框架，前身是 iBatis。它将 Java 代码与 SQL 语句分离，开发者自己编写 SQL，框架负责参数绑定、结果映射、资源管理。

"半自动"是相对于 JPA/Hibernate 的"全自动"而言：

  • 全自动 ORM（JPA/Hibernate）：开发者只需操作 Java 对象，框架自动生成 SQL，无需手写 SQL。
  • 半自动 ORM（MyBatis）：开发者需要手写 SQL，但参数绑定、结果映射、资源关闭由框架自动完成。

原理

MyBatis 通过"SQL 映射文件 + 接口绑定"的方式工作：

Java 接口方法  ←─ 映射 ─→  XML SQL语句
   ↓                            ↓
userMapper.findByUsername("admin")
   ↓                            ↓
   ↓                  SELECT * FROM sys_user
   ↓                  WHERE username = #{username}
   ↓                            ↓
MyBatis 拦截接口调用 → 找到对应SQL → 参数绑定 → 执行 → 结果映射
   ↓
返回 User 对象（自动映射）

MyBatis 内部通过 SqlSessionFactory → SqlSession → Mapper 代理 实现，最终底层仍是 JDBC。

问题/场景

场景：CTTS 项目需要实现"按角色查询用户列表"功能。如果用 MyBatis，开发者只需要：

  1. 编写 UserMapper 接口，定义 findByRole(String role) 方法
  2. 编写 UserMapper.xml，写 SQL 语句
  3. MyBatis 自动完成参数绑定、结果映射、资源关闭
// 接口定义
public interface UserMapper {
    List<User> findByRole(@Param("role") String role);
}
<!-- UserMapper.xml -->
<select id="findByRole" resultType="com.ctts.entity.User">
    SELECT id, username, password, name, role, phone, create_time
    FROM sys_user
    WHERE role = #{role}
</select>
// 使用方式（无需写 JDBC 代码）
List<User> teachers = userMapper.findByRole("teacher");

对比原生 JDBC：开发者无需关心加载驱动、获取连接、关闭资源，只需关注"SQL 怎么写"和"结果映射到哪个对象"。

图示 7：全自动 ORM 与半自动 ORM 对比
全自动 ORM

JPA / Hibernate

Java 对象 → 框架自动生成 SQL → 执行 → 自动映射。

优点：开发快；不足：SQL 可控性弱，复杂查询性能不易掌控。
半自动 ORM

MyBatis / MyBatis-Plus

开发者写 SQL 或使用条件构造器，框架负责参数绑定、执行和结果映射。

优点：SQL 可控，适合复杂业务查询。

易错点

  1. MyBatis 不是 JPA 实现：MyBatis 不遵循 JPA 规范，不能与 @Entity、EntityManager 等一起使用。
  2. MyBatis 不自动生成 SQL：所有 SQL 必须手写，包括简单的 SELECT * FROM xxx，框架不会帮你生成。
  3. MyBatis 与 MyBatis-Plus 不是替代关系：MyBatis-Plus 是 MyBatis 的增强工具，使用 MyBatis-Plus 时底层仍是 MyBatis，可以混用 MyBatis 原生功能。
  4. MyBatis 底层就是 JDBC：MyBatis 内部通过 SqlSession 调用 JDBC API 完成数据库操作，只是把模板代码封装了。

小结

MyBatis 的核心价值是"SQL 与代码分离"——把 SQL 从 Java 代码中抽出来写在 XML 或注解中，让 SQL 集中管理、可维护性高，同时保留开发者对 SQL 的完全控制权。但它没有解决"简单 CRUD 仍要手写 SQL"的痛点，于是有了 MyBatis-Plus。

K6-4 MyBatis-Plus简介与优势

定义

MyBatis-Plus（简称 MP） 是一款国产 MyBatis 增强工具，由国内开发者 baomidou 团队维护。它的核心理念是"只做增强不做改变"——在 MyBatis 基础上提供了一系列开箱即用的增强功能，不改变 MyBatis 原生任何功能，开发者可以无缝从 MyBatis 切换到 MyBatis-Plus。

原理（核心优势）

图示 8：MyBatis-Plus 五大核心优势
1

通用 CRUD

继承 BaseMapper 后获得 insert、updateById、selectById 等方法。

2

条件构造器

QueryWrapper / LambdaQueryWrapper 用链式 API 构造 WHERE 条件。

3

分页插件

配置 PaginationInnerInterceptor 后自动处理分页 SQL。

4

代码生成器

根据数据库表生成 Entity、Mapper、Service、Controller 骨架。

5

无侵入增强

兼容 MyBatis 原生 XML 与注解 SQL，需要复杂查询时仍可手写。

问题/场景

场景：CTTS 项目需要为 5 张表（sys_user、training_project、task、task_submission、task_review）各实现 CRUD 接口。如果用 MyBatis，每张表都要写 5 段 XML SQL（insert、update、delete、selectById、selectList），共 25 段 SQL，代码量巨大且重复。

MyBatis-Plus 解决方案：

// 1. 实体类
@Data
@TableName("sys_user")
public class User {
    @TableId(type = IdType.AUTO)
    private Long id;
    private String username;
    private String password;
    private String name;
    private String role;
    private String phone;
    private Date createTime;
}

// 2. Mapper接口（继承BaseMapper即拥有所有CRUD方法）
@Mapper
public interface UserMapper extends BaseMapper<User> {
    // 不用写任何方法，BaseMapper已经提供了：
    // insert(user)、updateById(user)、deleteById(id)
    // selectById(id)、selectList(null)、selectList(wrapper)
}

// 3. 使用方式
@Autowired
private UserMapper userMapper;

// 新增
userMapper.insert(user);
// 根据ID查询
User u = userMapper.selectById(1L);
// 查询所有
List<User> list = userMapper.selectList(null);
// 条件查询
List<User> teachers = userMapper.selectList(
    new QueryWrapper<User>().eq("role", "teacher")
);

代码量对比：5 张表共 25 段 SQL → 0 段 SQL（基础 CRUD 全部内置）。

完整示例代码

下面展示 MyBatis-Plus 条件构造器与分页的使用（仅作演示，第8次课详解）：

import com.baomidou.mybatisplus.core.conditions.query.QueryWrapper;
import com.baomidou.mybatisplus.extension.plugins.pagination.Page;

@Service
public class UserServiceImpl implements UserService {

    @Autowired
    private UserMapper userMapper;  // 继承了BaseMapper<User>

    // 简单查询
    public User findById(Long id) {
        return userMapper.selectById(id);  // 一行搞定
    }

    // 条件查询：查询角色为teacher且电话不为空的用户
    public List<User> findTeachersWithPhone() {
        QueryWrapper<User> wrapper = new QueryWrapper<>();
        wrapper.eq("role", "teacher")
               .isNotNull("phone")
               .orderByDesc("create_time");
        return userMapper.selectList(wrapper);
    }

    // 分页查询
    public Page<User> findPage(int current, int size) {
        Page<User> page = new Page<>(current, size);
        return userMapper.selectPage(page, null);
    }

    // 新增
    public int addUser(User user) {
        return userMapper.insert(user);
    }

    // 修改
    public int updateUser(User user) {
        return userMapper.updateById(user);
    }

    // 删除
    public int deleteUser(Long id) {
        return userMapper.deleteById(id);
    }
}

图示 9：MyBatis 与 MyBatis-Plus 的增强关系
核心引擎

MyBatis

  • SqlSession 管理执行过程
  • Mapper 代理调用 SQL
  • XML / 注解 SQL 映射
  • 参数绑定与结果映射
增强层

MyBatis-Plus

  • BaseMapper 提供通用 CRUD
  • QueryWrapper 组织条件
  • 分页插件处理分页 SQL
  • 代码生成器减少样板代码
MyBatis-Plus 不是替代 MyBatis，而是在 MyBatis 之上做增强；底层仍依赖 MyBatis，复杂 SQL 仍可回到 XML 或注解。

易错点

  1. MyBatis-Plus 不是替代 MyBatis：它增强 MyBatis，底层仍是 MyBatis。所有 MyBatis 原生功能（XML SQL、注解 SQL、动态 SQL）都能正常使用。
  2. BaseMapper 的方法名要记牢：insert、updateById、deleteById、selectById、selectList 是最常用的 5 个方法，注意 updateById/deleteById/selectById 都带 ById 后缀。
  3. @TableName 必须与表名一致：如果实体类叫 User，表叫 sys_user，必须加 @TableName("sys_user")，否则 MP 默认按类名 user 找表，会报"表不存在"。
  4. @TableId 主键策略：默认是 IdType.NONE（无策略），如果数据库主键是自增，需配置 @TableId(type = IdType.AUTO)，否则插入时主键不会自动回填。
  5. 驼峰自动映射：MP 默认开启驼峰映射，createTime 自动对应 create_time，无需手动配置。但若关闭会导致映射失败。

小结

MyBatis-Plus 是国产开源生态的代表作之一，在国内企业项目中被广泛采用。它的核心价值是"简单 CRUD 不用写 SQL"——通过 BaseMapper 内置 20+ 个通用方法，覆盖了日常 80% 的 CRUD 场景。剩下的 20% 复杂查询仍可使用 MyBatis 原生 XML SQL 实现。CTTS 项目后续将全程使用 MyBatis-Plus。

K6-5 环境集成

定义

环境集成指在 Spring Boot 3 项目中集成 MyBatis-Plus，包括三个步骤：

  1. 添加依赖（mybatis-plus-spring-boot3-starter、mysql-connector-j）
  2. 配置数据源（application.yml 中的 spring.datasource）
  3. 创建数据库与表（ctts 数据库 + sys_user 表）

原理

Spring Boot 通过自动装配（Auto-Configuration）机制集成 MyBatis-Plus：

引入mybatis-plus-spring-boot3-starter依赖
                ↓
Spring Boot启动时扫描META-INF/spring/...imports文件
                ↓
自动装配SqlSessionFactory、DataSource、MapperScannerConfigurer
                ↓
读取application.yml中的spring.datasource配置
                ↓
创建HikariCP连接池（默认）→ 建立与MySQL的TCP连接
                ↓
扫描@Mapper注解的接口 → 注册为Bean → 注入SqlSession
                ↓
项目启动成功，数据库连接就绪

问题/场景

场景：CTTS 项目需要从"模拟数据接口"过渡到"真实数据库访问"。本次课的目标是：完成 MyBatis-Plus 集成，创建 ctts 数据库与 sys_user 表，启动项目验证数据库连接成功。

操作步骤清单（学生需独立完成）：

  1. 确认 MySQL 8 已安装并启动
  2. 创建数据库 ctts
  3. 执行 sys_user 建表 SQL
  4. 在 pom.xml 添加 MyBatis-Plus 与 MySQL 驱动依赖
  5. 在 application.yml 配置数据源
  6. 启动项目，观察启动日志确认连接成功
  7. 排查常见报错（时区、驱动、密码）

易错点（常见报错排查）

报错1：时区错误

报错信息：

java.sql.SQLException: The server time zone value 'xxx' is unrecognized
or represents more than one time zone.

原因：MySQL 8 默认使用系统时区，JDBC 驱动无法识别。

解决：在 URL 中添加 serverTimezone=Asia/Shanghai：

url: jdbc:mysql://localhost:3306/ctts?serverTimezone=Asia/Shanghai

或者修改 MySQL 配置：

SET GLOBAL time_zone = '+8:00';
报错2：驱动类找不到

报错信息：

java.lang.ClassNotFoundException: com.mysql.cj.jdbc.Driver

原因：未引入 mysql-connector-j 依赖，或引错为旧版 mysql-connector-java。

解决：检查 pom.xml：

<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
    <scope>runtime</scope>
</dependency>

注意：MySQL 8.0.31 之后驱动包名从 mysql-connector-java 改为 mysql-connector-j，groupId 从 mysql 改为 com.mysql。

报错3：密码错误

报错信息：

java.sql.SQLException: Access denied for user 'root'@'localhost' (using password: YES)

原因：application.yml 中的 password 与 MySQL 实际密码不一致。

解决：

  1. 在 MySQL 命令行验证密码：mysql -u root -p
  2. 修改 application.yml 中的 password 字段
  3. 若忘记密码，重置 root 密码： 
    ALTER USER 'root'@'localhost' IDENTIFIED BY '新密码';
FLUSH PRIVILEGES;
报错4：连接超时

报错信息：

com.mysql.cj.jdbc.exceptions.CommunicationsException: Communications link failure

原因：MySQL 服务未启动，或端口 3306 被防火墙拦截，或端口被改。

解决：

  1. 检查 MySQL 服务：net start mysql80（Windows）
  2. 检查端口：netstat -ano | findstr 3306
  3. 检查 URL 端口：jdbc:mysql://localhost:3306/ctts
  4. 关闭防火墙测试
报错5：数据库不存在

报错信息：

java.sql.SQLSyntaxErrorException: Unknown database 'ctts'

原因：未创建 ctts 数据库。

解决：

CREATE DATABASE ctts DEFAULT CHARACTER SET utf8mb4;
报错6：表不存在

报错信息：

java.sql.SQLSyntaxErrorException: Table 'ctts.sys_user' doesn't exist

原因：未执行 sys_user 建表 SQL。

解决：执行本资料中的建表 SQL。

报错7：Public Key Retrieval 错误

报错信息：

java.sql.SQLException: Public Key Retrieval is not allowed

原因：MySQL 8 默认使用 caching_sha2_password 加密，需要公钥检索。

解决：URL 中添加 allowPublicKeyRetrieval=true：

url: jdbc:mysql://localhost:3306/ctts?allowPublicKeyRetrieval=true&...
报错8：MyBatis-Plus 依赖错版本

报错信息：

java.lang.ClassNotFoundException: org.mybatis.spring.SqlSessionFactoryBean

原因：Spring Boot 3 项目错用了 mybatis-plus-boot-starter（2.x 版本），应为 mybatis-plus-spring-boot3-starter。

解决：

<!-- 错误：Spring Boot 2.x 用 -->
<artifactId>mybatis-plus-boot-starter</artifactId>

<!-- 正确：Spring Boot 3.x 用 -->
<artifactId>mybatis-plus-spring-boot3-starter</artifactId>

小结

环境集成是 M3 模块的基础工作，集成不成功后续 Mapper 编写都无从谈起。掌握"依赖 + 配置 + 建表 + 验证"四步流程，能排查时区/驱动/密码三大常见报错，是后端工程师的基本功。本次课只做集成与连接验证，不写 Mapper 接口——下次课（第7次课）才开始编写 UserMapper 与 SQL 映射。

四、拓展阅读

1. 数据库连接池原理

Spring Boot 默认使用 HikariCP 连接池（号称"最快的连接池"）。连接池预先创建一批 Connection 对象放在内存中，每次请求从池中借出连接，用完归还，避免频繁创建/销毁 TCP 连接的开销。

图示 11：应用代码、连接池与数据库的交互

应用代码

1. 发起数据库操作
2. 借用连接 borrow(conn)
5. 执行完成后归还连接

连接池 HikariCP

维护可复用连接
3. 分配一个可用 Connection
6. 接收归还并继续复用

MySQL 数据库

真实 TCP 连接已经由连接池管理
4. 执行 SQL 并返回结果
连接不断开，等待下一次请求

常见连接池对比：HikariCP（性能最高，Spring Boot 默认）> Druid（阿里开源，监控功能强）> DBCP（老牌，性能一般）> C3P0（已淘汰）。

2. JDBC 4.0 自动加载驱动机制

JDBC 4.0 之后（Java 6+）引入了 SPI（Service Provider Interface）机制，驱动 jar 包的 META-INF/services/java.sql.Driver 文件中声明了驱动类全限定名，DriverManager 在类加载时自动发现并加载，因此 Class.forName("com.mysql.cj.jdbc.Driver") 这行代码可以省略。但教学场景建议保留，便于理解 JDBC 工作流程。

3. MyBatis 与 JPA/Hibernate 的对比

维度 MyBatis JPA/Hibernate
类型 半自动 ORM 全自动 ORM
SQL 编写 开发者手写 框架自动生成
灵活度 高，SQL 完全可控 低，复杂 SQL 难生成
学习成本 中等 较高
性能 可控（SQL 优化空间大） 框架生成 SQL，性能不易优化
适用场景 复杂业务 SQL、报表 简单 CRUD、对象关系映射
国内采用率 高（互联网公司主流） 低（传统企业较多）

国内互联网公司普遍采用 MyBatis/MyBatis-Plus，原因是业务复杂、SQL 灵活度要求高、性能优化空间大。

六、复习思考题

  1. JDBC 六步流程是什么？为什么必须按顺序执行？

    提示：加载驱动 → 获取连接 → 创建 Statement → 执行 SQL → 处理结果集 → 关闭资源。每一步依赖前一步的产物（Connection 依赖驱动加载，Statement 依赖 Connection）。

  2. JDBC 有哪些痛点？MyBatis/MyBatis-Plus 分别解决了哪些？

    提示：四大痛点——代码繁琐、资源泄漏、SQL 硬编码、手动映射。MyBatis 解决 SQL 分离与资源托管；MyBatis-Plus 进一步解决简单 CRUD 仍需手写 SQL 的问题。

  3. Statement 和 PreparedStatement 有什么区别？为什么推荐后者？

    提示：Statement 用于静态 SQL，存在 SQL 注入风险；PreparedStatement 预编译 SQL，参数绑定防注入，且支持参数复用、性能更好。

  4. MyBatis 是"半自动 ORM"，"半"在哪里？与 JPA 全自动 ORM 有何区别？

    提示："半"指 SQL 仍需开发者手写，框架只负责参数绑定与结果映射。JPA 全自动指 SQL 由框架生成，开发者只操作对象。

  5. MyBatis-Plus 是 MyBatis 的替代品吗？两者什么关系？

    提示：不是替代，是增强。MyBatis-Plus 在 MyBatis 之上提供 BaseMapper、QueryWrapper 等增强功能，底层仍是 MyBatis，可混用原生 XML SQL。

  6. Spring Boot 3 项目集成 MyBatis-Plus 应使用哪个 starter 依赖？

    提示：mybatis-plus-spring-boot3-starter（注意带 boot3）。Spring Boot 2.x 项目用 mybatis-plus-boot-starter。

  7. JDBC URL 中 serverTimezone=Asia/Shanghai 参数有什么作用？不写会怎样？

    提示：指定服务器时区。不写会报"The server time zone value 'xxx' is unrecognized"，MySQL 8 必填。

  8. MySQL 8 的 JDBC 驱动类全限定名是什么？与 MySQL 5 有何区别？

    提示：MySQL 8 是 com.mysql.cj.jdbc.Driver（带 cj），MySQL 5 是 com.mysql.jdbc.Driver（无 cj，已废弃）。

  9. try-with-resources 如何工作？为什么 JDBC 资源关闭推荐用它？

    提示：实现 AutoCloseable 接口的资源在 try 块结束时自动调用 close()，无需手动写在 finally 中。资源关闭顺序是"后声明先关闭"（rs → pstmt → conn），符合依赖关系。

  10. 如何验证 Spring Boot 项目成功连接到 MySQL？

    提示：观察启动日志中 HikariPool-1 - Start completed；运行 DataSourceConnectionTest 测试类获取 Connection 并打印元数据；通过 SELECT 1 测试查询。

  11. MyBatis-Plus 的 BaseMapper 提供了哪些常用方法？

    提示：insert、updateById、deleteById、selectById、selectList、selectPage、selectCount、selectByMap 等共 20+ 个通用方法。

  12. 如果项目启动报 Access denied for user 'root'@'localhost'，应该如何排查？

    提示：密码错误。先用 mysql -u root -p 验证密码；检查 application.yml 中 password 是否与实际一致；必要时通过 ALTER USER 重置密码。
