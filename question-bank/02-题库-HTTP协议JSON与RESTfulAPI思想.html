一、选择题（共 40 题，每题 2 分）

1.1 单项选择题（30 题）

02-选择-001（★ 知识点：K2-1） HTTP 协议采用的通信模型是？

  • A推送模型（服务器主动推送）
  • B请求-响应模型（客户端请求，服务器响应）
  • C广播模型
  • D订阅模型

答案：B 解析：HTTP 采用请求-响应模型，客户端发起请求，服务器返回响应。服务器不会主动推送（WebSocket 才支持双向推送）。

02-选择-002（★ 知识点：K2-1） 一个 HTTP 请求报文不包括以下哪一部分？

  • A请求行
  • B请求头
  • C请求体
  • D响应行

答案：D 解析：请求报文由请求行、请求头、请求体组成。响应行属于响应报文，不属于请求报文。

02-选择-003（★ 知识点：K2-1） HTTP 请求报文中，"POST /api/tasks HTTP/1.1" 属于哪一部分？

  • A请求头
  • B请求行
  • C请求体
  • D状态行

答案：B 解析：请求行由"方法 + 路径 + 版本"组成，即 POST /api/tasks HTTP/1.1，是请求报文的第一行。

02-选择-004（★ 知识点：K2-1） HTTP 请求头与请求体之间的分隔符是？

  • A一个分号
  • B一个空行
  • C一个空格
  • D一个特殊字符 ---

答案：B 解析：HTTP 规范规定，请求头结束后用一个空行（CRLF）分隔，其后才是请求体。

02-选择-005（★ 知识点：K2-2） 下列 URL 中，http://localhost:8080/api/tasks?projectId=1 的查询参数部分是？

  • Ahttp://
  • Blocalhost:8080
  • C/api/tasks
  • DprojectId=1

答案：D 解析：URL 结构为 协议://主机:端口/路径?查询参数。? 之后的部分 projectId=1 是查询参数。

02-选择-006（★ 知识点：K2-2） 按照 RESTful 规范，"查询某个任务"应使用的 HTTP 方法和路径是？

  • APOST /api/tasks/5
  • BGET /api/tasks/5
  • CGET /api/tasks?id=5
  • DDELETE /api/tasks/5

答案：B 解析：查询用 GET，单个资源用路径参数标识 ID，即 GET /api/tasks/5。A 是新增；C 查询单个应路径参数而非 query；D 是删除。

02-选择-007（★ 知识点：K2-2） 下列 HTTP 方法中，用于新增资源的是？

  • AGET
  • BPOST
  • CPUT
  • DDELETE

答案：B 解析：POST 用于新增资源。GET 查询、PUT 更新、DELETE 删除。

02-选择-008（★★ 知识点：K2-2） 关于 GET 和 POST 的区别，下列说法错误的是？

  • AGET 一般无请求体，POST 有请求体
  • BGET 参数在 URL 中，POST 参数在请求体中
  • CGET 是幂等的，POST 是非幂等的
  • DGET 比 POST 更安全（数据加密层面）

答案：D 解析：GET 和 POST 都是明文传输，安全性（加密）层面没有区别，要安全都需用 HTTPS。D 错误。A、B、C 都正确。

02-选择-009（★ 知识点：K2-3） HTTP 状态码 404 表示？

  • A服务器内部错误
  • B请求成功
  • C资源不存在
  • D未登录

答案：C 解析：404 Not Found 表示请求的资源不存在。500 是服务器错误；200 是成功；401 是未登录。

02-选择-010（★ 知识点：K2-3） HTTP 状态码 500 表示？

  • A请求参数错误
  • B服务器内部错误
  • C无权限
  • D资源不存在

答案：B 解析：500 Internal Server Error 表示服务器内部错误（如代码异常）。400 是参数错误；403 是无权限；404 是资源不存在。

02-选择-011（★★ 知识点：K2-3） 某用户已登录系统，但尝试访问只有管理员才能使用的接口，服务器应返回的状态码是？

  • A401
  • B403
  • C404
  • D500

答案：B 解析：用户已登录（已认证）但无权限，应返回 403 Forbidden。401 是未认证（未登录）；404 是资源不存在；500 是服务器错误。

02-选择-012（★★ 知识点：K2-3） 下列状态码中，表示"未认证（未登录）"的是？

  • A400
  • B401
  • C403
  • D404

答案：B 解析：401 Unauthorized 表示未认证（没登录或 Token 失效）。403 是已认证但无权限；400 是参数错误；404 是资源不存在。

02-选择-013（★ 知识点：K2-3） HTTP 状态码首位数字为 2 表示？

  • A信息性
  • B成功
  • C重定向
  • D客户端错误

答案：B 解析：2xx 表示成功（如 200、201）；1xx 信息性；3xx 重定向；4xx 客户端错误；5xx 服务器错误。

02-选择-014（★ 知识点：K2-4） Cookie 存储的位置是？

  • A服务器端
  • B客户端（浏览器）
  • C数据库
  • D路由器

答案：B 解析：Cookie 存储在客户端（浏览器），服务器通过 Set-Cookie 响应头下发。Session 存储在服务器端。

02-选择-015（★ 知识点：K2-4） Session 存储的位置是？

  • A客户端浏览器
  • B服务器端
  • C客户端硬盘
  • DDNS 服务器

答案：B 解析：Session 存储在服务器端，客户端只保存 SessionID（通常通过 Cookie 传递）。

02-选择-016（★★ 知识点：K2-4） 关于 Cookie 和 Session 的区别，下列说法正确的是？

  • ACookie 存服务器，Session 存客户端
  • BCookie 存客户端，Session 存服务器
  • C两者都存在客户端
  • D两者都存在服务器

答案：B 解析：Cookie 存客户端（浏览器），Session 存服务器端。SessionID 通过 Cookie 传递给客户端。

02-选择-017（★ 知识点：K2-5） 下列哪一个是合法的 JSON？

  • A{'name': '张三'}
  • B{"name": "张三"}
  • C{name: "张三"}
  • D{"name": "张三",}

答案：B 解析：JSON 键和字符串必须用双引号，不能有尾逗号。A 单引号错；C 键无引号错；D 尾逗号错。B 合法。

02-选择-018（★ 知识点：K2-5） JSON 中，对象的表示方式是？

  • A用 [] 包裹
  • B用 {} 包裹
  • C用 () 包裹
  • D用 <> 包裹

答案：B 解析：JSON 对象用 {} 包裹（键值对集合），数组用 [] 包裹。

02-选择-019（★ 知识点：K2-5） JSON 中，数组的表示方式是？

  • A{}
  • B[]
  • C()
  • D<>

答案：B 解析：JSON 数组用 [] 包裹，是有序列表。

02-选择-020（★★ 知识点：K2-5） 下列关于 JSON 的说法，错误的是？

  • AJSON 支持字符串、数字、布尔、null 类型
  • BJSON 的键必须用双引号
  • CJSON 支持注释（用 // 表示）
  • DJSON 支持对象和数组的嵌套

答案：C 解析：JSON 不支持注释。C 错误。A、B、D 都正确。

02-选择-021（★ 知识点：K2-6） RESTful API 设计中，URL 中的资源应使用？

  • A动词
  • B名词（通常复数）
  • C形容词
  • D副词

答案：B 解析：RESTful 中 URL 表示资源，用名词复数（如 /api/tasks），操作由 HTTP 方法表达。

02-选择-022（★★ 知识点：K2-6） 下列接口路径中，符合 RESTful 风格的是？

  • AGET /api/deleteTask?id=5
  • BPOST /api/addTask
  • CDELETE /api/tasks/5
  • DGET /api/getAllTasks

答案：C 解析：C 用 DELETE 方法删除 + 名词复数路径 + 路径参数 ID，符合 RESTful。A 用 GET 删除且动词；B 动词；D 动词。

02-选择-023（★ 知识点：K2-6） 按照 RESTful 规范，"新增一个任务"应使用？

  • AGET /api/tasks
  • BPOST /api/tasks
  • CPUT /api/tasks
  • DDELETE /api/tasks

答案：B 解析：新增用 POST，资源用名词复数，不带 ID（因为是新增）。POST /api/tasks 正确。

02-选择-024（★★ 知识点：K2-2） 关于 HTTP 方法的幂等性，下列说法正确的是？

  • AGET 是非幂等的
  • BPOST 是幂等的
  • CDELETE 是幂等的
  • DPUT 是非幂等的

答案：C 解析：幂等指多次执行效果相同。GET、PUT、DELETE 是幂等的；POST 是非幂等的（多次提交创建多条数据）。

02-选择-025（★ 知识点：K2-4） HTTP 请求头 Content-Type: application/json 的作用是？

  • A表示客户端接受的响应类型
  • B表示请求体的数据类型是 JSON
  • C表示服务器返回的状态码
  • D表示请求的方法

答案：B 解析：Content-Type 表示请求体（或响应体）的数据类型。application/json 表示数据是 JSON 格式。Accept 表示客户端接受的类型。

02-选择-026（★ 知识点：K2-1） HTTP 响应报文中，"HTTP/1.1 200 OK" 属于哪一部分？

  • A响应头
  • B响应体
  • C状态行
  • D请求行

答案：C 解析：状态行由"版本 + 状态码 + 原因短语"组成，即 HTTP/1.1 200 OK，是响应报文的第一行。

02-选择-027（★★ 知识点：K2-3） "请求参数缺失或格式不正确"应返回的状态码是？

  • A400
  • B401
  • C403
  • D404

答案：A 解析：400 Bad Request 表示客户端请求参数错误（缺失、格式不对）。401 未认证；403 无权限；404 资源不存在。

02-选择-028（★★ 知识点：K2-6） "查询项目 1 下的所有任务"，符合 RESTful 的路径设计是？

  • AGET /api/tasks?projectId=1
  • BGET /api/projects/1/tasks
  • CGET /api/getTasksByProject?projectId=1
  • DPOST /api/projects/1/tasks

答案：B 解析：子资源查询用嵌套路径 /api/projects/1/tasks，表示"项目 1 下的任务"，符合 RESTful 子资源设计。A 也可接受但 B 更 RESTful；C 动词；D 用 POST 不对（查询用 GET）。

02-选择-029（★★ 知识点：K2-4） 前后端分离项目更倾向使用 Token 而非 Session 的主要原因是？

  • AToken 比 Session 更安全（加密层面）
  • BToken 是无状态的，服务器不需存储会话，便于扩展
  • CToken 不能被篡改
  • DSession 不支持 HTTP 协议

答案：B 解析：Token（如 JWT）是无状态的，服务器不存会话数据，多服务器部署时无需共享 Session，便于扩展。A 错（安全性取决于实现）；C 错（Token 可被篡改，但有签名校验）；D 错。

02-选择-030（★★ 知识点：K2-1/K2-5） 服务器返回 Content-Type: application/json 的响应，其响应体最可能是？

  • A一段 HTML 页面
  • B一段 JSON 数据
  • C一张图片
  • D一段 CSS 样式

答案：B 解析：Content-Type 表示数据类型，application/json 表示响应体是 JSON 数据。HTML 是 text/html；图片是 image/*；CSS 是 text/css。

二、判断题（共 20 题，每题 1 分）

02-判断-001（★ 知识点：K2-1） HTTP 协议采用请求-响应模型，由客户端发起请求，服务器返回响应。（ ）

答案：正确 解析：HTTP 是请求-响应模型，客户端请求、服务器响应。

02-判断-002（★ 知识点：K2-1） HTTP 请求头与请求体之间用空行分隔。（ ）

答案：正确 解析：HTTP 规范规定请求头结束后用空行分隔请求体。

02-判断-003（★ 知识点：K2-1） GET 请求通常没有请求体。（ ）

答案：正确 解析：GET 用于查询，参数在 URL，一般无请求体。

02-判断-004（★ 知识点：K2-2） POST 请求用于新增资源，是非幂等的。（ ）

答案：正确 解析：POST 新增资源，多次提交会创建多条数据，非幂等。

02-判断-005（★ 知识点：K2-2） GET 请求可以用于删除资源。（ ）

答案：错误 解析：删除应使用 DELETE 方法。GET 只用于查询，不应有副作用。

02-判断-006（★ 知识点：K2-3） HTTP 状态码 404 表示服务器内部错误。（ ）

答案：错误 解析：404 表示资源不存在。服务器内部错误是 500。

02-判断-007（★★ 知识点：K2-3） 401 表示未认证（未登录），403 表示已认证但无权限。（ ）

答案：正确 解析：401 Unauthorized 是未认证；403 Forbidden 是已认证但无权限。

02-判断-008（★ 知识点：K2-4） Cookie 存储在服务器端。（ ）

答案：错误 解析：Cookie 存储在客户端（浏览器），Session 存储在服务器端。

02-判断-009（★ 知识点：K2-4） Session 存储在服务器端，相对 Cookie 更安全。（ ）

答案：正确 解析：Session 数据在服务器，客户端只存 SessionID，相对安全。

02-判断-010（★ 知识点：K2-5） JSON 的键必须用双引号包裹。（ ）

答案：正确 解析：JSON 规范要求键必须用双引号，不能用单引号或不加引号。

02-判断-011（★ 知识点：K2-5） JSON 支持使用单引号表示字符串。（ ）

答案：错误 解析：JSON 字符串必须用双引号，单引号不合法。

02-判断-012（★ 知识点：K2-5） JSON 允许在数据中添加注释。（ ）

答案：错误 解析：JSON 不支持注释。

02-判断-013（★ 知识点：K2-6） RESTful API 中，URL 的资源部分应使用名词（通常复数）。（ ）

答案：正确 解析：RESTful 资源用名词复数（如 /api/tasks），操作由 HTTP 方法表达。

02-简答-001（★★ 知识点：K2-2，分值：8 分） 请从语义、参数位置、幂等性、安全性（加密层面）四个方面说明 GET 与 POST 的区别。

参考答案要点：

  1. 语义（2 分）：GET 用于查询资源，POST 用于新增资源。
  2. 参数位置（2 分）：GET 参数放在 URL 的 query string 中；POST 参数放在请求体中。
  3. 幂等性（2 分）：GET 是幂等的（多次查询结果相同）；POST 是非幂等的（多次提交会创建多条数据）。
  4. 安全性（加密层面）（2 分）：GET 和 POST 本身都是明文传输，加密层面无区别，要安全都需使用 HTTPS。（注：GET 参数暴露在 URL，相对更容易被看到，但这不是加密层面的区别。）

评分标准：每方面 2 分，共 8 分。第 4 点需点明"两者都明文传输、需 HTTPS 才安全"，仅说"GET 不安全 POST 安全"不给分。

02-简答-002（★★ 知识点：K2-3，分值：6 分） 请说明 HTTP 状态码 401 与 403 的区别，并各举一个 CTTS 系统中的应用场景。

参考答案要点：

  1. 区别（3 分）：
    • 401 Unauthorized：未认证——服务器不知道用户身份（未登录、未带 Token 或 Token 失效）。
    • 403 Forbidden：已认证但无权限——服务器知道用户是谁，但该用户没有权限执行此操作。
  2. CTTS 场景（每场景 1.5 分，共 3 分）：
    • 401 场景：学生未登录就直接访问"查看任务列表"接口 → 返回 401。
    • 403 场景：学生已登录，但尝试调用"删除任务"接口（只有教师/管理员可删）→ 返回 403。

评分标准：区别 3 分 + 场景 3 分 = 6 分。区别部分需点出"401 是未认证、403 是已认证无权限"这一关键区分。

02-简答-003（★★ 知识点：K2-4，分值：6 分） 请说明 Cookie 和 Session 的区别，并解释为什么前后端分离项目更倾向使用 Token 而非 Session。

参考答案要点：

  1. Cookie 与 Session 区别（3 分）：
    • 存储位置：Cookie 存客户端（浏览器），Session 存服务器端。
    • 安全性：Session 更安全（数据在服务器），Cookie 在客户端可被查看篡改。
    • 依赖关系：Session 通常通过 Cookie 传递 SessionID。
  2. 前后端分离倾向 Token 的原因（3 分）：
    • Session 存在服务器，多服务器部署时需共享 Session（复杂）；
    • Token（如 JWT）是无状态的，服务器不存会话数据，客户端携带即可；
    • Token 便于跨域、多端（网页/APP/小程序）统一认证，利于系统扩展。

评分标准：区别 3 分 + Token 原因 3 分 = 6 分。Token 原因需点出"无状态""便于扩展"关键点。

02-简答-004（★★★ 知识点：K2-6，分值：10 分） 请阐述 RESTful API 的核心设计原则，并为 CTTS 的"实训项目（project）"资源设计一套完整的 CRUD 接口（含方法、路径、说明）。

  2. project 资源 CRUD 接口设计（每接口 1.5 分，共 6 分）： | 操作 | 方法 | 路径 | 说明 | | --- | --- | --- | --- | | 查询列表 | GET | /api/projects | 获取项目列表 | | 查询单个 | GET | /api/projects/5 | 获取 id=5 的项目 | | 新增 | POST | /api/projects | 请求体带新项目数据 | | 更新 | PUT | /api/projects/5 | 请求体带更新数据 | | 删除 | DELETE | /api/projects/5 | 删除 id=5 的项目 | （注：答出 4 个即给满分 6 分，需含方法+路径+说明）

评分标准：原则 4 分 + 接口设计 6 分 = 10 分。接口需方法与路径匹配正确（如 GET 查询、POST 新增），路径用名词复数+路径参数。
