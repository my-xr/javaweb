一、单项选择题（30题）

22-单选-01（★）

关于 Spring Boot 拦截器 HandlerInterceptor 的 preHandle 方法返回值的说法，正确的是？ A. 返回 false 表示请求处理继续，返回 true 表示中断 B. 返回 true 表示放行，返回 false 表示中断请求 C. 必须返回 null，由后续拦截器决定 D. 返回值类型是 void，不存在返回值

答案：B 解析：preHandle 返回 true 表示放行，请求继续传递到下一个拦截器或 Controller；返回 false 表示中断，后续拦截器与 Controller 不会执行。

22-单选-02（★）

在 WebMvcConfig 中注册多个拦截器时，执行顺序由什么决定？ A. 拦截器类名字母顺序 B. @Order 注解或 order() 方法，数值小的先执行 C. Bean 注入顺序 D. 随机执行

答案：B 解析：通过 InterceptorRegistry.addInterceptor(xxx).order(n) 指定执行顺序，数值小的先执行。

22-单选-03（★）

JWT Token 由三部分组成，正确顺序是？ A. Header.Payload.Signature B. Payload.Header.Signature C. Signature.Header.Payload D. Header.Signature.Payload

答案：A 解析：JWT 格式为 Header.Payload.Signature，三部分以 . 分隔，Base64URL 编码。

22-单选-04（★）

JWT 的 Payload 中通常不存放以下哪类信息？ A. 用户 ID B. 用户名 C. 角色编码列表 D. 用户密码

答案：D 解析：Payload 会被 Base64 解码可见，仅存放非敏感信息（uid、username、roles），密码等敏感信息绝对不能放入。

22-单选-05（★）

自定义注解 @RequireRole 要想在运行时被反射读取，@Retention 应配置为？ A. RetentionPolicy.SOURCE B. RetentionPolicy.CLASS C. RetentionPolicy.RUNTIME D. RetentionPolicy.DEFAULT

答案：C 解析：只有 RUNTIME 级别的注解才能在运行时通过反射读取，拦截器校验权限依赖此配置。

22-单选-06（★）

@RestControllerAdvice 注解的组合来源不包括？ A. @ControllerAdvice B. @ResponseBody C. @Component D. @Configuration

答案：D 解析：@RestControllerAdvice = @ControllerAdvice + @ResponseBody，而 @ControllerAdvice 本身组合了 @Component，不包含 @Configuration。

22-单选-07（★）

统一响应 Result<T> 中 data 字段使用泛型 T 的主要目的是？ A. 节省内存 B. 提高序列化速度 C. 保证类型安全，便于前端与文档识别 D. 强制使用 Object 类型

答案：C 解析：泛型保证返回数据类型明确，编译期类型检查，Knife4j 文档也能正确显示数据模型。

22-单选-08（★）

全局异常处理器中 @ExceptionHandler(Exception.class) 的作用是？ A. 处理所有自定义异常 B. 作为兜底处理器，处理未被其他处理器捕获的异常 C. 仅处理 RuntimeException D. 必须放在最前面

答案：B 解析：Exception.class 是所有异常的父类，作为兜底处理器，只在前面的具体异常处理器不匹配时执行。

22-单选-09（★）

MethodArgumentNotValidException 通常在什么场景下被抛出？ A. @RequestParam 参数缺失 B. @RequestBody 参数校验失败（@Valid） C. 路径变量类型不匹配 D. JSON 格式错误

答案：B 解析：@RequestBody + @Valid 校验失败抛出 MethodArgumentNotValidException，需在全局处理器中专门处理。

22-单选-10（★）

关于 ThreadLocal 在拦截器中的使用，下列说法错误的是？ A. 用于在拦截器与 Controller 之间传递用户信息 B. 必须在 afterCompletion 中调用 remove 清理 C. 适合存放请求维度数据 D. 适合存放全局共享数据

答案：D 解析：ThreadLocal 是线程隔离的，适合存放请求维度数据，不适合存放跨线程共享的全局数据。

22-单选-11（★★）

在 CTTS 项目中，JwtInterceptor 与 RoleInterceptor 的执行顺序应是？ A. RoleInterceptor 先执行，再 JwtInterceptor B. JwtInterceptor 先执行，再 RoleInterceptor C. 两者并行执行 D. 顺序不影响

答案：B 解析：RoleInterceptor 依赖 BaseContext.getCurrentRoles()，而该数据由 JwtInterceptor 解析 Token 后注入，因此必须先 JWT 后角色。

22-单选-12（★★）

@RequireRole 注解同时标注在类和方法上时，权限以哪个为准？ A. 类级注解优先 B. 方法级注解优先（覆盖类级） C. 取两者交集 D. 取两者并集

答案：B 解析：RoleInterceptor 优先读取方法级注解，若方法级存在则覆盖类级，便于在通用类中实现特殊方法精细化控制。

22-单选-13（★★）

以下哪类异常应使用 PermissionException（403）而非 AuthException（401）？ A. Token 过期 B. 未携带 Token C. Token 签名错误 D. 已登录但角色不匹配

答案：D 解析：AuthException（401）表示未认证（身份不明），PermissionException（403）表示已认证但无权限，角色不匹配属于后者。

22-单选-14（★★）

在 GlobalExceptionHandler 中，业务异常 BusinessException 应返回的 HTTP 状态码通常是？ A. 200 B. 400 C. 500 D. 403

答案：A 解析：业务异常是用户操作不当导致的预期异常，HTTP 状态码通常返回 200，通过 Result.code 字段区分业务错误码，便于前端统一处理。

22-单选-15（★★）

日志级别从低到高的正确顺序是？ A. DEBUG → INFO → WARN → ERROR B. INFO → DEBUG → WARN → ERROR C. ERROR → WARN → INFO → DEBUG D. DEBUG → WARN → INFO → ERROR

答案：A 解析：日志级别从低到高为 TRACE < DEBUG < INFO < WARN < ERROR，配置 INFO 级别时 DEBUG 不会输出。

22-单选-16（★★）

Logback 配置文件 logback-spring.xml 比 logback.xml 的优势是？ A. 加载速度更快 B. 可以使用 Spring Boot profile 特性 C. 不需要任何配置 D. 仅在测试环境生效

答案：B 解析：logback-spring.xml 由 Spring Boot 加载，支持 <springProfile> 标签按环境区分配置。

22-单选-17（★★）

关于 @Slf4j 注解，下列说法正确的是？ A. 是 Spring 提供的注解 B. 由 Lombok 提供，自动生成 log 字段 C. 必须手动 new Logger D. 仅能在 Controller 中使用

答案：B 解析：@Slf4j 由 Lombok 提供，编译期自动生成 private static final Logger log = LoggerFactory.getLogger(...)，简化日志使用。

22-单选-18（★★）

水平越权与垂直越权的区别是？ A. 垂直越权是同权限级别用户间互访 B. 水平越权是低权限访问高权限 C. 水平越权是同权限级别用户间互访对方数据 D. 二者没有区别

答案：C 解析：水平越权指相同权限级别的用户 A 访问用户 B 的数据；垂直越权指低权限用户访问高权限接口。

22-单选-19（★★）

防御 SQL 注入最有效的方式是？ A. 前端校验输入 B. 使用预编译语句（PreparedStatement） C. 隐藏数据库表名 D. 限制请求频率

答案：B 解析：预编译语句将 SQL 与参数分离，参数不会被当作 SQL 解析，从根本上防御注入。MyBatis-Plus 默认使用预编译。

22-单选-20（★★）

以下哪种做法可能导致水平越权漏洞？ A. Service 层根据 BaseContext.getCurrentUserId() 过滤数据 B. Controller 直接接收前端传入的 userId 参数并查询该用户数据 C. 使用 @RequireRole 限制角色 D. 拦截器校验 Token

答案：B 解析：直接信任前端传入的 userId 会导致用户 A 提交用户 B 的 ID 从而访问 B 的数据，应基于登录态的 userId 查询。

22-单选-21（★★）

在 Knife4j 配置中，为了让所有接口文档正常访问，WebMvcConfig 应放行哪些路径？ A. /auth/** B. /doc.html、/swagger-ui/**、/v3/api-docs/**、/webjars/** C. /static/** D. /resources/**

答案：B 解析：Knife4j 静态资源与 API 文档路径必须放行，否则被 JWT 拦截器拦截导致文档无法访问。

22-单选-22（★★）

@ResponseStatus(HttpStatus.UNAUTHORIZED) 注解的作用是？ A. 自动抛出异常 B. 设置 HTTP 响应状态码为 401 C. 阻止方法执行 D. 仅用于日志记录

答案：B 解析：@ResponseStatus 指定响应的 HTTP 状态码，配合 @ExceptionHandler 使用可让前端通过状态码识别异常类型。

22-单选-23（★★★）

CTTS 项目中，拦截器抛出的 PermissionException 能否被 GlobalExceptionHandler 捕获？ A. 不能，拦截器异常不进 Controller B. 能，Spring MVC 的 DispatcherServlet 会统一交给 HandlerExceptionResolver 处理 C. 仅在 Controller 内抛出才能被捕获 D. 需要手动 try-catch

答案：B 解析：拦截器 preHandle 抛出的异常会由 DispatcherServlet 交给 HandlerExceptionResolver，最终被 @RestControllerAdvice 捕获。

22-单选-24（★★★）

关于 JWT 签名算法，CTTS 项目推荐使用？ A. HS256（HMAC-SHA256） B. RS256（RSA-SHA256） C. none（不签名） D. MD5

答案：A 解析：单体项目使用 HS256 即可，密钥保密；分布式系统可使用 RS256 实现公钥验签、私钥签发。none 算法存在严重安全漏洞。

22-单选-25（★★★）

如果 JWT 密钥泄露，攻击者可以？ A. 仅能读取 Payload B. 能伪造任意用户的 Token C. 能修改数据库 D. 无法造成任何危害

答案：B 解析：密钥泄露后，攻击者可自行签发任意 uid/roles 的合法 Token，冒充任意用户，必须立即更换密钥。

22-单选-26（★★★）

在 CTTS 项目中，BaseContext.clear() 必须在哪个拦截器方法中调用？ A. preHandle B. postHandle C. afterCompletion D. 任意位置

答案：C 解析：afterCompletion 在请求完成后必定执行（即使出现异常），是清理 ThreadLocal 的安全位置，防止线程池复用导致内存泄漏。

22-单选-27（★★★）

关于 @RequestBody @Valid 触发的校验异常，以下说法正确的是？ A. Spring 自动返回 200 状态码 B. 抛出 MethodArgumentNotValidException，需由全局异常处理器统一处理 C. 会直接抛出 NullPointerException D. 不需要任何处理

答案：B 解析：@Valid 校验失败抛出 MethodArgumentNotValidException，需在 GlobalExceptionHandler 中捕获并返回友好的 Result。

22-单选-28（★★★）

以下哪种方式能最有效防御 Token 伪造？ A. 使用长密钥且保密 B. Token 中存放明文密码 C. 使用 none 算法 D. 不验证签名

答案：A 解析：长密钥 + 保密是 HMAC 算法安全的基石，配合 Jwts.parser().verifyWith(key) 严格校验签名。

22-单选-29（★★★）

日志中记录用户敏感信息（如密码、身份证号）的正确做法是？ A. 直接打印完整内容 B. 脱敏处理（如 idCard: 1234**5678）或不记录 C. 加密后打印 D. 仅记录到文件即可

答案：B 解析：日志文件可能被运维、第三方查看，敏感信息必须脱敏或不记录，符合个人信息保护合规要求。

22-单选-30（★★★）

关于"上线前自检"的工程素养，以下做法错误的是？ A. 编写漏洞自查清单逐项测试 B. 同伴交叉审查代码 C. 上线后再修复测试中发现的漏洞 D. 修复后重新回归测试

答案：C 解析：上线前发现的漏洞必须在上线前修复并回归测试，不能"先上线后修复"，否则可能造成数据泄露事故。

二、多项选择题（10题）

22-多选-01（★）

@RestControllerAdvice 注解可以用于声明哪些类型的增强？ A. @ExceptionHandler（异常处理） B. @InitBinder（数据绑定） C. @ModelAttribute（全局数据绑定） D. @RequestMapping（路由映射）

答案：A、B、C 解析：@RestControllerAdvice 可包含 @ExceptionHandler、@InitBinder、@ModelAttribute 三类方法，不用于路由映射。

22-多选-02（★）

以下属于 JWT Token 标准声明的字段有？ A. sub（subject） B. exp（expiration） C. iat（issued at） D. password

答案：A、B、C 解析：JWT 标准声明包括 iss、sub、aud、exp、nbf、iat、jti，不含 password。

22-多选-03（★★）

CTTS 项目中，应在 WebMvcConfig 中放行的路径包括？ A. /auth/login B. /doc.html C. /v3/api-docs/** D. /admin/**

答案：A、B、C 解析：登录接口、Knife4j 文档相关路径必须放行；/admin/** 是管理员接口，必须经过认证与权限校验，不能放行。

22-多选-04（★★）

GlobalExceptionHandler 应处理的异常类型包括？ A. 参数校验异常（MethodArgumentNotValidException） B. 业务异常（BusinessException） C. 认证异常（AuthException） D. 兜底异常（Exception）

答案：A、B、C、D 解析：四类异常均应统一处理，参数异常返回 400，业务异常返回 200+业务码，认证异常返回 401，兜底异常返回 500。

22-多选-05（★★）

以下属于水平越权测试场景的有？ A. 学生 A 访问学生 B 的汇报详情 B. 学生访问教师接口 C. 教师 A 修改教师 B 发布的任务 D. 未登录访问受保护接口

答案：A、C 解析：水平越权是同权限级别用户间互访对方数据（A、C）；B 是垂直越权；D 是未认证。

22-多选-06（★★）

关于 @RequireRole 注解，以下说法正确的有？ A. 可以标注在类上 B. 可以标注在方法上 C. 方法级注解覆盖类级注解 D. 必须配置 requireAll = true

答案：A、B、C 解析：@RequireRole 支持 TYPE 和 METHOD 目标，方法级优先；requireAll 默认 false（满足任一即可），非必需。

22-多选-07（★★★）

以下哪些措施有助于防御 Token 伪造？ A. 使用足够长的随机密钥 B. 设置合理的 Token 过期时间 C. 密钥硬编码在代码中并提交到 Git D. 使用 HTTPS 传输

答案：A、B、D 解析：密钥应通过配置文件或环境变量管理，不能硬编码提交到 Git 仓库；HTTPS 防止中间人窃取 Token。

22-多选-08（★★★）

以下哪些属于参数篡改测试？ A. 提交 SQL 注入字符串 B. 提交超长字符串 C. 篡改 URL 中的 ID 为负数 D. 使用合法 Token 访问合法接口

答案：A、B、C 解析：参数篡改测试包括 SQL 注入、超长字符串、非法 ID 等；D 是正常访问，不属于篡改。

22-多选-09（★★★）

日志规范应遵循的最佳实践包括？ A. 关键操作记录 INFO 级别 B. 异常记录 ERROR 级别并附带堆栈 C. 敏感信息脱敏 D. 生产环境开启 DEBUG 级别

答案：A、B、C 解析：生产环境应使用 INFO 或 WARN 级别，DEBUG 会产生大量日志影响性能且可能泄露细节。

22-多选-10（★★★）

CTTS 项目权限漏洞自查应覆盖的场景有？ A. 垂直越权（低权限访问高权限接口） B. 水平越权（同权限用户互访数据） C. Token 伪造与篡改 D. 参数篡改与 SQL 注入

答案：A、B、C、D 解析：完整的自查应覆盖四类场景，缺一不可，体现工程师"上线前自检"的严谨态度。

三、判断题（20题）

22-论述-01（★★）

请论述 CTTS 项目中 JWT 认证拦截器与角色权限拦截器的协作流程，并说明为什么必须按"先 JWT 后角色"的顺序执行。

评分标准（满分 10 分）：

  • JWT 拦截器职责说明（3 分）：解析 Token、校验有效性、注入用户信息到 ThreadLocal。
  • 角色拦截器职责说明（3 分）：读取 @RequireRole 注解、从 ThreadLocal 获取角色、匹配校验。
  • 顺序原因说明（4 分）：角色拦截器依赖 ThreadLocal 中的角色数据，必须由 JWT 拦截器先注入；若顺序颠倒，角色拦截器读到 null，导致所有请求被拦截。

参考答案：

  1. JWT 拦截器（order=1）：从请求头获取 Token，校验签名与过期时间，解析出 uid、username、roles，注入 BaseContext（ThreadLocal）。
  2. 角色拦截器（order=2）：通过反射读取目标方法或类上的 @RequireRole 注解，从 BaseContext.getCurrentRoles() 获取当前用户角色，匹配校验，不通过抛 PermissionException。
  3. 顺序原因：RoleInterceptor 强依赖 BaseContext 中的角色数据，而该数据由 JwtInterceptor 注入。若角色拦截器先执行，ThreadLocal 为空，会误判为"未登录"或"角色缺失"，导致合法用户被拦截。因此必须按"先 JWT 后角色"的顺序执行，体现拦截器间的依赖关系。

22-论述-02（★★）

评分标准（满分 10 分）：

  • 五类异常的语义差异说明（5 分，每类 1 分）。
  • HTTP 状态码设计合理性（2 分）。
  • Result.code 设计合理性（2 分）。
  • 不向前端暴露堆栈的安全考虑（1 分）。

参考答案：

  1. 参数校验异常：用户输入不符合约束（如字段为空、格式错误），返回 HTTP 400，Result.code=400，msg 包含具体字段错误。
  2. 业务异常：业务逻辑不满足（如任务不存在、状态非法），HTTP 200，Result.code 使用业务码（404/500 等），前端通过 code 判断业务结果。

七、编程接口设计题（2题）

22-编程-01（★★★）

题目：请为 CTTS 项目实现 @RequireRole 注解与 RoleInterceptor 拦截器，要求：

  1. @RequireRole 支持类级与方法级标注，支持多角色（满足任一即可）。
  2. RoleInterceptor 通过反射读取注解，方法级注解优先于类级。
  3. 未标注注解的接口默认放行（仅做登录校验）。
  4. 角色不匹配时抛出 PermissionException（code=403）。

请给出完整代码，并说明在 TaskController 上的使用示例（发布任务需要教师或管理员，删除任务仅管理员）。

评分标准（满分 15 分）：

  • @RequireRole 注解定义完整（3 分）：@Target、@Retention、value()、requireAll()。
  • RoleInterceptor 反射读取逻辑正确（5 分）：方法级优先、类级兜底、未标注放行。
  • 角色匹配算法正确（3 分）：anyMatch 或 allMatch。
  • 异常抛出正确（2 分）：抛出 PermissionException。
  • TaskController 使用示例正确（2 分）。

参考答案：

// ===== 1. 注解定义 =====
package com.ctts.annotation;

import java.lang.annotation.*;

@Target({ElementType.METHOD, ElementType.TYPE})
@Retention(RetentionPolicy.RUNTIME)
public @interface RequireRole {
    String[] value();
    boolean requireAll() default false;
}

// ===== 2. 拦截器实现 =====
package com.ctts.interceptor;

import com.ctts.annotation.RequireRole;
import com.ctts.common.BaseContext;
import com.ctts.exception.PermissionException;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Component;
import org.springframework.web.method.HandlerMethod;
import org.springframework.web.servlet.HandlerInterceptor;

import java.util.Arrays;
import java.util.Set;

@Slf4j
@Component
public class RoleInterceptor implements HandlerInterceptor {

    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) {
        if (!(handler instanceof HandlerMethod handlerMethod)) {
            return true;
        }

        // 方法级优先，类级兜底
        RequireRole methodAnno = handlerMethod.getMethodAnnotation(RequireRole.class);
        RequireRole classAnno = handlerMethod.getBeanType().getAnnotation(RequireRole.class);
        RequireRole anno = methodAnno != null ? methodAnno : classAnno;

        // 未标注注解默认放行
        if (anno == null) {
            return true;
        }

        Set<String> currentRoles = BaseContext.getCurrentRoles();
        if (currentRoles == null || currentRoles.isEmpty()) {
            throw new PermissionException("用户角色信息缺失，请重新登录");
        }

        String[] required = anno.value();
        boolean pass = anno.requireAll()
                ? Arrays.stream(required).allMatch(currentRoles::contains)
                : Arrays.stream(required).anyMatch(currentRoles::contains);

        if (!pass) {
            log.warn("[权限拦截] 角色不匹配, required={}, current={}",
                    Arrays.toString(required), currentRoles);
            throw new PermissionException("无权访问该资源，所需角色：" + Arrays.toString(required));
        }
        return true;
    }
}

// ===== 3. TaskController 使用示例 =====
@RestController
@RequestMapping("/tasks")
public class TaskController {

    @Autowired
    private TaskService taskService;

    // 教师或管理员可发布
    @PostMapping
    @RequireRole({"TCH", "ADMIN"})
    public Result<Void> publish(@RequestBody @Valid TaskDTO dto) {
        taskService.publish(dto);
        return Result.success();
    }

    // 仅管理员可删除
    @DeleteMapping("/{id}")
    @RequireRole({"ADMIN"})
    public Result<Void> delete(@PathVariable Long id) {
        taskService.deleteById(id);
        return Result.success();
    }

    // 所有登录用户可查看（无需 @RequireRole）
    @GetMapping("/{id}")
    public Result<TaskVO> getById(@PathVariable Long id) {
        return Result.success(taskService.getById(id));
    }
}

22-编程-02（★★★）

题目：请为 CTTS 项目设计并实现 GlobalExceptionHandler，要求处理以下五类异常并统一返回 Result<Void>：

  1. MethodArgumentNotValidException（参数校验异常，code=400）
  2. BusinessException（业务异常，code 取异常对象的 code）
  3. AuthException（认证异常，code=401，HTTP 401）
  4. PermissionException（权限异常，code=403，HTTP 403）
  5. Exception（兜底异常，code=500，HTTP 500，不暴露堆栈）

要求：参数校验异常的 msg 包含所有字段错误，使用 ; 分隔；兜底异常 msg 返回"系统繁忙，请稍后重试"，但日志中记录完整堆栈。

评分标准（满分 15 分）：

  • @RestControllerAdvice 与 @Slf4j 注解（1 分）。
  • 五类异常处理器完整（10 分，每类 2 分）。
  • 参数校验异常 msg 拼接正确（2 分）。
  • 兜底异常日志记录完整堆栈但不向前端暴露（2 分）。

参考答案：

package com.ctts.exception;

import com.ctts.common.Result;
import jakarta.validation.ConstraintViolation;
import jakarta.validation.ConstraintViolationException;
import lombok.extern.slf4j.Slf4j;
import org.springframework.http.HttpStatus;
import org.springframework.validation.BindException;
import org.springframework.validation.FieldError;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.ResponseStatus;
import org.springframework.web.bind.annotation.RestControllerAdvice;

import java.util.stream.Collectors;

@Slf4j
@RestControllerAdvice
public class GlobalExceptionHandler {

    // 1. 参数校验异常（@RequestBody @Valid）
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<Void> handleValidException(MethodArgumentNotValidException e) {
        String msg = e.getBindingResult().getFieldErrors().stream()
                .map(fe -> fe.getField() + ": " + fe.getDefaultMessage())
                .collect(Collectors.joining("; "));
        log.warn("[参数校验失败] {}", msg);
        return Result.fail(400, msg);
    }

    // 2. 业务异常
    @ExceptionHandler(BusinessException.class)
    public Result<Void> handleBusiness(BusinessException e) {
        log.warn("[业务异常] code={}, msg={}", e.getCode(), e.getMessage());
        return Result.fail(e.getCode(), e.getMessage());
    }

    // 3. 认证异常（401）
    @ExceptionHandler(AuthException.class)
    @ResponseStatus(HttpStatus.UNAUTHORIZED)
    public Result<Void> handleAuth(AuthException e) {
        log.warn("[认证异常] {}", e.getMessage());
        return Result.fail(401, e.getMessage());
    }

    // 4. 权限异常（403）
    @ExceptionHandler(PermissionException.class)
    @ResponseStatus(HttpStatus.FORBIDDEN)
    public Result<Void> handlePermission(PermissionException e) {
        log.warn("[权限异常] {}", e.getMessage());
        return Result.fail(403, e.getMessage());
    }

    // 5. 兜底异常（500）
    @ExceptionHandler(Exception.class)
    @ResponseStatus(HttpStatus.INTERNAL_SERVER_ERROR)
    public Result<Void> handleException(Exception e) {
        // 日志记录完整堆栈，便于排查
        log.error("[系统异常] 系统内部错误", e);
        // 前端只返回友好提示，不暴露堆栈
        return Result.fail(500, "系统繁忙，请稍后重试");
    }
}

关键点说明：

  • @Slf4j 提供日志支持。
  • @ResponseStatus 设置 HTTP 状态码，便于前端通过状态码识别异常类型。
  • 兜底异常 log.error("...", e) 第二个参数传入异常对象，Logback 会自动打印堆栈。
  • 返回 Result.fail(500, "系统繁忙") 不暴露 e.getMessage()，防止泄露系统细节。
