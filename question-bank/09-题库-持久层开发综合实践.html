一、单项选择题（30题）

09-D-01 ★

MyBatis-Plus 中，实体类与数据库表名映射的注解是？

  • A. @Table
  • B. @TableName
  • C. @Entity
  • D. @TableMap

答案：B 解析： MyBatis-Plus 用 @TableName("task") 指定实体类对应的表名。@Entity 是 JPA 注解，@Table 也是 JPA 体系，@TableMap 不存在。若实体类名与表名驼峰对应（如 Task → task），可省略该注解。

09-D-02 ★

@TableId(type = IdType.AUTO) 的含义是？

  • A. 主键使用雪花算法生成
  • B. 主键使用 UUID 生成
  • C. 主键由数据库自增
  • D. 主键由用户手动输入

答案：C 解析： IdType.AUTO 表示主键由数据库自增（AUTO_INCREMENT）。IdType.ASSIGN_ID 是雪花算法，IdType.ASSIGN_UUID 是 UUID，IdType.INPUT 是手动输入。

09-D-03 ★

实体类字段 projectId 对应数据库字段 project_id，下列说法正确的是？

  • A. 必须加 @TableField("project_id")
  • B. MyBatis-Plus 默认开启驼峰转下划线，可省略注解
  • C. 必须加 @Column("project_id")
  • D. 字段名必须改成 project_id

答案：B 解析： MyBatis-Plus 默认开启 map-underscore-to-camel-case，projectId 自动映射为 project_id，无需注解。@TableField 仅在命名规则不一致或需特殊配置时使用。@Column 是 JPA 注解。

09-D-04 ★★

关于 @TableLogic 注解，下列说法错误的是？

  • A. 标记逻辑删除字段
  • B. 执行 deleteById 时会变成 UPDATE 语句
  • C. 查询时会自动追加 WHERE deleted = 0
  • D. 删除字段必须叫 deleted

答案：D 解析： 字段名可以任意，如 is_deleted、del_flag 等，只需用 @TableLogic 标记并在全局配置中指定逻辑值。A、B、C 均正确。

09-D-05 ★

Mapper 接口继承 BaseMapper<T> 后，下列哪个方法不是默认提供的？

  • A. insert(T entity)
  • B. selectById(Serializable id)
  • C. selectByCondition(...)
  • D. deleteById(Serializable id)

答案：C 解析： selectByCondition 是自定义方法，需在 Mapper 中声明并在 XML 中实现。BaseMapper 默认提供 insert / deleteById / updateById / selectById / selectList / selectPage 等基础方法。

09-D-06 ★★

CTTS 中 task_submission 表的 task_id 字段是外键，指向 task.id。建表时该外键约束应写成？

  • A. FOREIGN KEY (task_id) REFERENCES task (id)
  • B. REFERENCES task (id) ON task_id
  • C. JOIN task ON task_id = task.id
  • D. CONSTRAINT task_id PRIMARY KEY

答案：A 解析： MySQL 外键语法为 CONSTRAINT 约束名 FOREIGN KEY (本表字段) REFERENCES 父表(父表字段)，约束名可省略。C 是 JOIN 语法，D 是主键语法。

09-D-07 ★★

@TableField(fill = FieldFill.INSERT) 的作用是？

  • A. 插入时该字段必填
  • B. 插入时由 MetaObjectHandler 自动填充
  • C. 该字段只在插入时查询
  • D. 该字段值固定为 INSERT

答案：B 解析： FieldFill.INSERT 表示插入时自动填充，需配合 MetaObjectHandler 实现类完成。常用于 create_time。FieldFill.INSERT_UPDATE 用于 update_time，插入和更新都填充。

09-D-08 ★

@TableField(select = false) 用在 deleted 字段上的作用是？

  • A. 禁止查询该表
  • B. 默认查询时不返回该字段
  • C. 该字段不参与逻辑删除
  • D. 该字段不能被更新

答案：B 解析： select = false 表示默认查询不返回该字段，常配合 @TableLogic 用在 deleted 字段，避免逻辑删除标志污染接口返回值。

09-D-09 ★★

@Param("studentId") 注解的作用是？

  • A. 给参数指定一个名字，供 XML 中 #{studentId} 引用
  • B. 限制参数类型
  • C. 给参数加密
  • D. 标记参数为必填

答案：A 解析： 当 Mapper 方法有多个参数时，需用 @Param 给每个参数起名，XML 中才能用 #{name} 引用。单参数时通常不需要，但建议加上以提升可读性。

09-D-10 ★

MyBatis XML 中，<where> 标签的核心作用是？

  • A. 替代 <if> 做条件判断
  • B. 自动添加 WHERE 关键字并去除首个多余的 AND/OR
  • C. 限制查询行数
  • D. 设置参数值

答案：B 解析： <where> 内部有内容时自动生成 WHERE，并去除首个条件前多余的 AND/OR；内部所有 <if> 都不成立时整个 WHERE 子句不生成。

09-D-11 ★★

对于数字类型字段 status，下列 <if> 写法正确的是？

  • A. <if test="status != null and status != ''">
  • B. <if test="status != ''">
  • C. <if test="status != null">
  • D. <if test="status">

答案：C 解析： 数字类型只需判 != null。status != '' 对数字无意义；<if test="status"> 在 status=0 时被判为 false，会漏掉有效值 0。

09-D-12 ★★

XML 中需要拼接 priority < 5，下列正确写法是？

  • A. <if test="priority < 5">
  • B. <if test="priority &lt; 5">
  • C. <if test="priority <![CDATA[<]]> 5">
  • D. B 和 C 都可以

答案：D 解析： XML 解析器会把 < 当作标签起始，需转义为 &lt; 或用 <![CDATA[<]]> 包裹。B、C 都正确。

09-D-13 ★★

<foreach> 标签的 collection 属性，当 Mapper 方法参数用 @Param("ids") 注解时，应填？

  • A. list
  • B. array
  • C. ids
  • D. collection

答案：C 解析： 用 @Param("ids") 显式命名后，collection 应填 ids。未用 @Param 且参数是 List 时默认 list；是数组时默认 array。

09-D-14 ★★

MyBatis-Plus 分页插件未注册时，调用 selectPage 会发生什么？

  • A. 抛出异常
  • B. 返回 null
  • C. 查出全部数据，不分页
  • D. 只返回第一页

答案：C 解析： 未注册分页插件时，MyBatis-Plus 不会拼接 LIMIT，selectPage 会查出所有满足条件的数据，total 等于全部记录数，分页失效。

09-D-15 ★

注册 MyBatis-Plus 分页插件时，需要添加的内部拦截器是？

  • A. PaginationInnerInterceptor
  • B. PageInterceptor
  • C. LimitInterceptor
  • D. PaginationExecutor

答案：A 解析： MyBatis-Plus 3.x 用 MybatisPlusInterceptor 作为容器，内部添加 PaginationInnerInterceptor(DbType.MYSQL) 实现分页。

09-D-16 ★★

QueryWrapper 与 LambdaQueryWrapper 的主要区别是？

  • A. 功能不同
  • B. LambdaQueryWrapper 用方法引用避免硬编码字段名
  • C. QueryWrapper 性能更好
  • D. LambdaQueryWrapper 不支持排序

答案：B 解析： 两者功能等价。LambdaQueryWrapper 用 Task::getTitle 这样的方法引用替代字符串 "title"，编译期就能检查字段名，重构时更安全。性能无差异。

09-D-17 ★★

多表 JOIN 查询时，两表都有 id、status 字段，正确的处理方式是？

  • A. 不用管，MyBatis 自动区分
  • B. 在 SQL 中用别名区分（如 s.id AS s_id, t.id AS t_id）
  • C. 删除其中一个表的同名字段
  • D. 只查一个表的字段

答案：B 解析： JDBC 结果集按列名取值，同名列会被覆盖。必须用 AS 别名区分，resultMap 中用别名列名映射。

09-D-18 ★★★

resultMap 中 <association> 标签用于？

  • A. 一对多关系映射
  • B. 一对一或多对一关系映射
  • C. 集合映射
  • D. 主键映射

答案：B 解析： <association> 用于"一对一"或"多对一"关系嵌套，如一个提交对应一个任务。<collection> 用于"一对多"，如一个任务对应多个提交。

09-D-19 ★★

@Select 注解与 XML <select> 的关系是？

  • A. 二者冲突，不能共存
  • B. 功能等价，简单 SQL 用注解，复杂动态 SQL 用 XML
  • C. 注解性能更好
  • D. XML 性能更好

答案：B 解析： 两者功能等价。@Select 适合简单静态 SQL（如统计查询）；XML 适合动态 SQL（<if>、<foreach>）和复杂 resultMap。性能无差异。

09-D-20 ★★

CTTS 中 task_review 表的 score 字段类型是 DECIMAL(5,2)，Java 实体类中对应类型应为？

  • A. Double
  • B. Float
  • C. BigDecimal
  • D. Integer

答案：C 解析： 金额、评分等需要精确小数的字段应使用 BigDecimal，避免 Double/Float 的浮点精度问题。DECIMAL(5,2) 表示共 5 位、小数 2 位，最大 999.99。

09-D-21 ★★

实体类继承 BaseMapper<T> 时，T 必须满足？

  • A. 必须实现 Serializable
  • B. 必须有无参构造
  • C. 必须是 final 类
  • D. 必须继承某个父类

答案：B 解析： MyBatis 反射实例化实体类时需要无参构造。推荐用 @Data（Lombok）自动生成。Serializable 不是必须，但分布式场景建议实现。

09-D-22 ★★★

<association> 的嵌套结果映射（JOIN + association）与嵌套查询映射（association + select）相比，主要优势是？

  • A. 代码更简洁
  • B. 一次 SQL 完成查询，避免 N+1 问题
  • C. 支持更多表关联
  • D. 不需要写 resultMap

答案：B 解析： 嵌套结果用 JOIN 一次 SQL 拿全所有字段，在内存组装对象；嵌套查询对每条主表记录发一条子查询，主表 N 条就发 N+1 次 SQL，性能差。一对一关系优先用嵌套结果。

09-D-23 ★★

下列哪种情况会导致 Invalid bound statement (not found) 错误？

  • A. XML 的 namespace 与 Mapper 接口全限定名不一致
  • B. XML 中 <select id> 与 Mapper 方法名不一致
  • C. application.yml 中 mapper-locations 路径配置错误
  • D. 以上都是

答案：D 解析： 三种情况都会导致 MyBatis 找不到对应语句。此外，XML 文件未被编译到 target/classes 也会触发此错误。

09-D-24 ★★

Page<Task> page = new Page<>(2, 10) 中，参数 2 和 10 分别表示？

  • A. 偏移量、每页条数
  • B. 当前页码、每页条数
  • C. 起始行、结束行
  • D. 总页数、总记录数

答案：B 解析： Page(current, size) 第一个参数是当前页码（从 1 开始），第二个是每页条数。Page(2, 10) 表示查第 2 页，每页 10 条，对应 SQL LIMIT 10 OFFSET 10。

09-D-25 ★★★

CTTS 综合示例中 TaskSubmissionVO extends TaskSubmission，再添加 private Task task 字段。这种设计的目的是？

  • A. 减少实体类数量
  • B. 在不污染原实体的前提下承载多表关联结果
  • C. 提高查询性能
  • D. 满足 MyBatis 强制要求

答案：B 解析： VO（View Object）用于承载查询结果，避免在 TaskSubmission 中加 task 字段破坏单表映射。继承原实体并扩展关联字段，是常见做法。

09-D-26 ★★

@TableField(fill = FieldFill.INSERT_UPDATE) 通常用在哪个字段？

  • A. id
  • B. create_time
  • C. update_time
  • D. deleted

答案：C 解析： INSERT_UPDATE 表示插入和更新都填充，update_time 在创建和修改时都要更新。create_time 用 INSERT，id 用 @TableId，deleted 用 @TableLogic。

09-D-27 ★★

XML 中 <where> 标签内部所有 <if> 都不成立时，生成的 SQL 是？

  • A. WHERE
  • B. WHERE 1=1
  • C. 不生成 WHERE 子句
  • D. 报错

答案：C 解析： <where> 会判断内部是否有内容，若所有 <if> 都不成立，则整个 WHERE 子句不生成，避免出现 WHERE 关键字后无条件的语法错误。

09-D-28 ★★

@TableLogic 标记 deleted 字段后，执行 taskMapper.deleteById(1L)，实际执行的 SQL 是？

  • A. DELETE FROM task WHERE id = 1
  • B. UPDATE task SET deleted = 1 WHERE id = 1
  • C. UPDATE task SET deleted = 0 WHERE id = 1
  • D. SELECT * FROM task WHERE id = 1

答案：B 解析： 逻辑删除下，deleteById 被改写为 UPDATE，将 deleted 设为删除标志值（默认 1）。物理 DELETE 不再执行。

09-D-29 ★★★

关于外键约束 ON DELETE CASCADE，下列说法正确的是？

  • A. 父表删除时子表对应记录也被自动删除
  • B. 子表删除时父表对应记录也被删除
  • C. 父表删除时禁止操作
  • D. 子表外键自动置空

答案：A 解析： ON DELETE CASCADE 表示级联删除：父表记录删除时，子表中引用它的记录自动删除。ON DELETE RESTRICT 是禁止删除有引用的父记录，ON DELETE SET NULL 是子表外键置空。

09-D-30 ★★

application.yml 中开启 SQL 日志输出的配置项是？

  • A. mybatis-plus.configuration.log-impl: org.apache.ibatis.logging.stdout.StdOutImpl
  • B. logging.level.sql=DEBUG
  • C. spring.datasource.log=true
  • D. mybatis-plus.show-sql=true

答案：A 解析： MyBatis-Plus 通过 log-impl: org.apache.ibatis.logging.stdout.StdOutImpl 在控制台输出 SQL、参数、结果。B 是 Spring 日志级别，不针对 MyBatis；D 不存在。

二、多项选择题（10题）

09-M-01 ★

本次课涉及的三张表是？

  • A. task
  • B. task_submission
  • C. task_review
  • D. sys_user

答案：A、B、C 解析： 第9次课交付 task、task_submission、task_review 三张表。sys_user、training_project 在前序课程已完成。

09-M-02 ★★

继承 BaseMapper<Task> 后，可直接使用的方法有？

  • A. insert(Task)
  • B. selectById(Long)
  • C. selectByCondition(...)
  • D. selectList(QueryWrapper)
  • E. selectPage(Page, QueryWrapper)

答案：A、B、D、E 解析： A、B、D、E 都是 BaseMapper 默认方法。C 是自定义方法，需在 Mapper 中声明并实现。

09-M-03 ★★

实体类 Task 上用到的注解有？

  • A. @TableName
  • B. @TableId
  • C. @TableField
  • D. @TableLogic
  • E. @Entity

答案：A、B、C、D 解析： @TableName 标表名、@TableId 标主键、@TableField 标字段填充/查询策略、@TableLogic 标逻辑删除。@Entity 是 JPA 注解，MyBatis-Plus 不使用。

09-M-04 ★★

下列属于 MyBatis 动态 SQL 标签的有？

  • A. <if>
  • B. <where>
  • C. <foreach>
  • D. <switch>
  • E. <set>

答案：A、B、C、E 解析： MyBatis 动态 SQL 标签包括 <if>、<where>、<foreach>、<choose>、<when>、<otherwise>、<set>、<trim>、<bind>。<switch> 不存在，对应功能用 <choose> 实现。

09-M-05 ★★

MyBatis-Plus 分页插件正确使用的前提条件有？

  • A. 注册 MybatisPlusInterceptor
  • B. 添加 PaginationInnerInterceptor
  • C. 指定数据库类型 DbType
  • D. 在 Mapper 中重写 selectPage 方法
  • E. 实体类实现 Serializable

答案：A、B、C 解析： 分页插件需注册 MybatisPlusInterceptor 并添加 PaginationInnerInterceptor(DbType.MYSQL)。selectPage 是 BaseMapper 默认方法，无需重写。Serializable 非必须。

09-M-06 ★★

resultMap 中可用的子标签有？

  • A. <id>
  • B. <result>
  • C. <association>
  • D. <collection>
  • E. <join>

答案：A、B、C、D 解析： <id> 映射主键、<result> 映射普通字段、<association> 映射一对一/多对一、<collection> 映射一对多。<join> 不存在，JOIN 是 SQL 层操作。

09-S-02 ★★★

请详细说明 resultMap 中 <association> 嵌套结果映射与嵌套查询映射的区别，以及各自的优缺点。

评分标准（满分 10 分）：

  • 说明嵌套结果映射的原理（3 分）
  • 说明嵌套查询映射的原理（3 分）
  • 对比优缺点（N+1 问题、SQL 次数）（4 分）

参考答案：

  1. 嵌套结果映射：通过 JOIN 一次 SQL 查出所有字段，在内存中按 resultMap 组装嵌套对象。SQL 次数少，无 N+1 问题，适合一对一关系。缺点是 SQL 较复杂，resultMap 配置繁琐。
  2. 嵌套查询映射：先查主表，再对每条主表记录发一条子查询（通过 <association select="..."> 指定）。代码结构清晰，子查询可复用。缺点是产生 N+1 问题——主表 N 条记录就发 N+1 次 SQL，性能差。
  3. 选择建议：一对一优先用嵌套结果（JOIN）；一对多若数据量小可用嵌套查询，数据量大用嵌套结果；可开启 lazyLoadingEnabled 延迟加载缓解 N+1。本次课综合示例采用嵌套结果，一次 SQL 查出提交及关联任务。

09-S-03 ★★

评分标准（满分 8 分）：

  • 说明分页插件工作原理（4 分）
  • 说明未注册时的现象（2 分）
  • 说明如何正确注册（2 分）

参考答案：

  1. 工作原理：PaginationInnerInterceptor 拦截 MyBatis 执行的 SQL，在 SQL 执行前做两件事：①把原 SQL 改写为 SELECT COUNT(*) 查询总记录数，填充到 Page.getTotal()；②在原 SQL 末尾追加 LIMIT offset, size 实现分页。
  2. 未注册时的现象：selectPage 不会抛异常，但不会拼接 LIMIT，查出全部满足条件的数据；total 等于全部记录数，分页失效。
  3. 注册方式：在配置类中 @Bean public MybatisPlusInterceptor mybatisPlusInterceptor() { MybatisPlusInterceptor i = new MybatisPlusInterceptor(); i.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL)); return i; }。

XML 映射：

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="com.ctts.mapper.TaskSubmissionMapper">

    <resultMap id="SubmissionWithTaskMap" type="com.ctts.vo.TaskSubmissionVO">
        <id     column="s_id"          property="id"/>
        <result column="s_task_id"     property="taskId"/>
        <result column="s_student_id"  property="studentId"/>
        <result column="s_content"     property="content"/>
        <result column="s_file_url"    property="fileUrl"/>
        <result column="s_status"      property="status"/>
        <result column="s_submit_time" property="submitTime"/>
        <result column="s_create_time" property="createTime"/>
        <association property="task" javaType="com.ctts.entity.Task">
            <id     column="t_id"          property="id"/>
            <result column="t_project_id"  property="projectId"/>
            <result column="t_title"       property="title"/>
            <result column="t_priority"    property="priority"/>
            <result column="t_status"      property="status"/>
            <result column="t_end_time"    property="endTime"/>
        </association>
    </resultMap>

    <select id="selectSubmissionsWithTask" resultMap="SubmissionWithTaskMap">
        SELECT
               s.id           AS s_id,
               s.task_id      AS s_task_id,
               s.student_id   AS s_student_id,
               s.content      AS s_content,
               s.file_url     AS s_file_url,
               s.status       AS s_status,
               s.submit_time  AS s_submit_time,
               s.create_time  AS s_create_time,
               t.id           AS t_id,
               t.project_id   AS t_project_id,
               t.title        AS t_title,
               t.priority     AS t_priority,
               t.status       AS t_status,
               t.end_time     AS t_end_time
          FROM task_submission s
          INNER JOIN task t ON s.task_id = t.id
         WHERE s.student_id = #{studentId}
           AND s.deleted = 0
           AND t.deleted = 0
         ORDER BY s.submit_time DESC
    </select>

</mapper>

关键说明：

  1. VO 继承实体：TaskSubmissionVO extends TaskSubmission 复用单表字段映射，扩展 Task task 承载关联结果；
  2. 列别名：JOIN 后两表有同名字段（id、status），用 s_ / t_ 前缀区分；
  3. <association>：一对一关系嵌套，property 是 VO 中的属性名 task，javaType 指定类型；
  4. INNER JOIN：业务上每条提交必有对应任务，用 INNER JOIN 性能优于 LEFT JOIN；
  5. 逻辑删除：两表都要加 deleted = 0 条件，避免查出已删除的任务或提交。
