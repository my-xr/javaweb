一、单项选择题（30题）

18-DAN-01 ★

CTTS系统中，下列属于"非功能需求"的是（ ）。

  • A
    学生可以提交任务成果
  • B
    教师可以对提交打分
  • C
    列表查询响应时间不超过500ms
  • D
    管理员可以审核项目

答案：C 解析：功能需求描述系统"做什么"（A/B/D均为具体功能），非功能需求描述系统"做得多好"（C属于性能要求）。CTTS的非功能需求还包括安全、可用性、可维护性等。

18-DAN-02 ★

在需求拆解方法中，"系统→模块→功能→用例"的拆解思路属于（ ）。

  • A
    自顶向下
  • B
    自底向上
  • C
    原型驱动
  • D
    敏捷开发

答案：A 解析：自顶向下从系统整体出发，逐层细化到模块、功能、用例；自底向上从用户故事聚合到模块。CTTS需求分析采用自顶向下方法。

18-DAN-03 ★

ER图的三要素是（ ）。

  • A
    实体、属性、主键
  • B
    实体、属性、关系
  • C
    表、字段、外键
  • D
    类、方法、属性

答案：B 解析：ER图三要素为实体（矩形）、属性（椭圆）、关系（菱形）。主键和外键是关系模型的实现，不是ER图基本要素。

18-DAN-04 ★

在数据库中实现"一对多"关系的方法是（ ）。

  • A
    在"一"的一方加外键
  • B
    在"多"的一方加外键引用"一"的一方主键
  • C
    建立中间表
  • D
    合并为一张表

答案：B 解析：一对多关系通过在"多"的一方加外键实现。例如一个项目有多个任务，在task表中加project_id外键引用training_project.id。中间表用于多对多关系。

18-DAN-05 ★

CTTS中training_project表与task表的关系是（ ）。

  • A
    一对一
  • B
    一对多
  • C
    多对多
  • D
    无关系

答案：B 解析：一个项目包含多个任务，一个任务只属于一个项目，属于一对多关系。task表通过project_id外键引用training_project.id。

18-DAN-06 ★

下列关于数据库第一范式（1NF）的说法，正确的是（ ）。

  • A
    非主属性必须完全依赖主键
  • B
    字段必须原子性，不可再分
  • C
    消除传递依赖
  • D
    必须有外键

答案：B 解析：1NF要求字段原子性，每个字段不可再分。A是2NF的要求，C是3NF的要求。外键不是范式要求。

18-DAN-07 ★

下列符合第二范式（2NF）要求的是（ ）。

  • A
    字段不可再分
  • B
    非主属性完全依赖主键
  • C
    非主属性不传递依赖主键
  • D
    所有字段必须有默认值

答案：B 解析：2NF要求非主属性完全依赖主键，主要针对复合主键场景。A是1NF，C是3NF。D与范式无关。

18-DAN-08 ★

CTTS的5张表均满足第三范式（3NF），其核心原因是（ ）。

  • A
    所有表都有主键
  • B
    所有表都使用了BIGINT类型
  • C
    通过外键拆分实体，不在表中冗余其他实体的非主属性
  • D
    所有字段都加了注释

答案：C 解析：3NF要求非主属性不传递依赖主键。CTTS通过外键关联获取其他实体信息，不在表中冗余存储（如不在task表中存项目名称），从而消除传递依赖，满足3NF。

18-DAN-09 ★

MySQL中，创建数据库并指定字符集为utf8mb4的正确语句是（ ）。

  • A
    CREATE DATABASE ctts CHARSET utf8mb4;
  • B
    CREATE DATABASE ctts DEFAULT CHARACTER SET utf8mb4;
  • C
    CREATE DATABASE ctts SET utf8mb4;
  • D
    CREATE DATABASE ctts WITH CHARSET utf8mb4;

答案：B 解析：MySQL创建数据库指定字符集的标准语法为CREATE DATABASE 库名 DEFAULT CHARACTER SET 字符集。utf8mb4支持emoji字符。

18-DAN-10 ★

CTTS建表时，存储引擎选择InnoDB而非MyISAM，主要原因是（ ）。

  • A
    InnoDB查询速度更快
  • B
    InnoDB支持事务和外键
  • C
    MyISAM不支持VARCHAR
  • D
    MyISAM不支持主键

答案：B 解析：InnoDB支持事务、行级锁和外键约束，适合关系型业务系统。MyISAM不支持事务和外键，CTTS表间有外键关系，必须使用InnoDB。

18-DAN-11 ★

CTTS中sys_user表的username字段应建立的索引类型是（ ）。

  • A
    主键索引
  • B
    唯一索引
  • C
    普通索引
  • D
    全文索引

答案：B 解析：username用于登录且必须保证唯一，应建唯一索引（UNIQUE KEY）。主键已用于id。普通索引不保证唯一性，不适用于username。

18-DAN-12 ★

下列关于主键索引的说法，错误的是（ ）。

  • A
    主键索引随PRIMARY KEY自动创建
  • B
    主键索引要求列值唯一且非空
  • C
    一张表只能有一个主键索引
  • D
    主键索引可以加速写入

答案：D 解析：索引会加速查询但拖慢写入（写入时需同步维护索引结构）。A/B/C均正确。

18-DAN-13 ★★

CTTS中，task_submission表同时包含task_id和user_id两个外键，其业务语义是（ ）。

  • A
    一条提交属于一个任务且由一个学生提交
  • B
    一条提交属于多个任务
  • C
    一条提交由多个学生共同完成
  • D
    一条提交无明确归属

答案：A 解析：task_id引用task表，表示提交针对哪个任务；user_id引用sys_user表，表示提交者是谁。两个外键共同确定"谁提交了哪个任务"。

18-DAN-14 ★★

下列CTTS字段设计中最合理的是（ ）。

  • A
    id INT AUTO_INCREMENT PRIMARY KEY
  • B
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY
  • C
    id VARCHAR(50) PRIMARY KEY
  • D
    id DOUBLE PRIMARY KEY

答案：B 解析：ID推荐使用BIGINT UNSIGNED，预留扩展空间且支持大数量。INT可能不够用，VARCHAR主键性能差，DOUBLE不适合做主键。

18-DAN-15 ★★

在CTTS的建表脚本中，下列外键约束命名最规范的是（ ）。

    fk1
  • B
    foreign_key_1
  • C
    fk_task_project
  • D
    task_project_fk

答案：C 解析：外键命名规范为fk_子表_引用表，如fk_task_project表示task表引用training_project表。语义清晰，便于维护。

18-DAN-16 ★★

CTTS中，下列哪种情况不建议建立索引（ ）。

  • A
    sys_user.username（登录查询）
  • B
    sys_user.role（按角色筛选）

    task_submission.status（仅2个取值）

18-DAN-17 ★★

18-DAN-18 ★★

执行CTTS建表脚本时，若先创建task表再创建training_project表，会出现的错误是（ ）。

  • B

18-DAN-19 ★★

CTTS中，若在task_submission表插入一条task_id为9999（不存在）的记录，MySQL会（ ）。

  • A
    正常插入
  • B

  • C
    自动将task_id改为NULL
  • D
    自动创建task_id为9999的任务

18-DAN-20 ★★

下列关于数据库范式的描述，正确的是（ ）。

  • A
    满足3NF一定满足2NF和1NF
  • B
    范式级别越高，查询性能一定越好
  • C
    反范式设计是错误的，必须严格遵循3NF
  • D
    1NF要求消除传递依赖

答案：A 解析：范式级别递进，满足3NF则必然满足2NF和1NF。B错误，范式过高可能导致JOIN增多、查询变慢。C错误，实际项目可适度反范式。D错误，1NF要求字段原子性。

18-DAN-23 ★★

18-DAN-24 ★★★

CTTS中若要支持"一个任务可由多个学生共同提交（小组任务）"，现有task_submission表的设计（ ）。

18-DAN-25 ★★★

18-DUO-02 ★

CTTS中包含的外键关系有（ ）。

  • A
    training_project.teacher_id → sys_user.id
  • B
    task.project_id → training_project.id
  • C
    task_submission.task_id → task.id

  1. training_project.teacher_id → sys_user.id（项目属于一个教师）

18-LUN-03 ★★★

请结合CTTS的task_submission表，分析其设计如何满足第三范式（3NF），并说明若在该表中冗余存储"任务标题"会带来什么问题。

参考答案： task_submission表设计满足3NF的分析：

  • 1NF：每个字段（task_id、user_id、content、file_url、submit_time、status）都是原子性的，不可再分。
  • 2NF：主键为单列id，所有非主属性（content、file_url等）完全依赖id，不存在部分依赖。
  • 3NF：非主属性间无传递依赖。task_submission不冗余存储任务标题、学生姓名，而是通过task_id、user_id外键关联获取。如需任务标题，JOIN task表获取。

若在task_submission中冗余存储"任务标题"的问题：

  1. 数据冗余：同一任务的多次提交会重复存储任务标题，浪费空间。
  2. 更新异常：当task表中的任务标题被修改时，task_submission中的冗余字段若未同步更新，会导致数据不一致。
  3. 插入异常：若某任务暂无提交，无法在task_submission中记录其标题。
  4. 删除异常：若删除某任务的所有提交，任务标题信息也随之丢失（虽然task表仍有，但冗余字段消失）。

这正是3NF要避免的传递依赖问题：任务标题依赖task.id，task.id依赖submission.id，形成传递依赖。消除传递依赖即满足3NF。

评分标准（满分10分）：

  • 1NF/2NF/3NF分析正确（4分）
  • 结合task_submission具体说明（2分）
  • 冗余存储问题列举完整（4分，每个问题1分）

18-LUN-04 ★★★

CTTS中sys_user表的username建立了唯一索引，role建立了普通索引。请论述索引的作用、代价，以及"何时建索引"的判断依据。

参考答案： 索引的作用：

  • 索引是数据库中用于加速查询的数据结构（默认B+树）。
  • 类比书籍目录，通过索引快速定位数据，避免全表扫描。
  • 例如username建索引后，登录查询WHERE username='stu001'可快速定位记录。

索引的代价：

  • 空间代价：索引占用额外存储空间。
  • 写入代价：INSERT/UPDATE/DELETE时需同步维护索引结构，拖慢写入性能。
  • 维护代价：索引过多增加数据库优化器的选择成本。

何时建索引的判断依据：

  1. 查询频繁：经常作为WHERE条件的列（如role常用于按角色筛选）。
  2. 区分度高：取值多样的列（如username区分度高；性别区分度低不适合）。
  3. JOIN关联列：外键列常用于JOIN，通常建索引（如task_submission.task_id）。
  4. 排序分组列：经常用于ORDER BY/GROUP BY的列。
  5. 数据量大：小表全表扫描更快，不必建索引。

何时不建索引：

  1. 数据量小的表。
  2. 区分度低的列（如status仅2-3个取值）。
  3. 写入极频繁、查询少的列。
  4. 频繁更新的列。

CTTS索引决策：

  • username：登录查询频繁，且需保证唯一，建唯一索引。
  • role：按角色筛选用户，区分度尚可（3值），建普通索引。
  • 外键列：常用于JOIN，建普通索引（如project_id、teacher_id）。
  • status：区分度低，是否建索引视查询频率而定，CTTS中可暂不建。

评分标准（满分10分）：

  • 索引作用阐述（2分）
  • 索引代价阐述（2分）
  • 何时建/不建索引的判断依据（4分）
  • 结合CTTS实例说明（2分）

18-BJ-01 ★★★

请根据CTTS需求，编写完整的task_review（评审表）建表SQL，要求：

  1. 包含id、submission_id、reviewer_id、score、comment、review_time字段。
  2. submission_id外键引用task_submission.id，reviewer_id外键引用sys_user.id。
  3. 外键命名规范为fk_子表_引用表。
  4. 为submission_id和reviewer_id建立普通索引。
  5. 字段类型合理，必填字段NOT NULL，每个字段添加COMMENT注释。
  6. 存储引擎InnoDB，字符集utf8mb4。

参考答案：

DROP TABLE IF EXISTS task_review;
CREATE TABLE task_review (
    id            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '评审ID',
    submission_id BIGINT UNSIGNED NOT NULL            COMMENT '提交ID（引用task_submission.id）',
    reviewer_id   BIGINT UNSIGNED NOT NULL            COMMENT '评审教师ID（引用sys_user.id）',
    score         INT           NOT NULL             COMMENT '评分',
    comment       VARCHAR(500)          DEFAULT NULL  COMMENT '评审评语',
    review_time   DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '评审时间',
    PRIMARY KEY (id),
    KEY idx_review_submission (submission_id),
    KEY idx_review_reviewer (reviewer_id),
    CONSTRAINT fk_review_submission FOREIGN KEY (submission_id) REFERENCES task_submission (id),
    CONSTRAINT fk_review_reviewer   FOREIGN KEY (reviewer_id)   REFERENCES sys_user (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='任务评审表';

解析：

  • id为BIGINT UNSIGNED主键自增。
  • submission_id和reviewer_id为外键，分别引用task_submission.id和sys_user.id。
  • 外键命名遵循fk_子表_引用表规范：fk_review_submission、fk_review_reviewer。
  • 为submission_id和reviewer_id建普通索引（常用于JOIN查询）。
  • score为INT类型，NOT NULL（评审必须有分数）。
  • comment允许NULL（评语可选）。
  • review_time默认当前时间。
  • 存储引擎InnoDB，字符集utf8mb4。

评分标准（满分15分）：

  • 字段定义完整、类型合理（5分）
  • 外键关系正确、命名规范（4分）
  • 索引建立正确（2分）
  • 约束与注释规范（2分）
  • 存储引擎与字符集正确（2分）

-- 1. 创建数据库
DROP DATABASE IF EXISTS ctts;
CREATE DATABASE ctts DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
USE ctts;

-- 2. 创建用户表
DROP TABLE IF EXISTS sys_user;
CREATE TABLE sys_user (
    id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '用户ID',
    username    VARCHAR(50)  NOT NULL                COMMENT '登录用户名',
    password    VARCHAR(100) NOT NULL                COMMENT '密码（BCrypt加密）',
    real_name   VARCHAR(50)  NOT NULL                COMMENT '真实姓名',
    role        TINYINT      NOT NULL                COMMENT '角色：1学生 2教师 3管理员',
    phone       VARCHAR(20)           DEFAULT NULL   COMMENT '手机号',
    email       VARCHAR(100)          DEFAULT NULL   COMMENT '邮箱',
    status      TINYINT      NOT NULL DEFAULT 1      COMMENT '状态：1正常 0禁用',
    create_time DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (id),
    UNIQUE KEY uk_user_username (username),
    KEY idx_user_role (role)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';

-- 3. 创建实训项目表
DROP TABLE IF EXISTS training_project;
CREATE TABLE training_project (
    id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '项目ID',
    title       VARCHAR(100) NOT NULL                COMMENT '项目标题',
    description VARCHAR(500)          DEFAULT NULL   COMMENT '项目描述',
    teacher_id  BIGINT UNSIGNED NOT NULL              COMMENT '负责教师ID（引用sys_user.id）',
    start_date  DATE          NOT NULL               COMMENT '开始日期',
    end_date    DATE          NOT NULL               COMMENT '结束日期',
    status      TINYINT       NOT NULL DEFAULT 1     COMMENT '状态：1待发布 2进行中 3已结束 4已下线',
    create_time DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (id),
    KEY idx_project_teacher (teacher_id),
    CONSTRAINT fk_project_teacher FOREIGN KEY (teacher_id) REFERENCES sys_user (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='实训项目表';
