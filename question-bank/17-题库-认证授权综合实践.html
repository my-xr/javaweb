一、单项选择题（30题）

17-XZ-01 ★

题目：CTTS系统中用户密码加密采用BCrypt，下列关于BCrypt的说法正确的是？ A. 同一明文每次加密结果相同 B. 加密结果以$2a$开头，包含盐值信息 C. BCrypt是可逆加密，可通过密文还原明文 D. BCrypt加密速度比MD5快

答案：B 解析：BCrypt每次加密会生成不同盐值，同一明文加密结果不同（A错）；它是单向不可逆哈希（C错）；由于自带盐值和慢哈希设计，加密速度比MD5慢（D错），这正是其防彩虹表、防暴力破解的优势。加密结果格式为$2a$10$...，其中$2a$是版本标识，10是cost因子，后面22位是盐值，31位是哈希值。

17-XZ-02 ★

题目：JWT Token由三部分组成，分别是？ A. Header、Payload、Signature B. Header、Body、Footer C. Token、Secret、Expire D. Username、Role、Timestamp

答案：A 解析：JWT（JSON Web Token）由Header（头部，含算法类型）、Payload（载荷，含用户声明）、Signature（签名，防篡改）三部分组成，用.连接，形如xxxxx.yyyyy.zzzzz。

17-XZ-03 ★

题目：CTTS登录成功后返回的JWT Token中，不应该包含以下哪个字段？ A. userId B. username C. role D. password

答案：D 解析：JWT的Payload虽然Base64解码可见，但仍不应放入敏感信息。password属于高敏感字段，绝不能放入Token。userId、username、role是业务必需的声明字段。

17-XZ-04 ★★

题目：在JwtUtil中生成Token时，signWith(key)使用的签名算法是？ A. HS256（HMAC-SHA256） B. RS256（RSA-SHA256） C. none D. MD5

答案：A 解析：本项目使用Keys.hmacShaKeyFor(secret)生成密钥，配合signWith(key)默认使用HS256对称签名算法。RS256是非对称算法需公私钥对；none不安全已被禁用；MD5不是JWT支持的签名算法。

17-XZ-05 ★★

题目：LoginInterceptor中解析Token后，将用户信息存入ThreadLocal的主要目的是？ A. 减少数据库查询次数 B. 方便后续业务代码获取当前用户 C. 加快Token解析速度 D. 防止Token被篡改

答案：B 解析：ThreadLocal实现请求线程内共享用户信息，业务层通过CurrentUserContext.getUserId()直接获取，无需层层传参。同时避免每个接口都查库（A也算部分原因但非主要目的）。Token解析在拦截器中已做，ThreadLocal不影响速度和防篡改。

17-XZ-06 ★★★

题目：LoginInterceptor.afterCompletion中必须调用CurrentUserContext.remove()的根本原因是？ A. 释放ThreadLocal对象本身占用的内存 B. 防止Tomcat线程池复用线程时残留上一个用户信息 C. 防止内存溢出 D. Spring框架强制要求

答案：B 解析：Tomcat默认使用线程池复用线程，若请求结束后未清理ThreadLocal，下一次请求复用该线程时会读到上一个用户的信息，导致用户串号——这是典型的"测试通过但生产事故"问题。remove()清除的是线程局部变量中的Entry值，防止串号。

17-XZ-07 ★★

题目：关于@RequireRole注解的@Retention策略，正确的是？ A. RetentionPolicy.SOURCE——编译期丢弃 B. RetentionPolicy.CLASS——字节码保留但运行时不可反射读取 C. RetentionPolicy.RUNTIME——运行时可反射读取 D. 任意策略均可

答案：C 解析：RoleInterceptor需要在运行时通过反射读取@RequireRole注解，因此必须使用RetentionPolicy.RUNTIME。SOURCE和CLASS策略运行时反射读取不到。

17-XZ-08 ★★

题目：WebMvcConfig中注册拦截器时，LoginInterceptor的order=1、RoleInterceptor的order=2，这意味着？ A. RoleInterceptor先执行 B. LoginInterceptor先执行 C. 两者并行执行 D. 执行顺序随机

答案：B 解析：order值越小优先级越高，越先执行。必须LoginInterceptor先执行解析Token、存入ThreadLocal，RoleInterceptor才能从ThreadLocal读到角色进行权限校验。顺序反了会导致RoleInterceptor读到null。

17-XZ-09 ★

题目：前端访问需认证接口时，Token应放在HTTP请求头的哪个字段？ A. Cookie B. X-Token C. Authorization: Bearer {token} D. Token

答案：C 解析：标准做法是放在Authorization头，格式为Bearer {token}（注意Bearer后有空格）。本项目LoginInterceptor据此解析authHeader.substring(7)截取token。

17-XZ-10 ★★

题目：注册接口POST /api/auth/register在WebMvcConfig中被excludePathPatterns排除，原因是？ A. 该接口不需要数据库操作 B. 注册时用户尚未登录，无Token可校验 C. 该接口性能要求高 D. 该接口仅供管理员调用

答案：B 解析：注册和登录是认证入口，用户此时尚无Token，必须放行。若被拦截器拦截会因无Token返回401，导致无法注册登录。

17-XZ-11 ★★

题目：BCrypt的passwordEncoder.matches(rawPassword, encodedPassword)方法，参数顺序正确的是？ A. (密文, 明文) B. (明文, 密文) C. (明文, 明文) D. (密文, 密文)

答案：B 解析：matches第一个参数是用户输入的明文密码，第二个是数据库存储的BCrypt密文。方法内部会从密文中提取盐值对明文进行同样加密后比对。

17-XZ-12 ★★

题目：JWT的Payload部分使用什么编码方式？ A. AES加密 B. Base64Url编码（可解码） C. SHA-256哈希 D. RSA加密

答案：B 解析：JWT的Header和Payload都用Base64Url编码（不是加密），任何人都能解码查看内容。因此Payload不能放敏感信息。只有Signature部分是加密签名。

17-XZ-13 ★

题目：CTTS系统中三角色分别是？ A. USER、ADMIN、ROOT B. STUDENT、TEACHER、ADMIN C. GUEST、USER、ADMIN D. STUDENT、TEACHER、MANAGER

答案：B 解析：CTTS（校园实训任务管理系统）三角色为学生、教师、管理员，对应角色码STUDENT、TEACHER、ADMIN。

17-XZ-14 ★★

题目：登录接口返回的数据结构中，userInfo对象故意不包含password字段，这种做法称为？ A. 数据脱敏 B. 数据加密 C. 数据压缩 D. 数据校验

答案：A 解析：返回给前端时清空或过滤敏感字段（如password）称为数据脱敏，防止敏感信息泄露。在UserServiceImpl的getCurrentUserInfo中通过user.setPassword(null)实现。

17-XZ-15 ★★★

题目：下列哪种情况下JWT Token会被判定为非法（返回401）？ A. Token未过期但用户已被禁用 B. Token过期 C. Token被篡改 D. 以上都是

答案：D 解析：Token过期会抛ExpiredJwtException；被篡改会导致签名校验失败抛JwtException；用户被禁用虽Token合法但业务层应主动校验status。本项目拦截器主要处理B和C，A需要在业务层额外判断。

17-XZ-16 ★★

题目：HandlerInterceptor接口的三个方法执行顺序是？ A. preHandle → afterCompletion → postHandle B. postHandle → preHandle → afterCompletion C. preHandle → postHandle → afterCompletion D. afterCompletion → preHandle → postHandle

答案：C 解析：preHandle在Controller执行前调用（返回false则中断）；postHandle在Controller返回后、视图渲染前调用；afterCompletion在请求完全结束后调用（用于清理资源，如ThreadLocal.remove）。

17-XZ-17 ★★

题目：RoleInterceptor中handler instanceof HandlerMethod判断的作用是？ A. 提高性能 B. 排除静态资源等非Controller方法 C. 校验用户权限 D. 防止异常

答案：B 解析：Spring MVC中handler可能是HandlerMethod（Controller方法）也可能是ResourceHttpRequestHandler（静态资源）等。非Controller方法没有@RequireRole注解，直接放行，避免误拦截静态资源。

17-XZ-18 ★★

题目：JWT的"无状态"特性意味着？ A. 服务端不存储Token，每次靠签名校验合法性 B. Token不可被解析 C. Token不能用于认证 D. 服务端必须查库才能校验

答案：A 解析：无状态指服务端不保存Session或Token信息，仅靠签名算法验证Token真伪和有效期。优点是易于横向扩展；缺点是无法主动让Token失效（除非引入Redis黑名单）。

17-XZ-19 ★★★

题目：用户修改密码后，原JWT Token仍然能正常访问接口，原因是？ A. 拦截器配置错误 B. JWT无状态，服务端无法感知密码已改 C. Token未过期 D. B和C

答案：D 解析：JWT无状态特性决定服务端不存储Token，只要Token未过期且签名合法就能通过校验。改密后旧Token失效需要额外机制（如Redis黑名单或版本号校验），这是JWT的固有局限。

17-XZ-20 ★★

题目：JwtUtil中@PostConstruct注解的init方法作用是？ A. 生成Token B. 在Bean初始化后初始化SecretKey C. 解析Token D. 注册拦截器

答案：B 解析：@PostConstruct在依赖注入完成后执行，用于初始化key对象（从配置的secret字符串生成SecretKey）。避免每次generateToken/parseToken都重新生成key，提升性能。

17-XZ-21 ★

题目：BCryptPasswordEncoder的cost因子（如$2a$10$中的10）表示？ A. 加密结果长度 B. 加密迭代次数（2的10次方） C. 盐值长度 D. 密钥长度

答案：B 解析：cost因子决定加密迭代次数（2^cost次），值越大加密越慢越安全。默认10表示2^10=1024次迭代。每增加1，时间翻倍。

17-XZ-22 ★★

题目：CTTS项目中@RequireRole({"TEACHER","ADMIN"})表示？ A. 必须同时具备TEACHER和ADMIN角色 B. 具备TEACHER或ADMIN任一角色即可 C. 仅TEACHER可访问 D. 仅ADMIN可访问

答案：B 解析：默认requireAll=false，表示角色数组是"或"关系，满足任一即可。若设requireAll=true则要求同时具备（一般用户只有一个角色，此场景少见）。

17-XZ-23 ★★★

题目：若LoginInterceptor的order设为2、RoleInterceptor的order设为1，会出现什么问题？ A. 一切正常 B. RoleInterceptor先执行，从ThreadLocal读到null角色，所有需权限接口都返回401 C. LoginInterceptor不执行 D. 报错启动失败

答案：B 解析：order小的先执行，RoleInterceptor先跑时ThreadLocal中无用户信息（LoginInterceptor还没执行），getRole()返回null，导致所有带@RequireRole的接口都返回401"未登录"。

17-XZ-24 ★★

题目：BusinessException.of(401, "用户名或密码错误")这种统一异常抛出方式的好处是？ A. 提高运行速度 B. 避免代码中满地return，统一由全局异常处理器包装响应 C. 减少数据库查询 D. 自动记录日志

答案：B 解析：业务层抛BusinessException，GlobalExceptionHandler统一捕获并包装成Result返回，避免Controller层写大量try-catch，使业务代码更聚焦。

17-XZ-25 ★

题目：Apifox中配置环境变量{{studentToken}}的作用是？ A. 加密Token B. 在多个请求间复用Token，避免每次手动复制 C. 校验Token D. 刷新Token

答案：B 解析：环境变量实现Token在登录后自动保存，后续请求通过{{studentToken}}引用，避免每个请求手动粘贴Token，提升测试效率。

17-XZ-26 ★★

题目：项目中UserMapper extends BaseMapper<User>，这里使用的是？ A. Spring Data JPA B. MyBatis-Plus C. Hibernate D. JDBC Template

答案：B 解析：BaseMapper是MyBatis-Plus提供的通用Mapper接口，内置selectById、insert、updateById、selectCount等方法，无需手写SQL即可完成单表CRUD。

17-XZ-27 ★★

题目：登录时为什么用passwordEncoder.matches(password, user.getPassword())而不是password.equals(user.getPassword())？ A. equals方法性能差 B. BCrypt每次加密盐值不同，同一明文加密结果不同，必须用matches内部比对 C. equals会抛异常 D. matches更快

答案：B 解析：BCrypt加密时盐值随机，同一明文两次加密结果不同，无法用equals直接比对字符串。matches方法会从密文中提取盐值对明文重新加密后比对。

17-XZ-28 ★

题目：JWT Token的标准声明字段exp表示？ A. 签发时间 B. 过期时间 C. 签发者 D. 主题

答案：B 解析：exp（Expiration Time）表示Token过期时间，超过此时间Token自动失效。iat是签发时间，iss是签发者，sub是主题（subject）。

17-XZ-29 ★★

题目：CTTS注册接口中校验用户名唯一的SQL等价操作是？ A. userMapper.selectById(username) B. userMapper.selectCount(new LambdaQueryWrapper<User>().eq(User::getUsername, username)) C. userMapper.selectAll() D. userMapper.delete(username)

答案：B 解析：使用MyBatis-Plus的LambdaQueryWrapper构造条件查询，selectCount返回满足条件的记录数，>0表示已存在。

17-XZ-30 ★★★

题目：下列关于ThreadLocal内存泄漏说法正确的是？ A. ThreadLocal本身一定导致内存泄漏 B. 使用线程池时，若不调用remove()，ThreadLocal中的对象在线程复用时仍然存在 C. ThreadLocal只能存String类型 D. remove()会销毁ThreadLocal实例

答案：B 解析：ThreadLocal的Entry是弱引用key但value是强引用，线程池复用线程时Entry中value不会被回收，导致数据残留。remove()清除当前线程的Entry值，不会销毁ThreadLocal实例本身。

二、多项选择题（10题）

17-DX-01 ★★

题目：CTTS认证授权全链路涉及以下哪些组件？（多选） A. BCryptPasswordEncoder B. JwtUtil C. LoginInterceptor D. RoleInterceptor E. CurrentUserContext F. WebMvcConfig

答案：ABCDEF 解析：全链路包含密码加密（A）、Token工具（B）、认证拦截器（C）、授权拦截器（D）、ThreadLocal上下文（E）、拦截器注册配置（F），缺一不可。

17-DX-02 ★★

题目：下列哪些是JWT相比传统Session的优势？（多选） A. 无状态，服务端无需存储Session B. 易于横向扩展（多服务器无需共享Session） C. 天然支持跨域 D. 可主动让Token失效 E. Payload可放任意数据无安全风险

答案：ABC 解析：JWT无状态便于扩展（A、B）；Token放Header中天然支持跨域（C）。D错，JWT无法主动失效（除非引入Redis黑名单）；E错，Payload是Base64可解码，不能放敏感数据。

17-DX-03 ★★

题目：LoginInterceptor的preHandle方法中处理Token校验时，可能抛出的异常包括？（多选） A. io.jsonwebtoken.ExpiredJwtException——Token过期 B. io.jsonwebtoken.SignatureException——签名不匹配（被篡改） C. io.jsonwebtoken.MalformedJwtException——Token格式错误 D. NullPointerException E. SQLException

答案：ABC 解析：JWT解析常见异常：ExpiredJwtException（过期）、SignatureException（签名非法）、MalformedJwtException（格式错误）。本项目通过try-catch统一处理为401。

17-DX-04 ★★

题目：关于@RequireRole注解的Target配置{ElementType.METHOD, ElementType.TYPE}，下列说法正确的是？（多选） A. 可标注在方法上 B. 可标注在类上 C. 可标注在字段上 D. 类上标注对所有方法生效，方法上标注优先级更高 E. 可标注在构造函数上

答案：ABD 解析：METHOD表示可标注方法，TYPE表示可标注类（含接口、注解、枚举）。RoleInterceptor优先读方法注解，无则取类注解，方法级覆盖类级。不支持字段和构造函数。

17-DX-05 ★★★

题目：下列哪些场景会导致用户串号（A用户看到B用户数据）？（多选） A. ThreadLocal未在afterCompletion中remove B. Tomcat线程池复用线程 C. 使用同步请求 D. JWT Payload中userId写错 E. 使用@Async异步方法且未传递用户上下文

答案：ABE 解析：A+B是典型ThreadLocal泄漏场景；E中异步线程无ThreadLocal上下文但若误用其他线程的也会串号；C与串号无关；D是数据错误不是串号。

17-DX-06 ★★

题目：CTTS项目中WebMvcConfig的addInterceptors配置中，excludePathPatterns通常包含哪些路径？（多选） A. /api/auth/register B. /api/auth/login C. /api/user/current D. 静态资源路径 E. /error

17-LW-02 ★★★

题目：什么是ThreadLocal内存泄漏？在CTTS项目中如何避免？请结合Tomcat线程池机制分析原因。

答案要点：

  1. 现象：A用户登录后访问接口，偶发性看到B用户的数据，称为"用户串号"。
  2. 根因：
    • Tomcat默认使用线程池（如maxThreads=200）复用线程处理请求。
    • ThreadLocal为每个线程独立存储变量，请求结束后若不remove，变量仍残留在线程的ThreadLocalMap中。
    • 下一个请求复用该线程时，CurrentUserContext.get()读到的是上一个用户的User对象。
  3. 避免方法：
    • 在LoginInterceptor.afterCompletion中调用CurrentUserContext.remove()。
    • afterCompletion无论Controller是否抛异常都会执行，是清理资源的最佳位置。
    • 不能在postHandle中清理，因为Controller抛异常时postHandle不执行。
  4. 扩展：ThreadLocal的Entry是弱引用key、强引用value，key被回收后value仍存在导致泄漏，remove()清除整个Entry。

评分标准（满分10分）：

  • 现象描述清晰（2分）
  • 根因分析涉及线程池复用（3分）
  • 解决方案正确（remove + afterCompletion）（3分）
  • 提及postHandle不可靠的原因（1分）
  • 扩展ThreadLocal底层原理（1分）

17-LW-03 ★★

题目：JWT的"无状态"特性是什么？它带来了哪些优势和劣势？在CTTS项目中如何弥补其劣势？

答案要点：

  1. 无状态定义：服务端不存储Session或Token信息，每次请求靠签名算法校验Token合法性。
  2. 优势：
    • 易于横向扩展：多服务器无需共享Session，任意节点都能校验。
    • 减少服务端存储开销：不占用内存/Redis存储Session。
    • 天然支持移动端和跨域：Token放Header即可。
  3. 劣势：
    • 无法主动失效：Token签发后在过期前一直有效，改密、注销都无法让旧Token失效。
    • Payload可解码：不能放敏感信息。
    • 续期复杂：无法像Session那样自动滑动过期。
  4. 弥补方案：
    • 引入Redis黑名单：注销/改密时将Token加入黑名单，拦截器校验是否在黑名单中。
    • 短有效期+刷新Token：access_token有效期短（如30分钟），refresh_token有效期长（如7天），access_token过期后用refresh_token换取新的。
    • 密码版本号：User表加password_version字段，改密时+1，Token中放version，拦截器校验版本号是否一致。

评分标准（满分10分）：

  • 无状态定义准确（2分）
  • 优势列举至少2点（2分）
  • 劣势列举至少2点（3分）
  • 弥补方案至少2种（3分）

// 黑名单（生产环境应用Redis）
private final Map<String, Long> blacklist = new ConcurrentHashMap<>();

public void addToBlacklist(String token) {
    // 存储Token及其原始过期时间，到期后自动清理
    try {
        Claims claims = parseToken(token);
        blacklist.put(token, claims.getExpiration().getTime());
    } catch (Exception e) {
        // Token已过期或非法，无需加入黑名单
    }
}

public boolean isBlacklisted(String token) {
    // 清理已过期的黑名单Token
    long now = System.currentTimeMillis();
    blacklist.entrySet().removeIf(e -> e.getValue() < now);
    return blacklist.containsKey(token);
}

（2）AuthController.logout方法：

@PostMapping("/user/logout")
public Result<Void> logout(@RequestHeader("Authorization") String authHeader) {

    CurrentUserContext.remove();  // 清理当前线程
    return Result.success(null);
}

package com.ctts.service;

package com.ctts.service.impl;

import com.ctts.common.BusinessException;
import com.ctts.context.CurrentUserContext;
import com.ctts.entity.Task;
import com.ctts.mapper.TaskMapper;
import com.ctts.service.TaskService;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Service;

@Service
@RequiredArgsConstructor
public class TaskServiceImpl implements TaskService {

    private final TaskMapper taskMapper;

    @Override
    public Long publishTask(Task task) {
        // 从ThreadLocal获取当前登录用户ID作为teacherId
        // 关键：不能信任前端传入的teacherId，防止越权
        Long teacherId = CurrentUserContext.getUserId();
        if (teacherId == null) {
            throw BusinessException.of(401, "未登录");
        }
        task.setTeacherId(teacherId);  // 强制覆盖，忽略前端传入
        task.setId(null);  // 防止前端传入id覆盖
        taskMapper.insert(task);
        return task.getId();
    }
}

package com.ctts.controller;

@RequiredArgsConstructor
public class TeacherController {

    private final TaskService taskService;

    /**
     * 发布实训任务（仅教师）
     */

    @PostMapping("/task")
