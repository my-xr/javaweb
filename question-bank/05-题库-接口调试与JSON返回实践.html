一、单项选择题（30题，每题2分，共60分）

05-单选-01 ★

题目：以下哪款工具是国产一体化 API 开发协作平台，定位为"Postman + Swagger + Mock"？

A. Postman B. Apifox C. JMeter D. curl

答案：B 解析：Apifox 是国产 API 开发协作工具，集接口文档、调试、测试、Mock 于一身，定位"Postman + Swagger + Mock"。Postman 是美国老牌工具，JMeter 主要用于性能测试，curl 是命令行工具。

05-单选-02 ★

题目：HTTP 请求报文的结构按顺序是？

A. 请求行 → 请求体 → 请求头 B. 请求头 → 请求行 → 请求体 C. 请求行 → 请求头 → 空行 → 请求体 D. 请求头 → 空行 → 请求行 → 请求体

答案：C 解析：HTTP 请求报文顺序为：请求行（方法 URL 协议）→ 请求头（键值对）→ 空行 → 请求体。空行是请求头与请求体的分隔符。

05-单选-03 ★

题目：以下 HTTP 请求方法中，通常用于"新增资源"的是？

A. GET B. POST C. PUT D. DELETE

答案：B 解析：POST 用于新增资源，GET 用于查询，PUT 用于整体修改，DELETE 用于删除，PATCH 用于局部修改。

05-单选-04 ★

题目：在 Apifox 中发送 JSON 请求体，Body 类型应选择？

A. form-data B. x-www-form-urlencoded C. json D. raw

答案：C 解析：发送 JSON 请求体应在 Body 区域选择 json 类型，Apifox 会自动设置 Content-Type: application/json。form-data 用于文件上传，x-www-form-urlencoded 用于表单提交。

05-单选-05 ★

题目：CTTS 项目登录接口 POST /api/auth/login，以下哪种 Content-Type 是正确的？

A. application/x-www-form-urlencoded B. application/json C. multipart/form-data D. text/plain

答案：B 解析：CTTS 使用 @RequestBody LoginDTO 接收参数，要求 application/json。若是 @RequestParam 则用表单类型。

05-单选-06 ★

题目：HTTP 状态码 404 表示？

A. 服务器内部错误 B. 请求参数错误 C. 资源未找到 D. 未授权

答案：C 解析：404 Not Found 表示请求的资源（路径）不存在。500 是服务器内部错误，400 是参数错误，401 是未授权。

05-单选-07 ★

题目：HTTP 状态码 500 通常表示？

A. 客户端请求格式错误 B. 服务器内部代码异常 C. 资源不存在 D. 请求方法不允许

答案：B 解析：500 Internal Server Error 表示服务器端代码异常，如空指针、SQL 异常等。4xx 系列才是客户端错误。

05-单选-08 ★

题目：调用接口返回 415 Unsupported Media Type，最可能的原因是？

A. URL 路径错误 B. 请求方法错误 C. Content-Type 与后端期望不符 D. 未携带 Token

答案：C 解析：415 表示服务器无法处理请求附带的媒体格式，典型原因是 Content-Type 设置错误，如后端要求 application/json 但客户端发送了 form-data。

05-单选-09 ★

题目：Knife4j 是基于以下哪个规范实现的？

A. WSDL B. OpenAPI 3 C. GraphQL Schema D. SOAP

答案：B 解析：Knife4j 基于 OpenAPI 3 规范（前身 Swagger Specification），WSDL/SOAP 用于 Web Service，GraphQL Schema 用于 GraphQL API。

05-单选-10 ★

题目：Knife4j 默认的访问路径是？

A. /swagger-ui.html B. /doc.html C. /api-docs.html D. /knife4j.html

答案：B 解析：Knife4j 增强UI的访问路径是 /doc.html。/swagger-ui.html 是原生 Swagger UI 路径，由 SpringDoc 提供。

05-单选-11 ★

题目：Spring Boot 3 项目集成 Knife4j，应使用以下哪个依赖？

A. knife4j-spring-boot-starter B. knife4j-openapi3-jakarta-spring-boot-starter C. springfox-boot-starter D. swagger-core

答案：B 解析：Spring Boot 3 基于 Jakarta EE，必须使用 knife4j-openapi3-jakarta-spring-boot-starter。选项A是 Spring Boot 2.x 使用的旧依赖。

05-单选-12 ★★

题目：OpenAPI 注解 @Tag 标注在哪个层级？

A. 字段 B. 方法 C. 类 D. 参数

答案：C 解析：@Tag(name="模块名", description="描述") 标注在 Controller 类上，用于对接口进行分组。@Operation 用于方法，@Parameter 用于参数，@Schema 用于 DTO 字段。

05-单选-13 ★★

题目：OpenAPI 注解 @Operation 的 summary 属性的作用是？

A. 接口的详细描述 B. 接口的简短标题 C. 接口所属分组 D. 接口的安全策略

答案：B 解析：summary 是接口的简短标题，显示在接口列表中；description 是详细描述，点开接口后展示。

05-单选-14 ★★

题目：标注 @Parameter(in = ParameterIn.PATH) 表示参数来源是？

A. 查询字符串 B. 请求头 C. 路径变量 D. 请求体

答案：C 解析：ParameterIn.PATH 表示路径变量（对应 @PathVariable）。QUERY 对应 @RequestParam，HEADER 对应 @RequestHeader。

05-单选-15 ★★

题目：以下哪个注解用于描述 DTO 字段在文档中的说明？

A. @Tag B. @Operation C. @Parameter D. @Schema

答案：D 解析：@Schema(description="字段说明") 用于 DTO 类或字段，让 Knife4j 文档展示字段含义。@Tag 用于类分组，@Operation 用于方法，@Parameter 用于方法参数。

05-单选-16 ★★

题目：Apifox 中配置全局 Token，应使用哪个功能？

A. 接口备注 B. 环境变量 + 后置操作提取 C. 全局参数 Header D. 接口分组

答案：B 解析：推荐做法是在"环境管理"中定义 token 变量，在登录接口的"后置操作"中通过 JSONPath 提取 Token 并写入变量，其他接口的 Header 引用 {{token}} 即可自动携带。

05-单选-17 ★★

题目：HTTP 状态码 401 表示？

A. 未认证（没 Token 或 Token 失效） B. 已认证但无权限 C. 资源不存在 D. 请求方法不支持

答案：A 解析：401 Unauthorized 表示未认证（未带 Token 或 Token 过期）。403 Forbidden 才是已认证但权限不足。404 是资源不存在，405 是方法不支持。

05-单选-18 ★★

题目：HTTP 状态码 403 与 401 的核心区别是？

A. 403 是客户端错误，401 是服务端错误 B. 401 是未认证，403 是已认证但无权限 C. 403 是路径不对，401 是参数错误 D. 二者没有区别

答案：B 解析：401 Unauthorized 是"不知道你是谁"（未登录），403 Forbidden 是"知道你是谁但不能做"（已登录但权限不足）。两者都是 4xx 客户端错误。

05-单选-19 ★★

题目：CTTS 统一返回结构 Result<T> 不包含以下哪个字段？

A. code B. message C. data D. exception

答案：D 解析：Result<T> 包含 code（业务状态码）、message（提示信息）、data（业务数据）三个字段。exception 不属于统一返回结构。

05-单选-20 ★★

题目：Knife4j 配置类中，@Bean OpenAPI 主要用于配置？

A. 接口分组 B. 文档元信息与全局鉴权方案 C. 数据库连接 D. 跨域策略

答案：B 解析：@Bean OpenAPI 用于配置文档元信息（title、description、version、contact）和全局鉴权方案（SecurityScheme）。接口分组用 GroupedOpenApi，跨域用 WebMvcConfigurer。

05-单选-21 ★★

题目：定义 Knife4j 接口分组应使用？

A. @Bean OpenAPI B. @Bean GroupedOpenApi C. @Configuration D. @Component

答案：B 解析：GroupedOpenApi.builder().group("模块名").pathsToMatch("/api/task/**").build() 用于定义分组，每个分组是一个 @Bean。

05-单选-22 ★★

题目：前端 http://localhost:5173 调用后端 http://localhost:8080 接口，浏览器报 CORS 错误，原因是？

A. 后端服务未启动 B. 端口不同视为跨域 C. Token 过期 D. Content-Type 错误

答案：B 解析：浏览器同源策略要求协议、域名、端口完全一致。5173 与 8080 端口不同，视为跨域，需后端配置 CORS。

05-单选-23 ★★

题目：Spring Boot 配置 CORS 时，allowCredentials(true) 与以下哪个不能同时使用？

A. allowedOrigins("") B. allowedMethods("GET") C. allowedHeaders("") D. maxAge(3600)

答案：A 解析：allowCredentials(true) 与 allowedOrigins("*") 不能同时使用，因为携带凭证时不能允许所有来源。应改用 allowedOriginPatterns("*")。

05-单选-24 ★★

题目：全局异常处理器 @RestControllerAdvice 中，处理 @Valid 校验失败的异常类型是？

A. NullPointerException B. MethodArgumentNotValidException C. HttpMessageNotReadableException D. NoHandlerFoundException

答案：B 解析：@Valid 校验 @RequestBody 参数失败时抛出 MethodArgumentNotValidException。HttpMessageNotReadableException 是 JSON 解析失败，NoHandlerFoundException 是路径不存在。

05-单选-25 ★★

题目：以下哪个配置可以让 Spring Boot 在 404 时抛出 NoHandlerFoundException 而非返回默认错误页？

A. spring.mvc.throw-exception-if-no-handler-found=true B. spring.web.resources.add-mappings=true C. spring.main.web-application-type=servlet D. server.error.whitelabel.enabled=true

答案：A 解析：spring.mvc.throw-exception-if-no-handler-found=true 让 Spring 抛出 NoHandlerFoundException，配合 spring.web.resources.add-mappings=false 关闭静态资源映射，才能被全局异常处理器捕获。

05-单选-26 ★★★

题目：Knife4j 配置类中，@Bean OpenAPI 配置 JWT 鉴权方案，SecurityScheme 的 type 应设置为？

A. SecurityScheme.Type.APIKEY B. SecurityScheme.Type.HTTP C. SecurityScheme.Type.OAUTH2 D. SecurityScheme.Type.OPENIDCONNECT

答案：B 解析：JWT 通常使用 SecurityScheme.Type.HTTP，配合 scheme("bearer") 和 bearerFormat("JWT")。APIKEY 用于 Query/Header 中传递固定 Key，OAUTH2 用于 OAuth2 流程。

05-单选-27 ★★★

题目：以下 Knife4j 注解用法错误的是？

A. @Tag(name="用户管理") 标注在 Controller 类上 B. @Operation(summary="登录") 标注在方法上 C. @Parameter(name="id", in=ParameterIn.PATH) 标注在参数上 D. @Schema(description="字段说明") 标注在方法上

答案：D 解析：@Schema 用于 DTO 类或字段，不能用于方法。方法上应使用 @Operation。

05-单选-28 ★★★

题目：CTTS 调用任务列表接口返回 200，但 data 为 null，最不可能的原因是？

A. 数据库无数据 B. SQL 查询条件错误 C. Service 返回 null D. Token 过期

答案：D 解析：Token 过期应返回 401，不会返回 200。返回 200 但 data 为 null 通常因数据库无数据、SQL 条件错误或 Service 返回 null，需查 SQL 日志和 Service 代码。

05-单选-29 ★★★

题目：Spring Boot 项目集成 Knife4j 后，访问 /doc.html 返回 401，最可能的原因是？

A. Spring Security 拦截了 /doc.html B. 依赖未正确添加 C. 配置类未生效 D. 主类未启动

答案：A 解析：Spring Security 默认拦截所有路径，需在 Security 配置中放行 /doc.html、/webjars/**、/v3/api-docs/**。依赖未添加会报 ClassNotFoundException，配置类未生效会显示空白。

05-单选-30 ★★★

题目：生产环境保护 Knife4j 文档不被外部访问，以下哪种方案不推荐？

A. 配置 knife4j.production: true B. 通过 Profile 区分环境，生产不加载 Knife4j 依赖 C. 在 Spring Security 中放行 /doc.html D. 配置 knife4j.basic.enable: true 加 Basic 认证

答案：C 解析：在 Spring Security 中"放行" /doc.html 等于公开文档，不能保护。正确做法是 production=true 关闭文档、用 Profile 不加载依赖，或加 Basic 认证。

二、多项选择题（10题，每题3分，共30分，多选少选不得分）

05-多选-01 ★

题目：以下属于 HTTP 请求头的是？（多选）

A. Content-Type B. Accept C. Authorization D. Status-Code

答案：ABC 解析：Content-Type、Accept、Authorization 都是 HTTP 请求头。Status-Code 是响应状态码（如 200、404），不属于请求头。

05-多选-02 ★

题目：Apifox 的核心功能包括？（多选）

A. 接口文档管理 B. 接口调试 C. 接口测试（自动化） D. Mock 服务

答案：ABCD 解析：Apifox 定位"Postman + Swagger + Mock"，集接口文档、调试、测试、Mock 于一体，四项都是核心功能。

05-多选-03 ★

题目：HTTP 状态码 4xx 系列 includes？（多选）

A. 200 B. 400 C. 404 D. 415

答案：BCD 解析：4xx 是客户端错误：400 Bad Request、404 Not Found、415 Unsupported Media Type。200 是 2xx 成功。

05-多选-04 ★★

题目：以下哪些是 Knife4j 相比 Swagger UI 的优势？（多选）

A. 中文 UI 友好 B. 支持文档导出（Markdown/HTML/PDF） C. 调试体验增强 D. 支持接口分组

答案：ABC 解析：Knife4j 中文友好、支持文档导出、调试体验增强。接口分组原生 Swagger UI 也支持（通过 GroupedOpenApi / swagger-ui tags），不是 Knife4j 独有优势。

05-多选-05 ★★

题目：以下哪些是 Knife4j 集成的必要步骤？（多选）

A. 添加 knife4j-openapi3-jakarta-spring-boot-starter 依赖 B. 创建 OpenAPIConfig 配置类 C. 在 Controller 上标注 @Tag/@Operation 注解 D. 在 application.yml 中配置 knife4j.enable=true

答案：ABC 解析：A 添加依赖、B 配置类（定义 @Bean OpenAPI）、C 标注解，三步是必要的。D knife4j.enable 默认就是 true，可省略；最少配置只需 A + B + C。

05-多选-06 ★★

题目：调用 CTTS 接口返回 500，排查步骤应包括？（多选）

A. 查看后端控制台异常堆栈 B. 定位堆栈中 com.ctts 开头的代码行 C. 根据异常类型判断根因（NPE/SQL 异常等） D. 重启服务器即可解决

答案：ABC 解析：500 排查应看堆栈、定位代码行、分析异常类型。D "重启即可解决"是错误做法，治标不治本，可能掩盖问题。

05-多选-07 ★★

题目：HTTP 请求中，以下哪些 Content-Type 适合发送 JSON 数据？（多选）

A. application/json B. application/x-www-form-urlencoded C. application/json;charset=UTF-8 D. text/plain

答案：AC 解析：application/json 和带字符集的 application/json;charset=UTF-8 都是 JSON。x-www-form-urlencoded 是表单，text/plain 是纯文本。

05-多选-08 ★★

题目：以下哪些注解属于 OpenAPI 3 规范（io.swagger.v3.oas.annotations）？（多选）

A. @Tag B. @Operation C. @Parameter D. @Schema

答案：ABCD 解析：四个注解都属于 OpenAPI 3（io.swagger.v3.oas.annotations）。注意不要与 Swagger 2 的 @Api、@ApiOperation 混淆。

05-多选-09 ★★★

题目：CTTS 项目跨域配置 CorsConfig 中，以下哪些配置是合理的？（多选）

A. allowedOriginPatterns("*") B. allowedMethods("GET","POST","PUT","DELETE","OPTIONS") C. allowedHeaders("*") D. allowCredentials(true) 配合 allowedOrigins("*")

答案：ABC 解析：A、B、C 都是合理配置。D 错误：allowCredentials(true) 与 allowedOrigins("*") 不能同时使用，应改用 allowedOriginPatterns("*")。

05-多选-10 ★★★

题目：以下哪些做法可以让生产环境不暴露 Knife4j 文档？（多选）

A. knife4j.production: true B. 通过 Maven Profile 在生产环境排除 Knife4j 依赖 C. knife4j.basic.enable: true 配置 Basic 认证 D. 在所有接口上加 @Operation 注解

答案：ABC 解析：A 关闭文档、B 不打包依赖、C 加认证，三种方式都能保护文档。D 是标注解，与文档保护无关。

三、判断题（20题，每题1分，共20分）

05-判断-01 ★

05-论述-04 ★★★

题目：什么是跨域问题？CTTS 项目前端 http://localhost:5173 调用后端 http://localhost:8080 出现 CORS 错误，请说明原因并给出至少2种解决方案。

参考答案： 跨域定义：浏览器同源策略限制，当请求的协议、域名、端口任一不同时，视为跨域。浏览器会拦截跨域请求，需后端通过 CORS（Cross-Origin Resource Sharing）响应头声明允许的来源。

CTTS 跨域原因：前端 http://localhost:5173 与后端 http://localhost:8080 端口不同，浏览器视为跨域，拦截请求并报 No 'Access-Control-Allow-Origin' header is present 错误。

解决方案1：全局 CORS 配置（推荐） 在 com.ctts.config 包下创建 CorsConfig 实现 WebMvcConfigurer：

@Configuration
public class CorsConfig implements WebMvcConfigurer {
    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/api/**")
                .allowedOriginPatterns("*")
                .allowedMethods("GET","POST","PUT","DELETE","OPTIONS")
                .allowedHeaders("*")
                .allowCredentials(true)
                .maxAge(3600);
    }
}

解决方案2：@CrossOrigin 注解（单接口） 在 Controller 类或方法上加 @CrossOrigin(origins = "http://localhost:5173")，适合少量接口。

解决方案3：CorsFilter Bean

@Bean
public CorsFilter corsFilter() {
    CorsConfiguration config = new CorsConfiguration();
    config.addAllowedOriginPattern("*");
    config.addAllowedMethod("*");
    config.addAllowedHeader("*");
    config.setAllowCredentials(true);
    UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
    source.registerCorsConfiguration("/**", config);
    return new CorsFilter(source);
}

解决方案4：前端代理（如 Vite/nginx） 在 vite.config.js 中配置 proxy，将 /api 代理到 http://localhost:8080，浏览器看到的是同源请求。

注意事项：

  • allowCredentials(true) 与 allowedOrigins("*") 不能同时使用，必须用 allowedOriginPatterns("*")
  • Spring Security 项目还需在 Security 配置中放行 OPTIONS 预检请求

  • 跨域定义与同源策略说明：2分
  • CTTS 跨域原因分析：2分
  • 至少2种解决方案（每种2分）：4分

05-编程-02 ★★★

题目：为 CTTS 项目实现全局异常处理器与跨域配置，要求：

  1. 包名 com.ctts.config，类名 GlobalExceptionHandler 和 CorsConfig
  2. GlobalExceptionHandler 用 @RestControllerAdvice，至少处理 4 类异常：
    • MethodArgumentNotValidException（参数校验失败，返回 400）
    • HttpMessageNotReadableException（JSON 解析失败，返回 400）
    • NoHandlerFoundException（路径不存在，返回 404）
    • Exception（兜底，返回 500）
  3. 所有异常返回 Result<Void> 统一结构
  4. CorsConfig 实现 WebMvcConfigurer，对 /api/** 开启跨域，允许所有来源（携带凭证）、常用方法、所有头
  5. 代码包含必要日志

参考答案：

package com.ctts.config;

import com.ctts.vo.Result;
import jakarta.servlet.http.HttpServletRequest;
import lombok.extern.slf4j.Slf4j;
import org.springframework.http.HttpStatus;
import org.springframework.http.converter.HttpMessageNotReadableException;
import org.springframework.validation.FieldError;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.ResponseStatus;
import org.springframework.web.bind.annotation.RestControllerAdvice;
import org.springframework.web.servlet.NoHandlerFoundException;

import java.util.stream.Collectors;

/**
 * 全局异常处理器
 */
@Slf4j
@RestControllerAdvice
public class GlobalExceptionHandler {

    /** 参数校验失败 → 400 */
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<Void> handleValid(MethodArgumentNotValidException e) {
        String msg = e.getBindingResult().getFieldErrors().stream()
                .map(fe -> fe.getField() + ":" + fe.getDefaultMessage())
                .collect(Collectors.joining(";"));
        log.warn("[参数校验失败] {}", msg);
        return Result.error(400, "参数校验失败：" + msg);
    }

    /** JSON 解析失败 → 400 */
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    @ExceptionHandler(HttpMessageNotReadableException.class)
    public Result<Void> handleJsonParse(HttpMessageNotReadableException e) {
        log.warn("[JSON解析失败] {}", e.getMessage());
        return Result.error(400, "请求体格式错误或为空");
    }

    /** 路径不存在 → 404 */
    @ResponseStatus(HttpStatus.NOT_FOUND)
    @ExceptionHandler(NoHandlerFoundException.class)
    public Result<Void> handleNotFound(NoHandlerFoundException e) {
        log.warn("[接口不存在] {}", e.getRequestURL());
        return Result.error(404, "接口不存在：" + e.getRequestURL());
    }

    /** 兜底异常 → 500 */
    @ResponseStatus(HttpStatus.INTERNAL_SERVER_ERROR)
    @ExceptionHandler(Exception.class)
    public Result<Void> handleException(Exception e, HttpServletRequest req) {
        log.error("[系统异常] {} - ", req.getRequestURI(), e);
        return Result.error(500, "服务器开小差了：" + e.getMessage());
    }
}
package com.ctts.config;

import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.CorsRegistry;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

/**
 * 跨域配置
 */
@Configuration
public class CorsConfig implements WebMvcConfigurer {

    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/api/**")
                .allowedOriginPatterns("*")
                .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
                .allowedHeaders("*")
                .allowCredentials(true)
                .maxAge(3600);
    }
}
