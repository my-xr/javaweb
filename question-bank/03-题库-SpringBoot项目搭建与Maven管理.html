1.1 单项选择题（30 题）

03-选择-001（★ 知识点：K3-1） Spring Boot 的核心设计理念是？

  • A取代 Spring 框架，提供全新编程模型
  • B简化 Spring 应用的初始搭建与开发过程
  • C提供可视化的代码生成工具
  • D替代 Maven 进行项目构建

答案：B 解析：Spring Boot 是基于 Spring 的二次封装，目的是简化 Spring 应用的搭建，而非取代 Spring。

03-选择-002（★ 知识点：K3-1） 下列哪一项不属于 Spring Boot 的核心特性？

  • A自动配置
  • B起步依赖
  • C内嵌 Web 容器
  • D强制使用 XML 配置

答案：D 解析：Spring Boot 提倡"约定优于配置"，几乎不需要写 XML，D 选项与其理念相反。

03-选择-003（★ 知识点：K3-1） Spring Boot 与 Spring Framework 的关系是？

  • ASpring Boot 是 Spring 的下一代，将替代 Spring
  • BSpring Boot 是 Spring 的封装与简化，底层仍是 Spring
  • C两者完全独立，无任何关系
  • DSpring 是 Spring Boot 的子模块

答案：B 解析：Spring Boot 底层就是 Spring Framework，它通过自动配置等特性简化 Spring 应用开发。

03-选择-004（★ 知识点：K3-1） Spring Boot 内嵌的默认 Web 容器是？

  • AJetty
  • BUndertow
  • CTomcat
  • DNetty

答案：C 解析：Spring Boot 默认内嵌 Tomcat，也可通过排除 starter-tomcat 引入 starter-jetty 切换为 Jetty。

03-选择-005（★ 知识点：K3-1） "约定优于配置"在 Spring Boot 中的典型体现是？

  • A必须手写 web.xml 才能启动
  • B配置文件必须命名为 config.xml
  • C默认端口 8080、默认配置文件名 application，无需配置即可启动
  • D必须手动安装 Tomcat 才能运行

答案：C 解析：Spring Boot 提供合理的默认值（8080 端口、application 配置文件名），无需配置即可启动，这就是"约定优于配置"。

03-选择-006（★ 知识点：K3-1） 关于 Spring Boot 自动配置，下列说法正确的是？

  • A自动配置会强制覆盖用户自定义的 Bean
  • B自动配置通过 @Conditional 系列注解判断是否生效
  • C自动配置会引入所有可能的 Bean，造成性能问题
  • D自动配置无法被关闭

答案：B 解析：自动配置大量使用 @ConditionalOnClass、@ConditionalOnMissingBean 等条件注解，满足条件才生效；用户自定义 Bean 优先。

03-选择-007（★ 知识点：K3-2） Spring Boot 项目中，Java 源代码应放在？

  • Asrc/main/resources
  • Bsrc/main/java
  • Csrc/test/java
  • D项目根目录

答案：B 解析：Maven 约定 src/main/java 存放主源代码，src/main/resources 存放配置文件，src/test/java 存放测试代码。

03-选择-008（★ 知识点：K3-2） Spring Boot 项目的主配置文件 application.yml 应放在？

  • Asrc/main/java
  • Bsrc/main/resources 根目录
  • Csrc/test/resources
  • D项目根目录

答案：B 解析：application.yml 必须放在 src/main/resources/ 根目录下，放子目录默认不会被加载。

03-选择-009（★ 知识点：K3-2） target/ 目录的作用是？

  • A存放用户自定义配置
  • B存放 Maven 编译输出的 class 文件和打包结果
  • C存放第三方依赖 jar 包
  • D存放测试代码

答案：B 解析：target/ 是 Maven 编译时自动生成的输出目录，包含 classes/、*.jar 等，可随时删除重新生成。

03-选择-010（★★ 知识点：K3-2） Spring Boot 启动类 @SpringBootApplication 默认的组件扫描范围是？

  • A整个项目所有包
  • B启动类所在包及其子包
  • C仅启动类所在的包
  • Dcom.example 包下

答案：B 解析：@SpringBootApplication 中的 @ComponentScan 默认扫描启动类所在包及其子包，所以启动类应放在根包下。

03-选择-011（★★ 知识点：K3-2） 若启动类位于 com.ctts.controller.CttsApplication，下列说法正确的是？

  • Acom.ctts.service 包下的 @Service 会被正常扫描
  • Bcom.ctts.mapper 包下的 @Mapper 会被正常扫描
  • Ccom.ctts.controller 子包下的组件会被扫描，但 service、mapper 不会
  • D所有包都会被扫描

答案：C 解析：组件扫描只覆盖启动类所在包及其子包。启动类在 com.ctts.controller，则只扫描 com.ctts.controller.*，service、mapper 是同级包，不会被扫描。

  • CgroupId、packaging、scope
  • DartifactId、version、packaging

03-选择-013（★ 知识点：K3-3） 在 Maven 坐标中，groupId 通常表示？

03-选择-015（★ 知识点：K3-3） Spring Boot 项目中统一管理依赖版本的机制是？

  • A中央仓库 → 本地仓库 → 私服

03-选择-017（★ 知识点：K3-3） 下列哪个依赖的 <scope> 应设为 test？

  • Bspring-boot-starter-test

  • Dlombok

  • Cmysql-driver
  • Dmysql-jdbc

03-选择-019（★★ 知识点：K3-3） 关于 spring-boot-starter-parent 的作用，下列说法错误的是？

二、判断题（共 20 题，每题 1 分）

正确填 √，错误填 ×。

03-判断-001（★ 知识点：K3-1） Spring Boot 是用于取代 Spring Framework 的全新框架。

答案：× 解析：Spring Boot 是 Spring 的封装与简化，底层仍是 Spring，并非取代关系。

03-判断-002（★ 知识点：K3-1） Spring Boot 默认内嵌 Tomcat，因此不需要单独安装外部 Tomcat 即可运行 Web 应用。

答案：√ 解析：内嵌 Web 容器是 Spring Boot 的核心特性之一，可直接 java -jar 启动。

03-判断-003（★ 知识点：K3-1） 自动配置会强制覆盖用户自定义的 Bean。

答案：× 解析：自动配置遵循"用户优先"原则，用户自定义的 Bean 不会被覆盖，自动配置会退让。

03-判断-004（★ 知识点：K3-2） Spring Boot 项目的配置文件 application.yml 可以放在 src/main/java 目录下。

答案：× 解析：application.yml 必须放在 src/main/resources 根目录下，放 src/main/java 下不会被加载。

03-判断-005（★ 知识点：K3-2） target/ 目录是 Maven 编译时自动生成的，可以随时删除重新生成。

答案：√ 解析：target/ 是编译输出目录，删除后重新编译会再次生成，不应纳入版本控制。

03-判断-006（★★ 知识点：K3-2） 启动类 CttsApplication 放在 com.ctts.controller 包下与放在 com.ctts 包下效果完全相同。

答案：× 解析：放在 com.ctts.controller 会导致 service、mapper 等同级包不被扫描，启动类应放在根包 com.ctts 下。

03-判断-007（★ 知识点：K3-3） Maven 通过 groupId + artifactId + version 三个坐标唯一定位一个依赖。

答案：√ 解析：GAV 三坐标是 Maven 依赖的唯一标识。

03-判断-008（★ 知识点：K3-3） Spring Boot 项目中必须为每一个依赖都显式声明 <version> 标签。

答案：× 解析：继承 spring-boot-starter-parent 后，官方依赖的版本由父 POM 统一管理，无需写 <version>。

03-判断-009（★★ 知识点：K3-3） spring-boot-starter-web 已经包含了 MyBatis-Plus。

答案：× 解析：spring-boot-starter-web 仅包含 Web 相关依赖，MyBatis-Plus 需单独引入 mybatis-plus-spring-boot3-starter。

03-判断-010（★ 知识点：K3-3） Maven 会先从本地仓库查找依赖，找不到再去远程仓库下载。

答案：√ 解析：Maven 仓库查找顺序为：本地仓库 → 私服/镜像 → 中央仓库。
