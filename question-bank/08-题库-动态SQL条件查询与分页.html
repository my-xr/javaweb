一、单项选择题（30题）

08-D-01 ★

MyBatis 动态 SQL 中，用于条件判断的标签是？

  • A. <condition>
  • B. <if>
  • C. <test>
  • D. <when>

答案：B 解析： <if test="..."> 是 MyBatis 动态 SQL 的条件判断标签，test 属性接收 OGNL 表达式。<when> 是 <choose> 内的分支标签，<condition> 和 <test> 不存在。

08-D-02 ★

<where> 标签的核心作用是？

  • A. 生成 WHERE 关键字
  • B. 自动处理首个条件前多余的 AND 或 OR
  • C. 替代 <if> 进行条件判断
  • D. 限制查询返回行数

答案：B 解析： <where> 会自动在内部有内容时添加 WHERE 关键字，并把首个条件前的 AND/OR 自动去除。如果内部所有 <if> 都不成立，则整个 WHERE 子句不生成。

08-D-03 ★

对于数字类型字段 status，下列 <if> 写法正确的是？

  • A. <if test="status != null and status != ''">
  • B. <if test="status != ''">
  • C. <if test="status != null">
  • D. <if test="status">

答案：C 解析： 数字类型只需判断 != null。status != '' 对数字无意义，OGNL 中虽然能比较但语义错；<if test="status"> 在 status=0 时被判断为 false，会漏掉有效值 0。

08-D-04 ★★

<foreach> 标签的 collection 属性值，当 Mapper 方法参数用 @Param("ids") 注解时，应填？

  • A. list
  • B. array
  • C. ids
  • D. collection

答案：C 解析： 用 @Param("ids") 显式命名后，collection 属性应填 ids。如果未使用 @Param 且参数是 List，默认 list；是数组默认 array。

08-D-05 ★

<set> 标签在 UPDATE 语句中的作用是？

  • A. 设置参数值
  • B. 自动去掉末尾多余逗号
  • C. 限制更新行数
  • D. 替代 <if> 判断

答案：B 解析： <set> 标签会自动生成 SET 关键字，并去除内部最后一个条件后多余的逗号，配合 <if> 实现按需更新字段。

08-D-06 ★★

MyBatis XML 中需要拼接 priority < 5，下列正确写法是？

  • A. <if test="priority < 5">
  • B. <if test="priority &lt; 5">
  • C. <if test="priority <![CDATA[<]]> 5">
  • D. B 和 C 都可以

答案：D 解析： XML 中 < 是特殊字符，必须转义为 &lt;，或用 <![CDATA[ ... ]]> 包裹。B、C 两种写法都正确。

08-D-07 ★★

<choose>、<when>、<otherwise> 三个标签的关系最接近哪种 Java 结构？

  • A. for
  • B. switch-case
  • C. try-catch
  • D. if-else if-else

答案：B 解析： <choose> 类似 switch，<when> 类似 case，<otherwise> 类似 default。多个 <when> 只会执行第一个匹配的分支。注意：与 if-else if-else 行为相似但语义上是 switch。

08-D-08 ★

MyBatis-Plus 的 QueryWrapper 主要用于构造？

  • A. SELECT 字段
  • B. WHERE 条件
  • C. GROUP BY
  • D. JOIN 子句

答案：B 解析： QueryWrapper 继承 AbstractWrapper，主要用于构造 WHERE 条件。SELECT 字段用 .select(...)，ORDER BY 用 .orderByXxx，但核心是 WHERE 条件构造。

08-D-09 ★★

下列代码中，wrapper.eq(status != null, "status", status) 中第一个参数 status != null 的作用是？

  • A. 编译检查
  • B. 当表达式为 false 时不拼接该条件
  • C. 当表达式为 true 时取反
  • D. 无实际作用

答案：B 解析： MyBatis-Plus 的条件方法三参重载形式 eq(condition, column, val)，第一参为 boolean 表达式，为 false 时跳过该条件，实现"条件可空"。

08-D-10 ★

wrapper.like("title", "需求") 生成的 SQL 片段是？

  • A. title = '需求'
  • B. title LIKE '需求'
  • C. title LIKE '%需求%'
  • D. title LIKE '%需求'

答案：C 解析： like 方法默认在参数两侧添加 %，生成 LIKE '%需求%'。若需单侧模糊，用 likeLeft 或 likeRight。

08-D-11 ★★

wrapper.between("priority", 1, 3) 生成的 SQL 是？

  • A. priority BETWEEN 1 AND 3
  • B. priority > 1 AND priority < 3
  • C. priority >= 1 AND priority <= 3
  • D. priority IN (1, 2, 3)

答案：A 解析： between(col, v1, v2) 生成 col BETWEEN v1 AND v2，等价于 col >= v1 AND col <= v2，是闭区间。

08-D-12 ★

下列哪个不是 MyBatis-Plus 的条件构造器？

  • A. QueryWrapper
  • B. LambdaQueryWrapper
  • C. UpdateWrapper
  • D. WhereWrapper

答案：D 解析： MyBatis-Plus 提供的构造器有 QueryWrapper、LambdaQueryWrapper、UpdateWrapper、LambdaUpdateWrapper，没有 WhereWrapper。

08-D-13 ★★

LambdaQueryWrapper<Task> 中方法引用 Task::getTitle 的作用是？

  • A. 调用 getTitle 方法
  • B. 表示 task 表的 title 列
  • C. 获取 title 属性值
  • D. 执行 SQL 查询

答案：B 解析： 方法引用 Task::getTitle 不调用方法，而是通过 SerializedLambda 解析出属性名 title，再转换为数据库列名 title，用于构造 WHERE 条件。

08-D-14 ★

启用 MyBatis-Plus 分页功能，必须配置？

  • A. PageInterceptor
  • B. MybatisPlusInterceptor + PaginationInnerInterceptor
  • C. @EnablePagination
  • D. PaginationAutoConfiguration

答案：B 解析： 必须在配置类中注册 MybatisPlusInterceptor Bean，并添加 PaginationInnerInterceptor 内部拦截器，否则 selectPage 不会真正分页。

08-D-15 ★★

new Page<Task>(2, 5) 中的两个参数分别表示？

  • A. 总记录数、每页大小
  • B. 起始行号、记录数
  • C. 当前页码、每页大小
  • D. 偏移量、页数

答案：C 解析： Page<T>(current, size)：current 是当前页码（从 1 开始），size 是每页记录数。new Page<>(2, 5) 表示查第 2 页，每页 5 条。

08-D-16 ★

selectPage 方法返回的类型是？

  • A. List<T>
  • B. Page<T>
  • C. IPage<T>
  • D. Optional<T>

答案：C 解析： BaseMapper.selectPage(IPage<T>, Wrapper<T>) 返回 IPage<T> 接口类型，实际对象是 Page<T>。IPage 是接口，便于扩展和 Mock。

08-D-17 ★★

IPage<T> 接口中不包含以下哪个属性？

  • A. records
  • B. total
  • C. current
  • D. tableName

答案：D 解析： IPage 包含 records(当前页数据列表)、total(总记录数)、size(每页大小)、current(当前页)、pages(总页数)。不含 tableName。

08-D-18 ★★

下列关于 PaginationInnerInterceptor 的描述，错误的是？

  • A. 必须设置 DbType 才能工作
  • B. 可通过 setMaxLimit 限制单页最大记录数
  • C. 默认会自动执行 COUNT 查询
  • D. 可通过 setOverflow(true) 处理页码越界

答案：A 解析： DbType 不设置时默认为 MYSQL，并非"必须设置"。但建议显式指定以避免未来版本变化。BCD 描述均正确。

08-D-19 ★

MyBatis-Plus 分页插件改写 SQL 时，对于 MySQL 数据库追加的子句是？

  • A. ROWNUM <= ?
  • B. LIMIT ?, ?
  • C. OFFSET ? FETCH NEXT ? ROWS ONLY
  • D. TOP ?

答案：B 解析： MySQL 分页用 LIMIT offset, size。Oracle 用 ROWNUM，SQL Server 用 OFFSET-FETCH，旧版 SQL Server 用 TOP。

08-D-20 ★★

下列关于 orderByDesc 多次链式调用的描述，正确的是？

  • A. 只有第一次调用生效
  • B. 只有最后一次调用生效
  • C. 按调用顺序生成多字段排序
  • D. 会报错

答案：C 解析： 多次调用 orderByDesc(A).orderByAsc(B) 会生成 ORDER BY A DESC, B ASC，按调用顺序追加，多字段排序生效。

08-D-21 ★★

下列关于动态 SQL 中 #{} 与 ${} 的区别，正确的是？

  • A. #{} 是字符串拼接，${} 是预编译占位
  • B. #{} 是预编译占位，${} 是字符串拼接
  • C. 两者都是预编译占位
  • D. 两者都是字符串拼接

答案：B 解析： #{} 生成 ? 占位符并由 JDBC 预编译，防 SQL 注入；${} 直接做字符串替换，有注入风险，仅用于表名/列名等结构场景。

08-D-22 ★

下列哪种场景下应使用 ${} 而不是 #{}？

  • A. 传入用户输入的查询值
  • B. 传入动态表名或列名
  • C. 传入 LIKE 的模糊关键字
  • D. 传入 IN 集合元素

答案：B 解析： 表名、列名不能用 ? 占位（JDBC 限制），必须用 ${} 拼接。但用户输入应严格校验防注入。其他场景都用 #{}。

08-D-23 ★★

wrapper.in("status", 1, 2, 3) 生成的 SQL 是？

  • A. status IN (1, 2, 3)
  • B. status = 1 OR status = 2 OR status = 3
  • C. status BETWEEN 1 AND 3
  • D. status = 1 AND status = 2 AND status = 3

答案：A 解析： in(column, v1, v2, ...) 生成 column IN (v1, v2, ...)。也可传集合：in("status", list)。

08-D-24 ★

下列关于 MyBatis-Plus 逻辑删除字段，正确的是？

  • A. 必须用 @TableField 注解
  • B. 必须用 @TableLogic 注解
  • C. 必须在 SQL 中手动加 deleted = 0
  • D. 与查询无关

答案：B 解析： 用 @TableLogic 标记逻辑删除字段后，MyBatis-Plus 自动在所有查询追加 deleted = 0，删除操作变为 UPDATE ... SET deleted = 1。

08-D-25 ★★

LambdaQueryWrapper 中 select(Task::getId, Task::getTitle) 的作用是？

  • A. 等同于 SELECT *
  • B. 只查询指定字段，避免大字段回填
  • C. 限制返回行数
  • D. 排序

答案：B 解析： select(SFunction...) 指定 SELECT 字段列表，避免查询 description 等大字段，减少网络传输与内存占用。

08-D-26 ★★

分页查询时，若当前页 current = 0，下列描述正确的是？

  • A. 自动查全部
  • B. 报错
  • C. 返回第 1 页结果
  • D. 返回空列表

答案：D 解析： MyBatis-Plus 中 current 从 1 开始。current=0 时计算的 offset 为负，部分版本报错，部分版本返回空。建议后端校验 page = Math.max(page, 1)。

08-D-27 ★

下列 Page 对象的属性中，表示总页数的是？

  • A. total
  • B. size
  • C. pages
  • D. current

答案：C 解析： pages = ceil(total / size) 是总页数。total 是总记录数，size 是每页大小，current 是当前页码。

08-D-28 ★★

下列关于 <foreach> 标签 separator 属性的描述，正确的是？

  • A. 分隔 collection 与 item
  • B. 指定每次循环之间拼接的分隔符
  • C. 指定 SQL 语句结束符
  • D. 指定 collection 的类型

答案：B 解析： separator="," 表示每次循环之间用逗号分隔，常用于 IN 查询 IN (1, 2, 3)。

08-D-29 ★

下列关于 wrapper 的链式调用，正确的是？

  • A. 每次调用返回新对象
  • B. 每次调用返回 this（当前对象）
  • C. 链式调用必须用 . 但不能换行
  • D. 链式调用有数量限制

答案：B 解析： 条件方法返回 this，因此可以连续链式调用。可以换行书写以提升可读性，无数量限制。

08-D-30 ★★★

关于 MyBatis-Plus 分页插件的 COUNT 语句生成，下列描述正确的是？

  • A. 用户必须手写 COUNT SQL
  • B. 自动去除原 SQL 中的 ORDER BY 再生成 COUNT
  • C. COUNT 语句性能一定与原查询一致
  • D. COUNT 结果会被缓存

答案：B 解析： 分页插件通过 JsqlParser 解析原 SQL，去掉 SELECT 字段和 ORDER BY 后生成 SELECT COUNT(*) FROM (...) t。COUNT 性能可能差（尤其有 JOIN 时），可用 page.setSearchCount(false) 禁用。

二、多项选择题（10题）

08-M-01 ★

下列属于 MyBatis 动态 SQL 标签的有？（多选）

  • A. <if>
  • B. <where>
  • C. <foreach>
  • D. <switch>
  • E. <choose>

答案：A、B、C、E 解析： MyBatis 提供 <if>、<where>、<foreach>、<choose>、<when>、<otherwise>、<set>、<trim>、<bind>、<sql> 等标签。没有 <switch>，分支用 <choose> 实现。

08-M-02 ★★

下列属于 QueryWrapper 支持的条件方法有？（多选）

  • A. eq
  • B. like
  • C. in
  • D. between
  • E. join

答案：A、B、C、D 解析： AbstractWrapper 提供 eq/ne/gt/ge/lt/le/like/notLike/likeLeft/likeRight/in/notIn/between/notBetween/isNull/isNotNull/inSql/exists 等条件方法。join 不是条件方法，关联查询用 XML 或 @Select 自定义。

08-M-03 ★★

关于 LambdaQueryWrapper 相比 QueryWrapper 的优势，正确的有？（多选）

  • A. 编译期检查字段名
  • B. 重构字段名时 IDE 同步提示
  • C. 自动完成驼峰转下划线
  • D. 性能显著优于 QueryWrapper
  • E. 支持动态表名

答案：A、B、C 解析： Lambda 方式通过方法引用编译期检查字段，重构友好，自动驼峰转下划线。性能与 QueryWrapper 几乎一致（Lambda 解析有缓存），优势不在性能。Lambda 不支持动态表名。

08-M-04 ★★

配置 MyBatis-Plus 分页插件 PaginationInnerInterceptor 时，可设置的属性有？（多选）

  • A. dbType（数据库类型）
  • B. maxLimit（单页最大记录数）
  • C. overflow（页码越界处理）
  • D. cacheTimeout（缓存超时）
  • E. optimizeJoin

答案：A、B、C、E 解析： PaginationInnerInterceptor 可设置 dbType、maxLimit、overflow、optimizeJoin（优化 LEFT JOIN）。没有 cacheTimeout 属性。

08-M-05 ★

下列属于 IPage<T> 接口方法的属性有？（多选）

  • A. records
  • B. total
  • C. size
  • D. current
  • E. pages

答案：A、B、C、D、E 解析： IPage 包含全部五项：records(当前页数据)、total(总记录数)、size(每页大小)、current(当前页)、pages(总页数)。

08-M-06 ★★

下列关于 <foreach> 标签属性，正确的有？（多选）

  • A. collection 指定要遍历的集合
  • B. item 指定每次循环的变量名
  • C. index 指定索引变量名
  • D. open 指定开始符号
  • E. close 指定结束符号
  • F. separator 指定分隔符

答案：A、B、C、D、E、F 解析： <foreach> 的全部六个属性：collection、item、index、open、close、separator。常用于 IN 查询和批量 INSERT。

08-M-07 ★★

在 MyBatis XML 中拼接 priority >= 1 AND priority <= 5，下列写法正确的有？（多选）

  • A. <if test="priority &gt;= 1">...</if>
  • B. <if test="priority <![CDATA[>=]]> 1">...</if>
  • C. <if test="priority >= 1">...</if>
  • D. 使用 wrapper.between("priority", 1, 5) 替代

答案：A、B、D 解析： XML 中 >、< 是特殊字符，必须转义（&gt;、&lt;）或用 CDATA 包裹。C 在 test 属性中虽可解析但不规范，部分 XML 解析器会报错；D 是 MyBatis-Plus 推荐方式。

08-M-08 ★★

下列哪些场景适合用动态 SQL XML 而非 QueryWrapper？（多选）

  • A. 多表 JOIN 关联查询
  • B. 复杂子查询
  • C. 简单单表 CRUD
  • D. 需要复用 SQL 片段（<sql> + <include>）
  • E. 动态表名查询

08-S-01 ★★

简述 MyBatis 动态 SQL 中 <if> 与 <choose>/<when>/<otherwise> 的区别，并各举一个适用场景。

参考答案：

  1. 结构差异：

    • <if> 是独立的条件判断，多个 <if> 之间相互独立，所有成立的条件都会拼接，是"与"关系。
    • <choose>/<when>/<otherwise> 是分支结构，类似 switch-case，多个 <when> 中只有第一个匹配的生效，最多走一个分支。

  2. 适用场景：

    • <if> 适合"多条件可空"查询：用户可同时按项目ID、状态、标题查询，每个条件独立判断是否拼接。 
      <if test="projectId != null">AND project_id = #{projectId}</if>
<if test="status != null">AND status = #{status}</if>
    • <choose> 适合"互斥分支"：根据排序字段名生成不同的 ORDER BY，只能选一种排序方式。 
      <choose>
  <when test="orderField == 'time'">ORDER BY create_time DESC</when>
  <when test="orderField == 'priority'">ORDER BY priority DESC</when>
  <otherwise>ORDER BY id DESC</otherwise>
</choose>

08-S-03 ★★

详细说明 MyBatis-Plus 分页插件的工作原理，并解释为何不配置时 selectPage 不分页。

参考答案：

工作原理：

  1. 拦截器注册： Spring Boot 启动时加载 MybatisPlusInterceptor Bean，内部包含 PaginationInnerInterceptor。
  2. 拦截点： MyBatis 在执行 SQL 时通过 Interceptor 接口拦截 Executor.query 方法。
  3. 参数解析： 拦截器从方法参数中提取 IPage 对象，获取 current、size。
  4. SQL 改写： 使用 JsqlParser 解析原始 SQL，生成两条 SQL：
    • 数据查询：在原 SQL 末尾追加 LIMIT offset, size（MySQL）；
    • COUNT 查询：去除 SELECT 字段与 ORDER BY，改写为 SELECT COUNT(*) FROM (...) t。
  5. 结果回填： 将数据列表填入 page.records，将 COUNT 结果填入 page.total，并计算 pages = ceil(total/size)。

不配置不分页的原因：

MyBatis-Plus 的分页能力完全依赖拦截器。如果不注册 PaginationInnerInterceptor：

  • 拦截器链中没有分页拦截器；
  • selectPage 方法本身只是 BaseMapper 的默认方法，内部调用 mapperSelectPage，把 IPage 当普通参数；
  • SQL 不会被改写，原 SQL 直接执行，返回全部数据；
  • COUNT 也不会执行，total 为 0。

因此，配置拦截器是分页生效的必要前提。

评分标准（满分 10 分）：

  • 准确描述分页插件的工作流程 5 步（5 分）
  • 解释不配置不分页的根本原因（3 分）
  • 提及 JsqlParser / 拦截器机制（2 分）

        this.taskMapper = taskMapper;
    }

    @Override
    public IPage<Task> queryPage(TaskQueryDto dto) {
        Page<Task> page = new Page<>(dto.getPage(), dto.getSize());

        LambdaQueryWrapper<Task> wrapper = new LambdaQueryWrapper<>();
        wrapper.eq(dto.getProjectId() != null, Task::getProjectId, dto.getProjectId())
               .eq(dto.getStatus() != null, Task::getStatus, dto.getStatus())
               .like(StringUtils.hasText(dto.getTitle()), Task::getTitle, dto.getTitle())
               .ge(dto.getMinPriority() != null, Task::getPriority, dto.getMinPriority())
               .orderByDesc(Task::getCreateTime);

        return taskMapper.selectPage(page, wrapper);
    }
}

题目： 请为 CTTS 系统编写一个 MyBatis 动态 SQL XML 映射文件，实现按多条件查询任务（不分页）。要求：

  1. 查询字段：id, title, description, project_id, status, priority, create_time
  2. 过滤条件（均为可空）：projectId（等值）、statusList（IN 查询）、title（模糊）、priorityRange（between 闭区间）
  3. 始终过滤 deleted = 0
  4. 按 create_time 倒序、id 升序排列
  5. 同时编写对应的 Mapper 接口方法
  6. 在 <set> 标签中实现按需更新 title、status、priority 三个字段

参考答案：

<?xml version="1.0" encoding="UTF-8" ?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="com.ctts.mapper.TaskMapper">

    <!-- 多条件动态查询 -->
    <select id="selectByConditions" resultType="com.ctts.entity.Task">
        SELECT id, title, description, project_id, status, priority, create_time
          FROM task
        <where>
            deleted = 0
            <if test="projectId != null">
                AND project_id = #{projectId}
            </if>
            <if test="title != null and title != ''">
                AND title LIKE CONCAT('%', #{title}, '%')
            </if>
            <if test="statusList != null and statusList.size() > 0">
                AND status IN
                <foreach collection="statusList" item="st" open="(" separator="," close=")">
                    #{st}
                </foreach>
            </if>
            <if test="minPriority != null and maxPriority != null">
                AND priority BETWEEN #{minPriority} AND #{maxPriority}
            </if>
        </where>
        ORDER BY create_time DESC, id ASC
    </select>

    <!-- 按需更新 -->
    <update id="updateSelective" parameterType="com.ctts.entity.Task">
        UPDATE task
        <set>
            <if test="title != null and title != ''">
                title = #{title},
            </if>
            <if test="status != null">
                status = #{status},
            </if>
            <if test="priority != null">
                priority = #{priority},
            </if>
        </set>
        WHERE id = #{id} AND deleted = 0
    </update>

</mapper>
