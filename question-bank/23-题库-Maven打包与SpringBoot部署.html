23-单选-01

Maven执行mvn clean package命令时，以下哪个阶段不会执行？

  • A
    clean
  • B
    compile
  • C
    install
  • D
    test
答案与解析

答案：C

解析：mvn clean package执行到package阶段为止，包含clean、compile、test、package，但不包含install（将jar安装到本地仓库）和deploy（发布到远程仓库）。install需要单独执行mvn install。

难度：★

23-单选-02

Spring Boot项目打包生成的可执行jar，其MANIFEST.MF文件中Main-Class属性指向的是？

  • A
    com.ctts.CttsApplication
  • B
    org.springframework.boot.loader.JarLauncher
  • C
    org.springframework.boot.SpringApplication
  • D
    org.apache.catalina.startup.Bootstrap
答案与解析

答案：B

解析：可执行jar的Main-Class是org.springframework.boot.loader.JarLauncher（Spring Boot启动器），而非业务主类。JarLauncher负责加载BOOT-INF/classes和BOOT-INF/lib，然后通过反射调用Start-Class（即com.ctts.CttsApplication）的main方法。

难度：★★

23-单选-03

关于-DskipTests和-Dmaven.test.skip=true，以下说法正确的是？

  • A
    两者完全等价
  • B
    -DskipTests跳过测试编译和执行，-Dmaven.test.skip=true仅跳过测试执行
  • C
    -DskipTests仅跳过测试执行，-Dmaven.test.skip=true跳过测试编译和执行
  • D
    两者都不跳过测试编译
答案与解析

答案：C

解析：

  • -DskipTests：跳过测试执行，但仍编译测试代码
  • -Dmaven.test.skip=true：跳过测试编译和执行

生产打包通常用-DskipTests，保留编译可发现测试代码的语法错误。

难度：★★

ctts.jar
├── META-INF/
│   └── MANIFEST.MF            # 包含Main-Class和Start-Class
├── org/springframework/boot/loader/  # 启动器代码
└── BOOT-INF/
    ├── classes/                # 项目自身class和资源文件
    └── lib/                    # 所有第三方依赖jar

MANIFEST.MF关键属性：

  • Main-Class: org.springframework.boot.loader.JarLauncher（启动器）
  • Start-Class: com.ctts.CttsApplication（业务主类）

  4. Spring上下文启动：SpringApplication.run()创建Spring容器，加载配置文件
  5. 内嵌Tomcat启动：创建Tomcat实例，注册DispatcherServlet，监听8080端口
  6. 应用就绪：发布ApplicationReadyEvent，应用开始接收请求

  • 内部结构说明（5分）：

一、"能运行不等于能交付"的理解（3分）：

"能运行"是指代码在开发者的IDE中可以正常启动和执行功能；"能交付"是指软件可以作为产品交付给用户使用，具备以下特征：

  • 可恢复：数据库脚本可重放、数据可备份恢复
  • 可信任：敏感信息不泄露、接口不暴露、安全有保障

一个能运行的系统，如果配置混乱、无法部署、数据不可恢复，就不能称为"可交付"。

2. 配置环节（3分）：

  • X-Real-IP：Nginx反向代理后，后端应用通过request.getRemoteAddr()获取的是Nginx的IP（127.0.0.1），而非客户端真实IP。设置X-Real-IP头传递客户端真实IP，后端可通过request.getHeader("X-Real-IP")获取。

#!/bin/bash
# ============================================================
# CTTS应用部署脚本
# 用法：./deploy.sh {start|stop|restart|status}
# ============================================================

# ==================== 变量配置 ====================
APP_NAME="ctts"
APP_DIR="/opt/ctts"
JAR_FILE="$APP_DIR/$APP_NAME.jar"
LOG_FILE="$APP_DIR/$APP_NAME.log"
PID_FILE="$APP_DIR/$APP_NAME.pid"
JAVA_OPTS="-Xms512m -Xmx1024m -XX:+UseG1GC"
SPRING_OPTS="--spring.profiles.active=prod"

# ==================== 函数定义 ====================

# 检查应用是否运行，返回PID（0表示未运行）
get_pid() {
    if [ -f "$PID_FILE" ]; then
        PID=$(cat "$PID_FILE")
        if ps -p "$PID" > /dev/null 2>&1; then
            echo "$PID"
            return 0
        fi
    fi
    echo "0"
    return 1
}

# 启动应用
start() {
    PID=$(get_pid)
    if [ "$PID" != "0" ]; then
        echo "[$APP_NAME] 应用已在运行，PID=$PID"
        return 0
    fi

    # 检查jar文件是否存在
    if [ ! -f "$JAR_FILE" ]; then
        echo "[$APP_NAME] 错误：jar文件不存在 - $JAR_FILE"
        return 1
    fi

    # 创建日志目录
    mkdir -p "$APP_DIR/logs"

    echo "[$APP_NAME] 正在启动..."
    nohup java $JAVA_OPTS -jar "$JAR_FILE" $SPRING_OPTS > "$LOG_FILE" 2>&1 &
    echo $! > "$PID_FILE"

    # 等待启动
    sleep 3

    PID=$(get_pid)
    if [ "$PID" != "0" ]; then
        echo "[$APP_NAME] 启动成功，PID=$PID"
        echo "[$APP_NAME] 日志文件：$LOG_FILE"
        echo "[$APP_NAME] 查看日志：tail -f $LOG_FILE"
    else
        echo "[$APP_NAME] 启动失败，请查看日志：$LOG_FILE"
        return 1
    fi
}

# 停止应用
stop() {
    PID=$(get_pid)
    if [ "$PID" == "0" ]; then
        echo "[$APP_NAME] 应用未运行"
        rm -f "$PID_FILE"
        return 0
    fi

    echo "[$APP_NAME] 正在停止，PID=$PID"
    kill -15 "$PID"

    # 等待5秒
    for i in $(seq 1 5); do
        if ! ps -p "$PID" > /dev/null 2>&1; then
            echo "[$APP_NAME] 已停止"
            rm -f "$PID_FILE"
            return 0
        fi
        sleep 1
        echo "[$APP_NAME] 等待退出... ($i/5)"
    done

    # 5秒后仍未退出，强制终止
    echo "[$APP_NAME] 优雅停止超时，强制终止"
    kill -9 "$PID"
    rm -f "$PID_FILE"
    echo "[$APP_NAME] 已强制停止"
}

# 重启应用
restart() {
    echo "[$APP_NAME] 正在重启..."
    stop
    sleep 2
    start
}

# 查看状态
status() {
    PID=$(get_pid)
    if [ "$PID" != "0" ]; then
        echo "[$APP_NAME] 运行中，PID=$PID"

        # 检查端口
        if command -v netstat &> /dev/null; then
            PORT=$(netstat -tlnp 2>/dev/null | grep "$PID" | awk '{print $4}' | awk -F: '{print $NF}' | head -1)
            if [ -n "$PORT" ]; then
                echo "[$APP_NAME] 监听端口：$PORT"
            fi
        fi

        # 显示内存占用
        MEM=$(ps -o rss= -p "$PID" 2>/dev/null | awk '{printf "%.1f MB", $1/1024}')
        echo "[$APP_NAME] 内存占用：$MEM"
    else
        echo "[$APP_NAME] 未运行"
    fi
}

# ==================== 主逻辑 ====================

case "$1" in
    start)
        start
        ;;
    stop)
        stop
        ;;
    restart)
        restart
        ;;
    status)
        status
        ;;
    *)
        echo "用法：$0 {start|stop|restart|status}"
        echo "  start   启动应用"
        echo "  stop    停止应用"
        echo "  restart 重启应用"
        echo "  status  查看状态"
        exit 1
        ;;
esac

exit 0

./deploy.sh restart
./deploy.sh stop

二、Linux启动命令：

#!/bin/bash
# CTTS生产环境启动命令

APP_DIR="/opt/ctts"
JAR_FILE="$APP_DIR/ctts.jar"
LOG_FILE="$APP_DIR/ctts.log"
PID_FILE="$APP_DIR/ctts.pid"

# 创建日志目录
mkdir -p "$APP_DIR/logs"

# 启动应用（含JVM调优参数）
nohup java \
    -Xms512m \
    -Xmx1024m \
    -XX:+UseG1GC \
    -XX:MaxGCPauseMillis=200 \
    -XX:+HeapDumpOnOutOfMemoryError \
    -XX:HeapDumpPath=$APP_DIR/logs/dump.hprof \
    -Dfile.encoding=UTF-8 \
    -Duser.timezone=Asia/Shanghai \
    -jar "$JAR_FILE" \
    --spring.profiles.active=prod \
    > "$LOG_FILE" 2>&1 &

# 保存PID
echo $! > "$PID_FILE"

# 输出提示
echo "CTTS启动中..."
echo "PID: $!"
echo "日志: tail -f $LOG_FILE"
echo "停止: kill -15 $(cat $PID_FILE)"

-XX:+UseG1GC 使用G1垃圾回收器
-XX:MaxGCPauseMillis=200 GC最大停顿200ms
-XX:+HeapDumpOnOutOfMemoryError OOM时生成堆dump
-XX:HeapDumpPath dump文件路径
-Dfile.encoding=UTF-8 文件编码UTF-8
-Duser.timezone=Asia/Shanghai 时区上海
