一、单项选择题（30题）

04-单选-01 ★

关于 @RestController 注解，下列说法正确的是：

  • A
    @RestController 是 Spring MVC 4.0 引入的注解，等价于 @Controller + @RequestMapping
  • B
    @RestController 标注的类中所有方法返回值都会被序列化为 JSON 写入响应体
  • C
    @RestController 只能返回 JSON 字符串，不能返回 Java 对象
  • D
    @RestController 标注的类中方法可以返回 JSP 视图名

答案：B

解析：@RestController = @Controller + @ResponseBody，组合的是 @ResponseBody 而非 @RequestMapping，A 错；它可返回 String、List、Map、自定义对象，由 Jackson 自动序列化，C 错；因为有 @ResponseBody，返回值不会作为视图名，D 错。B 正确。

04-单选-02 ★

下列注解中，不属于 Spring MVC 请求映射注解的是：

  • A
    @GetMapping
  • B
    @PostMapping
  • C
    @RequestMapping
  • D
    @JsonFormat

答案：D

解析：@JsonFormat 是 Jackson 的序列化注解，用于格式化日期等字段，不属于请求映射注解。其余三个都是 Spring MVC 的请求映射注解。

04-单选-03 ★

@GetMapping("/projects/{id}") 中，{id} 表示的是：

  • A
    查询参数
  • B
    路径变量
  • C
    请求头
  • D
    请求体

答案：B

解析：URL 路径中以 {xxx} 形式定义的占位符是路径变量，需配合 @PathVariable 取值。

04-单选-04 ★

下列用于接收 URL 查询参数（query string）的注解是：

  • A
    @PathVariable
  • B
    @RequestBody
  • C
    @RequestParam
  • D
    @RequestHeader

答案：C

解析：@RequestParam 用于接收 URL 中 ?key=value 形式的查询参数；@PathVariable 接收路径段；@RequestBody 接收请求体；@RequestHeader 接收请求头。

04-单选-05 ★

用于接收 POST 请求体中 JSON 数据的注解是：

  • A
    @RequestParam
  • B
    @PathVariable
  • C
    @RequestBody
  • D
    @RequestHeader

答案：C

解析：@RequestBody 通过 HttpMessageConverter 将请求体反序列化为 Java 对象，典型场景是接收 JSON。

04-单选-06 ★

关于 @RequestParam 的 required 属性，默认值是：

  • A
    false
  • B
    true
  • C
    null
  • D
    不存在默认值

答案：B

解析：@RequestParam 默认 required = true，若前端未传该参数会返回 400 错误。可选参数需显式写 required = false。

04-单选-07 ★★

下列代码片段中，访问 GET /projects/1 能正确返回的是：

  • A
    @GetMapping("/projects/{id}")
public Project getById(@RequestParam Long id) { ... }
  • B
    @GetMapping("/projects/{id}")
public Project getById(@PathVariable Long id) { ... }
  • C
    @GetMapping("/projects/{id}")
public Project getById(@RequestBody Long id) { ... }
  • D
    @GetMapping("/projects/{id}")
public Project getById(@RequestHeader Long id) { ... }

答案：B

解析：路径变量 {id} 必须用 @PathVariable 接收。GET 请求一般无请求体，C 错；A 用 @RequestParam 接收的是 query 参数；D 用 @RequestHeader 接收请求头。

04-单选-08 ★★

关于 @RequestMapping 注解，下列说法错误的是：

  • A
    可标注在类上，定义该控制器所有接口的统一前缀
  • B
    可标注在方法上，定义具体的访问路径
  • C
    可通过 method 属性限定 HTTP 方法
  • D
    标注在类上时，方法上的 @GetMapping 路径会覆盖类上的路径

答案：D

解析：方法路径与类路径是拼接关系（类路径 + 方法路径），不是覆盖。

04-单选-09 ★★

下列代码中，前端访问 POST /projects，能正确接收 JSON 的是：

  • A
    @PostMapping("/projects")
public String add(@RequestParam Project project) { ... }
  • B
    @PostMapping("/projects")
public String add(@PathVariable Project project) { ... }
  • C
    @PostMapping("/projects")
public String add(@RequestBody Project project) { ... }
  • D
    @PostMapping("/projects")
public String add(@RequestHeader Project project) { ... }

答案：C

解析：POST 请求体中的 JSON 必须用 @RequestBody 接收。

04-单选-10 ★★

下列哪个 HTTP 方法对应的 Spring MVC 注解不存在？

  • A
    @GetMapping
  • B
    @PostMapping
  • C
    @PatchMapping
  • D
    @OptionsMapping

答案：D

解析：Spring MVC 提供了 @GetMapping、@PostMapping、@PutMapping、@DeleteMapping、@PatchMapping，没有 @OptionsMapping。OPTIONS 方法用 @RequestMapping(method = RequestMethod.OPTIONS)。

04-单选-11 ★★

某接口路径为 /projects/{id}/tasks，访问 GET /projects/5/tasks，下列方法签名正确的是：

  • A
    getTasks(@RequestParam("id") Long projectId)
  • B
    getTasks(@PathVariable("id") Long projectId)
  • C
    getTasks(@RequestBody("id") Long projectId)
  • D
    getTasks(@RequestHeader("id") Long projectId)

答案：B

解析：路径中的 {id} 是路径变量，用 @PathVariable 接收。即使方法参数名是 projectId，也通过 @PathVariable("id") 显式指定路径变量名。

04-单选-12 ★★

@RestController 与 @Controller 的核心区别在于：

  • A
    @RestController 只能处理 AJAX 请求
  • B
    @RestController 隐式包含了 @ResponseBody，方法返回值直接写入响应体
  • C
    @Controller 不能用于前后端分离项目
  • D
    @RestController 性能比 @Controller 高

答案：B

解析：@RestController 是 @Controller + @ResponseBody 的组合注解，核心差异在于 @ResponseBody。其余选项均不正确。

04-单选-13 ★★

下列关于 @PathVariable 的描述，正确的是：

  • A
    用于接收 URL 查询字符串中的参数
  • B
    用于接收请求体中的 JSON 数据
  • C
    用于接收 URL 路径中以 {xxx} 形式定义的变量
  • D
    默认 required = false

答案：C

解析：@PathVariable 接收路径变量，A 描述的是 @RequestParam，B 描述的是 @RequestBody。@PathVariable 默认 required = true。

04-单选-14 ★★

某查询接口需要接收 keyword、page、size 三个可选参数，下列设计最合理的是：

  • A
    全部使用 @PathVariable
  • B
    全部使用 @RequestBody
  • C
    全部使用 @RequestParam，并设置 required = false 或 defaultValue
  • D
    全部使用 @RequestHeader

答案：C

解析：查询、分页、过滤类可选参数应放在 query string 中，用 @RequestParam 接收。

04-单选-15 ★★

下列代码运行后，前端未传 keyword 参数时会发生什么？

@GetMapping("/search")
public String search(@RequestParam String keyword) {
    return keyword;
}
  • A
    返回 null
  • B
    返回空字符串
  • C
    返回 400 错误
  • D
    返回 500 错误

答案：C

解析：@RequestParam 默认 required = true，前端未传该参数时返回 400 Bad Request。若想允许为空，需显式写 required = false 或 defaultValue。

04-单选-16 ★★

关于 @RequestBody，下列说法正确的是：

  • A
    一个方法可以有多个 @RequestBody 参数
  • B
    通常用于 GET 请求
  • C
    不要求请求头设置 Content-Type
  • D
    可以与 @RequestParam 在同一个方法中共存

答案：D

解析：@RequestBody 接收请求体，@RequestParam 接收 query string，二者可共存于同一方法（如 POST /projects?notify=true Body 还有 JSON）。A 错（最多一个），B 错（一般用于 POST/PUT/PATCH），C 错（默认要求 Content-Type: application/json）。

04-单选-17 ★★

@JsonIgnore 注解的作用是：

  • A
    序列化时把字段值置为 null
  • B
    序列化与反序列化时都忽略该字段
  • C
    仅序列化时忽略该字段
  • D
    仅反序列化时忽略该字段

答案：B

解析：@JsonIgnore 默认在序列化与反序列化两个方向都忽略该字段。若只想单向忽略，需用 @JsonProperty(access = Access.READ_ONLY) 或 WRITE_ONLY。

04-单选-18 ★★

实体类中有 LocalDateTime createTime 字段，希望 JSON 返回格式为 yyyy-MM-dd HH:mm:ss，应使用的注解是：

04-单选-20 ★★

04-单选-21 ★★★

@RestController

04-单选-23 ★★★

下列代码中，访问 GET /projects/1 的返回值是：

@RestController
public class ProjectController {

04-单选-24 ★★★

关于 @RequestBody 反序列化，下列描述错误的是：

  • A
    JSON 字段名必须与 Java 对象字段名完全一致

04-单选-25 ★★★

某 POST 接口接收 JSON {"projectName":"电商实训"}，实体类字段为 name，下列哪种方式能让 JSON 正确映射到 name 字段？

04-单选-26 ★★★

下列代码中，@RequestMapping 的 method 属性可以省略吗？

@RestController
@RequestMapping("/projects")
public class ProjectController {
    @RequestMapping(value = "/list", method = RequestMethod.GET)

}
  • A
    可以省略，省略后默认支持所有 HTTP 方法
  • B
    可以省略，省略后默认只支持 GET
  • C
    不可以省略，否则启动报错
  • D
    可以省略，但必须用 @GetMapping 替换

答案：A

04-单选-27 ★★★

下列关于 @RequestHeader 的描述，错误的是：

  • A

  • B
    通过 value 属性指定请求头名称
  • C
    默认 required = true
  • D

答案：D

解析：一个方法可以有多个 @RequestHeader 参数，分别接收不同的请求头字段，如同时接收 Authorization 和 User-Agent。

04-单选-28 ★★★

下列代码启动后会出现的现象是：

@RestController
@RequestMapping("/projects")
public class ProjectController {

    @GetMapping
    public List<Project> list() { ... }

    @GetMapping
    public List<Project> all() { ... }
}
  • A
    启动正常，两个方法都能访问
  • B
    启动时报 Ambiguous mapping 异常
  • C
    启动正常，只有第一个方法能访问
  • D
    启动正常，只有第二个方法能访问

答案：B

解析：同一控制器中两个方法映射了完全相同的路径（/projects + GET），Spring 启动时会检测到冲突并抛出 Ambiguous mapping 异常。

04-单选-29 ★★★

RESTful 风格中，"根据 ID 删除一个项目"的接口设计最规范的是：

  • B
    GET /projects/delete/1
  • C
    DELETE /projects/1
  • D
    POST /projects/1/delete

答案：C

解析：RESTful 用 HTTP 方法表达动作，DELETE 表删除；资源 ID 作为路径变量。DELETE /projects/1 是最规范的设计。

04-单选-30 ★★★

某接口同时接收路径参数和请求体，下列签名正确的是：

04-多选-02 ★

下列关于 @RestController 的描述，正确的有（多选）：

  • A
    它是 @Controller + @ResponseBody 的组合
  • B
    标注的类中方法返回值会被自动序列化为 JSON
  • C
    适合用于前后端分离项目
  • D

  • E
    是 Spring 4.0 引入的注解

答案：ABCE

04-多选-03 ★★

下列注解中，用于接收 HTTP 请求参数的有（多选）：

  • A
    @RequestParam
  • B
    @PathVariable
  • C
    @RequestBody
  • D
    @RequestHeader
  • E
    @RequestMapping

答案：ABCD

解析：A、B、C、D 分别用于接收 query、path、body、header 中的参数。@RequestMapping 用于映射请求，不是接收参数。

04-多选-04 ★★

下列关于 @RequestParam 的描述，正确的有（多选）：

  • A
    默认 required = true

  1. 区别：
    • @Controller 是 Spring MVC 传统的控制器注解，标记一个类为控制器。其方法默认返回视图名，由 ViewResolver 解析跳转到页面（如 JSP、Thymeleaf）。

    • @RestController 自动包含 @ResponseBody，省去在每个方法上重复添加注解。
    • 与前端框架（Vue、React）的 axios/fetch 调用天然契合，前端直接拿到 JSON 数据。
  3. 示例： 
    @RestController
@RequestMapping("/projects")
public class ProjectController {
    @GetMapping("/{id}")
    public Project getById(@PathVariable Long id) {
        return projectService.getById(id);
    }
}

  • 给出完整的类代码（含 package、import、注解、方法签名、方法体可写 return null;）

package com.ctts.controller;

import com.ctts.entity.Task;
import com.ctts.service.TaskService;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.web.bind.annotation.*;

import java.util.List;

@RestController
public class TaskController {

    @Autowired
    private TaskService taskService;

    /**
     * 接口1：查询某项目下的任务列表
     * GET /projects/{projectId}/tasks?status=0&page=1&size=10
     *
     * 说明：projectId 是路径变量（资源标识），status/page/size 是查询参数（筛选过滤）
     */
    @GetMapping("/projects/{projectId}/tasks")
    public List<Task> listByProject(
            @PathVariable Long projectId,
            @RequestParam(value = "status", required = false) Integer status,
            @RequestParam(value = "page", defaultValue = "1") int page,
            @RequestParam(value = "size", defaultValue = "10") int size) {
        return taskService.listByProject(projectId, status, page, size);
    }

    /**
     * 接口2：根据任务 ID 查询任务详情
     * GET /tasks/{id}
     *
     * 说明：id 是路径变量（资源唯一标识）
     */
    @GetMapping("/tasks/{id}")
    public Task getById(@PathVariable Long id) {
        return taskService.getById(id);
    }

    /**
     * 接口3：新增任务
     * POST /tasks
     * Body: {"title":"设计登录页","projectId":1,"assigneeId":10}
     *
     * 说明：复杂对象数据载体用 @RequestBody 接收
     */
    @PostMapping("/tasks")
    public Task add(@RequestBody Task task) {
        return taskService.add(task);
    }
}

设计说明：

  • 接口1的路径设计遵循 RESTful 嵌套资源风格，体现"项目下的任务"的从属关系。
  • 接口2和接口3的路径直接用 /tasks，因为这两个操作不依赖于具体项目上下文。
  • 类上没有加 @RequestMapping 定统一前缀，因为不同接口的前缀不同（/projects/... 和 /tasks/...）。

04-编程设计-02 ★★★

请为 CTTS 项目设计一个 UserController（用户控制器），需要实现以下 4 个接口：

  1. 用户登录：POST /users/login，请求体 JSON 包含 username、password，返回 {"token": "xxx"}
  2. 获取当前登录用户信息：GET /users/me，从请求头 Authorization 中获取 Token
  3. 分页查询用户列表：GET /users?keyword=张&page=1&size=10
  4. 更新用户信息：PUT /users/{id}，请求体 JSON 包含更新后的用户数据

要求：

  • 使用 @RestController，类级别加 @RequestMapping("/users")
  • 正确选择参数接收注解
  • 返回值类型自定（可用 Map<String, Object> 或自定义 User 实体）
  • 给出完整的类代码
  • 对每个接口的参数设计理由作简要注释说明

参考答案：

package com.ctts.controller;

import com.ctts.entity.User;
import com.ctts.service.UserService;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.web.bind.annotation.*;

import java.util.HashMap;
import java.util.List;
import java.util.Map;

@RestController
@RequestMapping("/users")
public class UserController {

    @Autowired
    private UserService userService;

    /**
     * 接口1：用户登录
     * POST /users/login
     * Body: {"username":"admin","password":"123456"}
     *
     * 设计理由：登录提交的是结构化数据（用户名+密码），适合用 @RequestBody 接收 JSON。
     * 返回 Map<String,Object> 表达 token，灵活方便。
     */
    @PostMapping("/login")
    public Map<String, Object> login(@RequestBody Map<String, String> body) {
        String username = body.get("username");
        String password = body.get("password");
        String token = userService.login(username, password);
        Map<String, Object> result = new HashMap<>();
        result.put("token", token);
        return result;
    }

    /**
     * 接口2：获取当前登录用户信息
     * GET /users/me
     * Header: Authorization: Bearer xxx-token
     *
     * 设计理由：Token 放在请求头中是行业标准，用 @RequestHeader 接收。
     * required = false 便于未登录时返回提示而不是 400。
     */
    @GetMapping("/me")
    public Map<String, Object> me(
            @RequestHeader(value = "Authorization", required = false) String token) {
        Map<String, Object> result = new HashMap<>();
        if (token == null || token.isEmpty()) {
            result.put("code", 401);
            result.put("msg", "未登录");
            return result;
        }
        User user = userService.getByToken(token);
        result.put("code", 200);
        result.put("data", user);
        return result;
    }

    /**
     * 接口3：分页查询用户列表
     * GET /users?keyword=张&page=1&size=10
     *
     * 设计理由：分页与搜索条件是可选的筛选过滤参数，适合用 @RequestParam。
     * keyword 可选（required = false），page/size 有默认值。
     */
    @GetMapping
    public List<User> list(
            @RequestParam(value = "keyword", required = false) String keyword,
            @RequestParam(value = "page", defaultValue = "1") int page,
            @RequestParam(value = "size", defaultValue = "10") int size) {
        return userService.list(keyword, page, size);
    }

    /**
     * 接口4：更新用户信息
     * PUT /users/{id}
     * Body: {"nickname":"张三","email":"zhangsan@ctts.com"}
     *
     * 设计理由：id 是资源唯一标识放路径（@PathVariable），更新数据放请求体（@RequestBody）。
     * PUT 方法符合 RESTful 全量更新语义。
     */
    @PutMapping("/{id}")
    public User update(@PathVariable Long id, @RequestBody User user) {
        user.setId(id);
        return userService.update(user);
    }
}

设计要点：

  1. 登录接口：用 @RequestBody Map<String, String> 而非自定义 DTO，因为登录字段少且无需建实体。生产中建议用专门的 LoginDTO。
  2. 获取当前用户：Token 放请求头是行业惯例（避开 URL 被日志记录的风险），用 @RequestHeader(required = false) 容错。
  3. 分页查询：keyword 可选，page/size 有默认值，典型 query 参数场景。
  4. 更新接口：路径参数 + 请求体的组合是 RESTful 全量更新的标准模式。

评分标准（满分 15 分）：

  • 类注解 @RestController + @RequestMapping("/users")（2 分）
  • 4 个接口方法签名完整正确（每个 2 分，共 8 分）
  • 参数接收注解选择合理（3 分）
  • 注释说明设计理由（2 分）
