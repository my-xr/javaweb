一、单项选择题（30 题）

21-单选-01 ★

CTTS 系统中，教师端"创建实训项目"接口的请求路径应为？ A. POST /api/projects B. POST /api/teacher/projects C. POST /api/admin/projects D. POST /teacher/projects

答案：B 解析：教师端接口统一以 /api/teacher 为前缀，创建项目属于教师端业务，路径为 POST /api/teacher/projects。

21-单选-02 ★

CTTS 系统包含的三种角色是？ A. 学生、教师、访客 B. 学生、教师、管理员 C. 用户、管理员、超级管理员 D. 学生、助教、教师

答案：B 解析：CTTS 系统设计三角色：STUDENT（学生）、TEACHER（教师）、ADMIN（管理员）。

21-单选-03 ★

本项目技术栈中，用于接口文档的工具是？ A. Swagger2 B. Knife4j C. Postman D. YApi

答案：B 解析：项目使用 Knife4j 作为接口文档工具，访问路径为 http://localhost:8080/doc.html。

21-单选-04 ★

统一响应类 Result<T> 中不包含以下哪个字段？ A. code B. message C. data D. method

答案：D 解析：Result<T> 包含 code、message、data、timestamp 四个字段，不包含 method。

21-单选-05 ★

全局异常处理器 GlobalExceptionHandler 使用的注解是？ A. @ControllerAdvice B. @RestControllerAdvice C. @Component D. @Configuration

答案：B 解析：@RestControllerAdvice = @ControllerAdvice + @ResponseBody，返回 JSON 格式异常信息。

21-单选-06 ★★

教师端"查看项目下任务列表"接口需要返回任务所属项目标题和提交人数，这种查询属于？ A. 单表查询 B. 多表关联查询 C. 聚合统计查询 D. 子查询

答案：B 解析：需要关联 task、project、submission 三张表，属于多表关联查询。

21-单选-07 ★★

MyBatis-Plus 中，用于自定义多表关联 SQL 的文件是？ A. Entity.java B. Mapper.java C. Mapper.xml D. Service.java

答案：C 解析：复杂的多表关联 SQL 在 Mapper.xml 中编写，通过 namespace 与 Mapper 接口方法绑定。

21-单选-08 ★★

TaskCreateDTO 中 deadline 字段标注 @Future 注解的作用是？ A. 校验日期格式 B. 校验时间必须晚于当前时间 C. 校验时间不能为空 D. 校验时间必须为工作日

答案：B 解析：@Future 确保 LocalDateTime 值必须是将来的时间，用于任务截止时间校验。

21-单选-09 ★★

学生端"提交任务成果"接口中，同一学生对同一任务未评审前不可重复提交，该校验属于？ A. 参数格式校验 B. 唯一性业务校验 C. 权限校验 D. 非空校验

答案：B 解析：这是基于业务规则的唯一性校验，需查询数据库判断是否存在 PENDING 状态的提交。

21-单选-10 ★★

评审提交接口中，若得分超过任务满分，应抛出的异常是？ A. NullPointerException B. BusinessException C. IllegalArgumentException D. RuntimeException

答案：B 解析：业务规则校验失败应抛出 BusinessException，由全局异常处理器捕获并返回友好提示。

21-单选-11 ★★

SubmissionMapper.xml 中查询学生提交情况时，LEFT JOIN 的表是？ A. task B. project C. user D. role

答案：C 解析：需要关联 user 表获取学生姓名（real_name）和班级（class_name）信息。

21-单选-12 ★

@Transactional 注解的 rollbackFor 属性默认回滚的异常是？ A. Exception B. RuntimeException C. IOException D. Throwable

答案：B 解析：默认只回滚 RuntimeException 和 Error，建议显式指定 rollbackFor = Exception.class 以覆盖所有受检异常。

21-单选-13 ★★

管理员端创建用户时，密码应如何存储？ A. 明文存储 B. Base64 编码 C. MD5 加密 D. BCrypt 加密

答案：D 解析：使用 BCryptPasswordEncoder 加密，每次加密结果不同，安全性高于 MD5。

21-单选-14 ★

Project 实体的 status 字段不包含以下哪个值？ A. DRAFT B. PUBLISHED C. ARCHIVED D. CLOSED

答案：C 解析：项目状态有三种：DRAFT（草稿）、PUBLISHED（已发布）、CLOSED（已关闭），不包含 ARCHIVED。

21-单选-15 ★★

学生端"查看实训项目列表"接口只返回 status 为 PUBLISHED 的项目，这体现了？ A. 参数校验 B. 权限隔离 / 数据范围控制 C. 事务管理 D. 接口文档规范

答案：B 解析：不同角色可见数据范围不同，学生只能看到已发布项目，属于权限隔离中的数据范围控制。

21-单选-16 ★

Knife4j 接口文档的访问地址是？ A. http://localhost:8080/swagger-ui.html B. http://localhost:8080/doc.html C. http://localhost:8080/api-docs D. http://localhost:8080/knife4j

答案：B 解析：Knife4j 默认访问路径为 /doc.html。

21-单选-17 ★★

Result.fail(ResultCode.NOT_FOUND) 返回的 code 是？ A. 200 B. 400 C. 404 D. 500

答案：C 解析：ResultCode.NOT_FOUND 的 code 为 404。

21-单选-18 ★★

以下哪个注解用于校验请求体参数？ A. @Validated B. @Valid C. @RequestParam D. @PathVariable

答案：B 解析：@Valid 用于标注在 @RequestBody 参数前，触发 JSR-303 校验。

21-单选-19 ★★★

在 TaskMapper.xml 中统计每个任务的提交人数，正确的 SQL 片段是？ A. SELECT task_id, COUNT(*) FROM submission B. SELECT task_id, COUNT(*) FROM submission GROUP BY task_id C. SELECT COUNT(*) FROM submission WHERE task_id = #{taskId} D. SELECT task_id, SUM(*) FROM submission GROUP BY task_id

答案：B 解析：按 task_id 分组统计，需使用 GROUP BY task_id 和 COUNT(*)。

21-单选-20 ★★

Submission 实体的 status 字段值为 GRADED 表示？ A. 待评审 B. 已评分 C. 已删除 D. 已驳回

答案：B 解析：PENDING 表示待评审，GRADED 表示已评分。

21-单选-21 ★

本项目基础包名是？ A. com.example B. com.ctts C. cn.ctts D. org.ctts

答案：B 解析：项目基础包名为 com.ctts。

21-单选-22 ★★

@TableField(fill = FieldFill.INSERT) 的作用是？ A. 插入时自动填充 B. 更新时自动填充 C. 查询时自动填充 D. 删除时自动填充

答案：A 解析：FieldFill.INSERT 表示在插入时自动填充字段（如 createTime）。

21-单选-23 ★★★

教师端"查看学生提交情况"返回的 SubmissionReviewVO 中，studentName 字段对应数据库 user 表的哪个字段？ A. username B. real_name C. password D. role

答案：B 解析：studentName 显示学生真实姓名，对应 user 表的 real_name 字段。

21-单选-24 ★★

AdminUserCreateDTO 中 username 字段的 @Pattern 正则 ^[a-zA-Z0-9_]{4,20}$ 表示？ A. 4-20 位字母数字下划线 B. 4-20 位任意字符 C. 只能字母 D. 只能数字

答案：A 解析：正则要求用户名长度 4-20，仅允许字母、数字、下划线。

21-单选-25 ★★

以下哪个接口需要 @PathVariable 注解获取参数？ A. 创建项目 B. 发布任务 C. 查看项目下任务列表 D. 提交任务成果

答案：C 解析：查看项目下任务列表路径为 /api/teacher/projects/{pid}/tasks，需用 @PathVariable 获取 pid。

21-单选-26 ★★

ProjectStatusDTO 中 status 字段使用 @Pattern 校验，允许的值不包括？ A. DRAFT B. PUBLISHED C. CLOSED D. PENDING

答案：D 解析：@Pattern(regexp = "DRAFT|PUBLISHED|CLOSED") 不允许 PENDING（PENDING 是 submission 的状态）。

21-单选-27 ★★★

学生端"查看个人成绩"接口的 SQL 需要关联几张表？ A. 1 张 B. 2 张 C. 3 张 D. 4 张

答案：C 解析：关联 submission、task、project 三张表，获取成绩、任务标题、项目标题。

21-单选-28 ★★

@Size(min = 10, max = 5000) 注解校验的是？ A. 字符串长度在 10-5000 之间 B. 数字大小在 10-5000 之间 C. 集合元素数量在 10-5000 之间 D. 数组长度在 10-5000 之间

答案：A 解析：@Size 用于字符串时校验长度，用于集合时校验元素数量。此处应用于提交内容字符串。

21-单选-29 ★★

评审接口 PUT /api/teacher/submissions/{sid}/review 中，评审完成后 submission 的 status 应更新为？ A. PENDING B. GRADED C. REVIEWED D. CLOSED

答案：B 解析：评审后状态变为 GRADED（已评分）。

21-单选-30 ★★★

以下关于接口设计的说法，错误的是？ A. RESTful 风格使用 HTTP 方法区分操作 B. 路径中的资源名应使用复数 C. 所有接口必须使用 POST 方法 D. 接口应返回统一的响应结构

答案：C 解析：RESTful 风格应根据操作语义使用 GET/POST/PUT/DELETE 等方法，并非全部用 POST。

三、判断题（20 题）

21-判断-01 ★

CTTS 系统的教师端、学生端、管理员端接口共用同一个 Controller 类。

  • A. 正确
  • B. 错误

答案：B 解析：三端接口分别在不同 Controller 包下，教师端在 controller.teacher，学生端在 controller.student，管理员端在 controller.admin。

21-判断-02 ★

Result<T> 类的 success() 方法可以不传 data 参数。

  • A. 正确
  • B. 错误

答案：A 解析：Result.success() 无参重载方法返回 data 为 null 的成功响应。

21-判断-03 ★★

@RestControllerAdvice 注解等同于 @ControllerAdvice + @ResponseBody。

  • A. 正确
  • B. 错误

答案：A 解析：@RestControllerAdvice 是组合注解，返回值自动转为 JSON。

21-判断-04 ★★

在 MyBatis-Plus 中，所有多表关联查询都可以通过 LambdaQueryWrapper 实现，无需写 XML。

  • A. 正确
  • B. 错误

答案：B 解析：复杂的多表关联查询（如带子查询、聚合统计）仍需通过 XML 自定义 SQL 实现。

21-判断-05 ★

学生端只能查看 status 为 PUBLISHED 的项目。

  • A. 正确
  • B. 错误

答案：A 解析：学生端 listProjects 方法通过 eq(Project::getStatus, "PUBLISHED") 过滤。

21-判断-06 ★★

评审提交时，得分可以超过任务的 maxScore。

  • A. 正确
  • B. 错误

答案：B 解析：review 方法会校验 score 不超过 task.maxScore，否则抛出 BusinessException。

21-判断-07 ★★

同一学生对同一任务可以无限次提交，只要尚未评审。

  • A. 正确
  • B. 错误

答案：B 解析：存在 PENDING 状态的提交时，不允许重复提交，会抛出 SUBMISSION_DUPLICATE 异常。

21-判断-08 ★

管理员创建用户时密码使用明文存储。

  • A. 正确
  • B. 错误

答案：B 解析：使用 BCryptPasswordEncoder 加密存储。

21-判断-09 ★★

@Future 注解可以用于校验 LocalDateTime 类型的字段。

  • A. 正确
  • B. 错误

答案：A 解析：@Future 支持校验 Date、Calendar、LocalDateTime 等时间类型。

21-判断-10 ★★

SubmissionMapper.xml 中查询学生提交情况时使用的是 INNER JOIN。

  • A. 正确
  • B. 错误

答案：B 解析：使用的是 LEFT JOIN，确保即使 user 表无对应记录也能返回 submission 数据。

21-判断-11 ★

本项目所有接口均需要 JWT 鉴权。

  • A. 正确
  • B. 错误

答案：A 解析：所有业务接口都需在请求头携带 Authorization: Bearer 。

21-判断-12 ★★

@TableField(fill = FieldFill.INSERT_UPDATE) 表示插入和更新时都自动填充。

  • A. 正确
  • B. 错误

答案：A 解析：INSERT_UPDATE 表示插入和更新时均触发自动填充，常用于 updateTime 字段。

21-判断-13 ★★

教师端"查看项目下任务列表"返回的 VO 类型是 Task。

  • A. 正确
  • B. 错误

答案：B 解析：返回 TaskVO，包含关联字段 projectTitle 和 submissionCount。

21-判断-14 ★★

BusinessException 继承自 RuntimeException。

21-论述-02 ★★

请说明统一响应结构 Result<T> 和全局异常处理器的设计意义，并分析"接口契约让前后端各司其职"这一思政理念如何体现在代码中。

参考答案：

  • 统一响应意义：所有接口返回 {code, message, data, timestamp} 结构，前端无需针对不同接口写不同的解析逻辑，降低沟通成本；统一的 code 便于前端做错误分支处理；体现行业规范化。
  • 全局异常意义：将异常处理从业务代码中抽离，Service 只需抛出 BusinessException，由 GlobalExceptionHandler 统一转换为 Result.fail()，避免向前端暴露堆栈信息，提升安全性和可维护性。
  • 思政体现：接口契约（接口清单表）规定了请求路径、参数、响应结构，前端按契约开发页面调用，后端按契约实现逻辑，双方各司其职、互不阻塞。统一响应就是契约的具体形式，全局异常保证了契约在任何异常情况下都不被破坏（始终返回结构化 JSON）。这体现了团队协作中"契约精神"的价值：每个人做好本职、遵守约定，系统才能高效运转。

评分标准（10 分）：

  • 统一响应意义 3 分
  • 全局异常意义 3 分
  • 思政理念结合代码分析 4 分

21-论述-03 ★★★

学生端"提交任务成果"接口中包含多项校验（参数校验、唯一性校验、任务存在性校验、截止时间校验），请分析这些校验为何要分层放置（Controller 层 vs Service 层），并说明如果将所有校验都放在 Controller 层会有什么问题。

参考答案：

  • 分层放置原则：
    • Controller 层：参数格式校验（@Valid + JSR-303 注解），如 content 非空、长度 10-5000。这类校验与业务无关，只关心参数格式。
    • Service 层：业务规则校验，如唯一性（是否已有 PENDING 提交）、任务存在性、截止时间。这类校验需要查询数据库，依赖业务状态。
  • 全部放 Controller 层的问题：
    1. Controller 职责膨胀，既处理请求又处理业务，违反单一职责原则。
    2. 业务校验逻辑无法复用，若其他入口（如批量导入）也需同样校验，只能复制代码。
    3. 数据库访问提前到 Controller 层，破坏分层架构，Service 层失去对业务的一致性控制。
    4. 事务边界不清晰，业务校验与业务操作可能不在同一事务中，导致一致性风险。
  • 结论：参数校验在 Controller，业务校验在 Service，是分层架构的最佳实践，保证职责清晰、可复用、事务一致。

评分标准（10 分）：

  • 分层原则说明 4 分
  • Controller 层 / Service 层校验举例各 2 分，共 4 分
  • 全放 Controller 层的问题分析 2 分

21-论述-04 ★★

请结合本课"教师端-查看项目下任务列表"的多表关联查询，说明为什么使用 LEFT JOIN 而非 INNER JOIN，以及 IFNULL 函数在此查询中的作用。

参考答案：

  • 使用 LEFT JOIN 的原因：查询需要返回项目下所有任务，即使某任务还没有任何提交记录。若用 INNER JOIN，无提交的任务会被过滤掉，导致任务列表不完整。LEFT JOIN 保证 task 表的记录全部返回，submission 子查询无匹配时字段为 NULL。
  • IFNULL 的作用：LEFT JOIN 后，若某任务无提交记录，子查询的 cnt 字段为 NULL。直接返回 NULL 会让前端处理麻烦（需判空）。IFNULL(s.cnt, 0) 将 NULL 转换为 0，让 submissionCount 字段始终是整数，便于前端直接显示"提交人数：0"。
  • 延伸：这是 SQL 查询中处理"可能无匹配"场景的常见模式，体现对数据完整性和前端友好性的兼顾。

评分标准（10 分）：

  • LEFT JOIN 原因 4 分
  • IFNULL 作用 4 分
  • 延伸理解 2 分

@Override
@Transactional(rollbackFor = Exception.class)
public Integer batchReview(Long taskId, BatchReviewDTO dto) {
    Task task = taskMapper.selectById(taskId);
    if (task == null) {
        throw new BusinessException(ResultCode.NOT_FOUND.getCode(), "任务不存在");
    }
    int successCount = 0;
    for (ReviewItemDTO item : dto.getReviews()) {
        Submission sub = getById(item.getSubmissionId());
        if (sub == null || !sub.getTaskId().equals(taskId)) {
            throw new BusinessException(ResultCode.PARAM_ERROR.getCode(),
                    "提交" + item.getSubmissionId() + "不属于该任务");
        }
        if (item.getScore() > task.getMaxScore()) {
            throw new BusinessException(ResultCode.PARAM_ERROR.getCode(),
                    "得分不能超过满分" + task.getMaxScore());
        }
        sub.setScore(item.getScore());
        sub.setComment(item.getComment());
        sub.setStatus("GRADED");
        sub.setReviewTime(LocalDateTime.now());
        updateById(sub);
        successCount++;
    }
    return successCount;
}

@Override
public GradeStatisticsVO getGradeStatistics(Long studentId) {
    List<GradeVO> grades = submissionMapper.selectGrades(studentId);
    GradeStatisticsVO vo = new GradeStatisticsVO();
    vo.setGrades(grades);
    if (grades.isEmpty()) {
        vo.setTotalCount(0);
        vo.setAverageScore(0.0);
        vo.setMaxScore(0);
        vo.setMinScore(0);
    } else {
        vo.setTotalCount(grades.size());
        Double avg = grades.stream()
                .mapToInt(GradeVO::getScore)
                .average()
                .orElse(0.0);
        vo.setAverageScore(Math.round(avg * 100) / 100.0);
        vo.setMaxScore(grades.stream().mapToInt(GradeVO::getScore).max().orElse(0));
        vo.setMinScore(grades.stream().mapToInt(GradeVO::getScore).min().orElse(0));
    }
    return vo;
}
