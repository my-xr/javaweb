1.1 单项选择题（30 题）

01-选择-001（★ 知识点：K1-1 后端开发职责） Web 后端开发的核心职责可以概括为以下哪一项？

  • A设计网页界面与用户交互效果
  • B接收请求、处理业务、访问数据、返回结果
  • C部署服务器与配置网络设备
  • D编写 SQL 语句并优化数据库性能

答案：B 解析：后端开发的核心职责是"接收请求 → 处理业务 → 访问数据 → 返回结果"。A 是前端职责；C 偏运维；D 只是后端访问数据的工具之一，不是全部职责。B 涵盖了后端工作的完整链路。

01-选择-002（★ 知识点：K1-1 后端开发职责） 后端程序运行的位置是？

  • A用户的浏览器中
  • B用户的个人电脑本地
  • C服务器端
  • D路由器中

答案：C 解析：后端程序运行在服务器端，用户通过浏览器（前端）发请求访问服务器。A、B 是前端运行位置；D 路由器是网络设备，不运行应用后端。

01-选择-003（★ 知识点：K1-2 B/S 与 C/S） 下列关于 B/S 架构的描述，正确的是？

  • A客户端需要安装专门的程序才能使用
  • B客户端是浏览器，无需安装专门的应用程序
  • C升级时客户端必须重新下载安装
  • D只能在特定操作系统上运行

答案：B 解析：B/S（Browser/Server）架构的客户端是浏览器，无需安装专门程序，天然跨平台。A、C 是 C/S 架构的特点；D 错误，B/S 通过浏览器可跨平台使用。

01-选择-004（★ 知识点：K1-2 B/S 与 C/S） 下列软件中，属于 C/S 架构的是？

  • A淘宝网页版
  • B教务系统网页版
  • C微信 PC 版
  • D在线文档（网页版）

答案：C 解析：微信 PC 版需要安装专用客户端程序，属于 C/S 架构。A、B、D 都通过浏览器访问，属于 B/S 架构。

01-选择-005（★ 知识点：K1-3 前后端分离） 前后端分离开发模式中，后端返回给前端的数据格式通常是？

  • AHTML 页面
  • BJSP 页面
  • CJSON 数据
  • DCSS 样式表

答案：C 解析：前后端分离后，后端只返回 JSON 数据，前端拿到数据后自行渲染界面。A、B 是未分离模式（JSP）的返回形式；D 是前端样式，与后端返回无关。

01-选择-006（★★ 知识点：K1-3 前后端分离） 下列关于前后端分离的说法，正确的是？

  • A前后端分离就是前端和后端部署在两台不同的物理服务器上
  • B前后端分离后，后端仍然负责生成完整的 HTML 页面
  • C前后端分离指前端与后端代码和职责分离，通过 API（JSON）通信
  • D前后端分离后前端不再需要与后端通信

答案：C 解析：前后端分离是指代码与职责的分离，不是物理服务器分离（A 错）。分离后后端只返回 JSON 数据，不生成 HTML（B 错）。前端仍需通过 API 与后端通信获取数据（D 错）。C 准确描述了前后端分离的本质。

01-选择-007（★★ 知识点：K1-2/K1-3） 关于 B/S 架构与前后端分离的关系，下列说法正确的是？

  • AB/S 架构一定就是前后端分离
  • BJSP 开发的 Web 系统属于前后端分离
  • CB/S 架构的客户端是浏览器，但 B/S 不等于前后端分离
  • D前后端分离只能在 C/S 架构中使用

答案：C 解析：B/S 是指客户端用浏览器访问服务器，是一种架构模式；前后端分离是一种开发模式。JSP 也是 B/S，但 HTML 与 Java 混写，未前后端分离。因此 B/S 不等于前后端分离，C 正确。A、B、D 均错误。

01-选择-008（★ 知识点：K1-1 后端开发职责） 下列工作中，不属于 Web 后端开发职责的是？

  • A设计并实现业务逻辑
  • B编写接口供前端调用
  • C访问数据库读写数据
  • D用 CSS 美化页面按钮样式

答案：D 解析：CSS 美化页面是前端职责。A、B、C 都是后端开发的核心职责。

01-选择-009（★ 知识点：K1-4 岗位与流程） 在企业项目研发流程中，"前后端联调"环节通常发生在？

  • A需求分析阶段之前
  • B编码开发之后、测试之前
  • C部署上线之后
  • D运维维护阶段

答案：B 解析：企业流程通常是：需求 → 设计 → 编码 → 联调 → 测试 → 部署 → 维护。联调在编码之后、测试之前进行。

01-选择-010（★ 知识点：K1-4 岗位与流程） 下列哪一项不是 Java 后端开发常用的技术工具？

  • ASpring Boot
  • BMyBatis-Plus
  • CVue.js
  • DMaven

答案：C 解析：Vue.js 是前端框架，不是后端技术。Spring Boot（后端框架）、MyBatis-Plus（持久层）、Maven（构建工具）都是后端常用技术。

01-选择-011（★ 知识点：K1-5 Servlet/JSP 背景） 关于 Servlet 与 Spring Boot 的关系，下列说法正确的是？

  • ASpring Boot 完全抛弃了 Servlet，使用了全新的底层技术
  • BServlet 是 JavaWeb 的底层规范，Spring Boot 底层仍基于 Servlet
  • CServlet 和 Spring Boot 是完全无关的两套技术
  • DSpring Boot 是 Servlet 的前身

答案：B 解析：Servlet 是 JavaWeb 的底层规范，Spring MVC 封装了 Servlet，Spring Boot 又封装了 Spring MVC。因此 Spring Boot 底层仍基于 Servlet，B 正确。

01-选择-012（★★ 知识点：K1-5 Servlet/JSP 背景） 现代 JavaWeb 项目大多选择 Spring Boot 而非直接使用 Servlet，主要原因不包括？

  • AServlet 开发配置繁琐，效率低
  • BSpring Boot 简化了配置，开发效率高
  • CSpring Boot 天然支持前后端分离返回 JSON
  • DServlet 不支持 HTTP 协议

答案：D 解析：Servlet 本身就是为处理 HTTP 请求而设计的，完全支持 HTTP 协议，D 错误。A、B、C 都是选择 Spring Boot 的合理原因。

01-选择-013（★ 知识点：K1-1 后端开发职责） 在一个 Web 系统中，负责持久化存储数据的组件是？

  • A前端
  • B后端
  • C数据库
  • D浏览器

答案：C 解析：数据库负责持久化存储数据（如 MySQL）。后端负责访问数据库，前端负责展示，浏览器是前端运行环境。

01-选择-014（★★ 知识点：K1-3 前后端分离） 传统 JSP 模式被前后端分离模式取代，JSP 的主要问题是？

  • AJSP 不能处理 HTTP 请求
  • BJSP 中 HTML 与 Java 代码混合，前后端耦合，难以维护
  • CJSP 不支持连接数据库
  • DJSP 只能在 Linux 上运行

答案：B 解析：JSP 的核心问题是 HTML 与 Java 混写在同一文件中，前后端耦合，难以分工维护。A、C、D 均错误，JSP 能处理请求、能连数据库、可跨平台。

01-选择-015（★ 知识点：K1-6 CTTS 项目） 校园实训任务管理系统（CTTS）中，不包含以下哪种角色？

  • A学生
  • B教师

答案：D 解析：CTTS 系统包含三种角色：学生、教师、管理员。访客（无登录权限）不是系统定义的角色。

01-选择-016（★ 知识点：K1-6 CTTS 项目） CTTS 系统中，负责"创建实训项目、发布任务、评审学生提交"的角色是？

  • A学生
  • B教师
  • C管理员
  • D所有角色均可

答案：B 解析：教师的职责是创建/维护实训项目、发布任务、评审学生提交。学生负责提交成果，管理员负责用户与基础数据维护。

01-选择-017（★★ 知识点：K1-4 岗位与流程） 后端开发工程师在"需求分析"阶段的主要工作是？

  • A编写 Controller 和 Service 代码
  • B部署项目到服务器
  • C理解业务需求，明确系统要做什么
  • D与前端进行接口联调

答案：C 解析：需求分析阶段的核心是理解业务、明确系统目标。A 是编码阶段；B 是部署阶段；D 是联调阶段。

01-选择-018（★ 知识点：K1-2 B/S 与 C/S） B/S 架构相比 C/S 架构的主要优势是？

  • A能充分利用客户端硬件性能
  • B客户端免安装，升级维护只需更新服务器
  • C适合开发大型 3D 游戏
  • D离线能力强

答案：B 解析：B/S 的客户端是浏览器，免安装、升级只更新服务器即可，易维护。A、C、D 是 C/S 的优势（原生客户端性能强、适合游戏、离线能力强）。

01-选择-019（★★ 知识点：K1-3 前后端分离） 前后端分离带来的好处不包括？

  • A前后端可并行开发，提升效率
  • B同一套后端 API 可服务网页版、APP、小程序
  • C前端和后端代码完全不需要约定即可独立开发
  • D前后端职责清晰，便于维护

答案：C 解析：前后端分离仍需约定接口（请求路径、参数、返回格式）才能协作，并非"完全不需要约定"。C 错误。A、B、D 都是前后端分离的真实好处。

01-选择-020（★ 知识点：K1-5 Servlet/JSP 背景） 下列技术按出现时间从早到晚排序，正确的是？

  • ASpring Boot → Servlet → JSP
  • BJSP → Spring Boot → Servlet
  • CServlet → JSP → Spring Boot
  • DSpring Boot → JSP → Servlet

答案：C 解析：Servlet（1997）最早出现，随后 JSP 在 Servlet 基础上发展，Spring Boot 是较新的现代框架。正确顺序：Servlet → JSP → Spring Boot。

01-选择-021（★ 知识点：K1-1 后端开发职责） 当用户在浏览器点击"查看任务列表"按钮后，下列描述正确的是？

  • A浏览器直接读取本地数据库并显示
  • B前端发起 HTTP 请求，后端处理并返回数据，前端再渲染显示
  • C后端主动推送数据到浏览器
  • D数据库直接将数据发送到浏览器显示

答案：B 解析：Web 请求由前端发起 HTTP 请求，后端接收并处理（访问数据库），返回数据给前端，前端渲染显示。A、C、D 都跳过了正常的请求-响应链路。

01-选择-022（★★ 知识点：K1-3 前后端分离） 在前后端分离模式下，前端工程师和后端工程师协作的"契约"是？

01-选择-025（★★ 知识点：K1-2 B/S 与 C/S） 下列关于手机 APP 与 B/S 架构关系的说法，正确的是？

01-选择-028（★ 知识点：K1-1 后端开发职责） "后端开发就是写 SQL"，这一说法？

01-选择-029（★★ 知识点：K1-5 Servlet/JSP 背景） 对比早期 Servlet 写法与现代 Spring Boot 写法，Spring Boot 的主要优势是？

01-选择-030（★★ 知识点：K1-3/K1-4 综合） 某公司要开发一个"员工考勤系统"，要求网页版和手机 APP 版都能用同一套后端接口。采用前后端分离模式的主要原因是？

答案：B 解析：前后端分离后，后端提供统一的 JSON API，网页版和 APP 版都可调用同一套接口，复用性强。A、C、D 均错误。

01-简答-001（★★ 知识点：K1-3，分值：8 分） 请简述"前后端分离"开发模式与传统 JSP 模式的区别，并说明前后端分离的至少三个好处。

    • 前后端职责清晰，便于维护；
    • 前端可做局部刷新，体验更好。
  3. 表述清晰度（1 分）。

01-简答-002（★★ 知识点：K1-2/K1-3，分值：6 分） 请说明 B/S 架构与 C/S 架构的区别，并解释为什么"B/S 不等于前后端分离"。

  1. B/S 与 C/S 区别（3 分）：
    • B/S：客户端是浏览器，免安装，跨平台，升级只更新服务器；
    • C/S：客户端需安装专用程序，性能强，但升级需重新安装。
  2. B/S 不等于前后端分离的原因（3 分）：
    • B/S 是指客户端用浏览器访问服务器的架构模式；
    • 前后端分离是一种开发模式（前端管界面、后端管数据、JSON 通信）；
    • JSP 也是 B/S 架构，但 HTML 与 Java 混写，前后端未分离；
    • 因此 B/S（架构模式）≠ 前后端分离（开发模式）。

01-简答-003（★★ 知识点：K1-5，分值：6 分） 现代 JavaWeb 项目大多选择 Spring Boot 而非直接使用 Servlet/JSP，请说明至少三个原因。

参考答案要点（每点 2 分，答出 3 点得 6 分）：

  1. 配置繁琐：Servlet/JSP 需要大量 web.xml 配置，易出错；Spring Boot 用注解和自动配置简化，开发效率高。
  2. 前后端耦合：JSP 中 HTML 与 Java 混写，难以分离开发；Spring Boot 天然支持返回 JSON，契合前后端分离。
  3. 开发效率低：Servlet 实现一个简单功能要写 Servlet + 配置 + 页面，步骤多；Spring Boot 注解即可完成。
  4. 难以维护：传统模式业务逻辑、页面、数据访问混在一起；Spring Boot 鼓励分层架构，便于维护。
  5. 生态完善：Spring Boot 起步依赖、内嵌容器、丰富的 starter，开箱即用。

评分标准：每点 2 分，答出任意 3 点给满分 6 分。需说明具体原因，不能只说"Spring Boot 更好"。

01-编程-001（★★ 知识点：K1-3/K1-6，分值：15 分） 题目：为 CTTS 系统设计"学生查看任务列表"接口的请求与响应格式（本题为接口设计题，不要求写完整代码，只要求设计接口契约）。

要求： （1）设计该接口的 HTTP 请求方式与路径（路径需体现 RESTful 风格，资源用名词复数）。（4 分） （2）设计请求参数（如有）。（3 分） （3）设计返回的 JSON 响应结构（需包含统一响应字段 code、message、data，data 中为任务列表）。（5 分） （4）说明该接口体现了前后端分离的哪个特点。（3 分）

输入输出说明：

  • 业务场景：学生登录后查看某个实训项目下的所有任务。
  • 任务包含字段：id、title（任务标题）、deadline（截止时间）、status（任务状态）。

参考答案： （1）请求方式：GET（2 分）；路径：/api/tasks（2 分）。参数 projectId 通过 query 传递。答 GET + /api/tasks 给满分；路径用名词复数 tasks 体现 RESTful。 （2）请求参数：projectId（Long 类型，通过 @RequestParam 或 query string 传递，如 ?projectId=1）（3 分）。 （3）JSON 响应结构（5 分）：

{
  "code": 200,
  "message": "success",
  "data": [
    {"id": 1, "title": "任务1：搭建项目", "deadline": "2026-08-01", "status": "进行中"},
    {"id": 2, "title": "任务2：实现登录", "deadline": "2026-08-10", "status": "未开始"}
  ]
}

评分：含 code/message/data 三个统一字段（2 分），data 为数组（1 分），数组元素含 id/title/deadline/status（2 分）。 （4）体现前后端分离特点：后端只返回 JSON 数据，不返回 HTML 页面，前端拿到 JSON 后自行渲染界面（3 分）。

评分标准：共 15 分，按小题分值给分。第（1）题必须用 GET 且路径用名词复数才算体现 RESTful；第（3）题必须含统一响应结构 code/message/data。

01-编程-002（★★★ 知识点：K1-1/K1-4/K1-6，分值：20 分） 题目：结合 CTTS 系统的"学生提交任务成果"业务，分析并描述该操作中后端需要完成的工作，并设计对应的接口契约。

业务场景：学生登录后，针对某个任务提交自己的实训成果（文本内容），后端需要记录提交信息并更新任务状态。

要求： （1）分析后端在该操作中需要完成的工作（从接收请求、处理业务、访问数据、返回结果四方面分析）。（8 分） （2）设计该接口的 HTTP 请求方式与路径（RESTful 风格）。（3 分） （3）设计请求参数（JSON body 格式，包含必要字段）。（4 分） （4）设计返回的 JSON 响应结构（统一响应格式）。（3 分） （5）说明该接口在设计上应考虑的数据安全或业务校验点（至少 2 点）。（2 分）

输入输出说明：

  • 提交需要记录：任务 ID、学生 ID、提交内容、提交时间。
  • 提交后任务状态应更新为"已提交"。

参考答案： （1）后端需完成的工作（每方面 2 分，共 8 分）：

  • 接收请求：接收学生提交的 POST 请求，获取任务 ID、学生 ID、提交内容等参数；
  • 处理业务：校验学生是否有权提交该任务、任务是否在截止时间内、是否重复提交；生成提交记录、更新任务状态为"已提交"；
  • 访问数据：向 task_submission 表插入提交记录，更新 task 表中对应任务状态；
  • 返回结果：返回提交成功/失败的 JSON 响应。 （2）请求方式：POST（1 分）；路径：/api/submissions（2 分）。POST 用于新增资源，submissions 为名词复数。 （3）请求参数（JSON body，4 分）：
{
  "taskId": 1,
  "studentId": 1001,
  "content": "这是我的实训成果..."
}

评分：包含 taskId、studentId、content 三个关键字段（每缺一个扣 1.5 分），格式为 JSON（0.5 分）。 （4）返回响应（3 分）：

{
  "code": 200,
  "message": "提交成功",
  "data": {"submissionId": 501, "status": "已提交"}
}

评分：含统一字段 code/message/data（2 分），data 含提交结果（1 分）。 （5）数据安全/业务校验点（每点 1 分，答出 2 点得 2 分）：

  • 校验学生身份（是否登录、是否为该任务所属学生）；
  • 校验截止时间（是否已过截止时间）；
  • 防重复提交（同一学生对同一任务是否已提交）；
  • 校验任务是否存在；
  • 提交内容长度/合法性校验。

评分标准：共 20 分，按小题分值给分。第（1）题需从四个方面分析，每方面 2 分；第（5）题答出任意 2 点给满分。本题考察综合分析能力，为本次课综合题。
