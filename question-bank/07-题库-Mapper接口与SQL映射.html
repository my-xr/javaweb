07-单选-01 ★

题目：在 MyBatis-Plus 中，将 Mapper 接口注册到 Spring 容器的两种注解是？

  • A
    @Mapper 和 @MapperScan
  • B
    @Repository 和 @Mapper
  • C
    @Component 和 @MapperScan
  • D
    @Service 和 @Mapper

答案：A 解析：@Mapper 标注在接口上逐个声明；@MapperScan 标注在启动类上批量扫描 mapper 包。两者二选一，不要同时使用。

07-单选-02 ★

题目：@MapperScan 注解通常标注在哪个类上？

  • A
    Mapper 接口
  • B
    实体类
  • C
    启动类（@SpringBootApplication）
  • D
    Controller 类

答案：C 解析：@MapperScan 标注在启动类或任意 @Configuration 类上，批量扫描指定包下的所有 Mapper 接口。

07-单选-03 ★

题目：CTTS 项目启动类上有 @MapperScan("com.ctts.mapper")，以下说法正确的是？

  • A
    com.ctts.mapper 包下的所有接口都会被视为 Mapper
  • B
    com.ctts.mapper 包下的所有类都会被视为 Mapper
  • C
    只有加了 @Mapper 注解的接口才会被扫描
  • D
    只扫描 com.ctts.mapper 包，不扫描子包

答案：A 解析：@MapperScan 扫描指定包及其子包下的所有接口，将其视为 Mapper 注册为 Bean，无需再加 @Mapper 注解。

07-单选-04 ★

    主键类型
  • B

  • D

07-单选-05 ★

07-单选-08 ★

题目：实体类 SysUser 对应表 sys_user，应使用哪个注解映射表名？

    @Table
  • B
    @TableName("sys_user")
  • C
    @Entity("sys_user")
  • D
    @TableField("sys_user")

答案：B 解析：MyBatis-Plus 用 @TableName("表名") 注解映射实体类与数据库表名。@TableField 用于字段映射，@Entity 是 JPA 注解。

07-单选-09 ★

题目：实体类主键 id 是数据库自增的，@TableId 应配置为？

    @TableId(type = IdType.NONE)

    @TableId(type = IdType.ASSIGN_ID)
  • D
    @TableId(type = IdType.UUID)

07-单选-10 ★

题目：实体类中有 confirmPassword 字段，但数据库表中无此列，应如何标注？

    @TableField(exist = true)

    @TableField(exist = false)
  • D
    @TableField(ignore = true)

答案：C 解析：@TableField(exist = false) 表示该字段在数据库表中不存在，不参与 CRUD 映射。常用于前端校验字段、计算字段等。

07-单选-11 ★

    createTime → createtime
  • B
    createTime → create_time
  • C
    createTime → Create_Time
  • D
    createTime → create-Time

07-单选-12 ★

题目：注解 SQL 中，#{username} 的作用是？

  • A
    字符串拼接
  • B
    预编译占位符
  • C
    注释
  • D
    变量声明

答案：B 解析：#{param} 是预编译占位符，被 MyBatis 替换为 JDBC 的 ?，参数通过 PreparedStatement.setXxx() 绑定，防 SQL 注入。

07-单选-13 ★

题目：以下哪种参数绑定方式会导致 SQL 注入风险？

  • A
    #{param}
  • B
    ${param}
  • C
    ?param
  • D
    :param

答案：B 解析：${param} 是字符串拼接，直接把参数值拼入 SQL 字符串，可被注入恶意 SQL。#{param} 是预编译占位符，安全。

07-单选-14 ★

题目：查询 sys_user 表中按用户名模糊查询的注解 SQL 写法，正确的是？

  • A
    @Select("SELECT * FROM sys_user WHERE username LIKE '%#{keyword}%'")
  • B
    @Select("SELECT * FROM sys_user WHERE username LIKE '%${keyword}%'")
  • C
    @Select("SELECT * FROM sys_user WHERE username LIKE CONCAT('%', #{keyword}, '%')")
  • D
    @Select("SELECT * FROM sys_user WHERE username LIKE CONCAT('%', ${keyword}, '%')")

答案：C 解析：#{} 在单引号内不会被解析，A 错；B、D 用 ${} 有注入风险；C 用 CONCAT 函数配合 #{}，安全且正确。

07-单选-21 ★★

题目：以下 @Select 写法中，多参数绑定正确的是？

  • A
    @Select("... WHERE role = #{role} AND status = #{status}") List<SysUser> select(String role, String status);
  • B
    @Select("... WHERE role = #{role} AND status = #{status}") List<SysUser> select(@Param("role") String role, @Param("status") String status);
  • C
    @Select("... WHERE role = ${role} AND status = ${status}") List<SysUser> select(String role, String status);
  • D
    @Select("... WHERE role = ? AND status = ?") List<SysUser> select(String role, String status);

答案：B 解析：多参数必须用 @Param("名") 显式指定参数名，MyBatis 才能将 #{role} 与 #{status} 正确绑定到对应参数。A 缺 @Param 会报错；C 用 ${} 有注入风险；D 不能用 ? 占位符。

07-单选-22 ★★

题目：关于 @Mapper 和 @MapperScan 的使用，以下说法正确的是？

  • A
    必须同时使用才能生效
  • B
    二选一即可，推荐用 @MapperScan
  • C
    @Mapper 比 @MapperScan 性能更好
  • D
    @MapperScan 只能扫描一个包

答案：B 解析：两者二选一即可，不要同时使用。@MapperScan 批量扫描更省事，新增 Mapper 无需改注解，是项目推荐方式。@MapperScan 支持扫描多个包：@MapperScan({"com.ctts.mapper", "com.ctts.ext"})。

07-单选-23 ★★

题目：userMapper.updateById(user) 方法，若 user 的某字段为 null，该字段会被更新到数据库吗？

  • A
    会，更新为 null
  • B
    不会，null 字段不参与 UPDATE
  • C
    取决于数据库配置
  • D
    报空指针异常

答案：B 解析：MyBatis-Plus 默认策略 FieldStrategy.NOT_NULL，null 字段不会被拼入 UPDATE 语句，避免误覆盖。若需更新为 null，需用 UpdateWrapper.set("字段", null) 或调整字段策略。

07-单选-24 ★★

题目：XML 中 resultMap 与 resultType 的关系是？

  • A
    必须同时使用
  • B
    二选一，不能同时用
  • C
    resultType 优先级更高
  • D
    resultMap 优先级更高

答案：B 解析：<select> 标签中 resultMap 与 resultType 只能选一个。resultType 直接指定返回类型（要求字段名与属性名一致或驼峰映射）；resultMap 引用 <resultMap> 定义，处理复杂映射。

07-单选-25 ★★

题目：以下哪种场景必须使用 ${} 而不能用 #{}？

  • A
    WHERE 条件值
  • B
    INSERT VALUES 值
  • C
    动态排序字段（ORDER BY 后的列名）
  • D
    LIKE 模糊查询值

答案：C 解析：动态排序字段（ORDER BY ${column}）不能用 #{}，因为 #{} 会被替换为 ? 占位符，而 ORDER BY ? 在 SQL 语法中非法。表名/列名/排序方向都只能用 ${}，且必须做白名单校验。

07-单选-26 ★★

题目：调用 userMapper.selectBatchIds(Arrays.asList(1L, 2L, 3L)) 生成的 SQL 是？

    SELECT * FROM sys_user WHERE id = 1 AND id = 2 AND id = 3
  • B
    SELECT * FROM sys_user WHERE id IN (1, 2, 3)
  • C
    SELECT * FROM sys_user WHERE id = 1 OR id = 2 OR id = 3
  • D
    SELECT * FROM sys_user WHERE id BETWEEN 1 AND 3

答案：B 解析：selectBatchIds 接收集合参数，生成 WHERE id IN (...) 的批量查询 SQL。

07-单选-27 ★★

题目：实体类字段使用基本类型 int status 与包装类型 Integer status，以下说法正确的是？

  • A
    两者完全等价
  • B
    基本类型默认值 0，会被 MyBatis-Plus 误认为有值参与更新
  • C
    包装类型默认 0，会被误更新
  • D
    基本类型性能更好，推荐使用

答案：B 解析：基本类型 int 默认值为 0（不是 null），MyBatis-Plus 会认为该字段"有值"而参与 UPDATE，可能误覆盖数据库中的 null。包装类型 Integer 默认 null，不参与更新，更安全。实体类字段一律用包装类型。

07-单选-28 ★★

题目：若 XML 文件放在 src/main/resources/xml/ 目录下，application.yml 应如何配置？

答案：B 解析：classpath: 前缀表示从类路径（src/main/resources 编译后到 target/classes）下查找。XML 在 resources/xml/ 下，对应 classpath:xml/*.xml。

07-单选-29 ★★

题目：调用 userMapper.selectOne(wrapper) 时，若查询结果有多条记录，会发生什么？

  • A
    返回第一条
  • B
    返回最后一条
  • C
    抛出 TooManyResultsException
  • D
    返回 null

07-单选-30 ★★★

题目：以下关于 #{} 与 ${} 的说法，错误的是？

  • A
    #{} 通过预编译占位符防注入，参数会被转义
  • B
    ${} 是字符串拼接，有 SQL 注入风险
  • C
    #{} 会被替换为 JDBC 的 ? 占位符
  • D
    #{} 和 ${} 功能完全等价，可以互换使用

答案：D 解析：D 错误。两者本质完全不同：#{} 是预编译占位符（替换为 ?，参数转义，防注入）；${} 是字符串拼接（直接拼入 SQL，有注入风险）。绝大多数场景用 #{}，仅动态表名/列名/排序方向用 ${} 且需白名单校验。

区别与定义：

  • @Mapper 是接口级注解，标注在每个 Mapper 接口上，逐个声明该接口为 Mapper。

// 方式一：@Mapper 逐个声明
@Mapper
public interface SysUserMapper extends BaseMapper<SysUser> { ... }

// 方式二：@MapperScan 批量扫描（推荐）
@SpringBootApplication

public class CttsApplication { ... }
// mapper 包下的接口无需加 @Mapper

适用场景：

  • @Mapper：Mapper 数量少；接口分散在多个不同包；只需个别接口注册。

07-论述-02 ★★★

题目：详细说明 #{} 与 ${} 的本质区别、执行原理、防注入机制，并举例说明各自的适用场景与禁用场景。

评分标准（10分）：

  • 本质区别说明（2分）
  • 执行原理（预编译 vs 拼接）（3分）
  • 防注入机制（2分）
  • 适用场景与禁用场景举例（3分）

参考答案：

本质区别：

  • #{} 是预编译占位符，被 MyBatis 替换为 JDBC 的 ?，参数通过 PreparedStatement.setXxx() 绑定。
  • ${} 是字符串拼接，直接把参数值原样拼入 SQL 字符串中。

执行原理：

  • #{}：SELECT * FROM sys_user WHERE username = #{username} → 解析为 SELECT * FROM sys_user WHERE username = ? → PreparedStatement.setString(1, "admin' OR '1'='1") → 参数被 JDBC 驱动转义，作为纯字符串值传递。
  • ${}：SELECT * FROM sys_user WHERE username = '${username}' → 直接拼接为 SELECT * FROM sys_user WHERE username = 'admin' OR '1'='1' → 原样执行。

防注入机制：

  • #{} 通过预编译使参数不参与 SQL 语法解析——参数值永远被当作数据而非代码，即使含 '、;、-- 等特殊字符也会被转义，从根本上防止注入。
  • ${} 拼接后参数参与 SQL 语法解析，攻击者可注入任意 SQL 片段。

适用场景：

  • #{}：WHERE 条件值、INSERT VALUES、UPDATE SET、LIKE 模糊查询值（配合 CONCAT）等所有参数值场景。
  • ${}：动态表名（FROM ${table}）、动态列名（ORDER BY ${column}）、动态排序方向（ORDER BY x ${order}）——这些位置不能用 ? 占位符。

禁用场景：

  • 禁止用 ${} 处理用户输入的查询条件、登录用户名密码等——会导致 SQL 注入。
  • ${} 用于动态表名/列名时必须做白名单校验，只允许预定义合法值。

07-论述-03 ★★

题目：对比注解 SQL 与 XML SQL 两种 SQL 映射方式的优缺点及适用场景，并说明 CTTS 项目为何同时使用两种方式。

评分标准（10分）：

  • 两种方式特点说明（4分，每种2分）
  • 优缺点对比（3分）
  • 适用场景与 CTTS 选择理由（3分）

参考答案：

注解 SQL 特点：SQL 直接写在 Mapper 接口方法上的 @Select/@Insert/@Update/@Delete 注解中。

  • 优点：简洁直观，SQL 与方法定义在一起，便于查看；无需额外 XML 文件。
  • 缺点：不支持动态标签（<if>/<where>/<foreach>）；复杂 SQL 写在注解中可读性差；修改 SQL 需重新编译。
  • 适用场景：简单、固定的 SQL，如按主键查询、按单条件查询。

XML SQL 特点：SQL 写在独立的 XxxMapper.xml 文件中，通过 namespace 与接口绑定。

  • 优点：支持动态 SQL 标签，适合复杂条件查询；SQL 与 Java 代码分离，便于维护；可复用 <sql> 片段。
  • 缺点：文件较多，配置相对繁琐；需注意 namespace 与 id 的对应关系。
  • 适用场景：复杂动态 SQL，多条件查询，多表关联查询。

CTTS 项目同时使用两种方式的原因：

  • SysUserMapper 用注解 SQL：用户查询相对简单（按角色、按用户名模糊查询），注解足够表达。
  • TrainingProjectMapper 用 XML SQL：项目查询后续会扩展为多条件动态查询（状态+教师+日期范围），XML 的 <if> 标签更适合。
  • 这样设计既让学生对比两种写法，又符合企业实践——简单查询用注解，复杂查询用 XML，两者可在同一项目混用。
